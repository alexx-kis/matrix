# React Portals — порталы в React

- разберём тему с нуля: что такое Portal, зачем он нужен, как он работает внутри React, чем отличается React-дерево от DOM-дерева и почему события продолжают всплывать через порталы
- отдельно рассмотрим практические примеры, типичные ошибки и вопросы, которые могут задать на собеседовании

## 1. что такое Portal и зачем он нужен

- в React мы обычно создаём компоненты, а React превращает их в элементы DOM, которые браузер отображает на странице
- чаще всего DOM-элементы компонента находятся внутри DOM-элемента его родителя, поэтому визуальная структура страницы примерно соответствует структуре компонентов
- но иногда нам нужно, чтобы компонент оставался частью определённой ветки React, но физически отображался в совершенно другом месте DOM-дерева
- для этого и существуют Portals — порталы
- Portal позволяет отрисовать содержимое React-компонента в DOM-узле, который находится вне обычного DOM-контейнера этого компонента
- например, представим приложение с такой структурой:

```js
function App() {
  return (
    <div className='app'>
      <h1>моя страница</h1>
      <Modal />
    </div>
  );
}
```

- обычный компонент `Modal` отрисуется внутри `.app`, потому что именно там React размещает его DOM-элементы
- но модальное окно часто удобнее разместить непосредственно внутри `body`, чтобы оно не зависело от ограничений родительских элементов
- можно создать отдельный DOM-узел для модальных окон и использовать его как цель портала

```jsx
<body>
  <div id='root'></div>
  <div id='modal-root'></div>
</body>
```

- `#root` — контейнер основного React-приложения
- `#modal-root` — отдельный DOM-контейнер, в который мы будем выводить содержимое модального окна
- оба контейнера находятся в одном DOM-документе, но являются соседними узлами, а не вложенными друг в друга

## 2. как создать Portal

- для создания портала React предоставляет функцию `createPortal`, которую нужно импортировать из `react-dom`

```js
import { createPortal } from 'react-dom';

function Modal() {
  return createPortal(
    <div className='modal'>
      <h2>подтверждение действия</h2>
      <p>вы действительно хотите продолжить?</p>
    </div>,
    document.getElementById('modal-root'),
  );
}
```

- у `createPortal` два основных аргумента: React-содержимое, которое нужно отрисовать, и DOM-узел, в который его нужно поместить
- первый аргумент — обычный JSX, который может содержать любые элементы и компоненты React
- второй аргумент — уже существующий DOM-элемент, например результат `document.getElementById('modal-root')`
- обратите внимание: `createPortal` не создаёт сам DOM-контейнер, а использует переданный ему контейнер
- если `document.getElementById('modal-root')` вернёт `null`, потому что такого узла нет в документе, портал не сможет корректно отрисоваться
- при использовании TypeScript это тоже важно учитывать, поскольку `getElementById` возвращает тип `HTMLElement | null`
- теперь компонент `Modal` можно использовать в обычном React-дереве

```js
function App() {
  return (
    <div className='app'>
      <h1>главная страница</h1>
      <Modal />
    </div>
  );
}
```

- с точки зрения React компонент `Modal` остаётся дочерним компонентом `App`
- но с точки зрения DOM содержимое модального окна находится внутри `#modal-root`, а не внутри `.app`
- это ключевая особенность порталов: место компонента в React-дереве и место его DOM-элементов в DOM-дереве могут различаться

## 3. зачем нужны порталы на практике

- главная причина использования порталов — возможность разместить интерфейсный элемент в другом месте DOM-дерева, сохранив его связь с исходным React-компонентом
- чаще всего порталы применяют для следующих элементов

### модальные окна

- модальное окно часто должно перекрывать всю страницу и располагаться поверх остальных элементов
- если поместить его внутрь элемента с `overflow: hidden`, часть окна может оказаться обрезанной
- если у предка есть определённые CSS-свойства, например `transform`, они могут изменить поведение позиционирования или контекст наложения элементов
- портал позволяет вынести окно в отдельный DOM-контейнер и упростить управление его положением и слоями

### всплывающие подсказки и выпадающие меню

- меню может открываться рядом с кнопкой, но при этом выходить за границы контейнера, внутри которого находится кнопка
- портал позволяет разместить меню в отдельном контейнере и избежать некоторых ограничений родительской разметки

### уведомления

- уведомления часто выводят в отдельную область страницы, например в правом верхнем углу
- их удобно хранить в отдельном DOM-контейнере, независимо от того, из какого компонента приложения они были вызваны
- важно понимать, что портал не решает автоматически все проблемы с CSS: для правильного позиционирования, `z-index`, доступности и поведения на мобильных устройствах всё равно может потребоваться дополнительная работа

## 4. что происходит внутри React

- здесь нужно чётко разделять два понятия: React-дерево и DOM-дерево
- React-дерево — это структура компонентов и отношений между ними, которую React использует для организации приложения
- DOM-дерево — это реальная структура HTML-элементов в документе браузера
- рассмотрим пример

```js
function ModalContent() {
  return createPortal(<button>нажми меня</button>, document.getElementById('modal-root'));
}

function PageContent() {
  return (
    <section>
      <h2>основная страница</h2>
      <ModalContent />
    </section>
  );
}
```

- в React-дереве `ModalContent` остаётся внутри `PageContent`, потому что один компонент используется внутри JSX другого
- в DOM-дереве кнопка окажется в `#modal-root`, а не внутри `section`
- следовательно, портал меняет место размещения DOM-элементов, но не меняет логическое родительство компонентов в React
- из этого следуют два важных свойства
- первое: контекст React продолжает работать через портал, поэтому компонент внутри портала может получать значение из подходящего `Context.Provider`, расположенного выше него в React-дереве
- второе: события React могут всплывать к родительским компонентам по React-дереву, даже если DOM-элементы физически находятся в разных ветках DOM
- второе свойство особенно важно для собеседований, поэтому разберём его отдельно

## 5. всплытие событий через Portal — event bubbling

- в браузере событие обычно проходит через DOM-элементы, связанные отношением вложенности
- этот процесс называется event bubbling — всплытие события
- например, если кнопка находится внутри `div`, то при клике на кнопку событие `click` может дойти до обработчика на этом `div`
- но с порталами возникает интересная ситуация: React сохраняет логическую связь компонентов, даже если их DOM-элементы не вложены друг в друга
- рассмотрим пример

```js
function PortalButton() {
  return createPortal(
    <button onClick={() => console.log('клик по кнопке')}>нажми меня</button>,
    document.getElementById('modal-root'),
  );
}

function ParentContainer() {
  return (
    <div onClick={() => console.log('клик по родителю')}>
      <h2>родительский компонент</h2>
      <PortalButton />
    </div>
  );
}
```

- предположим, что `#modal-root` находится рядом с `#root` внутри `body`, поэтому кнопка физически не находится внутри `div` компонента `ParentContainer`
- если нажать на кнопку, в консоли появятся сообщения в таком порядке

```
клик по кнопке
клик по родителю
```

- почему срабатывает обработчик родителя, если кнопка не является его DOM-потомком?
- потому что React распространяет событие через дерево React-компонентов, а не только через физическую структуру DOM
- в нашем примере `PortalButton` логически является потомком `ParentContainer`, поэтому обработчик родителя получает событие, пришедшее от кнопки внутри портала
- запомните различие: нативное всплытие DOM-события следует структуре DOM, а всплытие синтетических событий React учитывает структуру React-дерева
- React использует собственную систему обработки событий, часто называемую системой синтетических событий — Synthetic Events
- это не означает, что браузер вообще не участвует в обработке кликов: React опирается на браузерные события, но организует обработчики с учётом своей модели событий и дерева компонентов

## 6. как остановить всплытие события через Portal

- допустим, у нас есть родительский компонент, который реагирует на клики, но клик внутри модального окна не должен запускать действие родителя
- поскольку событие всплывает по React-дереву, обычная логика обработчиков родителя всё ещё имеет значение
- для остановки всплытия можно использовать `event.stopPropagation()`

```js
function IsolatedModal() {
  return createPortal(
    <div className='modal' onClick={(event) => event.stopPropagation()}>
      <button onClick={() => console.log('действие выполнено')}>подтвердить</button>
    </div>,
    document.getElementById('modal-root'),
  );
}

function ClickableParent() {
  return (
    <div onClick={() => console.log('клик по родителю')}>
      <h2>родительский компонент</h2>
      <IsolatedModal />
    </div>
  );
}
```

- если нажать на кнопку, событие сначала попадёт в обработчик самой кнопки, затем дойдёт до обработчика `div.modal`, где вызов `stopPropagation()` остановит дальнейшее всплытие
- обработчик `ClickableParent` не сработает, поскольку событие не будет распространяться дальше по React-дереву
- здесь важно понимать, что `stopPropagation()` не отменяет уже выполненные обработчики и не отменяет само действие кнопки
- этот метод останавливает дальнейшее распространение события, но не является универсальным способом запретить любые другие обработчики
- также не путайте `stopPropagation()` с `preventDefault()`: первый останавливает распространение события, а второй предотвращает стандартное действие браузера, если оно предусмотрено для данного события

## 7. какие ещё нюансы нужно знать

### портал не изолирует компонент от контекста

- если компонент находится внутри `Context.Provider` в React-дереве, он может получать значение этого контекста даже тогда, когда его DOM-элементы размещены через Portal в другом месте документа

```js
import { createContext, useContext } from 'react';
import { createPortal } from 'react-dom';

const ThemeContext = createContext('light');

function ThemeModal() {
  const themeValue = useContext(ThemeContext);

  return createPortal(
    <div className={themeValue}>текущее значение темы: {themeValue}</div>,
    document.getElementById('modal-root'),
  );
}

function ThemedApp() {
  return (
    <ThemeContext.Provider value='dark'>
      <ThemeModal />
    </ThemeContext.Provider>
  );
}
```

- хотя содержимое портала находится в другом DOM-контейнере, `ThemeModal` получает значение `dark`, потому что провайдер является его предком в React-дереве

### портал не создаёт отдельное React-приложение

- `createPortal` не запускает новое React-приложение и не создаёт независимое дерево компонентов
- компоненты внутри портала по-прежнему участвуют в обновлениях исходного React-дерева, используют его контексты и могут получать события от своих React-родителей

### контейнер портала должен существовать

- если мы передаём в `createPortal` результат `document.getElementById('modal-root')`, необходимо убедиться, что DOM-узел уже существует
- в браузере обращение к `document` допустимо, но при серверном рендеринге `document` обычно недоступен, поэтому такой код нельзя безоговорочно выполнять на сервере
- в приложениях с SSR контейнер обычно получают на клиенте, например после монтирования компонента, и только затем отображают портал

### изменение контейнера может привести к пересозданию содержимого

- если при следующем рендере передать в `createPortal` другой DOM-контейнер, React удалит содержимое из старого контейнера и создаст его в новом
- поэтому смена контейнера может привести к размонтированию и повторному монтированию компонентов внутри портала

### портал не отменяет правила доступности

- для модального окна по-прежнему важно правильно управлять фокусом, поддерживать клавиатурную навигацию, закрытие по `Escape` и доступные для вспомогательных технологий атрибуты
- использование `createPortal` решает задачу размещения DOM-элементов, а не все задачи поведения модального окна

## 8. частые ошибки на собеседовании

- ошибка № 1: «портал перемещает компонент в другое место React-дерева» — нет, он размещает содержимое в другом DOM-контейнере, сохраняя логическую связь компонентов
- ошибка № 2: «события внутри портала не всплывают к родителям» — всплытие синтетических событий React продолжается по React-дереву, даже если DOM-элементы не вложены друг в друга
- ошибка № 3: «портал нужен только для модальных окон» — нет, его также используют для меню, подсказок, уведомлений и других элементов, которым удобно иметь отдельное место в DOM
- ошибка № 4: «портал создаёт независимое React-приложение» — нет, он остаётся частью исходного React-дерева
- ошибка № 5: «с помощью портала можно решить любую проблему с `z-index`» — нет, портал может помочь избежать некоторых ограничений позиционирования, но правильные слои и стили всё равно нужно настраивать

## 9. как ответить на собеседовании

- если попросят кратко объяснить, что такое Portal, можно ответить так

- React Portal — это механизм, позволяющий отрисовывать содержимое React-компонента в произвольном DOM-узле, который может находиться вне DOM-контейнера этого компонента
- для создания портала используется `createPortal` из `react-dom`, которая принимает React-содержимое и DOM-контейнер
- порталы часто применяются для модальных окон, выпадающих меню и уведомлений, поскольку помогают размещать эти элементы отдельно от основной DOM-структуры приложения
- при этом портал не меняет логическую структуру React-компонентов: контекст продолжает работать, а синтетические события React могут всплывать к родителям по React-дереву, даже если DOM-элементы физически не вложены друг в друга
