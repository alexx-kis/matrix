## props

- `props` — это объект с данными, которые **родительский компонент передаёт дочернему компоненту**
- они нужны для того, чтобы компоненты могли обмениваться данными сверху вниз по дереву React-компонентов
- можно представить это как аргументы функции: родитель вызывает дочерний компонент и передаёт ему некоторый набор значений

### что именно находится в props

- например, есть родительский компонент, которому нужно передать дочернему имя пользователя

```jsx
function UserPage() {
  return <UserCard name='Alex' age={25} />;
}
```

- здесь `UserPage` — родитель, а `UserCard` — дочерний компонент
- значения `name` и `age` становятся `props` дочернего компонента

```jsx
function UserCard(props) {
  console.log(props.name);
  console.log(props.age);

  return <h1>{props.name}</h1>;
}
```

- фактически в дочерний компонент приходит объект примерно такого вида

```js
{
  name: "Alex",
  age: 25
}
```

- поэтому можно обращаться к `props.name`, `props.age` и другим переданным значениям

### props и children

- содержимое между открывающим и закрывающим тегом компонента также передаётся через `props`, но находится в специальном свойстве `children`

```jsx
function UserCard(props) {
  return <div>{props.children}</div>;
}
```

- при таком использовании

```jsx
<UserCard>
  <span>Hello</span>
</UserCard>
```

- в `props.children` окажется `<span>Hello</span>`

### почему props readonly

- `props` являются **входными данными компонента**, а не его собственностью
- дочерний компонент не должен самостоятельно изменять данные, которые ему передал родитель
- поэтому нельзя делать что-то вроде

```jsx
function UserCard(props) {
  props.name = 'Bob';

  return <h1>{props.name}</h1>;
}
```

- концептуально это нарушает одно из фундаментальных правил React — **данные движутся сверху вниз, от родителя к ребёнку**

- если ребёнку разрешить произвольно менять `props`, родителю становится непонятно, какое сейчас значение он фактически передал компоненту

- это делает поток данных непредсказуемым и значительно усложняет отслеживание изменений

- важно понимать, что `readonly` здесь означает не обязательно физическую неизменяемость самого JavaScript-объекта на уровне языка

- это прежде всего **правило модели React** — компонент должен воспринимать `props` как входные данные и не мутировать их

- React ожидает от компонента примерно такую модель

```
props → component → UI
```

- получил входные данные
- на их основе вычислил результат
- вернул UI
- но не изменил сами входные данные

### почему тогда компонент может что-то менять

- если дочернему компоненту нужно изменить состояние, он использует собственный `state`

- если нужно сообщить родителю об изменении, используется функция, которую родитель передал через `props`

- например, родитель хранит счётчик

```jsx
function CounterPage() {
  const [count, setCount] = React.useState(0);

  return <Counter count={count} onIncrement={() => setCount(count + 1)} />;
}
```

- дочерний компонент получает `count` и функцию `onIncrement`

```jsx
function Counter(props) {
  return (
    <div>
      <span>{props.count}</span>
      <button onClick={props.onIncrement}>+</button>
    </div>
  );
}
```

- когда пользователь нажимает кнопку, `Counter` **не изменяет `props.count`**
- вместо этого он вызывает `props.onIncrement()`
- функция выполняется уже в родительском компоненте и изменяет его `state`
- после изменения `state` родитель ререндерится и передаёт ребёнку новое значение `count`

### как организовать reverse data flow

- обычный поток данных в React направлен

```
parent
   ↓
child
```

- но иногда ребёнок должен сообщить родителю о каком-то событии
- например, ребёнок получил пользовательский ввод и хочет сообщить родителю новое значение
- React не заставляет нас напрямую передавать данные снизу вверх
- вместо этого родитель передаёт ребёнку **callback-функцию**

```
parent
   ↓
callback
   ↓
child
   │
   └── вызывает callback
           ↓
        parent
```

- например

```jsx
function SearchPage() {
  const [query, setQuery] = React.useState('');

  function handleQueryChange(value) {
    setQuery(value);
  }

  return <SearchInput onQueryChange={handleQueryChange} />;
}
```

- ребёнок получает функцию через `props`

```jsx
function SearchInput(props) {
  function handleInput(event) {
    props.onQueryChange(event.target.value);
  }

  return <input onChange={handleInput} />;
}
```

- здесь важно увидеть главное

- `SearchInput` не получает прямого доступа к `setQuery`

- родитель сам решает, **что именно произойдёт**, когда ребёнок сообщит о событии

- ребёнок лишь вызывает переданную ему функцию и передаёт необходимые данные

- поэтому термин **reverse data flow** немного условный

- сами `props` по-прежнему идут только сверху вниз

- снизу вверх идёт не `prop`, а **вызов функции**, которую родитель передал ребёнку

### что нужно уметь объяснить на собеседовании

- `props` — это объект входных данных, который родитель передаёт дочернему компоненту
- props используются для конфигурации компонентов и передачи между ними данных
- props считаются readonly, потому что дочерний компонент не должен мутировать данные, которыми управляет родитель
- React придерживается однонаправленного потока данных — данные передаются от родителя к ребёнку
- для коммуникации ребёнка с родителем родитель передаёт callback через `props`
- ребёнок вызывает callback и при необходимости передаёт ему данные
- после этого родитель может изменить свой `state`, что приведёт к новому рендеру и передаче новых `props` ребёнку
- таким образом, **данные всё равно движутся сверху вниз, а события/сигналы об изменениях могут инициироваться снизу вверх**
