# patterns в React: condition render, render props, HOC и custom HOC

- разберём четыре темы с нуля, чтобы ты мог не просто написать код на собеседовании, а объяснить, какую проблему решает каждый паттерн, как он работает и когда его стоит применять

- сначала важно понять общую идею: паттерн (pattern) — это типичный способ организовать код для решения повторяющейся задачи, а не специальная команда или встроенная функция React

- в React паттерны помогают управлять отображением компонентов, переиспользовать логику и не дублировать один и тот же код в разных местах

## 1. condition render — условный рендеринг

### что это такое и зачем нужно

- условный рендеринг — это способ определить, что именно React должен отобразить, исходя из определённого условия

- представь, что у тебя есть приложение с авторизацией: если пользователь вошёл в аккаунт, нужно показать личный кабинет, а если нет — форму входа

- можно было бы создать два отдельных приложения, но это избыточно, потому что достаточно проверить одно условие и отобразить нужный компонент

```js
function AccountPanel() {
  const isAuthorized = true;

  if (isAuthorized) {
    return <h1>личный кабинет</h1>;
  }

  return <h1>вход в аккаунт</h1>;
}
```

- React вызовет функцию `AccountPanel`, получит JSX и отобразит его, а при следующем рендере компонент может вернуть уже другой JSX в зависимости от значения `isAuthorized`

### основные способы условного рендеринга

#### способ 1 — `if`

- используется, когда условия сложные или когда для разных случаев нужно возвращать существенно разную разметку

```js
function UserGreeting() {
  const isLoggedIn = true;

  if (isLoggedIn) {
    return <h1>с возвращением!</h1>;
  }

  return <h1>пожалуйста, войдите</h1>;
}
```

- `return` завершает выполнение функции, поэтому после первого сработавшего `return` оставшийся код этой функции уже не выполняется

#### способ 2 — тернарный оператор

- тернарный оператор позволяет выбрать одно из двух выражений по условию и особенно удобен непосредственно внутри JSX

```js
function AccessMessage() {
  const hasAccess = false;

  return <div>{hasAccess ? <p>доступ разрешён</p> : <p>доступ запрещён</p>}</div>;
}
```

- его структура выглядит так: `условие ? значениеЕслиИстина : значениеЕслиЛожь`

- если `hasAccess` равен `true`, отобразится первый элемент, а если `false` — второй

- тернарный оператор возвращает значение, поэтому его можно использовать внутри JSX, в отличие от обычного `if`, который нельзя напрямую поместить внутрь фигурных скобок JSX как выражение

#### способ 3 — логический оператор `&&`

- используется, когда нужно отобразить элемент только при выполнении условия, а в противном случае не отображать ничего

```js
function NotificationBadge() {
  const hasNotifications = true;

  return (
    <div>
      <h2>уведомления</h2>
      {hasNotifications && <span>есть новые уведомления</span>}
    </div>
  );
}
```

- если `hasNotifications` равен `true`, выражение справа от `&&` будет отображено, а если `false`, React не отобразит булево значение `false`

- важный нюанс для собеседования: не каждое ложное значение одинаково безопасно использовать слева от `&&`

```js
function CartCounter() {
  const itemCount = 0;

  return <div>{itemCount && <span>товаров: {itemCount}</span>}</div>;
}
```

- здесь на странице может появиться `0`, потому что оператор `&&` возвращает первый операнд, если он ложный, а React отображает числовые значения

- это одна из распространённых ошибок в React

- правильнее явно преобразовать число в логическое условие или проверить его отдельно

```js
function SafeCartCounter() {
  const itemCount = 0;

  return <div>{itemCount > 0 && <span>товаров: {itemCount}</span>}</div>;
}
```

#### способ 4 — вернуть `null`

- если компонент должен существовать в дереве React, но ничего не должен отображать, он может вернуть `null`

```js
function AdminNotice() {
  const isAdmin = false;

  if (!isAdmin) {
    return null;
  }

  return <p>панель администратора</p>;
}
```

- возврат `null` не означает, что функция перестала быть React-компонентом, — она по-прежнему участвует в рендеринге, но не создаёт видимого DOM-элемента

### что происходит при изменении условия

- допустим, компонент показывает кнопку, когда пользователь авторизован, и скрывает её в противном случае

- если значение условия меняется из-за изменения `state` или `props`, React повторно рендерит компонент и определяет, какой результат должен отображаться теперь

```js
import { useState } from 'react';

function LoginToggle() {
  const [isLoggedIn, setIsLoggedIn] = useState(false);

  return (
    <section>
      {isLoggedIn ? (
        <button onClick={() => setIsLoggedIn(false)}>выйти</button>
      ) : (
        <button onClick={() => setIsLoggedIn(true)}>войти</button>
      )}
    </section>
  );
}
```

- важно понимать разницу между скрытием элемента через CSS и исключением элемента из JSX

- при условном рендеринге React может удалить DOM-элемент, а при скрытии через CSS элемент остаётся в DOM, хотя пользователь его не видит

- если React исключает компонент из дерева, его локальное состояние обычно сбрасывается при последующем монтировании заново, поэтому условный рендеринг влияет не только на внешний вид, но и на жизненный цикл компонентов

## 2. render props — передача логики через функцию

### какую проблему решает этот паттерн

- представь, что в приложении несколько компонентов должны отслеживать одну и ту же информацию, например координаты мыши, но отображать её по-разному

- один компонент должен показывать координаты текстом, второй — двигать за курсором картинку, а третий — показывать всплывающую подсказку

- если написать отслеживание мыши отдельно для каждого компонента, придётся дублировать одну и ту же логику

- Render Props — это паттерн, при котором компонент получает функцию через `props` и вызывает её, чтобы определить, что именно нужно отобразить

### как это работает

- начнём с простого примера без React, чтобы понять саму идею

```js
function DataProvider({ render }) {
  const userName = 'Анна';

  return render(userName);
}

function UserPage() {
  return <DataProvider render={(name) => <h1>привет, {name}</h1>} />;
}
```

- разберём по шагам, что здесь происходит

- 1 — `UserPage` создаёт компонент `DataProvider` и передаёт ему функцию через prop с именем `render`

- 2 — `DataProvider` получает эту функцию в параметре `render`

- 3 — внутри `DataProvider` вызывается `render(userName)`, то есть функция получает строку `'Анна'`

- 4 — функция возвращает JSX `<h1>привет, Анна</h1>`

- 5 — `DataProvider` возвращает полученный JSX, который React отображает на странице

- обрати внимание: `render` — это не встроенное свойство React, а произвольно выбранное имя prop

### почему это называется render props

- название состоит из двух частей: `render` означает отображение, а `props` — свойства, которые родитель передаёт компоненту

- функция в prop определяет, какой интерфейс должен быть отрисован на основании данных, предоставленных компонентом

- у такого паттерна есть важное преимущество: компонент, предоставляющий данные или поведение, не обязан знать, как именно они будут отображаться

### практический пример — отслеживание мыши

- сделаем компонент, который отслеживает положение курсора внутри определённой области и передаёт координаты функции `render`

```js
import { useState } from 'react';

function MouseTracker({ render }) {
  const [position, setPosition] = useState({
    x: 0,
    y: 0,
  });

  function handleMouseMove(event) {
    setPosition({
      x: event.clientX,
      y: event.clientY,
    });
  }

  return (
    <div onMouseMove={handleMouseMove} style={{ height: 200, border: '1px solid black' }}>
      {render(position)}
    </div>
  );
}

function MouseCoordinates() {
  return (
    <MouseTracker
      render={({ x, y }) => (
        <p>
          x: {x}, y: {y}
        </p>
      )}
    />
  );
}
```

- компонент `MouseTracker` отвечает за отслеживание курсора и хранение координат в состоянии

- компонент `MouseCoordinates` решает, как показать эти координаты пользователю

- при движении мыши вызывается `handleMouseMove`, обновляется состояние `position`, после чего React повторно рендерит `MouseTracker` и вызывает переданную функцию с новыми координатами

- теперь другой компонент может использовать тот же `MouseTracker`, но отображать данные иначе

```js
function MouseCrosshair() {
  return (
    <MouseTracker
      render={({ x, y }) => (
        <div>
          курсор находится в точке ({x}, {y})
        </div>
      )}
    />
  );
}
```

- логика отслеживания не дублируется, а способ отображения задаётся снаружи

### обязательно ли называть prop `render`

- нет, это может быть любое имя, если через него передаётся функция

- существует распространённый вариант Render Props, в котором функция передаётся через `children`

```js
function TemperatureProvider({ children }) {
  const temperature = 24;

  return children(temperature);
}

function WeatherWidget() {
  return <TemperatureProvider>{(degrees) => <p>температура: {degrees} °C</p>}</TemperatureProvider>;
}
```

- здесь `children` — функция, а не JSX-элемент

- обычно `children` содержит вложенный JSX, но React позволяет передавать в него и функцию, поскольку `children` — это обычный prop, а не отдельный механизм, который сам по себе обязан содержать разметку

- важный нюанс: React не вызывает функцию `children` автоматически просто потому, что она передана в компонент, — в этом примере её явно вызывает `TemperatureProvider`

### когда применять Render Props

- этот паттерн полезен, когда нужно отделить переиспользуемое поведение от представления и при этом предоставить вызывающему коду контроль над отображением

- исторически его часто применяли для повторного использования состояния и логики в React-компонентах

- в современном React часть таких задач удобнее решать с помощью кастомных хуков, потому что они позволяют переиспользовать логику без создания дополнительного компонента-обёртки

- однако Render Props по- прежнему полезен для понимания старого React-кода и некоторых API библиотек

## 3. HOC — Higher-Order Component

### что это такое

- HOC (Higher-Order Component) — это функция, которая принимает React-компонент и возвращает новый компонент, расширяющий или изменяющий его поведение

- по-русски это обычно называют компонентом высшего порядка, хотя технически HOC — именно функция, работающая с компонентами

- чтобы понять название, сначала вспомним более общее понятие из JavaScript — функцию высшего порядка

- функция высшего порядка — это функция, которая принимает другую функцию в аргументах или возвращает функцию в качестве результата

```js
function createMultiplier(multiplier) {
  return function multiplyNumber(number) {
    return number * multiplier;
  };
}

const multiplyByThree = createMultiplier(3);

console.log(multiplyByThree(5)); // 15
```

- здесь `createMultiplier` принимает число и возвращает новую функцию

- в HOC идея аналогичная, но вместо обычной функции мы передаём React-компонент и возвращаем новый React-компонент

### зачем нужен HOC

- представь, что несколько компонентов должны показывать индикатор загрузки, если данные ещё не получены

- без переиспользования логики каждый компонент мог бы самостоятельно проверять `isLoading` и решать, что отображать

- если таких компонентов много, одинаковая логика начинает повторяться

- HOC позволяет вынести эту логику в одну функцию, а затем оборачивать ею разные компоненты

### простой пример HOC

```js
function withLoading(WrappedComponent) {
  return function LoadingWrapper({ isLoading, ...props }) {
    if (isLoading) {
      return <p>загрузка...</p>;
    }

    return <WrappedComponent {...props} />;
  };
}
```

- разберём каждую часть

- `withLoading` — функция HOC, которая принимает компонент в аргументе `WrappedComponent`

- `LoadingWrapper` — новый компонент, который возвращает HOC

- `isLoading` — специальный prop, который использует обёртка для принятия решения

- `...props` — остальные свойства, переданные обёртке, которые не относятся к `isLoading`

- если `isLoading` равен `true`, возвращается сообщение о загрузке

- если `isLoading` равен `false`, возвращается исходный компонент с передачей ему остальных props

### используем HOC на практике

```js
function ProductDetails({ productName }) {
  return <h2>товар: {productName}</h2>;
}

const ProductDetailsWithLoading = withLoading(ProductDetails);
```

- теперь `ProductDetailsWithLoading` — новый компонент, который умеет показывать загрузку и отображать `ProductDetails`, когда загрузка завершена

```js
function ProductPage() {
  return <ProductDetailsWithLoading isLoading={false} productName='ноутбук' />;
}
```

- когда `isLoading` равен `false`, компонент покажет `товар: ноутбук`

- если установить `isLoading` в `true`, исходный компонент не будет отображён, а вместо него появится текст `загрузка...`

- сам `ProductDetails` при этом не нужно изменять, и его можно использовать отдельно, без логики загрузки

### что означает `...props` в HOC

- это важная часть паттерна, потому что обёртка часто должна передавать исходному компоненту все свойства, которые она сама не обрабатывает

```js
return <WrappedComponent {...props} />;
```

- оператор `...` в данном случае раскрывает свойства объекта в JSX

- если в `props` находятся `productName`, `price` и `category`, они будут переданы в `WrappedComponent` как отдельные props

- если забыть передать нужные props, обёрнутый компонент может перестать работать правильно

### HOC не изменяет исходный компонент

- классический HOC не должен мутировать исходный компонент, то есть изменять его непосредственно

- вместо этого он создаёт новый компонент, который использует исходный внутри себя

- это позволяет сохранять исходный компонент независимым и комбинировать разные HOC

- например, теоретически можно создать `withLoading(withPermissions(ProductDetails))`, если оба HOC совместимы по своим интерфейсам

### важные нюансы HOC для собеседования

- первый нюанс — не создавай HOC внутри рендера другого компонента

- если каждый рендер вызывает `withLoading(ProductDetails)` заново, React может воспринимать результат как новый тип компонента, что приводит к повторному монтированию и потере локального состояния дочернего компонента

- правильнее создавать обёртку на уровне модуля, как в примере с `ProductDetailsWithLoading`

- второй нюанс — не передавай служебные props дальше без необходимости

- если `isLoading` нужен только обёртке, обычно его не следует передавать в `ProductDetails`, особенно если исходный компонент не должен знать о механизме загрузки

- третий нюанс — следи за именами и статическими свойствами

- HOC создаёт новый компонент, поэтому его имя может быть неочевидным при отладке, а статические свойства исходного компонента не копируются автоматически

- четвёртый нюанс — не все HOC можно безопасно комбинировать

- обёртки могут ожидать разные props или изменять их по-разному, поэтому их интерфейсы должны быть согласованы

### когда применяют HOC

- HOC можно встретить в коде, где логика авторизации, прав доступа, аналитики или подключения к внешнему источнику данных вынесена в переиспользуемые обёртки

- исторически этот подход широко использовался библиотеками вроде Redux и React Router

- в современном React для повторного использования логики часто выбирают хуки, но HOC остаётся важным паттерном для чтения существующих проектов и понимания архитектуры React

## 4. custom HOC — создание собственного HOC

### чем отличается от предыдущей темы

- по сути, Custom HOC — это HOC, который ты самостоятельно проектируешь под конкретную задачу, а не используешь готовый из библиотеки

- предыдущий пример `withLoading` уже был пользовательским HOC, поэтому теперь разберём более реалистичный случай и обратим внимание на архитектуру

### пример — добавление проверки прав доступа

- допустим, есть компоненты, которые должны быть доступны только администраторам

- можно добавить проверку в каждый компонент, но тогда проверка будет дублироваться

- создадим HOC `withAdminAccess`, который решает, можно ли отображать переданный компонент

```js
function withAdminAccess(WrappedComponent) {
  return function AdminAccessWrapper({ userRole, ...props }) {
    if (userRole !== 'admin') {
      return <p>у вас нет доступа к этой странице</p>;
    }

    return <WrappedComponent {...props} />;
  };
}
```

- теперь создадим обычный компонент страницы

```js
function AdminDashboard({ dashboardTitle }) {
  return <h1>{dashboardTitle}</h1>;
}

const ProtectedDashboard = withAdminAccess(AdminDashboard);
```

- и используем обёртку

```js
function AdminPage() {
  return <ProtectedDashboard userRole='admin' dashboardTitle='панель управления' />;
}
```

- если передать `userRole="admin"`, отобразится панель управления

- если передать `userRole="guest"`, вместо панели появится сообщение об отсутствии доступа

### как правильно проектировать Custom HOC

- при создании своего HOC полезно разделять ответственность между обёрткой и исходным компонентом

- обёртка должна решать одну конкретную задачу, например проверять права доступа, добавлять обработчик события или подключать данные

- исходный компонент должен по возможности оставаться независимым от способа, которым HOC выполняет эту задачу

- следует заранее определить, какие props получает обёртка, какие она использует сама и какие передаёт дальше

- если HOC добавляет новые props, стоит убедиться, что они не конфликтуют с props исходного компонента

### ограничение примера с авторизацией

- в примере выше проверка `userRole` управляет только отображением интерфейса, но не обеспечивает реальную безопасность

- если речь идёт о настоящем приложении, сервер тоже должен проверять права доступа при выполнении защищённых операций, потому что клиентский код можно изменить или обойти

## 5. что важно запомнить для собеседования

- Condition Render — это не отдельный API React, а применение возможностей JavaScript для выбора JSX

- Render Props позволяет передавать функцию, с помощью которой компонент определяет, что именно отображать, используя предоставленные данные

- HOC принимает компонент и возвращает новый компонент, добавляя поведение без обязательного изменения исходного компонента

- Custom HOC — собственная реализация этого паттерна под задачу проекта

- эти подходы не исключают друг друга, потому что решают разные задачи: условный рендеринг выбирает представление, Render Props передаёт управление представлением через функцию, а HOC расширяет компонент с помощью обёртки

- современный React также предлагает хуки для повторного использования логики, поэтому при разработке нового кода нужно выбирать решение по задаче, а не автоматически использовать исторический паттерн
