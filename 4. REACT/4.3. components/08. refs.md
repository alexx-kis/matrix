# refs в React — подробный разбор с нуля

- `ref` — одна из возможностей React, которая позволяет получить доступ к конкретному DOM-элементу или сохранить значение, которое должно оставаться между рендерами компонента, но изменение которого само по себе не должно вызывать повторный рендер

- чтобы понять, зачем нужны refs, сначала нужно разобраться, какую проблему они решают и почему в React обычно не принято напрямую обращаться к DOM

## 1. зачем вообще нужны refs

### как обычно работает React

- представим, что мы пишем компонент с кнопкой и полем ввода

```js
function SearchPanel() {
  const [searchText, setSearchText] = React.useState('');

  return (
    <div>
      <input value={searchText} onChange={(event) => setSearchText(event.target.value)} />

      <button onClick={() => console.log(searchText)}>Search</button>
    </div>
  );
}
```

- здесь React управляет отображением интерфейса, а мы описываем, как он должен выглядеть при определённом состоянии

- когда пользователь вводит текст, вызывается `setSearchText`, React обновляет состояние и повторно вызывает компонент, чтобы получить актуальное описание интерфейса

- в обычной ситуации нам не нужно самостоятельно искать DOM-элемент поля ввода, читать его содержимое или изменять его вручную — React делает это через состояние и props

### а что, если нужно обратиться непосредственно к DOM

- представим, что нам нужно автоматически установить курсор в поле ввода после появления компонента

- можно ли решить эту задачу через state?

- состояние позволяет описывать данные интерфейса, но оно не предоставляет прямого доступа к DOM-методам вроде `focus()`

- нам нужен способ получить ссылку на конкретный DOM-элемент, чтобы вызвать его метод

- именно для подобных случаев и существует `ref`

```js
function SearchPanelWithFocus() {
  const searchInputRef = React.useRef(null);

  function focusSearchInput() {
    searchInputRef.current.focus();
  }

  return (
    <div>
      <input ref={searchInputRef} />

      <button onClick={focusSearchInput}>Focus input</button>
    </div>
  );
}
```

- когда React создаст DOM-элемент `input` и привяжет к нему ref, в `searchInputRef.current` будет находиться ссылка на этот элемент

- при нажатии кнопки мы вызываем стандартный DOM-метод `focus()`, и браузер переводит фокус в поле ввода

- обрати внимание: мы не ищем элемент через `document.querySelector()` и не используем идентификаторы — React сам связывает ref с нужным элементом

## 2. что такое ref в React

- `ref` — это ссылка на определённый объект или значение, которое React может предоставить компоненту либо которое компонент может хранить самостоятельно

- в зависимости от того, как используется ref, он может указывать на разные вещи

- DOM-элемент — например, на HTML-элемент `input`, `button` или `div`

- экземпляр классового компонента — например, объект, у которого доступны публичные методы компонента

- значение, сохранённое через `useRef` — например, идентификатор таймера или предыдущее значение переменной

- важно не путать сам объект ref и то, на что он ссылается

```js
const searchInputRef = React.useRef(null);
```

- после выполнения этой строки `searchInputRef` — это объект примерно следующей структуры

```js
{
  current: null;
}
```

- `current` — свойство, в котором хранится текущее значение ссылки

- изначально мы передали `null`, поэтому `current` равен `null`

- когда React прикрепит этот ref к DOM-элементу, значение `current` станет ссылкой на этот элемент

- схематично это выглядит так

```
searchInputRef
[объект ref]
      ↓
свойство current
      ↓
HTMLInputElement
[реальный DOM-элемент в браузере]
[focus(), blur(), select(), value и другие свойства]
```

- благодаря этой ссылке можно обращаться к DOM-элементу напрямую, не выполняя поиск по всему документу

## 3. как работает useRef

- `useRef` — это React Hook, который позволяет создать объект ref, доступный между рендерами одного экземпляра компонента

- его синтаксис выглядит так

```js
const timerRef = React.useRef(null);
```

- функция `useRef` принимает начальное значение и возвращает объект с полем `current`

- React сохраняет этот объект между рендерами, поэтому при следующем вызове компонента мы получаем тот же объект, а не новый

### чем useRef отличается от обычной переменной

- посмотрим на пример с обычной переменной

```js
function RenderCounter() {
  let renderCount = 0;

  renderCount += 1;

  return <p>Render count: {renderCount}</p>;
}
```

- при каждом рендере функция `RenderCounter` вызывается заново, поэтому `renderCount` снова создаётся со значением `0`

- результатом каждого рендера будет `1`, даже если компонент вызывался много раз

- теперь используем `useRef`

```js
function PersistentCounter() {
  const renderCountRef = React.useRef(0);

  renderCountRef.current += 1;

  return <p>Render count: {renderCountRef.current}</p>;
}
```

- здесь объект `renderCountRef` сохраняется между рендерами, поэтому его свойство `current` не сбрасывается при повторном вызове компонента

- однако у этого примера есть нюанс: изменять `ref.current` во время рендера для обычной логики приложения не рекомендуется, а счётчик рендеров таким способом не будет сам обновлять отображаемый текст

- для отслеживания рендеров в реальном приложении обычно используют инструменты разработчика или специальную отладочную логику

### главное отличие useRef от useState

- `useState` хранит состояние, изменение которого может привести к повторному рендеру компонента

- `useRef` хранит значение между рендерами, но изменение `current` само по себе не вызывает рендер

```js
function ClickTracker() {
  const [visibleClicks, setVisibleClicks] = React.useState(0);
  const totalClicksRef = React.useRef(0);

  function handleTrackedClick() {
    totalClicksRef.current += 1;
    setVisibleClicks((previousClicks) => previousClicks + 1);
  }

  return (
    <div>
      <p>Clicks displayed: {visibleClicks}</p>

      <button onClick={handleTrackedClick}>Click me</button>
    </div>
  );
}
```

- при каждом нажатии мы увеличиваем значение `totalClicksRef.current` и обновляем state

- обновление state вызывает рендер, поэтому React отображает новое значение `visibleClicks`

- `totalClicksRef.current` тоже сохраняет своё значение, но если бы мы изменяли только его, компонент не перерисовывался бы

- такой ref можно использовать для внутреннего учёта данных, которые не обязаны отображаться в интерфейсе

- важное правило: не используй `ref.current` как замену state, если изменение значения должно отражаться в интерфейсе

## 4. основные сценарии использования refs

### 4.1. управление фокусом

- один из самых распространённых случаев — установить фокус на поле ввода, например при открытии формы или нажатии кнопки

```js
function LoginForm() {
  const emailInputRef = React.useRef(null);

  function focusEmailField() {
    emailInputRef.current?.focus();
  }

  return (
    <form>
      <input ref={emailInputRef} type='email' placeholder='Enter email' />

      <button type='button' onClick={focusEmailField}>
        Focus email
      </button>
    </form>
  );
}
```

- оператор `?.` называется optional chaining и позволяет не вызывать `focus()`, если `current` в этот момент равен `null`

- такой подход полезен, если элемент может ещё не существовать в DOM или уже был удалён

### 4.2. управление медиаэлементами

- у HTML-элементов есть встроенные методы, которые удобно вызывать через refs

- например, можно управлять воспроизведением видео

```js
function VideoPlayer() {
  const videoElementRef = React.useRef(null);

  function startPlayback() {
    videoElementRef.current?.play();
  }

  function stopPlayback() {
    videoElementRef.current?.pause();
  }

  return (
    <div>
      <video ref={videoElementRef} src='/videos/intro.mp4' controls />

      <button onClick={startPlayback}>Play</button>
      <button onClick={stopPlayback}>Pause</button>
    </div>
  );
}
```

- здесь React отвечает за создание и отображение видеоэлемента, а ref даёт возможность вызвать методы браузера для управления им

### 4.3. хранение идентификатора таймера

- refs полезны не только для DOM, поскольку они могут хранить любое значение

- например, идентификатор таймера не обязательно выводить на экран, но его нужно сохранить, чтобы позднее отменить таймер

```js
function DelayedNotification() {
  const timeoutIdRef = React.useRef(null);

  function scheduleNotification() {
    timeoutIdRef.current = setTimeout(() => {
      console.log('Notification triggered');
    }, 3000);
  }

  function cancelNotification() {
    clearTimeout(timeoutIdRef.current);
  }

  return (
    <div>
      <button onClick={scheduleNotification}>Schedule</button>

      <button onClick={cancelNotification}>Cancel</button>
    </div>
  );
}
```

- идентификатор таймера хранится между рендерами, поэтому функция отмены может обратиться к нему позднее

- в полноценном компоненте также стоит очищать таймер при размонтировании компонента, чтобы избежать выполнения ненужной работы

### 4.4. хранение предыдущего значения

- иногда нужно сравнить текущее значение с предыдущим, например при анализе изменения props или состояния

- для хранения предыдущего значения можно использовать ref

```js
function PriceDisplay({ price }) {
  const previousPriceRef = React.useRef(price);

  React.useEffect(() => {
    previousPriceRef.current = price;
  }, [price]);

  return (
    <p>
      Current: {price}, previous: {previousPriceRef.current}
    </p>
  );
}
```

- после изменения `price` эффект обновляет сохранённое значение

- при этом есть тонкость: обновление `ref.current` внутри эффекта происходит после рендера, поэтому во время первого рендера и во время рендера с новым `price` в JSX может отображаться предыдущее сохранённое значение не совсем так, как ожидается

- если нужно корректно выводить историю изменений, её лучше хранить в state, а ref использовать для внутренней логики

## 5. когда использовать refs не нужно

- refs дают возможность напрямую взаимодействовать с DOM или хранить значения вне state, но это не означает, что их следует использовать для всего

- например, не стоит менять текст DOM-элемента вручную, если тот же результат можно получить через состояние

```js
function MessageToggle() {
  const [message, setMessage] = React.useState('Hello');

  return (
    <div>
      <p>{message}</p>

      <button onClick={() => setMessage('Goodbye')}>Change message</button>
    </div>
  );
}
```

- React самостоятельно обновит текст в DOM в соответствии со state

- если вместо этого изменить `textContent` через ref, React и вручную изменённый DOM могут начать расходиться в своих представлениях интерфейса

- refs обычно подходят для таких задач, как фокус, выделение текста, прокрутка, управление медиаплеером, интеграция со сторонними DOM-библиотеками и хранение служебных значений

- state подходит для данных, от которых зависит отображение интерфейса

## 6. как ref передаётся в DOM-элемент

- чтобы связать ref с DOM-элементом, нужно передать его в специальный атрибут `ref`

```js
function UsernameField() {
  const usernameRef = React.useRef(null);

  return <input ref={usernameRef} type='text' placeholder='Username' />;
}
```

- React устанавливает `usernameRef.current` в ссылку на DOM-элемент после его создания и сбрасывает ссылку при удалении элемента из DOM

- поэтому не стоит обращаться к `current` во время рендера в надежде получить только что созданный DOM-элемент — в этот момент ссылка ещё может быть `null`

- для работы с DOM после появления элемента обычно используют обработчики событий или эффекты, в зависимости от задачи

## 7. refs и классовые компоненты

- в классовых компонентах refs тоже используются, но доступ к ним организуется иначе

```js
class SearchInput extends React.Component {
  constructor(props) {
    super(props);

    this.searchFieldRef = React.createRef();
  }

  focusField = () => {
    this.searchFieldRef.current?.focus();
  };

  render() {
    return (
      <div>
        <input ref={this.searchFieldRef} />

        <button onClick={this.focusField}>Focus</button>
      </div>
    );
  }
}
```

- `React.createRef()` создаёт объект ref с полем `current`

- в классовом компоненте его обычно создают в конструкторе и сохраняют в свойстве экземпляра

- в функциональных компонентах для аналогичной задачи обычно используют `useRef`, потому что он сохраняет один и тот же объект между рендерами

- не путай `createRef` и `useRef`: оба связаны с refs, но рассчитаны на разные способы организации компонентов

## 8. что такое forwardRef

- до React 19 функциональный компонент обычно не мог просто получить `ref` от родителя как обычный prop и автоматически передать его своему DOM-элементу

- для такого сценария существовал `React.forwardRef`

- представим, что у нас есть компонент-обёртка над полем ввода

```js
const CustomInput = React.forwardRef(function CustomInput(props, ref) {
  return <input {...props} ref={ref} />;
});
```

- компонент `CustomInput` принимает props и специальный аргумент `ref`, а затем передаёт его реальному DOM-элементу `input`

- теперь родитель может управлять фокусом на поле ввода, хотя сам элемент находится внутри другого компонента

```js
function RegistrationForm() {
  const passwordInputRef = React.useRef(null);

  function focusPassword() {
    passwordInputRef.current?.focus();
  }

  return (
    <div>
      <CustomInput ref={passwordInputRef} type='password' placeholder='Password' />

      <button onClick={focusPassword}>Focus password</button>
    </div>
  );
}
```

- когда пользователь нажимает кнопку, родитель обращается через ref к тому DOM-элементу `input`, который находится внутри `CustomInput`

### почему нельзя просто передать ref как обычный prop

- исторически React обрабатывал `ref` особым образом, поэтому в функциональном компоненте до React 19 запись `props.ref` не работала как обычная передача ссылки на DOM-элемент

- `forwardRef` позволял компоненту получить ref специальным вторым аргументом и передать его дальше

### что изменилось в React 19

- начиная с React 19, функциональные компоненты могут получать `ref` как обычный prop, поэтому для новых компонентов `forwardRef` больше не обязателен

- например, в React 19 тот же компонент можно написать так

```js
function CustomInputV19({ ref, ...props }) {
  return <input {...props} ref={ref} />;
}
```

- этот синтаксис рассчитан именно на React 19 и более новые версии, поддерживающие такую модель

- в старых проектах, в том числе на React 18, нужно использовать `forwardRef`, если необходимо передать ref через функциональный компонент

- это не означает, что `forwardRef` мгновенно исчез из React: он остаётся важным для понимания существующего кода и совместимости с более старыми версиями

## 9. зачем передавать ref через несколько компонентов

- представим архитектуру, где родитель использует `RegistrationForm`, форма использует `CustomInput`, а `CustomInput` создаёт обычный `input`

- родителю иногда нужен доступ к настоящему DOM-элементу, но он не должен знать все внутренние детали реализации дочерних компонентов

- передача ref позволяет открыть такой доступ явно, не заставляя родителя искать элемент через глобальный DOM

- однако передавать refs через всю компонентную иерархию без необходимости не стоит

- если задача заключается в передаче данных, лучше использовать props, а если нужно сообщить родителю о действии — callback-функцию

- ref нужен именно тогда, когда требуется ссылка на элемент или императивный API

## 10. useImperativeHandle — управление тем, что видит родитель

- иногда родителю не нужно получать весь DOM-элемент дочернего компонента

- например, у компонента `CustomInput` можно открыть только методы `focus()` и `clear()`, не предоставляя родителю прямую ссылку на `input`

- для этого существует `useImperativeHandle`

```js
const ControlledInput = React.forwardRef(function ControlledInput(props, ref) {
  const internalInputRef = React.useRef(null);

  React.useImperativeHandle(
    ref,
    () => ({
      focus() {
        internalInputRef.current?.focus();
      },

      clear() {
        if (internalInputRef.current) {
          internalInputRef.current.value = '';
        }
      },
    }),
    [],
  );

  return <input {...props} ref={internalInputRef} />;
});
```

- родитель получит объект с методами `focus` и `clear`, а не сам DOM-элемент

- это позволяет компоненту контролировать, какие императивные операции доступны извне

- в React 19 можно использовать `ref` как prop и без `forwardRef`, но назначение `useImperativeHandle` от этого не меняется

- такой подход особенно полезен для библиотечных компонентов, когда нужно предоставить небольшой публичный API и скрыть внутреннюю реализацию

## 11. callback refs

- кроме передачи объекта, созданного через `useRef` или `createRef`, React позволяет использовать callback ref — функцию, которую React вызывает при присоединении и отсоединении ссылки

```js
function MeasuredBox() {
  const [boxWidth, setBoxWidth] = React.useState(0);

  const attachBoxRef = React.useCallback((element) => {
    if (element) {
      setBoxWidth(element.getBoundingClientRect().width);
    }
  }, []);

  return (
    <div>
      <div ref={attachBoxRef}>Measure this box</div>

      <p>Width: {boxWidth}px</p>
    </div>
  );
}
```

- когда DOM-элемент присоединяется к ref, callback получает этот элемент

- при отсоединении callback ref вызывается с `null` в традиционном варианте использования

- в React 19 callback refs также поддерживают возможность возвращать функцию очистки, которая вызывается при отсоединении

- callback refs полезны, когда нужно выполнить действие непосредственно в момент присоединения DOM-элемента, например измерить его размеры или зарегистрировать его во внешней системе

- в примере выше `useCallback` помогает сохранить идентичность функции между рендерами, чтобы избежать лишнего отсоединения и повторного присоединения ref при каждом рендере

## 12. важные правила и ограничения refs

- изменение `ref.current` не вызывает рендер — если интерфейс должен обновиться вслед за значением, используй state

- не читай и не изменяй ref без необходимости во время рендера — обычно доступ к DOM и изменение служебных значений следует выполнять в обработчиках событий, эффектах или callback refs

- DOM-ref может быть `null` — например, до появления элемента, после его удаления или если элемент условно не отображается

- не используй refs вместо props — props предназначены для передачи данных от родителя к ребёнку, а refs — для доступа к DOM или явно предоставленному императивному API

- не изменяй DOM вручную там, где достаточно декларативного React-кода — ручные изменения могут конфликтовать с последующими обновлениями React

- не полагайся на ref для хранения данных, которые нужно визуально отобразить — React не узнает об изменении `current` и не перерисует компонент автоматически

## 13. как объяснить refs на собеседовании

- если на собеседовании спросят, что такое ref, можно ответить так

* `ref` в React — это механизм для получения ссылки на DOM-элемент или сохранения значения между рендерами без автоматического вызова повторного рендера при изменении этого значения

* чаще всего refs применяются для управления фокусом, прокруткой, выделением текста, медиаплеерами и интеграции со сторонними библиотеками

* для функциональных компонентов обычно используют `useRef`, а для классовых компонентов — `createRef`

* если ref нужно передать через функциональный компонент, в React 18 и более ранних версиях обычно используют `forwardRef`, тогда как в React 19 можно принимать `ref` как prop

* если родителю нужно предоставить только определённые методы дочернего компонента, используют `useImperativeHandle`

* в отличие от state, изменение `ref.current` само по себе не вызывает повторный рендер, поэтому refs не должны заменять состояние, от которого зависит интерфейс

- самое важное для понимания — React обычно управляет интерфейсом декларативно через props и state, а refs дают ограниченный способ императивно обратиться к DOM или сохранить вспомогательное значение, когда декларативного подхода недостаточно
