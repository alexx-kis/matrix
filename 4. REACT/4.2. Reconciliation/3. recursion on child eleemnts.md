# recursion on child elements

- эта тема логически продолжает `Fiber` и приоритизацию, потому что React при построении и обработке дерева компонентов должен не просто найти один компонент, а **пройти всё его поддерево**

## что такое recursion в контексте React

- рекурсия — это когда функция вызывает саму себя, чтобы обработать структуру, которая состоит из элементов того же типа

- дерево React идеально подходит для такого подхода, потому что каждый элемент может иметь дочерние элементы, а каждый дочерний элемент в свою очередь может иметь собственных детей

```jsx
function App() {
  return (
    <div>
      <Header />
      <main>
        <Content />
        <Footer />
      </main>
    </div>
  );
}
```

- здесь структура имеет примерно такой вид

```
App
└── div
    ├── Header
    └── main
        ├── Content
        └── Footer
```

- если React хочет обработать `App`, ему недостаточно обработать только сам `App`

- нужно спуститься в `div`, затем в `Header`, `main`, затем в `Content` и `Footer`

- именно поэтому обработка дерева естественным образом выражается через рекурсивный подход

## зачем нужна рекурсия на child elements

- главная причина — **дерево имеет неизвестную заранее глубину**

- например, мы можем иметь

```
App
└── div
    └── main
        └── section
            └── article
                └── div
                    └── span
```

- невозможно написать отдельный код вида «обработать родителя, потом ребёнка, потом ребёнка ребёнка, потом ещё одного ребёнка»

- вместо этого можно описать одно правило

```
обработай текущий элемент
→ найди его child
→ обработай child
→ если у child есть свои children, обработай их тем же способом
```

- это и есть рекурсивный обход дерева

## простой пример без React

- представим обычное дерево

```js
const treeNode = {
  name: 'App',
  children: [
    {
      name: 'Header',
      children: [],
    },
    {
      name: 'Main',
      children: [
        {
          name: 'Content',
          children: [],
        },
        {
          name: 'Footer',
          children: [],
        },
      ],
    },
  ],
};
```

- чтобы пройти всё дерево, можно использовать рекурсивную функцию

```js
function walkTree(node) {
  console.log(node.name);

  for (const childNode of node.children) {
    walkTree(childNode);
  }
}

walkTree(treeNode);
```

- результат будет таким

```
App
Header
Main
Content
Footer
```

- обрати внимание на ключевой момент

```js
walkTree(childNode);
```

- функция не знает заранее, насколько глубоко находится `childNode`

- она просто говорит «обработай этот child тем же алгоритмом»

- если у него есть дети, они тоже будут обработаны

- если детей нет, цикл ничего не сделает и функция завершится

## как это связано с React

- в React дерево элементов и компонентов может быть очень большим и глубоко вложенным

- условно React может выполнять логику такого типа

```
обработать текущий Fiber
        ↓
найти child
        ↓
обработать child
        ↓
найти его child
        ↓
обработать его child
        ↓
...
```

- поэтому идея рекурсивного обхода здесь очень естественна

- если говорить именно про React Fiber, важно понимать одну тонкость

## рекурсия и Fiber — не одно и то же

- исторически React использовал рекурсивный обход дерева при reconciliation

- проблема такого подхода заключалась в том, что обычная JavaScript-рекурсия плохо подходит для возможности **приостановить работу и продолжить её позже**

- например, условно

```js
function renderNode(node) {
  processNode(node);

  for (const childNode of node.children) {
    renderNode(childNode);
  }
}
```

- если дерево огромное, такой вызов может уйти очень глубоко в call stack

- кроме того, выполнение такой функции сложно прервать посередине так, чтобы потом нормально продолжить с того же места

- Fiber был во многом создан именно для решения этой проблемы

- вместо того чтобы полагаться на глубокую рекурсию JavaScript, React представляет каждый узел дерева отдельным **Fiber-объектом** и хранит связи между ними

```
Fiber
 ├── child
 ├── sibling
 └── return
```

- `child` указывает на первого ребёнка

- `sibling` указывает на следующего ребёнка

- `return` указывает на родительский Fiber

- поэтому React может перемещаться по дереву итеративно, сохраняя своё текущее положение

```
parent
  ↓
child → sibling → sibling
  ↑
return
```

- это принципиально важно для предыдущей темы про приоритизацию

- React может обработать часть дерева

```
App
 ↓
Header
 ↓
Main
```

- затем остановиться

- выполнить более приоритетную работу

- а потом продолжить обход дерева с сохранённого места

## что значит "recursion on child elements" на собеседовании

- если тебя спрашивают, зачем нужна рекурсия при обработке дочерних элементов, основной ответ должен быть таким

- **React работает с деревом элементов, поэтому для обработки всего поддерева нужно переходить от родителя к его детям, а затем обрабатывать детей тем же способом, поскольку каждый ребёнок сам может иметь детей**

- если спрашивают, почему нельзя просто обработать один уровень

- потому что структура React-дерева имеет произвольную глубину, поэтому необходимо повторять одну и ту же операцию для каждого уровня вложенности

- если спрашивают именно про Fiber, стоит добавить важный нюанс

- **концептуально обход дерева похож на рекурсивный обход, но Fiber позволяет реализовать его без обычной глубокой JavaScript-рекурсии, сохраняя связи `child`, `sibling` и `return` и позволяя приостанавливать и продолжать работу**

## как применять такой подход на практике

- если тебе дают задачу «обойти вложенную структуру», первым делом нужно определить базовый случай и рекурсивный шаг

- базовый случай — у текущего узла нет детей

- рекурсивный шаг — обработать каждого ребёнка той же функцией

```js
function visitNode(currentNode) {
  console.log(currentNode.name);

  if (currentNode.children.length === 0) {
    return;
  }

  for (const nestedNode of currentNode.children) {
    visitNode(nestedNode);
  }
}
```

- схема здесь очень простая

```
visitNode(parent)
       ↓
  есть children?
    ↙       ↘
  нет        да
  ↓          ↓
return   visit each child
             ↓
        visitNode(child)
             ↓
        повторить то же
```

- именно этот паттерн нужно уметь узнавать в задачах с DOM, AST, React-деревом, файловыми структурами и любыми другими древовидными данными

## что важно не перепутать

- **рекурсия нужна не потому, что React-компоненты обязательно вызывают сами себя**

- рекурсия здесь относится к **обходу структуры дерева**

- компонент `App` не обязан напрямую вызывать `App`

- функция обхода получает один узел и вызывает себя уже для его дочерних узлов

- поэтому правильная ментальная модель такая

```
не «компонент вызывает сам себя»

а

«алгоритм обработки узла применяет себя к его children»
```

- для уровня собеседования здесь достаточно уверенно объяснять дерево, рекурсивный обход, базовый случай и связь этого подхода с Fiber

- особенно важно понимать переход от обычной рекурсии к Fiber: **React всё равно должен пройти дерево, но Fiber превращает работу с деревом в управляемый процесс, который можно прерывать и продолжать**
