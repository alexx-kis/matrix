# Lazy imports и dynamic imports в React

- разберём тему от базовых принципов загрузки JavaScript до механики `React.lazy`, `Suspense`, разделения кода и типичных ошибок

## 1. зачем нужны dynamic imports и lazy loading

- когда браузер загружает React-приложение, ему необходимо получить JavaScript-код, выполнить его и отобразить интерфейс
- если приложение небольшое, можно обойтись одним JavaScript-файлом, но по мере роста приложения в нём появляются десятки страниц, редакторы, графики, модальные окна и другие тяжёлые компоненты
- представим приложение с тремя страницами: главной, аналитикой и настройками

```js
import HomePage from './HomePage';
import AnalyticsPage from './AnalyticsPage';
import SettingsPage from './SettingsPage';

function App() {
  // Здесь выбирается текущая страница
}
```

- даже если пользователь открыл только главную страницу, статические импорты создают зависимости от всех трёх модулей
- если эти зависимости входят в начальный JavaScript-бандл, браузеру придётся загрузить код аналитики и настроек, хотя пользователь пока ими не пользуется
- здесь важно различать две концепции: dynamic import отвечает за динамическую загрузку модуля, а lazy loading — за стратегию загрузки ресурса только тогда, когда он действительно нужен

## 2. dynamic import — динамический импорт

- `import()` — это встроенный механизм JavaScript, позволяющий загрузить модуль динамически во время выполнения программы
- в отличие от статического `import`, он вызывается как функция и возвращает `Promise`, который разрешается в объект модуля

```js
// Статический импорт
import { calculateReport } from './report.js';

// Динамический импорт
import('./report.js').then((reportModule) => {
  const result = reportModule.calculateReport();
  console.log(result);
});
```

- при статическом импорте зависимость объявляется на верхнем уровне модуля, а при динамическом импорте код может решить, когда именно запрашивать модуль
- сборщики вроде Vite и webpack обычно используют динамический `import()` как сигнал для создания отдельного чанка — дополнительного JavaScript-файла
- например, логика приложения может выглядеть так:

```js
async function loadReport() {
  const reportModule = await import('./report.js');

  return reportModule.calculateReport();
}
```

- пока `loadReport()` не вызвана, этот динамический импорт не инициирует загрузку соответствующего модуля
- когда функция вызывается, браузер при необходимости загружает чанк, после чего выполняется код модуля
- сам по себе динамический импорт не гарантирует, что модуль будет загружен исключительно один раз или что для него обязательно создадут отдельный файл: это зависит от кэширования модулей, сборщика и его конфигурации

### зачем нужен `import()`

- code splitting — разделение кода на несколько частей, которые можно загружать независимо
- условная загрузка — загрузка функциональности только при определённых условиях
- уменьшение начального объёма JavaScript — возможность не отправлять весь код приложения при первом открытии
- загрузка по действию пользователя — например, при открытии редактора или нажатии кнопки экспорта
- пример загрузки тяжёлой библиотеки только при необходимости:

```js
async function exportReport() {
  const { default: pdfLibrary } = await import('some-pdf-library');

  // Здесь можно использовать загруженную библиотеку
  console.log(pdfLibrary);
}
```

- такой подход особенно полезен, когда функциональность редко используется, а сама библиотека существенно увеличивает размер начального бандла

## 3. lazy loading компонентов в React

- в React для ленивой загрузки компонентов существует API `React.lazy`
- он позволяет объявить компонент, модуль которого будет загружаться через динамический импорт, когда React впервые попытается отобразить этот компонент

```js
import { lazy, Suspense } from 'react';

const AnalyticsPage = lazy(() => import('./AnalyticsPage'));

function App() {
  return (
    <Suspense fallback={<p>Загрузка аналитики...</p>}>
      <AnalyticsPage />
    </Suspense>
  );
}
```

- здесь происходит несколько важных вещей
- `lazy(() => import('./AnalyticsPage'))` — создаёт ленивый компонент, не загружая его модуль непосредственно в момент объявления
- `Suspense` — определяет, что React должен показывать, пока необходимый компонент ещё не готов к отображению
- `fallback` — временный интерфейс: спиннер, скелетон, текст загрузки или другой React-элемент
- при первом отображении `AnalyticsPage` React инициирует загрузку модуля, а если компонент ещё не готов, ближайший подходящий `Suspense` показывает `fallback`
- после успешной загрузки React использует экспортированный компонент и отображает его

## 4. как работает lazy loading под капотом

- рассмотрим последовательность событий при открытии страницы аналитики

1. приложение запускается - загружается начальный JavaScript-бандл, содержащий основной код приложения

2. React начинает рендерить AnalyticsPage - React обнаруживает, что ленивый компонент ещё не готов

3. загружается необходимый чанк - сборщик и браузер обеспечивают получение соответствующего модуля

4. отображается компонент - React получает компонент из модуля и повторяет попытку рендеринга, если загрузка завершилась успешно

- технически `React.lazy` ожидает, что переданный загрузчик вернёт Promise, разрешающийся в объект с компонентом в поле `default`
- React также кэширует результат загрузки и разрешённое значение для соответствующего ленивого типа компонента
- важно: `React.lazy` не выполняет сетевые запросы самостоятельно в обход JavaScript-модулей — он использует переданную функцию загрузки, а в типичном случае это `import()`

## 5. почему нужен Suspense

- `Suspense` позволяет описать границу интерфейса, внутри которой React может временно показывать запасной UI, если дочернее дерево приостановило рендеринг

```js
import { lazy, Suspense } from 'react';

const SettingsPage = lazy(() => import('./SettingsPage'));

function App() {
  return (
    <main>
      <h1>Настройки</h1>

      <Suspense fallback={<p>Загрузка...</p>}>
        <SettingsPage />
      </Suspense>
    </main>
  );
}
```

- заголовок `Настройки` находится за пределами `Suspense`, поэтому его можно отобразить независимо от готовности ленивого компонента
- если бы весь интерфейс находился внутри одной границы `Suspense`, при приостановке рендеринга React мог бы заменить всё её содержимое на `fallback`
- границы `Suspense` позволяют выбирать, какую именно часть интерфейса заменять загрузочным состоянием, поэтому в больших приложениях их обычно размещают осмысленно, а не оборачивают всё приложение одним большим блоком без необходимости

### а что будет, если загрузка завершится ошибкой?

- `Suspense` обрабатывает ожидание результата, но не является обработчиком ошибок загрузки
- если `import()` отклонит Promise, например из-за сетевой ошибки, ошибка должна быть обработана через Error Boundary или другой подходящий механизм обработки ошибок

```js
import { Component, lazy, Suspense } from 'react';

const ReportsPage = lazy(() => import('./ReportsPage'));

class ReportsErrorBoundary extends Component {
  state = { hasError: false };

  static getDerivedStateFromError() {
    return { hasError: true };
  }

  render() {
    if (this.state.hasError) {
      return <p>Не удалось загрузить отчёты</p>;
    }

    return this.props.children;
  }
}

function ReportsSection() {
  return (
    <ReportsErrorBoundary>
      <Suspense fallback={<p>Загрузка...</p>}>
        <ReportsPage />
      </Suspense>
    </ReportsErrorBoundary>
  );
}
```

- в этом примере `Suspense` отвечает за состояние ожидания, а `ReportsErrorBoundary` — за отображение интерфейса при ошибке рендеринга или загрузки ленивого компонента
- в реальном приложении также может понадобиться возможность повторить загрузку, например после обновления страницы или повторного монтирования с новой стратегией импорта

## 6. практическое применение: lazy loading страниц

- один из самых распространённых сценариев — ленивый импорт страниц, особенно если приложение использует React Router

```js
import { lazy, Suspense } from 'react';
import { BrowserRouter, Routes, Route } from 'react-router-dom';

const HomePage = lazy(() => import('./pages/HomePage'));
const AnalyticsPage = lazy(() => import('./pages/AnalyticsPage'));
const SettingsPage = lazy(() => import('./pages/SettingsPage'));

function App() {
  return (
    <BrowserRouter>
      <Suspense fallback={<p>Загрузка страницы...</p>}>
        <Routes>
          <Route path='/' element={<HomePage />} />
          <Route path='/analytics' element={<AnalyticsPage />} />
          <Route path='/settings' element={<SettingsPage />} />
        </Routes>
      </Suspense>
    </BrowserRouter>
  );
}
```

- в этом примере все три страницы объявлены как ленивые компоненты, но их модули не обязаны загружаться при первом запуске приложения
- если пользователь открыл `/`, React попытается отобразить `HomePage`, а модули других страниц могут оставаться незагруженными до необходимости
- `Suspense` здесь оборачивает маршруты целиком, поэтому при загрузке страницы запасной интерфейс может заменять содержимое всех маршрутов внутри этой границы
- при проектировании приложения нужно учитывать не только размер начального чанка, но и то, насколько быстро пользователь сможет перейти к нужной странице после запуска

## 7. когда использовать lazy loading, а когда нет

- ленивую загрузку стоит рассматривать, когда модуль тяжёлый, редко используется или относится к отдельному пользовательскому сценарию
- типичные примеры — графические редакторы, страницы аналитики, административные разделы, тяжёлые библиотеки графиков и PDF-экспорта
- не стоит бездумно превращать каждый небольшой компонент в отдельный динамический импорт
- большое количество мелких чанков может увеличить количество сетевых запросов, добавить накладные расходы и привести к задержкам при переходах
- если компонент нужен почти каждому пользователю сразу после запуска, его отдельная загрузка может оказаться невыгодной
- также нужно учитывать предварительную загрузку: если приложение заранее знает, что пользователь, вероятно, откроет определённый раздел, соответствующий модуль можно попытаться загрузить заранее через `import()`, чтобы уменьшить задержку при переходе

## 8. типичные ошибки на собеседовании

- путать dynamic import и `React.lazy` — `import()` является механизмом JavaScript, а `React.lazy` интегрирует загрузку модуля с рендерингом React-компонента
- считать, что `Suspense` загружает компоненты — он определяет поведение интерфейса, пока дочернее дерево ожидает необходимый результат
- забывать про `default export` — `React.lazy` ожидает объект модуля с компонентом в поле `default`
- считать, что lazy loading автоматически ускоряет всё приложение — он способен уменьшить начальный объём загружаемого кода, но добавляет потенциальную задержку при первом открытии отложенной функциональности
- путать загрузку модуля с загрузкой данных — `React.lazy` предназначен для ленивой загрузки кода компонентов, а не является универсальным API для получения данных с сервера
- не обрабатывать ошибки — для отказа динамического импорта нужен механизм обработки ошибок, например Error Boundary

## 9. что нужно уметь объяснить своими словами

- dynamic import — это механизм JavaScript для загрузки модуля во время выполнения программы, который позволяет откладывать получение кода до момента необходимости
- code splitting — разделение JavaScript-приложения на отдельные чанки, чтобы не загружать весь код сразу
- lazy loading в React — способ отложить загрузку кода компонента до момента, когда React потребуется его отобразить
- `React.lazy` — API, которое создаёт ленивый компонент на основе функции загрузки модуля
- `Suspense` — механизм задания резервного интерфейса для дерева, которое приостановило рендеринг
- главная цель — уменьшить объём первоначально загружаемого кода, сохраняя возможность загружать дополнительную функциональность по мере необходимости
