# Virtualization в React

- virtualization — это техника оптимизации рендеринга больших списков и таблиц, при которой React отображает только те элементы, которые сейчас нужны пользователю для просмотра, вместо создания DOM-элементов для всего набора данных
- это важная тема для frontend-разработчика, потому что она находится на пересечении React rendering, работы браузерного DOM и оптимизации производительности

## 1. зачем нужна virtualization

- представим, что мы разрабатываем страницу с таблицей пользователей, в которой содержится 20 000 записей

```js
function UserList() {
  const users = Array.from({ length: 20000 }, (_, index) => ({
    id: index,
    name: `User ${index}`,
  }));

  return (
    <ul>
      {users.map((user) => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}
```

- при таком подходе React должен обработать все 20 000 элементов списка, а браузер — создать и поддерживать соответствующие DOM-узлы
- в реальном приложении каждый элемент может содержать несколько компонентов, аватар, кнопки, обработчики событий и другие вложенные элементы, что увеличивает стоимость первоначального рендеринга и последующих обновлений
- проблема заключается не только в React: большое количество DOM-узлов увеличивает нагрузку на браузер, потребление памяти и потенциальную стоимость вычисления стилей, layout и paint
- при этом пользователь обычно видит лишь несколько десятков элементов одновременно, а остальные находятся за пределами видимой области

основная идея virtualization:

```
20 000 записей в данных
          ↓
определение видимой области списка
          ↓
рендеринг видимых элементов + небольшой запас
          ↓
обычно несколько десятков DOM-элементов
```

- данные по-прежнему могут содержать все 20 000 записей, но в DOM находится только небольшая часть списка
- важно понимать, что virtualization не уменьшает количество данных в памяти сама по себе и не заменяет пагинацию или загрузку данных с сервера

## 2. как работает virtualization

### обычный список

```
Элемент 1

Элемент 2

Элемент 3

Элемент 4

Элемент 5

Элемент 6

Элемент 7

Элемент 8
```

- все элементы списка присутствуют в DOM, включая невидимые при прокрутке

### виртуализированный список

```
... элементы выше видимой области ...

Элемент 101

Элемент 102

Элемент 103

Элемент 104

... элементы ниже видимой области ...
```

- в DOM находятся только элементы, необходимые для текущей позиции прокрутки, и при необходимости небольшой запас

- схема выше иллюстрирует идею: пользователь может находиться в середине списка из тысяч записей, хотя в DOM присутствует лишь небольшой диапазон элементов
- для этого библиотека виртуализации должна определить несколько параметров:
  - `scrollOffset` — текущая позиция прокрутки
  - `viewportSize` — высота или ширина видимой области
  - `itemSize` — размер элемента, если он фиксированный
  - `overscan` — количество дополнительных элементов за пределами видимой области, которые рендерятся заранее
- например, если высота видимой области составляет 600 px, а высота каждого элемента — 30 px, то в ней помещается примерно 20 элементов
- с `overscan` по 5 элементов сверху и снизу библиотека может рендерить около 30 элементов вместо 20 000
- при прокрутке библиотека пересчитывает диапазон элементов, которые должны быть отображены, и React обновляет соответствующее поддерево

### почему нельзя просто удалить невидимые элементы

- если отрендерить только видимые строки без учёта их положения в общем списке, прокрутка не будет соответствовать реальной высоте содержимого
- поэтому виртуализированные списки должны сохранять геометрию всего списка, обычно с помощью контейнера общей высоты, spacer-элементов или позиционирования строк
- условная схема для фиксированной высоты строки:

```
общая высота = количество элементов × высота строки

20 000 × 30 px = 600 000 px
```

- библиотека может создать контейнер высотой 600 000 px, но поместить в него лишь несколько десятков строк в нужных позициях
- это позволяет браузеру корректно отображать полосу прокрутки, а виртуализатору — вычислять, какие строки соответствуют текущей позиции

## 3. virtualization и React rendering

- здесь важно различать несколько процессов, которые часто объединяют под общим словом «рендеринг»
- React rendering — вычисление React-дерева на основе текущих props и state
- reconciliation — сопоставление нового React-дерева с предыдущим, чтобы определить необходимые изменения
- DOM commit — применение необходимых изменений к реальному DOM
- браузерный rendering pipeline — вычисление стилей, layout, paint и compositing
- virtualization прежде всего сокращает количество одновременно отображаемых элементов и объём DOM, а также может уменьшать объём работы React при обновлении виртуализированного списка
- однако она не гарантирует, что любое обновление станет быстрым: если каждый видимый элемент выполняет тяжёлые вычисления, виртуализатор всё равно должен обрабатывать эти элементы
- также важно понимать, что при прокрутке диапазон видимых элементов меняется, поэтому React может размонтировать одни строки и смонтировать другие

### virtualization не равна React.memo

- `React.memo` позволяет пропустить повторный рендеринг компонента при неизменившихся props, если соблюдаются условия сравнения
- virtualization ограничивает число элементов, которые вообще представлены в DOM и React-дереве виртуализированного участка
- эти подходы решают разные задачи и могут использоваться вместе

```js
const UserRow = React.memo(function UserRow({ user }) {
  return <div>{user.name}</div>;
});
```

- если в списке 20 000 строк, `React.memo` сам по себе не избавит от первоначального создания всех строк
- виртуализация, напротив, позволяет изначально отрисовать только небольшое подмножество строк
- после этого `React.memo` может дополнительно сократить ненужные повторные рендеры тех строк, которые остаются смонтированными, если их props не меняются

## 5. практический пример с TanStack Virtual

- рассмотрим список пользователей, который содержит тысячи записей, но отображает лишь небольшую часть одновременно
- сначала установим библиотеку:

```bash
npm install @tanstack/react-virtual
```

- пример ниже использует API `useVirtualizer` и фиксированную высоту строк

```js
import { useRef } from 'react';
import { useVirtualizer } from '@tanstack/react-virtual';

const users = Array.from({ length: 20000 }, (_, index) => ({
  id: index + 1,
  name: `User ${index + 1}`,
}));

export function VirtualizedUserList() {
  const parentRef = useRef(null);

  const rowVirtualizer = useVirtualizer({
    count: users.length,
    getScrollElement: () => parentRef.current,
    estimateSize: () => 36,
    overscan: 5,
  });

  return (
    <div
      ref={parentRef}
      style={{
        height: 400,
        overflow: 'auto',
      }}
    >
      <div
        style={{
          height: rowVirtualizer.getTotalSize(),
          width: '100%',
          position: 'relative',
        }}
      >
        {rowVirtualizer.getVirtualItems().map((virtualRow) => {
          const user = users[virtualRow.index];

          return (
            <div
              key={user.id}
              style={{
                position: 'absolute',
                top: 0,
                left: 0,
                width: '100%',
                height: virtualRow.size,
                transform: `translateY(${virtualRow.start}px)`,
              }}
            >
              {user.name}
            </div>
          );
        })}
      </div>
    </div>
  );
}
```

- разберём ключевые части примера, потому что именно они показывают принцип работы виртуализатора

### `count`

```js
count: users.length;
```

- сообщает виртуализатору общее количество элементов, включая те, которые сейчас не находятся в DOM
- библиотека использует это значение при расчёте диапазона строк и общей геометрии списка

### `getScrollElement`

```js
getScrollElement: () => parentRef.current;
```

- возвращает DOM-элемент, прокрутку которого отслеживает виртуализатор
- в данном случае это внешний контейнер с `overflow: auto`
- `useRef` нужен, чтобы получить ссылку на DOM-элемент после его появления, не вызывая дополнительный рендеринг при изменении `ref.current`

### `estimateSize`

```js
estimateSize: () => 36;
```

- сообщает примерную высоту одной строки в пикселях
- при фиксированной высоте это значение совпадает с фактическим размером элемента
- при переменной высоте оценка используется для первоначальных расчётов, а библиотека может уточнять размеры с помощью измерений

### `overscan`

```js
overscan: 5;
```

- добавляет небольшой запас элементов за пределами видимой области
- если запас слишком маленький, при быстрой прокрутке может быть заметно появление строк
- если запас слишком большой, виртуализация теряет часть преимуществ, поскольку увеличивается количество одновременно отображаемых элементов

### `getTotalSize`

```js
height: rowVirtualizer.getTotalSize();
```

- задаёт общую высоту внутреннего контейнера, соответствующую всему списку
- при 20 000 строках по 36 px расчётная высота составит 720 000 px
- этот контейнер обеспечивает корректную прокрутку, хотя все строки не находятся в DOM

### `getVirtualItems`

```js
rowVirtualizer.getVirtualItems().map(...)
```

- возвращает только те элементы, которые библиотека считает необходимым отобразить сейчас, включая overscan
- поэтому `map` вызывается не для всех 20 000 пользователей, а только для текущего виртуального диапазона

### `transform: translateY(...)`

```js
transform: `translateY(${virtualRow.start}px)`;
```

- размещает строку в нужной позиции внутри общего контейнера
- поскольку строки позиционируются независимо, их положение определяется рассчитанной координатой, а не обычным последовательным расположением в потоке документа
- это и позволяет отображать, например, строку с индексом 10 000 без необходимости создавать в DOM все предыдущие строки

## 6. основные сложности virtualization

### динамическая высота элементов

- фиксированная высота — наиболее простой сценарий, потому что позицию строки можно вычислить арифметически
- если высота строк зависит от содержимого, библиотеке приходится измерять фактические размеры и уточнять позиции следующих элементов
- изменение высоты строки может повлиять на положение остальных строк, поэтому важно корректно обновлять измерения и сохранять ожидаемое поведение прокрутки

### ключи элементов

- при виртуализации строки могут часто размонтироваться и монтироваться заново, поэтому стабильные ключи по идентификаторам данных остаются важными
- использование индекса в качестве ключа может привести к проблемам при сортировке, фильтрации или изменении порядка данных, особенно если строки хранят локальное состояние

### локальное состояние компонентов

- если строка размонтируется после ухода за пределы виртуального диапазона, её локальный React state не сохраняется автоматически
- например, введённый пользователем текст в поле внутри строки может потеряться, если значение хранится только внутри компонента этой строки
- если состояние должно переживать размонтирование, его следует хранить на более высоком уровне, в модели данных или во внешнем хранилище

### доступность и взаимодействие

- элементы, отсутствующие в DOM, не доступны для обычного поиска браузером, навигации по всем DOM-элементам или некоторых сценариев скринридеров
- для списков с клавиатурной навигацией, фокусом, поиском и выделением элементов нужно дополнительно продумать поведение при прокрутке и размонтировании строк

### поиск и данные

- виртуализация не означает, что все данные обязательно должны загружаться одновременно
- для очень больших наборов данных её часто комбинируют с серверной пагинацией или бесконечной загрузкой: сервер ограничивает количество полученных записей, а виртуализатор ограничивает количество отображаемых DOM-элементов

## 7. rendering optimization: как выбирать подход

- виртуализация — не универсальный способ оптимизации любого React-компонента
- если на странице отображается 15 простых элементов, виртуализация, вероятно, добавит лишнюю сложность
- если список содержит тысячи сложных элементов, виртуализация может существенно сократить объём работы браузера и React
- на практике стоит придерживаться следующего порядка:
  - сначала измерить производительность с помощью React DevTools Profiler и инструментов производительности браузера
  - определить, что именно тормозит: вычисления компонентов, большое количество DOM-узлов, layout, обработчики событий или получение данных
  - если проблема связана с большим количеством отображаемых строк, рассмотреть virtualization
  - если повторно рендерятся неизменившиеся компоненты, проверить стабильность props и при необходимости применить `React.memo`
  - если тяжёлыми являются вычисления, рассмотреть оптимизацию алгоритма, кэширование результатов или перенос работы из рендера
  - после изменений повторно измерить производительность и проверить, улучшилось ли поведение интерфейса
- важно: `useMemo`, `useCallback` и `React.memo` не заменяют virtualization, если основной проблемой является чрезмерное количество DOM-узлов

## 8. что важно уметь объяснить на собеседовании

- что такое virtualization? — техника, при которой рендерится только видимая часть большого списка и небольшой запас элементов вокруг неё
- какую проблему она решает? — сокращает количество одновременно существующих DOM-узлов и объём работы, необходимой для отображения большого списка
- как обеспечивается прокрутка по всему списку? — виртуализатор рассчитывает общую геометрию списка и размещает отображаемые элементы в позициях, соответствующих их индексам
- чем virtualization отличается от pagination? — pagination ограничивает набор данных, доступный на одной странице, а virtualization ограничивает количество элементов, одновременно отображаемых в DOM
- чем она отличается от `React.memo`? — virtualization сокращает количество отображаемых элементов, а `React.memo` помогает пропускать повторные рендеры уже существующих компонентов при неизменившихся props
- какие у неё недостатки? — усложнение работы с динамическими размерами, фокусом, доступностью, локальным состоянием и измерениями элементов
- когда её стоит использовать? — когда большое количество одновременно отображаемых элементов действительно создаёт измеримую проблему производительности
- главное, что стоит запомнить: virtualization — это оптимизация количества одновременно отображаемых элементов, а не универсальная оптимизация всех аспектов React rendering
