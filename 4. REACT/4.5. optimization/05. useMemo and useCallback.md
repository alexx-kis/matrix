# useMemo и useCallback в React

- эти два хука относятся к инструментам оптимизации React и решают похожую задачу — позволяют повторно использовать результат вычислений или ссылку на функцию между рендерами, пока определённые зависимости не изменились
- для уверенного прохождения собеседования важно не просто знать разницу между хуками, а понимать, что именно они сохраняют, как React проверяет зависимости, когда мемоизация действительно помогает и почему иногда она только усложняет код

## 1. базовые понятия: рендеринг и ссылки

- перед изучением хуков нужно вспомнить несколько особенностей JavaScript и React

### каждый рендер создаёт новые значения

- при повторном вызове функционального компонента JavaScript заново выполняет его тело, создавая локальные переменные и функции

```js
function UserProfile({ user }) {
  const greeting = `Привет, ${user.name}`;

  const handleClick = () => {
    console.log(user.name);
  };

  return <button onClick={handleClick}>{greeting}</button>;
}
```

- при каждом рендере создаются новые значения `greeting` и `handleClick`, хотя исходные данные `user` могут оставаться прежними
- для примитивов, таких как строки и числа, сравнение значений может показать равенство, но функции и объекты являются ссылочными значениями

```js
const firstHandler = () => console.log('click');
const secondHandler = () => console.log('click');

console.log(firstHandler === secondHandler); // false
```

- несмотря на одинаковое содержимое, `firstHandler` и `secondHandler` — две разные функции с разными ссылками

### почему это важно для React

- создание новой функции само по себе обычно не является проблемой, но новая ссылка может влиять на оптимизации компонентов, сравнение зависимостей эффектов и других хуков
- например, `React.memo` может пропустить повторный рендер дочернего компонента, если его пропсы не изменились, но новая ссылка на функцию считается изменившимся пропсом

```js
import { memo, useState } from 'react';

const UserButton = memo(function UserButton({ onClick }) {
  console.log('UserButton rendered');

  return <button onClick={onClick}>Нажать</button>;
});

function UserPanel() {
  const [count, setCount] = useState(0);

  const handleClick = () => {
    console.log('Clicked');
  };

  return (
    <>
      <p>{count}</p>
      <button onClick={() => setCount((value) => value + 1)}>Увеличить счётчик</button>
      <UserButton onClick={handleClick} />
    </>
  );
}
```

- при изменении `count` компонент `UserPanel` рендерится повторно и создаёт новую функцию `handleClick`, поэтому `UserButton` тоже рендерится, несмотря на `memo`
- именно в подобных ситуациях могут пригодиться `useMemo` и `useCallback`

## 2. useMemo — мемоизация результата вычисления

- `useMemo` позволяет сохранить результат вычисления между рендерами, пока его зависимости не изменились

```js
import { useMemo, useState } from 'react';

function ProductList({ products }) {
  const [query, setQuery] = useState('');
  const [theme, setTheme] = useState('light');

  const filteredProducts = useMemo(() => {
    console.log('Filtering products');

    return products.filter((product) => product.name.toLowerCase().includes(query.toLowerCase()));
  }, [products, query]);

  return (
    <div className={theme}>
      <input value={query} onChange={(event) => setQuery(event.target.value)} />

      <button onClick={() => setTheme((current) => (current === 'light' ? 'dark' : 'light'))}>Change theme</button>

      {filteredProducts.map((product) => (
        <p key={product.id}>{product.name}</p>
      ))}
    </div>
  );
}
```

- рассмотрим ключевой фрагмент

```js
const filteredProducts = useMemo(() => {
  return products.filter(product =>
    product.name.toLowerCase().includes(query.toLowerCase())
  );
}, [products, query]);
```

- первый аргумент — функция, которая вычисляет значение, а второй — массив зависимостей, определяющих, когда вычисление нужно повторить
- при первом рендере React выполняет функцию и сохраняет полученный массив `filteredProducts`
- при следующем рендере React сравнивает текущие зависимости с предыдущими с помощью `Object.is`
- если `products` и `query` не изменились, React может вернуть сохранённый результат без повторного вызова функции
- если хотя бы одна зависимость изменилась, React вычисляет результат заново и сохраняет новое значение

### когда использовать useMemo

- когда выполняется достаточно дорогое вычисление, которое не нужно повторять при каждом рендере

```js
const sortedProducts = useMemo(() => {
  return [...products].sort((first, second) => {
    return first.price - second.price;
  });
}, [products]);
```

- когда нужно сохранить ссылку на объект или массив, передаваемый в оптимизированный дочерний компонент

```js
const filters = useMemo(() => {
  return {
    category: selectedCategory,
    inStock: onlyInStock,
  };
}, [selectedCategory, onlyInStock]);
```

- во втором примере мемоизация полезна не столько для ускорения создания объекта, сколько для сохранения его ссылки, пока зависимости не меняются
- при этом мемоизация не делает массив или объект неизменяемым — если изменить сохранённый объект напрямую, `useMemo` не предотвратит побочные эффекты такого изменения

### важный нюанс: useMemo не гарантирует постоянное хранение

- `useMemo` — это механизм оптимизации, а не хранилище данных, на которое должна опираться корректность приложения
- React может отбросить сохранённое значение в определённых ситуациях, поэтому код должен оставаться правильным и без предположения о вечном сохранении результата
- если значение должно сохраняться как часть состояния компонента, используй `useState` или `useReducer`, а не `useMemo`

## 3. useCallback — мемоизация ссылки на функцию

- `useCallback` позволяет сохранить ссылку на функцию между рендерами, пока её зависимости не изменились

```js
import { memo, useCallback, useState } from 'react';

const UserButtonMemoized = memo(function UserButtonMemoized({ onClick }) {
  console.log('UserButtonMemoized rendered');

  return <button onClick={onClick}>Нажать</button>;
});

function UserPanelMemoized() {
  const [count, setCount] = useState(0);

  const handleClick = useCallback(() => {
    console.log('Clicked');
  }, []);

  return (
    <>
      <p>{count}</p>

      <button onClick={() => setCount((value) => value + 1)}>Увеличить счётчик</button>

      <UserButtonMemoized onClick={handleClick} />
    </>
  );
}
```

- теперь `handleClick` сохраняет одну и ту же ссылку между обычными повторными рендерами, пока React сохраняет соответствующую мемоизацию и зависимости не меняются
- благодаря этому `React.memo` может пропустить повторный рендер `UserButtonMemoized`, если остальные пропсы тоже остались прежними

### как работают зависимости useCallback

```js
const handleSelect = useCallback(() => {
  console.log(selectedUserId);
}, [selectedUserId]);
```

- если `selectedUserId` не изменился, React возвращает ранее сохранённую функцию
- если `selectedUserId` изменился, React возвращает функцию, созданную во время нового рендера
- важно, что React не обновляет тело старой функции — он возвращает новую функцию с новым лексическим окружением, когда меняются зависимости

### useCallback не предотвращает выполнение функции

- он не вызывает функцию автоматически и не кеширует результат её выполнения

```js
const calculateTotal = useCallback((price, quantity) => {
  return price * quantity;
}, []);

const total = calculateTotal(100, 3);
```

- здесь `useCallback` сохраняет ссылку на `calculateTotal`, а вычисление `price * quantity` выполняется каждый раз при вызове функции
- если нужно кешировать именно результат вычисления, рассматривай `useMemo`

## 4. главная разница между useMemo и useCallback

- запомни простое правило: `useMemo` возвращает сохранённое значение, а `useCallback` — сохранённую функцию

### useMemo

```js
const result = useMemo(() => {
  return expensiveCalculation(value);
}, [value]);
```

- сохраняет результат вызова функции
- функция вычисления выполняется при первом рендере и при изменении зависимостей

### useCallback

```js
const handler = useCallback(() => {
  submitForm(formData);
}, [formData]);
```

- сохраняет ссылку на функцию
- сама функция вызывается только тогда, когда её вызывают

* есть и более глубокая связь: `useCallback(fn, deps)` концептуально эквивалентен `useMemo(() => fn, deps)`
* это означает, что оба хука используют один общий принцип мемоизации, но предоставляют разные удобные интерфейсы

## 5. как правильно работать с зависимостями

- массив зависимостей — одна из наиболее важных частей обоих хуков
- в него нужно включать все реактивные значения, которые используются внутри функции вычисления или колбэка: пропсы, переменные компонента и значения, возвращаемые другими хуками, если они могут меняться между рендерами

### ошибка № 1 — забыли зависимость

```js
const handleSave = useCallback(() => {
  saveUser(userId, formData);
}, [userId]);
```

- здесь используется `formData`, но он отсутствует в зависимостях
- если `formData` изменится, а `userId` останется прежним, React продолжит возвращать старую функцию, которая замкнула прежнее значение `formData`
- это классическая проблема stale closure — устаревшего замыкания
- правильный вариант:

```js
const handleSave = useCallback(() => {
  saveUser(userId, formData);
}, [userId, formData]);
```

### ошибка № 2 — зависимость каждый раз создаётся заново

```js
function SearchPanel({ items }) {
  const options = { matchMode: 'exact' };

  const visibleItems = useMemo(() => {
    return filterItems(items, options);
  }, [items, options]);

  return <div>{visibleItems.length}</div>;
}
```

- на каждом рендере создаётся новый объект `options`, поэтому его ссылка меняется
- следовательно, `useMemo` не получает ожидаемой пользы от кеширования: зависимость `options` каждый раз считается изменившейся
- предпочтительнее создавать объект внутри функции вычисления:

```js
function SearchPanel({ items }) {
  const visibleItems = useMemo(() => {
    const options = { matchMode: 'exact' };

    return filterItems(items, options);
  }, [items]);

  return <div>{visibleItems.length}</div>;
}
```

- теперь зависимостью является только `items`, а объект `options` создаётся при выполнении вычисления

### ошибка № 3 — пустой массив зависимостей не всегда правильный

```js
const handleSubmit = useCallback(() => {
  submitOrder(orderId);
}, []);
```

- если `orderId` может меняться, функция продолжит использовать значение из первоначального рендера
- пустой массив подходит только тогда, когда функция действительно не зависит от изменяющихся реактивных значений либо использует подходящий способ работы с ними

## 6. как избежать избыточной мемоизации

- главная ошибка при оптимизации React — использовать `useMemo` и `useCallback` повсюду, считая, что это автоматически делает приложение быстрее
- мемоизация имеет собственную стоимость: React должен хранить результат или функцию, сравнивать зависимости и поддерживать дополнительную сложность кода
- в большинстве случаев создание небольшого объекта или простой функции обходится дешевле, чем необходимость обосновывать и поддерживать мемоизацию

### когда useMemo, скорее всего, не нужен

```js
const fullName = `${firstName} ${lastName}`;
const isAdult = age >= 18;
const doubledValue = value * 2;
```

- здесь нет дорогих вычислений, а результаты являются примитивными значениями
- добавление `useMemo` ради таких выражений обычно только усложнит код

### когда useCallback, скорее всего, не нужен

```js
function UserCard({ user }) {
  const handleClick = () => {
    console.log(user.id);
  };

  return <button onClick={handleClick}>Открыть</button>;
}
```

- если `UserCard` не передаёт функцию дальше в компонент, оптимизированный через `React.memo`, и ссылка на функцию не используется в зависимостях других хуков, мемоизация часто ничего полезного не даёт
- обработчики событий сами по себе не требуют обязательного использования `useCallback`

### как понять, нужна ли оптимизация

- сначала найди реальную проблему: дорогие вычисления, лишние рендеры или нестабильные ссылки, из-за которых не срабатывает существующая оптимизация
- затем используй React DevTools Profiler, чтобы посмотреть, какие компоненты рендерятся, сколько это занимает времени и какие изменения вызывают работу
- после этого добавь мемоизацию и сравни результат
- если измеримого улучшения нет, дополнительная мемоизация, вероятно, не нужна

## 7. связь с React.memo

- `React.memo` и `useCallback` часто используются вместе, потому что решают связанные, но разные задачи

```js
const SaveButton = memo(function SaveButton({ onSave }) {
  console.log('SaveButton rendered');

  return <button onClick={onSave}>Сохранить</button>;
});

function Editor({ documentId }) {
  const [draft, setDraft] = useState('');

  const handleSave = useCallback(() => {
    saveDocument(documentId, draft);
  }, [documentId, draft]);

  return (
    <>
      <textarea value={draft} onChange={(event) => setDraft(event.target.value)} />
      <SaveButton onSave={handleSave} />
    </>
  );
}
```

- здесь `Editor` обновляется при каждом изменении `draft`, а `handleSave` тоже получает новую ссылку при каждом таком изменении, потому что `draft` входит в зависимости
- следовательно, `SaveButton` будет рендериться повторно при изменении `draft`, и это ожидаемое поведение: пропс `onSave` действительно изменился
- если же `Editor` рендерится по другой причине, а `documentId` и `draft` не изменились, `useCallback` сохраняет ссылку, и `React.memo` может пропустить лишний рендер `SaveButton`
- важный вывод: `useCallback` не гарантирует отсутствие повторных рендеров, а лишь позволяет сохранить ссылку, когда зависимости стабильны

## 8. нюансы для продвинутого уровня

### функциональное обновление состояния

- иногда можно сократить зависимости, используя функциональную форму обновления состояния

```js
const handleIncrement = useCallback(() => {
  setCount((previousCount) => previousCount + 1);
}, []);
```

- здесь `count` не нужно включать в зависимости, потому что функция обновления получает актуальное предыдущее значение состояния от React
- это полезный приём, когда колбэк должен оставаться стабильным, но ему необходимо обновлять состояние на основе его предыдущего значения

### useMemo не является заменой useEffect

- `useMemo` предназначен для вычисления значения во время рендера, а не для выполнения побочных эффектов
- не стоит использовать его для запросов к API, подписок, изменения внешнего состояния или другой работы, которая должна происходить как побочный эффект
- для таких задач применяются подходящие механизмы, например `useEffect`, а для событий — обработчики событий

### React Compiler

- в современных проектах стоит учитывать React Compiler, если он используется в конфигурации проекта
- компилятор способен автоматически выполнять многие оптимизации повторного использования значений и функций, для которых раньше вручную добавляли `useMemo` и `useCallback`
- это уменьшает потребность в ручной мемоизации, но не отменяет необходимость понимать зависимости, замыкания, корректность кода и измерение производительности

## 9. что отвечать на собеседовании

- в чём разница между `useMemo` и `useCallback`?
- `useMemo` мемоизирует результат вычисления, а `useCallback` — ссылку на функцию; оба хука сравнивают зависимости с предыдущим рендером через `Object.is` и позволяют повторно использовать сохранённое значение, если зависимости не изменились
- когда стоит использовать `useMemo`?
- когда вычисление достаточно дорогое или стабильная ссылка на объект либо массив помогает избежать лишней работы в других частях приложения
- когда стоит использовать `useCallback`?
- когда стабильная ссылка на функцию действительно важна, например при передаче её в компонент с `React.memo` или использовании в зависимостях других хуков
- почему нельзя добавлять эти хуки повсюду?
- потому что мемоизация имеет собственную стоимость и усложняет код, а для дешёвых вычислений и функций без значимых ссылочных зависимостей обычно не даёт ощутимого преимущества
- что такое stale closure?
- это ситуация, когда функция использует значения из более раннего рендера, потому что её замыкание осталось прежним, а необходимые зависимости не были указаны правильно

## итог

- `useMemo` — сохраняет результат вычисления
- `useCallback` — сохраняет ссылку на функцию
- `React.memo` — позволяет пропустить повторный рендер компонента при неизменившихся пропсах
- массив зависимостей определяет, когда мемоизированное значение или функция должны обновиться
- стабильные ссылки полезны не сами по себе, а когда помогают избежать реальной лишней работы
- сначала нужно понимать причину проблемы и по возможности измерять её, а затем добавлять мемоизацию
