# binding в JavaScript и React

- в этой теме разберём, что такое `this`, почему он иногда теряется в обработчиках событий React, зачем нужен `bind`, чем отличаются `bind`, `call` и `apply`, а также какие способы решения этой проблемы используются в классовых и функциональных компонентах
- главная цель — научиться понимать, какое значение будет у `this` в момент вызова функции и как гарантировать, что оно будет указывать на нужный объект

## 1. что такое this и зачем нужен binding

- `this` — это специальное значение JavaScript, которое внутри обычной функции позволяет обратиться к контексту её вызова
- например, у нас есть объект пользователя, который содержит имя и метод для его вывода

```js
const userProfile = {
  name: 'Анна',

  sayName() {
    console.log(this.name);
  },
};

userProfile.sayName();
```

- в консоли появится `Анна`, потому что метод вызывается через объект `userProfile`, поэтому внутри `sayName` значением `this` будет этот объект
- здесь важно понять первый принцип: для обычной функции значение `this` в большинстве случаев определяется тем, как её вызвали, а не тем, где её объявили
- рассмотрим другой пример

```js
const userProfile = {
  name: 'Анна',

  sayName() {
    console.log(this.name);
  },
};

const detachedMethod = userProfile.sayName;

detachedMethod();
```

- теперь мы сначала достали функцию из объекта и сохранили её в отдельную переменную, а затем вызвали отдельно
- связь между вызовом `detachedMethod()` и объектом `userProfile` потерялась, поэтому функция больше не вызывается как метод этого объекта
- в строгом режиме (`strict mode`) у обычной функции в таком случае `this` будет равен `undefined`, и обращение к `this.name` приведёт к ошибке
- в нестрогом режиме обычного JavaScript `this` у такой функции может указывать на глобальный объект, поэтому поведение будет отличаться
- именно эту проблему часто называют потерей контекста (losing context)

## 2. что означает bind

- `bind` — это метод функции, который создаёт новую функцию с заранее привязанным значением `this`
- сам по себе `bind` не вызывает исходную функцию, а возвращает новую функцию, которую можно вызвать позднее

```js
const accountOwner = {
  name: 'Иван',

  showName() {
    console.log(this.name);
  },
};

const boundShowName = accountOwner.showName.bind(accountOwner);

boundShowName();
```

- в консоли появится `Иван`, хотя `boundShowName` вызывается отдельно от объекта `accountOwner`
- это работает потому, что `bind(accountOwner)` создаёт функцию, для которой `this` зафиксирован на объекте `accountOwner`
- даже если передать `boundShowName` в другое место или сохранить в другую переменную, привязка `this` сохранится
- важно не путать две операции: `accountOwner.showName` — это ссылка на функцию, а `accountOwner.showName.bind(accountOwner)` — новая функция с привязанным контекстом

### что возвращает bind

- метод `bind` возвращает новую функцию, которую часто называют bound function, то есть привязанная функция
- исходная функция при этом не изменяется

```js
const scoreKeeper = {
  score: 10,

  printScore() {
    console.log(this.score);
  },
};

const firstBoundPrint = scoreKeeper.printScore.bind(scoreKeeper);
const secondBoundPrint = scoreKeeper.printScore.bind({ score: 50 });

firstBoundPrint();
secondBoundPrint();
scoreKeeper.printScore();
```

- результатом будут числа `10`, `50` и `10` соответственно
- первая привязанная функция всегда использует исходный объект, вторая использует переданный объект со значением `score: 50`, а исходный метод по-прежнему работает с `scoreKeeper`
- повторный вызов `bind` на уже привязанной функции не позволяет обычным способом заменить её ранее установленный `this`

## 3. почему this теряется в React

- проблема особенно часто встречалась при работе с обработчиками событий в классовых компонентах React
- рассмотрим пример классового компонента

```js
import React from 'react';

class UserGreeting extends React.Component {
  constructor(props) {
    super(props);

    this.state = {
      name: 'Анна',
    };
  }

  handleClick() {
    console.log(this.state.name);
  }

  render() {
    return <button onClick={this.handleClick}>показать имя</button>;
  }
}
```

- на первый взгляд кажется, что всё должно работать, потому что `handleClick` объявлен внутри класса и обращается к его `state`
- однако при нажатии на кнопку мы можем получить ошибку `Cannot read properties of undefined`, связанную с обращением к `this.state`
- почему так происходит
- `handleClick` — обычный метод класса, а обычные методы классов JavaScript не привязывают `this` к экземпляру автоматически
- когда мы пишем `this.handleClick`, мы получаем ссылку на функцию, но не вызываем её через экземпляр класса
- затем React вызывает переданный обработчик в рамках своей системы обработки событий, и полагаться на то, что `this` автоматически окажется экземпляром компонента, нельзя
- это не означает, что React специально удаляет контекст, — причина в правилах JavaScript и способе вызова функции
- чтобы разобраться в проблеме, представим упрощённую ситуацию без React

```js
class CounterMachine {
  constructor() {
    this.count = 0;
  }

  increment() {
    console.log(this.count);
  }
}

const counterMachine = new CounterMachine();

counterMachine.increment();

const detachedIncrement = counterMachine.increment;

detachedIncrement();
```

- первый вызов `counterMachine.increment()` выполняется через объект и поэтому получает правильный `this`
- второй вызов `detachedIncrement()` выполняется отдельно от объекта, поэтому в строгом режиме `this` будет равен `undefined`
- именно похожая ситуация возникает, когда метод передают как обработчик события без предварительной привязки

## 4. первый способ решения — bind в конструкторе

- классический способ решения проблемы в классовых компонентах React — один раз привязать нужный метод к экземпляру компонента в конструкторе

```js
import React from 'react';

class BoundUserGreeting extends React.Component {
  constructor(props) {
    super(props);

    this.state = {
      name: 'Анна',
    };

    this.handleClick = this.handleClick.bind(this);
  }

  handleClick() {
    console.log(this.state.name);
  }

  render() {
    return <button onClick={this.handleClick}>показать имя</button>;
  }
}
```

- ключевая строка здесь — `this.handleClick = this.handleClick.bind(this)`
- разберём её по частям
- правая часть `this.handleClick.bind(this)` создаёт новую функцию, которая всегда будет использовать текущий экземпляр компонента в качестве `this`
- левая часть `this.handleClick = ...` записывает эту новую функцию в свойство экземпляра компонента
- в результате обработчик можно передавать в JSX как `onClick={this.handleClick}`, не опасаясь потери контекста
- конструктор вызывается при создании экземпляра класса, поэтому привязка выполняется один раз для каждого экземпляра компонента
- если компонент создаётся повторно как новый экземпляр, для него будет создана собственная привязанная функция

### почему bind вызывается именно в конструкторе

- нам важно создать привязанную функцию один раз, а не при каждом рендере компонента
- если писать `this.handleClick.bind(this)` непосредственно в JSX, при каждом выполнении `render` будет создаваться новая функция

```js
<button onClick={this.handleClick.bind(this)}>показать имя</button>
```

- такой вариант обычно работает корректно с точки зрения `this`, но создаёт новую привязанную функцию при каждом рендере
- это может быть нежелательно, например если функция передаётся дочернему компоненту, который оптимизирует рендеринг с помощью `React.memo` или `PureComponent`
- новая ссылка на функцию может сделать сравнение пропсов неуспешным и вызвать дополнительный рендер дочернего компонента
- при этом само создание новой функции не является автоматически серьёзной проблемой производительности, и в небольшом компоненте оно часто не имеет практического значения

## 5. второй способ — arrow function в JSX

- ещё один вариант — передать стрелочную функцию, внутри которой вызывается метод компонента

```js
import React from 'react';

class ArrowHandlerGreeting extends React.Component {
  state = {
    name: 'Анна',
  };

  handleClick() {
    console.log(this.state.name);
  }

  render() {
    return <button onClick={() => this.handleClick()}>показать имя</button>;
  }
}
```

- здесь `handleClick` по-прежнему является обычным методом класса и сам по себе не привязан к экземпляру
- однако стрелочная функция создаётся в контексте выполнения `render`, где `this` указывает на экземпляр компонента
- стрелочные функции не создают собственный `this`, а используют `this` из окружающего лексического контекста
- поэтому при вызове `this.handleClick()` внутри стрелочной функции метод вызывается через экземпляр компонента и получает правильный контекст
- у этого подхода есть тот же нюанс с созданием новой функции: при каждом рендере создаётся новая стрелочная функция
- кроме того, обработчик вызывается через дополнительную функцию-обёртку, что может быть полезно, когда необходимо передать аргументы

```js
<button onClick={() => this.handleUserAction(42)}>выполнить действие</button>
```

- в данном случае стрелочная функция позволяет вызвать метод с аргументом, сохраняя нужный контекст

## 6. третий способ — метод класса в виде стрелочного свойства

- в современном JavaScript можно объявить обработчик как стрелочную функцию непосредственно в поле класса

```js
import React from 'react';

class ArrowPropertyGreeting extends React.Component {
  state = {
    name: 'Анна',
  };

  handleClick = () => {
    console.log(this.state.name);
  };

  render() {
    return <button onClick={this.handleClick}>показать имя</button>;
  }
}
```

- это решение часто называют class fields или arrow class fields
- здесь `handleClick` — не обычный метод, находящийся в прототипе класса, а свойство экземпляра, значением которого является стрелочная функция
- стрелочная функция захватывает `this` из контекста создания, то есть из экземпляра компонента, поэтому её не требуется дополнительно привязывать через `bind`
- при создании экземпляра класса поле инициализируется для этого экземпляра, поэтому у разных экземпляров будут разные функции
- обработчик можно передавать напрямую: `onClick={this.handleClick}`
- этот подход избавляет от необходимости вручную вызывать `bind` в конструкторе и не требует создавать стрелочную обёртку в каждом `render`
- это один из наиболее удобных способов объявления обработчиков в классовых компонентах, если проект поддерживает поля классов

## 7. сравнение трёх способов

| способ                   | как выглядит                                     | нужно ли явно привязывать this          | новая функция при каждом рендере      |
| ------------------------ | ------------------------------------------------ | --------------------------------------- | ------------------------------------- |
| `bind` в конструкторе    | `this.handleClick = this.handleClick.bind(this)` | да, один раз                            | нет                                   |
| стрелочная обёртка в JSX | `onClick={() => this.handleClick()}`             | нет, если метод вызывается через `this` | да                                    |
| стрелочное поле класса   | `handleClick = () => {}`                         | нет                                     | нет, функция создаётся для экземпляра |

- здесь под отсутствием новой функции при каждом рендере понимается именно то, что ссылка на обработчик не пересоздаётся при повторном выполнении `render`
- стрелочное поле класса создаёт функцию при инициализации экземпляра, а не один раз для всего класса, как это происходит с обычным методом в прототипе
- у каждого подхода есть своя область применения, но для собеседования особенно важно понимать, почему они работают, а не только запомнить синтаксис

## 8. а что происходит в функциональных компонентах

- в функциональных компонентах React проблема с `this` обычно вообще не возникает, потому что функциональные компоненты не используют экземпляр класса и не обращаются к состоянию через `this.state`

```js
import { useState } from 'react';

function FunctionalGreeting() {
  const [name, setName] = useState('Анна');

  function handleClick() {
    console.log(name);
  }

  return <button onClick={handleClick}>показать имя</button>;
}
```

- здесь `handleClick` использует переменную `name` из окружающего лексического окружения, а не `this`
- когда React вызывает обработчик, функция сохраняет доступ к переменным своего лексического окружения благодаря механизму замыканий JavaScript
- замыкание — это способность функции обращаться к переменным из внешней области видимости, даже когда функция вызывается позднее
- поэтому в функциональном компоненте обычно не нужно использовать `bind` для обработчиков событий
- важно не путать две независимые вещи: `this` относится к правилам вызова обычных функций и стрелочных функций, а замыкание позволяет функции обращаться к переменным внешней области видимости

### означает ли это, что в функциональных компонентах никогда не бывает проблем с контекстом

- нет, проблемы с контекстом могут возникать в обычном JavaScript-коде, который используется внутри функционального компонента, например при передаче метода стороннего объекта

```js
function ExternalServiceButton() {
  const serviceClient = {
    serviceName: 'NotificationService',

    send() {
      console.log(this.serviceName);
    },
  };

  return <button onClick={serviceClient.send}>отправить уведомление</button>;
}
```

- в этом примере мы передаём метод `serviceClient.send` как обработчик отдельно от объекта, поэтому нельзя рассчитывать, что `this` будет указывать на `serviceClient`
- один из вариантов решения — вызвать метод через стрелочную функцию

```js
function SafeExternalServiceButton() {
  const serviceClient = {
    serviceName: 'NotificationService',

    send() {
      console.log(this.serviceName);
    },
  };

  return <button onClick={() => serviceClient.send()}>отправить уведомление</button>;
}
```

- теперь `send()` вызывается непосредственно через `serviceClient`, поэтому `this` указывает на нужный объект
- другой вариант — заранее создать привязанную функцию с помощью `bind`, если она должна передаваться независимо от объекта

## 9. как работают call, apply и bind

- все три метода позволяют явно указать `this` для обычной функции, но различаются тем, когда выполняется вызов и как передаются аргументы
- `call` немедленно вызывает функцию, передавая `this` первым аргументом, а остальные аргументы — по одному
- `apply` тоже немедленно вызывает функцию, но аргументы передаются одним массивом или другим подходящим массивоподобным значением
- `bind` не вызывает исходную функцию немедленно, а возвращает новую функцию с привязанным `this` и, при необходимости, заранее заданными аргументами

```js
function describeProduct(category, price) {
  console.log(`${this.name}: ${category}, цена ${price}`);
}

const productOwner = {
  name: 'Мария',
};

describeProduct.call(productOwner, 'книга', 500);

describeProduct.apply(productOwner, ['книга', 500]);

const boundProductDescription = describeProduct.bind(productOwner, 'книга');

boundProductDescription(500);
```

- все три варианта выведут `Мария: книга, цена 500`
- разница заключается в том, что `call` и `apply` выполняют функцию сразу, а `bind` позволяет подготовить функцию для последующего вызова
- в React для решения проблемы потери контекста в классовых компонентах чаще всего обсуждают именно `bind`, поскольку обработчик нужно передать сейчас, а выполнить позднее — при событии

## 10. почему стрелочная функция ведёт себя иначе

- чтобы глубоко понимать binding, нужно знать главное отличие стрелочных функций от обычных функций
- у обычной функции `this` определяется способом вызова, если он не зафиксирован, например, с помощью `bind`
- у стрелочной функции собственного `this` нет, поэтому она использует `this` из внешнего лексического контекста

```js
const contextOwner = {
  name: 'Алексей',

  regularMethod() {
    console.log(this.name);
  },

  arrowMethod: () => {
    console.log(this.name);
  },
};

contextOwner.regularMethod();
contextOwner.arrowMethod();
```

- `regularMethod()` вызывается через `contextOwner`, поэтому `this.name` будет равно `Алексей`
- `arrowMethod` — стрелочная функция, которая не получает `this` от `contextOwner`, несмотря на то что хранится в его свойстве
- её `this` определяется внешним лексическим окружением в месте создания, поэтому она не подходит для методов, которым необходимо получать контекст объекта через обычный вызов `object.method()`
- конкретный результат второго вызова зависит от внешнего окружения, но рассчитывать на `contextOwner` в качестве `this` нельзя
- отсюда следует важное правило: не нужно автоматически превращать все методы объектов в стрелочные функции, если они должны использовать `this` самого объекта
- зато стрелочные функции отлично подходят для обработчиков классовых компонентов, когда требуется сохранить `this` экземпляра, а также для функций-обёрток в JSX

## 11. несколько нюансов binding, которые спрашивают на собеседованиях

### можно ли перепривязать this повторным bind

- обычным повторным вызовом `bind` нельзя заменить `this`, уже зафиксированный первой привязкой

```js
function printCurrentUser() {
  console.log(this.name);
}

const firstUserContext = { name: 'Анна' };
const secondUserContext = { name: 'Иван' };

const firstBoundUser = printCurrentUser.bind(firstUserContext);
const secondBoundUser = firstBoundUser.bind(secondUserContext);

secondBoundUser();
```

- в консоли появится `Анна`, потому что повторный `bind` не изменяет контекст, закреплённый за `firstBoundUser`

### можно ли использовать bind со стрелочной функцией

- технически можно вызвать `bind` у стрелочной функции, но это не позволит изменить её `this`, поскольку стрелочная функция не использует собственный `this`

```js
const arrowContextExample = () => {
  console.log(this);
};

const attemptedBinding = arrowContextExample.bind({ name: 'Иван' });

attemptedBinding();
```

- `attemptedBinding` будет новой функцией, но переданный объект не станет её `this`
- при этом `bind` всё ещё может быть полезен для предварительной передачи аргументов стрелочной функции, даже если привязка `this` не имеет эффекта

### почему bind в конструкторе не нужно вызывать в render

- потому что вызов `bind` возвращает новую функцию, и при каждом повторном вызове `bind` будет создаваться новая привязанная функция
- если каждый раз создавать её во время `render`, ссылка на обработчик будет меняться при каждом рендере
- это не обязательно ломает обработку события, но может мешать оптимизации дочерних компонентов, зависящих от стабильности ссылок на пропсы

### обязательно ли использовать bind в каждом классовом компоненте

- нет, `bind` нужен не для каждого метода класса, а только когда необходимо обеспечить определённое значение `this` при вызове функции
- если метод всегда вызывается через экземпляр, например `this.handleClick()`, дополнительная привязка обычно не нужна
- если метод передаётся отдельно как обработчик события, callback или аргумент другой функции, необходимо проверить, каким образом он будет вызван
- для обработчиков классовых компонентов эту проблему обычно решают через `bind` в конструкторе или через стрелочные поля класса

## 12. как ответить на собеседовании

- если спросят «что такое binding и как не потерять контекст в React?», можно ответить так

- в JavaScript значение `this` у обычной функции зависит от способа её вызова, поэтому при передаче метода отдельно от объекта контекст может потеряться
- для решения этой проблемы существует метод `bind`, который возвращает новую функцию с зафиксированным значением `this`
- в классовых компонентах React эта проблема часто возникает при передаче обычных методов в обработчики событий, например через `onClick={this.handleClick}`, поскольку нельзя рассчитывать, что React вызовет метод с правильным контекстом
- традиционное решение — выполнить `this.handleClick = this.handleClick.bind(this)` в конструкторе, альтернативное решение — объявить обработчик как стрелочное поле класса, которое сохраняет лексический `this`
- также можно передать стрелочную функцию в JSX, например `onClick={() => this.handleClick()}`, но при каждом рендере будет создаваться новая функция
- в функциональных компонентах проблема с `this` обычно отсутствует, потому что состояние и другие значения доступны через замыкания, а обработчики объявляются как обычные или стрелочные функции

## 13. что нужно запомнить в первую очередь

- `this` у обычной функции зависит от способа вызова, а не просто от места объявления

- `bind` возвращает новую функцию и заранее фиксирует её `this`

- обычные методы классов JavaScript автоматически не привязываются к экземпляру

- в классовых компонентах React можно использовать `bind` в конструкторе или стрелочные поля класса

- стрелочная функция не имеет собственного `this` и использует его из внешнего лексического контекста

- в функциональных компонентах React для обычных обработчиков событий `bind` не требуется, поскольку обычно используются замыкания

- главное на собеседовании — уметь объяснить не только синтаксис, но и причину потери контекста, а также понимать, почему конкретный способ решения работает
