# SyntheticEvent в React

- разберём тему с нуля: что такое `SyntheticEvent`, зачем React понадобилось создавать собственную систему событий, какие события поддерживаются и что изменилось в React 17

## 1. что такое событие и зачем оно нужно

- начнём с обычного JavaScript, потому что без этого сложно понять, что именно React добавляет поверх браузерных событий
- событие (event) — это объект, который описывает произошедшее действие, например клик мышью, ввод текста, отправку формы или нажатие клавиши

```js
const actionButton = document.querySelector('#action-button');

actionButton.addEventListener('click', (event) => {
  console.log(event);
});
```

- здесь `addEventListener` подписывает DOM-элемент на событие `click`, а браузер при клике вызывает обработчик и передаёт ему объект события в параметре `event`
- этот объект содержит информацию о произошедшем действии, например:
  - `event.target` — элемент, на котором первоначально произошло событие
  - `event.currentTarget` — элемент, на котором сейчас выполняется обработчик
  - `event.type` — тип события, например `click`
  - `event.preventDefault()` — отменяет стандартное действие браузера, если оно отменяемо
  - `event.stopPropagation()` — останавливает дальнейшее распространение события по дереву DOM
- например, при клике по кнопке браузер создаёт событие `click`, и обработчик получает доступ к информации об этом событии

## 2. что такое SyntheticEvent

- `SyntheticEvent` — это объект события, который React предоставляет обработчику события вместо непосредственной передачи исходного браузерного объекта
- слово synthetic переводится как «синтетический», то есть созданный или организованный поверх существующего механизма
- React оборачивает нативное событие браузера своим объектом, предоставляя унифицированный интерфейс для работы с событиями в разных браузерах
- рассмотрим пример на React

```js
function ActionButton() {
  function handleAction(event) {
    console.log(event);
    console.log(event.type);
    console.log(event.target);
    console.log(event.nativeEvent);
  }

  return <button onClick={handleAction}>нажми меня</button>;
}
```

- когда пользователь нажмёт кнопку, React вызовет `handleAction` и передаст ему объект `SyntheticEvent`
- в этом примере `event.type` вернёт тип события, `event.target` укажет на DOM-элемент, на котором произошло событие, а `event.nativeEvent` позволит получить связанное с ним нативное событие браузера
- важно понимать, что `SyntheticEvent` — не отдельный тип пользовательского действия, а объект, через который React предоставляет информацию о таком действии

### зачем React понадобился SyntheticEvent

- у разных браузеров исторически существовали различия в реализации событий и доступных свойствах, поэтому React создал общий интерфейс, чтобы разработчики могли писать обработчики единообразно
- у этого подхода есть несколько важных преимуществ
- единый интерфейс — основные свойства и методы события доступны в привычном виде независимо от браузера
- интеграция с React — React самостоятельно организует обработку событий и связывает её с компонентами и обновлением интерфейса
- управление распространением событий — React реализует собственную систему делегирования и распространения событий, которая взаимодействует с DOM
- при этом `SyntheticEvent` не означает, что React полностью заменяет браузерную систему событий, поскольку нативные события по-прежнему существуют и лежат в основе взаимодействия

## 3. основные свойства SyntheticEvent

- у объекта `SyntheticEvent` есть набор свойств и методов, которые полезно знать для собеседования

```
| свойство или метод        | для чего нужен
|---------------------------|-----------------------------------------------------------------------------------------|
| `event.type`              | тип события, например `click`
| `event.target`            | DOM-элемент, на котором событие первоначально возникло
| `event.currentTarget`     | DOM-элемент, чей обработчик сейчас выполняется
| `event.nativeEvent`       | исходное нативное событие
| `event.preventDefault()`  | отменяет стандартное действие браузера
| `event.stopPropagation()` | останавливает дальнейшее распространение события
| `event.bubbles`           | показывает, всплывает ли событие согласно его свойствам
| `event.cancelable`        | показывает, можно ли отменить стандартное действие события
| `event.defaultPrevented`  | показывает, была ли отмена стандартного действия
| `event.timeStamp`         | время возникновения события, представленное временной меткой
| `event.isTrusted`         | показывает, было ли событие инициировано пользователем или браузером, а не программным вызовом
```

- рассмотрим разницу между `target` и `currentTarget`, потому что она особенно важна для понимания всплытия событий

```js
function EventArea() {
  function handleAreaClick(event) {
    console.log('target:', event.target);
    console.log('currentTarget:', event.currentTarget);
  }

  return (
    <div onClick={handleAreaClick}>
      <button>нажми меня</button>
    </div>
  );
}
```

- если нажать на кнопку, обработчик родительского `div` тоже выполнится благодаря всплытию события
- в таком случае `event.target` будет указывать на кнопку, а `event.currentTarget` — на родительский `div`, где установлен текущий обработчик
- запомни главное различие: `target` — где событие началось, `currentTarget` — где выполняется текущий обработчик

### как работают preventDefault и stopPropagation

- эти методы решают разные задачи, и их нельзя считать взаимозаменяемыми

```js
function FormExample() {
  function handleFormSubmit(event) {
    event.preventDefault();
    console.log('форма обработана без стандартной отправки');
  }

  function handleButtonClick(event) {
    event.stopPropagation();
    console.log('клик не всплывает дальше');
  }

  return (
    <form onSubmit={handleFormSubmit}>
      <button type='submit'>отправить</button>
      <button type='button' onClick={handleButtonClick}>
        отдельное действие
      </button>
    </form>
  );
}
```

- `preventDefault()` отменяет действие браузера по умолчанию, например обычную отправку формы или переход по ссылке, если соответствующее действие отменяемо
- `stopPropagation()` останавливает распространение события к следующим обработчикам на пути распространения, но сам по себе не отменяет стандартное действие браузера
- например, `stopPropagation()` не мешает ссылке перейти по адресу, а `preventDefault()` не мешает событию всплыть к родителю
- также важно помнить, что возвращение `false` из React-обработчика само по себе не отменяет стандартное действие и не останавливает всплытие — для этого нужно явно вызвать соответствующий метод

## 4. какие события поддерживает React

- React поддерживает большое количество событий, а обработчики в JSX обычно задаются через свойства с именами в `camelCase`, например `onClick` и `onChange`

- основные группы событий и примеры приведены ниже

### Мышь

- **Обработчики:** `onClick`, `onDoubleClick`, `onMouseEnter`, `onMouseLeave`, `onMouseMove`
- **Когда используются:** клики, наведение, перемещение мыши

### Клавиатура

- **Обработчики:** `onKeyDown`, `onKeyUp`, `onKeyPress`
- **Когда используются:** нажатие и отпускание клавиш

### Формы

- **Обработчики:** `onChange`, `onInput`, `onSubmit`, `onInvalid`, `onReset`
- **Когда используются:** ввод данных и работа с формами

### Фокус

- **Обработчики:** `onFocus`, `onBlur`
- **Когда используются:** получение и потеря фокуса

### Указатель

- **Обработчики:** `onPointerDown`, `onPointerUp`, `onPointerMove`, `onPointerEnter`
- **Когда используются:** взаимодействие с мышью, пером и сенсорным вводом

### Сенсорный ввод

- **Обработчики:** `onTouchStart`, `onTouchMove`, `onTouchEnd`
- **Когда используются:** касания экрана

### Буфер обмена

- **Обработчики:** `onCopy`, `onCut`, `onPaste`
- **Когда используются:** копирование, вырезание и вставка

### Перетаскивание

- **Обработчики:** `onDragStart`, `onDragOver`, `onDrop`, `onDragEnd`
- **Когда используются:** drag-and-drop

### Прокрутка

- **Обработчики:** `onScroll`
- **Когда используются:** прокрутка элемента

### Колесо мыши

- **Обработчики:** `onWheel`
- **Когда используются:** прокрутка колёсиком мыши

### Медиа

- **Обработчики:** `onPlay`, `onPause`, `onEnded`, `onTimeUpdate`
- **Когда используются:** управление аудио и видео

### Изображения

- **Обработчики:** `onLoad`, `onError`
- **Когда используются:** загрузка изображения и обработка ошибок

### CSS-анимации

- **Обработчики:** `onAnimationStart`, `onAnimationEnd`, `onAnimationIteration`
- **Когда используются:** начало, завершение и повторение анимации

### CSS-переходы

- **Обработчики:** `onTransitionEnd`
- **Когда используются:** завершение CSS-перехода

### Выделение

- **Обработчики:** `onSelect`
- **Когда используются:** изменение выделения текста

### Композиция текста

- **Обработчики:** `onCompositionStart`, `onCompositionUpdate`, `onCompositionEnd`
- **Когда используются:** ввод текста через IME, например с помощью экранной клавиатуры или редактора ввода

- это основные группы, а не абсолютно полный перечень всех обработчиков React

### почему имена событий в React отличаются от нативных

- в обычном JavaScript обработчик устанавливается так

```js
document.addEventListener('click', handleDocumentClick);
```

- в JSX тот же тип взаимодействия задаётся через свойство

```js
<button onClick={handleDocumentClick}>нажми меня</button>
```

- обрати внимание на два различия: в DOM используется строка `'click'`, а в React — `onClick`, и обработчику передаётся функция, а не результат её немедленного вызова
- для многих событий можно использовать фазу перехвата, добавив `Capture` к имени обработчика, например `onClickCapture` вместо `onClick`

```js
function PropagationExample() {
  function handleParentCapture() {
    console.log('перехват родителя');
  }

  function handleChildClick() {
    console.log('клик по кнопке');
  }

  function handleParentClick() {
    console.log('всплытие к родителю');
  }

  return (
    <div onClickCapture={handleParentCapture} onClick={handleParentClick}>
      <button onClick={handleChildClick}>нажми меня</button>
    </div>
  );
}
```

- при обычном клике последовательность будет следующей: сначала `handleParentCapture`, затем `handleChildClick`, затем `handleParentClick`
- это происходит потому, что сначала событие проходит фазу перехвата сверху вниз, затем достигает целевого элемента и после этого всплывает снизу вверх
- есть исключения: например, `onMouseEnter` и `onMouseLeave` ведут себя не как обычные всплывающие события, а начиная с React 17 `onScroll` больше не имитирует всплытие к родителям

## 5. что изменилось в обработке событий начиная с React 17

- это один из наиболее важных вопросов по `SyntheticEvent` на собеседовании

- в React 17 изменилось несколько деталей системы событий, но две основные темы — делегирование событий и отказ от pooling, то есть повторного использования объектов событий

### изменение № 1 — делегирование событий

- сначала разберём, что означает делегирование (event delegation)

- представим страницу, на которой находится тысяча кнопок

- если каждому DOM-элементу назначить отдельный нативный обработчик одного и того же типа события, получится множество обработчиков

- альтернативный подход — установить обработчик на общий родительский элемент и определить, где именно произошло событие, по мере его всплытия

- это и есть делегирование событий

- React давно использует делегирование, но в React 16 и более ранних версиях большинство событий обрабатывалось через делегирование на уровне `document`, а начиная с React 17 основные обработчики делегируются на уровне корневого DOM-контейнера React-приложения

### до React 17

`document`

уровень делегирования

`#root`

React-компоненты и DOM-элементы

### начиная с React 17

`document`

обычные обработчики документа, если они установлены

`#root`

уровень делегирования React

React-компоненты и DOM-элементы

- схема упрощённая: она показывает уровень делегирования, а не полную внутреннюю реализацию системы событий

- зачем понадобилось это изменение

- представим, что на одной странице одновременно работают два приложения, использующие разные версии React, или React-приложение встроено в страницу с обработчиками на jQuery

- если все версии React делегируют события на `document`, им сложнее изолировать свои деревья событий и корректно взаимодействовать друг с другом

- например, вызов `stopPropagation()` внутри вложенного React-приложения в старой архитектуре не всегда мог предотвратить обработку события другим приложением, потому что его обработчик на `document` мог уже получить событие

- перенос делегирования на корневой контейнер делает распространение событий более предсказуемым и упрощает постепенное обновление приложений с разных версий React
- важно: это изменение касается внутреннего механизма обработки событий, а не того, как ты пишешь обычный JSX-обработчик

### изменение № 2 — удаление event pooling

- event pooling — это механизм повторного использования объектов событий
- до React 17, в том числе в React 16, React повторно использовал объекты `SyntheticEvent` в целях оптимизации, а после завершения обработчика очищал их свойства
- поэтому код, который обращался к событию асинхронно, мог столкнуться с неожиданным поведением

```js
function InputExample() {
  function handleInputChange(event) {
    setTimeout(() => {
      console.log(event.target.value);
    }, 1000);
  }

  return <input onChange={handleInputChange} />;
}
```

- в React 16 и более ранних версиях такой код мог не сработать ожидаемым образом, поскольку объект события после выполнения обработчика очищался

- одним из прежних решений был вызов `event.persist()`, который исключал событие из пула повторного использования

- начиная с React 17 pooling удалён, поэтому объект `SyntheticEvent` больше не очищается по этой причине, и приведённый пример работает без `persist()`

- однако это не означает, что `event.target` всегда останется доступным и неизменным: если сам DOM-элемент будет удалён или значение поля изменится, результат асинхронного чтения может отличаться от ожидаемого

- если нужно сохранить именно значение поля на момент изменения, лучше сохранить его отдельно

```js
function StableInputExample() {
  function handleInputChange(event) {
    const currentInputValue = event.target.value;

    setTimeout(() => {
      console.log(currentInputValue);
    }, 1000);
  }

  return <input onChange={handleInputChange} />;
}
```

- здесь `currentInputValue` — обычная строковая переменная, содержащая значение в момент вызова обработчика, поэтому дальнейшие изменения поля на неё не влияют
- метод `event.persist()` существует и в React 17+, но для обычного React DOM он больше не нужен, поскольку pooling был удалён

### другие изменения в React 17

- помимо двух основных изменений, есть несколько деталей, которые полезно знать

- `onScroll` перестал искусственно всплывать в React, что приблизило его поведение к нативному DOM

- обработчики фазы `Capture` стали использовать браузерную фазу перехвата

- для `onFocus` и `onBlur` React стал использовать нативные события `focusin` и `focusout` для реализации соответствующего поведения

- все эти изменения относятся к внутренней системе событий и не требуют переписывать большинство стандартных JSX-обработчиков

## 6. частые вопросы на собеседовании

- вопрос: чем SyntheticEvent отличается от нативного события?

- ответ: `SyntheticEvent` — это предоставляемая React обёртка над нативным событием браузера, которая обеспечивает унифицированный интерфейс и интеграцию с системой событий React

- вопрос: зачем нужен `nativeEvent`?

- ответ: через `event.nativeEvent` можно получить исходный объект события браузера, если требуются его специфические свойства или поведение

- вопрос: что изменилось в React 17?

- ответ: делегирование большинства событий было перенесено с `document` на корневой DOM-контейнер React, а повторное использование объектов `SyntheticEvent` было удалено

- вопрос: зачем раньше вызывали `event.persist()`?

- ответ: до React 17 он позволял сохранить объект события за пределами обработчика, исключив его из пула повторного использования, а начиная с React 17 в React DOM он больше ничего не делает

- вопрос: чем отличаются `target` и `currentTarget`?

- ответ: `target` указывает на элемент, на котором первоначально произошло событие, а `currentTarget` — на элемент, обработчик которого выполняется сейчас

- вопрос: чем отличаются `preventDefault()` и `stopPropagation()`?

- ответ: первый отменяет стандартное действие браузера, а второй останавливает дальнейшее распространение события

- вопрос: означает ли SyntheticEvent, что React не использует нативные события?

- ответ: нет, React строит собственную систему обработки поверх браузерных событий и предоставляет обработчикам унифицированный объект события

## 7. что важно запомнить

- `SyntheticEvent` — унифицированная обёртка React над нативным событием

- в обработчиках React доступны основные свойства и методы события, включая `target`, `currentTarget`, `preventDefault()` и `stopPropagation()`

- имена обработчиков в JSX обычно записываются в `camelCase`, например `onClick` и `onSubmit`

- для фазы перехвата обычно используется суффикс `Capture`, например `onClickCapture`

- в React 17 делегирование большинства событий перенесли на корневой контейнер, а pooling объектов событий удалили

- на собеседовании важно не просто перечислить изменения React 17, а объяснить, какую проблему решало каждое из них
