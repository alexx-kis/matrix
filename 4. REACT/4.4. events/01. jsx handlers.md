# JSX handlers — обработчики событий в React

- в этой теме нам нужно разобраться, чем обработчики событий в обычном JavaScript (native handlers) отличаются от обработчиков событий в React (React handlers), как они работают под капотом, почему в React используется свой подход и какие нюансы важно знать на собеседовании

## 1. что такое обработчик события

- начнём с самого понятия события, потому что без этого разница между обычным JavaScript и React будет не совсем понятна
- событие (event) — это сигнал о том, что что-то произошло в браузере, например пользователь кликнул по кнопке, ввёл текст, отправил форму или навёл курсор на элемент
- обработчик события (event handler) — это функция, которую браузер или библиотека вызывает в ответ на определённое событие
- например, нам нужно, чтобы при клике на кнопку в консоли появлялось сообщение

```js
function handleClick() {
  console.log('кнопка нажата');
}
```

- сама по себе функция ничего не знает о кликах и не запускается автоматически, потому что мы только объявили её, но ещё не связали с событием
- чтобы функция вызывалась при клике, её нужно зарегистрировать как обработчик события

## 2. native handlers — обработчики в обычном JavaScript

- в нативном JavaScript мы можем работать с событиями несколькими способами, но наиболее распространённый и гибкий подход — использовать метод `addEventListener`

### способ 1 — addEventListener

```js
<button id='nativeButton'>нажми меня</button>
```

```js
const nativeButton = document.querySelector('#nativeButton');

function handleNativeClick(event) {
  console.log('кнопка нажата');
  console.log(event.target);
}

nativeButton.addEventListener('click', handleNativeClick);
```

- разберём каждую часть
- `document.querySelector('#nativeButton')` находит кнопку в DOM и возвращает ссылку на соответствующий DOM-элемент
- `addEventListener('click', handleNativeClick)` регистрирует функцию `handleNativeClick` в качестве обработчика события `click`
- когда пользователь нажимает на кнопку, браузер создаёт объект события и вызывает зарегистрированный обработчик, передавая ему этот объект в аргументе `event`
- `event.target` — DOM-элемент, на котором событие первоначально возникло
- важно понимать, что `addEventListener` не вызывает функцию немедленно, а регистрирует её для последующего вызова при возникновении события

### способ 2 — обработчик через HTML-атрибут

```js
<button onclick="console.log('нажато')">нажми меня</button>
```

- здесь обработчик задаётся непосредственно в HTML через атрибут `onclick`
- это тоже нативный механизм браузера, но такой подход обычно менее удобен для сложного приложения, поскольку смешивает HTML-разметку и JavaScript-логику

### способ 3 — свойство DOM-элемента

```js
const nativeActionButton = document.querySelector('#nativeButton');

nativeActionButton.onclick = function (event) {
  console.log('клик по кнопке');
};
```

- здесь мы записываем функцию в свойство `onclick` DOM-элемента
- у этого подхода есть важный нюанс: если несколько раз присвоить новое значение `onclick`, предыдущий обработчик будет заменён

```js
nativeActionButton.onclick = function () {
  console.log('первый обработчик');
};

nativeActionButton.onclick = function () {
  console.log('второй обработчик');
};
```

- после двух присваиваний при клике выполнится только второй обработчик
- у `addEventListener` поведение другое: можно зарегистрировать несколько обработчиков одного типа на одном элементе

```js
nativeActionButton.addEventListener('click', function () {
  console.log('первый обработчик');
});

nativeActionButton.addEventListener('click', function () {
  console.log('второй обработчик');
});
```

- в этом случае оба обработчика будут вызваны при клике

## 3. JSX handlers — обработчики событий в React

- в React мы обычно не ищем DOM-элемент вручную и не вызываем у него `addEventListener`, а указываем обработчик непосредственно в JSX

```js
function NativeReactButton() {
  function handleReactClick(event) {
    console.log('кнопка нажата');
    console.log(event.target);
  }

  return <button onClick={handleReactClick}>нажми меня</button>;
}
```

- внешне это похоже на HTML-атрибут `onclick`, но между ними есть существенные различия
- `onClick` — это JSX-проп, через который React получает функцию-обработчик и связывает её с соответствующим событием
- `handleReactClick` — обычная JavaScript-функция, а `event` — объект события, который React передаёт при вызове обработчика
- обратите внимание на регистр букв: в HTML пишется `onclick`, а в JSX — `onClick`
- в JSX используется camelCase, то есть имя свойства начинается с маленькой буквы, а следующие слова — с заглавной
- ещё одно отличие заключается в том, что в JSX мы передаём функцию в фигурных скобках, а не строку с JavaScript-кодом

```js
<button onClick={handleReactClick}>нажми меня</button>
```

- здесь мы передаём ссылку на функцию, чтобы React мог вызвать её при наступлении события
- а вот такой вариант означает немедленный вызов функции во время выполнения кода компонента

```js
<button onClick={handleReactClick()}>нажми меня</button>
```

- это распространённая ошибка: React ожидает получить функцию, но вместо этого получает результат вызова `handleReactClick()`
- если функция ничего не возвращает, обработчик фактически окажется равен `undefined`, а сама функция выполнится во время рендеринга
- если нам нужно передать аргумент в обработчик, можно использовать стрелочную функцию

```js
function ArgumentReactButton() {
  function handleUserAction(userId) {
    console.log('действие пользователя:', userId);
  }

  return <button onClick={() => handleUserAction(42)}>выполнить действие</button>;
}
```

- в этом примере в JSX передаётся функция-обёртка, которая вызовет `handleUserAction(42)` только при клике

## 4. главные отличия native handlers от React handlers

| характеристика         | native JavaScript                                         | React JSX                                                                                   |
| ---------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| регистрация            | `addEventListener` или DOM-свойство                       | JSX-проп, например `onClick`                                                                |
| имя события            | `'click'`                                                 | `onClick`                                                                                   |
| регистр                | обычно lowercase для названия события                     | camelCase                                                                                   |
| передача обработчика   | `addEventListener('click', fn)`                           | `onClick={fn}`                                                                              |
| объект события         | нативный `Event` или его наследник                        | обычно React `SyntheticEvent`                                                               |
| управление DOM         | элемент часто ищут вручную                                | React связывает обработчик с элементом через JSX                                            |
| отмена обработки       | `removeEventListener` для снятия слушателя                | изменение JSX и обновление React обычно управляют привязкой                                 |
| несколько обработчиков | можно зарегистрировать несколько через `addEventListener` | обычно передаётся одна функция на конкретный JSX-проп, но она может вызывать другие функции |

- важно не сделать из таблицы неправильный вывод: React не создаёт отдельную физическую кнопку и не перестаёт использовать браузерные события, а предоставляет собственный декларативный интерфейс для работы с ними

## 5. что такое SyntheticEvent

- одна из важных особенностей React handlers — использование объекта события, который называется `SyntheticEvent`
- SyntheticEvent — это объект-обёртка React над нативным событием браузера, предоставляющий согласованный интерфейс для работы с событиями
- например, в обычном JavaScript мы можем получить нативный объект события так

```js
nativeButton.addEventListener('click', function (event) {
  console.log(event.nativeEvent);
});
```

- здесь `event` — уже нативное событие, поэтому свойства `nativeEvent` у него обычно нет
- в React ситуация другая

```js
function SyntheticEventButton() {
  function handleSyntheticClick(event) {
    console.log(event);
    console.log(event.nativeEvent);
    console.log(event.target);
    console.log(event.currentTarget);
  }

  return <button onClick={handleSyntheticClick}>проверить событие</button>;
}
```

- здесь `event` — объект `SyntheticEvent`, а `event.nativeEvent` позволяет обратиться к соответствующему нативному событию браузера
- рассмотрим основные свойства:
  - `event.target` — элемент, на котором первоначально возникло событие
  - `event.currentTarget` — элемент, для которого в данный момент выполняется обработчик
  - `event.preventDefault()` — отменяет стандартное действие браузера, если это действие можно отменить
  - `event.stopPropagation()` — останавливает дальнейшее распространение события по DOM-пути
  - `event.nativeEvent` — ссылка на нативное событие браузера

### зачем React нужен SyntheticEvent

- исторически браузеры имели некоторые различия в поведении событий и их API, поэтому React предоставлял унифицированный интерфейс для разных браузеров
- благодаря этому разработчик мог пользоваться согласованным API событий, не разбираясь в особенностях каждого браузера
- в современных браузерах многие различия уже неактуальны, но `SyntheticEvent` по-прежнему остаётся частью модели событий React
- начиная с React 17, React перестал переиспользовать объекты `SyntheticEvent` через механизм pooling, поэтому вручную вызывать `event.persist()` в современных версиях React обычно не требуется
- на собеседовании не стоит утверждать, что `SyntheticEvent` обязательно создаётся ради поддержки старых браузеров или что каждое событие React полностью независимо от нативного события, — это упрощение исторического механизма

## 6. как React обрабатывает события под капотом

- теперь разберём важную часть, которая помогает понять, почему React handlers отличаются от обычных обработчиков
- в нативном JavaScript мы можем непосредственно зарегистрировать обработчик на DOM-элементе

```js
nativeButton.addEventListener('click', handleNativeClick);
```

- при этом браузер хранит зарегистрированный обработчик и вызывает его, когда происходит соответствующее событие
- в React мы обычно пишем только JSX

```js
<button onClick={handleReactClick}>нажми меня</button>
```

- React получает информацию о том, какой обработчик соответствует какому элементу, и организует обработку событий через свою систему событий
- для многих распространённых событий React использует делегирование событий: вместо отдельного нативного слушателя на каждом DOM-элементе обработка организуется на общем предке, обычно на корневом DOM-контейнере React
- когда пользователь кликает по кнопке, браузер генерирует нативное событие, оно распространяется по DOM, а система React распознаёт событие и вызывает подходящие обработчики, связанные с React-деревом
- важно понимать, что конкретная реализация зависит от типа события и версии React, поэтому утверждение «React всегда ставит один слушатель на `document`» будет неправильным
- начиная с React 17, делегирование большинства событий React привязано к корневому DOM-контейнеру, а не к `document`, как это было характерно для многих событий в более ранних версиях
- кроме того, React различает распространение событий по реальному DOM и распространение событий по React-дереву, что особенно важно при работе с порталами

## 7. всплытие событий: native JavaScript и React

- всплытие (bubbling) — это механизм, при котором событие, возникшее на вложенном DOM-элементе, распространяется от него к родительским элементам
- рассмотрим обычный JavaScript

```js
<div id='nativeParent'>
  <button id='nativeChild'>нажми</button>
</div>
```

```js
const nativeParent = document.querySelector('#nativeParent');
const nativeChild = document.querySelector('#nativeChild');

nativeParent.addEventListener('click', function () {
  console.log('родитель');
});

nativeChild.addEventListener('click', function () {
  console.log('дочерний элемент');
});
```

- если нажать на кнопку, консоль выведет сначала `дочерний элемент`, затем `родитель`, поскольку событие всплывает от кнопки к родительскому `div`
- в React аналогичное поведение можно увидеть так

```js
function BubblingReactExample() {
  function handleContainerClick() {
    console.log('родитель');
  }

  function handleInnerClick() {
    console.log('дочерний элемент');
  }

  return (
    <div onClick={handleContainerClick}>
      <button onClick={handleInnerClick}>нажми</button>
    </div>
  );
}
```

- при клике на кнопку React вызовет дочерний обработчик, а затем родительский
- чтобы остановить всплытие, можно вызвать `event.stopPropagation()`

```js
function StopReactBubblingExample() {
  function handleOuterClick() {
    console.log('внешний элемент');
  }

  function handleInnerClick(event) {
    event.stopPropagation();
    console.log('внутренний элемент');
  }

  return (
    <div onClick={handleOuterClick}>
      <button onClick={handleInnerClick}>нажми</button>
    </div>
  );
}
```

- при клике на кнопку выведется только `внутренний элемент`, потому что распространение события по соответствующему пути будет остановлено
- здесь есть важный нюанс: `stopPropagation()` не отменяет стандартное действие браузера, например переход по ссылке или отправку формы, — для этого используется `preventDefault()`

## 8. preventDefault и stopPropagation — не одно и то же

- эти методы часто путают на собеседованиях, поэтому важно чётко различать их назначение
- `preventDefault()` — отменяет действие браузера по умолчанию, если оно отменяемое
- `stopPropagation()` — останавливает дальнейшее распространение события по пути распространения
- например, при отправке формы можно отменить её стандартную отправку

```js
function PreventFormSubmitExample() {
  function handleFormSubmit(event) {
    event.preventDefault();
    console.log('форма обработана через JavaScript');
  }

  return (
    <form onSubmit={handleFormSubmit}>
      <button type='submit'>отправить</button>
    </form>
  );
}
```

- здесь браузер не выполнит стандартную отправку формы, а обработчик сможет выполнить собственную логику, например валидацию или отправку запроса
- при этом событие `submit` само по себе не перестаёт всплывать из-за вызова `preventDefault()`

## 9. onClick и onClickCapture

- в React есть не только обработчики всплытия, но и обработчики фазы захвата (capture phase)
- при обычном распространении события сначала происходит фаза захвата: событие проходит от внешних элементов к целевому элементу, затем выполняются обработчики на целевом элементе, после чего начинается всплытие к родителям
- в JSX для фазы захвата используется суффикс `Capture`, например `onClickCapture`

```js
function CaptureReactExample() {
  function handleParentCapture() {
    console.log('захват родителя');
  }

  function handleChildClick() {
    console.log('клик по дочернему элементу');
  }

  function handleParentBubble() {
    console.log('всплытие к родителю');
  }

  return (
    <div onClickCapture={handleParentCapture} onClick={handleParentBubble}>
      <button onClick={handleChildClick}>нажми</button>
    </div>
  );
}
```

- при клике на кнопку порядок вывода будет таким: `захват родителя`, `клик по дочернему элементу`, `всплытие к родителю`
- это поведение полезно, например, когда нужно отследить событие на внешнем уровне до того, как оно достигнет вложенных элементов

## 10. почему в React не стоит вручную использовать addEventListener для каждого элемента

- React построен вокруг декларативного описания интерфейса: разработчик описывает, как интерфейс должен выглядеть и какие обработчики должны быть привязаны, а React управляет обновлением DOM и обработкой событий
- если для обычной кнопки использовать `onClick`, React сам организует обработку события в соответствии со своей моделью
- если же вручную добавлять слушатели через `addEventListener`, то ответственность за их регистрацию, удаление и актуальность замыканий переходит к разработчику
- например, если слушатель устанавливается внутри `useEffect`, его обычно нужно удалить при очистке эффекта, иначе можно получить лишние обработчики или утечки ресурсов

```js
import { useEffect, useRef } from 'react';

function ManualNativeListenerExample() {
  const manualButtonRef = useRef(null);

  useEffect(() => {
    const buttonElement = manualButtonRef.current;

    function handleManualClick() {
      console.log('нативный обработчик');
    }

    buttonElement.addEventListener('click', handleManualClick);

    return () => {
      buttonElement.removeEventListener('click', handleManualClick);
    };
  }, []);

  return <button ref={manualButtonRef}>нажми</button>;
}
```

- здесь мы используем `useRef`, чтобы получить доступ к DOM-элементу, и `useEffect`, чтобы зарегистрировать слушатель после того, как React добавит элемент в DOM
- при очистке эффекта слушатель удаляется, причём для `removeEventListener` нужно передать тот же тип события, ту же функцию и совместимые параметры регистрации
- в реальном приложении для обычных событий кнопки предпочтительнее `onClick`, а ручная регистрация полезна, когда необходимо подписаться на внешние события, например `resize` окна, `keydown` на `document` или события сторонней библиотеки

## 11. важные нюансы для собеседования

- обработчик не запускается во время рендеринга — если мы передаём `onClick={handleReactClick}`, React получает ссылку на функцию, а вызывает её при соответствующем событии
- JSX — это не HTML — `onClick` является JavaScript-пропом JSX, а не буквальным HTML-атрибутом, который браузер самостоятельно обрабатывает точно так же, как `onclick`
- объект события React — это SyntheticEvent — он предоставляет согласованный API и позволяет получить исходное событие через `nativeEvent`
- React не гарантирует отдельный нативный слушатель на каждый JSX-обработчик — он использует собственную систему событий и делегирование для многих типов событий
- `target` и `currentTarget` отличаются — `target` указывает на источник события, а `currentTarget` — на элемент, чей обработчик сейчас выполняется
- `preventDefault` и `stopPropagation` решают разные задачи — первый отменяет стандартное действие браузера, второй останавливает распространение события
- React handlers обычно привязаны к React-дереву — например, события из портала могут всплывать к родителям в React-дереве, даже если соответствующие элементы не являются родителями друг друга в DOM
- не все события распространяются одинаково — некоторые браузерные события не всплывают, а React может предоставлять для отдельных событий специальное поведение или синтезировать привычный интерфейс обработки

## 12. как ответить на собеседовании

- если на собеседовании спросят: «в чём разница между native handlers и React handlers?», можно ответить следующим образом

- в обычном JavaScript обработчики событий можно регистрировать непосредственно на DOM-элементах, например через `addEventListener`, либо через DOM-свойства вроде `onclick`
- в React обработчики обычно указываются декларативно в JSX через props, например `onClick={handleClick}`, причём имена событий записываются в camelCase, а сам обработчик передаётся как функция, а не вызывается во время рендеринга
- React использует собственную систему обработки событий и для многих событий применяет делегирование, а объект события обычно представляет собой `SyntheticEvent`, предоставляющий унифицированный интерфейс и доступ к нативному событию через `nativeEvent`
- при этом React handlers сохраняют привычные возможности работы с событиями, включая всплытие, фазу захвата, `preventDefault()` и `stopPropagation()`, но их распространение нужно рассматривать с учётом модели событий React, особенно при работе с порталами
