# event types в React

- разберём тему с нуля: какие бывают события в React, чем они отличаются друг от друга, как обрабатываются и что важно уметь объяснить на собеседовании
- сначала дам короткую классификацию, затем подробно разберём каждую группу, особенности React и практические примеры

## 1. кратко: какие бывают типы событий в React

- события мыши — `onClick`, `onDoubleClick`, `onMouseEnter`, `onMouseLeave`
- события клавиатуры — `onKeyDown`, `onKeyUp`
- события ввода и форм — `onChange`, `onInput`, `onSubmit`, `onFocus`, `onBlur`
- события указателя — `onPointerDown`, `onPointerMove`, `onPointerUp`
- события касания — `onTouchStart`, `onTouchMove`, `onTouchEnd`
- события перетаскивания — `onDragStart`, `onDragOver`, `onDrop`
- события прокрутки — `onScroll`
- события буфера обмена — `onCopy`, `onCut`, `onPaste`
- события загрузки и ошибок — `onLoad`, `onError`
- события анимации и переходов — `onAnimationEnd`, `onTransitionEnd`
- события медиа — `onPlay`, `onPause`, `onEnded`
- события контекстного меню — `onContextMenu`
- это классификация по назначению, а не официальный перечень категорий React — сами обработчики соответствуют различным типам событий браузера, которые React предоставляет через свою систему событий

## 2. что вообще такое событие

- событие (event) — это информация о том, что произошло в интерфейсе или с элементом страницы, например пользователь нажал кнопку, ввёл символ или отправил форму
- допустим, на странице есть кнопка

```js
function SaveButton() {
  function handleSave() {
    console.log('данные сохранены');
  }

  return <button onClick={handleSave}>сохранить</button>;
}
```

- здесь `onClick` — специальный JSX-проп React, через который мы передаём функцию-обработчик нажатия
- `handleSave` — функция, которую React вызовет, когда произойдёт соответствующее событие
- важно: мы передаём функцию `handleSave`, а не вызываем её как `handleSave()`, потому что нам нужно выполнить её при событии, а не во время рендеринга компонента
- когда пользователь нажимает кнопку, браузер генерирует событие, а React вызывает зарегистрированный обработчик и передаёт ему объект события

```js
function InspectButton() {
  function handleInspect(event) {
    console.log(event.type);
    console.log(event.target);
    console.log(event.currentTarget);
  }

  return <button onClick={handleInspect}>проверить</button>;
}
```

- `event.type` содержит тип события, в данном случае строку `"click"`
- `event.target` указывает на элемент, на котором событие первоначально возникло
- `event.currentTarget` указывает на элемент, для которого сейчас выполняется обработчик
- например, если внутри кнопки находится `span` и пользователь нажимает именно на него, `event.target` может указывать на `span`, а `event.currentTarget` — на `button`

## 3. подробно о каждой группе событий

### 3.1. события мыши — Mouse Events

- эти события возникают, когда пользователь взаимодействует с элементами при помощи мыши

| обработчик      | когда вызывается                                                               |
| --------------- | ------------------------------------------------------------------------------ |
| `onClick`       | при нажатии и отпускании кнопки мыши с формированием клика                     |
| `onDoubleClick` | при двойном клике                                                              |
| `onMouseDown`   | при нажатии кнопки мыши                                                        |
| `onMouseUp`     | при отпускании кнопки мыши                                                     |
| `onMouseMove`   | при перемещении мыши над элементом                                             |
| `onMouseEnter`  | при входе курсора в область элемента                                           |
| `onMouseLeave`  | при выходе курсора из области элемента                                         |
| `onMouseOver`   | при наведении курсора на элемент, в том числе при переходе между его потомками |
| `onMouseOut`    | при уходе курсора с элемента, в том числе при переходе к его потомкам          |
| `onContextMenu` | при вызове контекстного меню, обычно правой кнопкой мыши                       |

- рассмотрим пример, который показывает разницу между нажатием и кликом

```js
function MouseEventsDemo() {
  function handleMouseDown() {
    console.log('кнопка мыши нажата');
  }

  function handleClick() {
    console.log('произошёл клик');
  }

  return (
    <button onMouseDown={handleMouseDown} onClick={handleClick}>
      нажми меня
    </button>
  );
}
```

- `onMouseDown` срабатывает непосредственно при нажатии кнопки мыши, а `onClick` — после завершения последовательности взаимодействия, соответствующей клику
- если пользователь нажмёт кнопку мыши, переместит курсор за пределы элемента и отпустит кнопку там, обычный `click` на исходном элементе может не возникнуть
- `onMouseEnter` и `onMouseLeave` полезны для реализации простых эффектов наведения, а `onMouseOver` и `onMouseOut` имеют дополнительную особенность: они могут срабатывать при перемещении курсора между дочерними элементами
- для интерфейсов, которые должны работать не только с мышью, но и с сенсорным экраном или стилусом, часто лучше подходят события указателя

### 3.2. события клавиатуры — Keyboard Events

- эти события позволяют реагировать на нажатия клавиш, например обрабатывать горячие клавиши, перемещаться по интерфейсу с клавиатуры или реагировать на `Escape`

| обработчик  | назначение                         |
| ----------- | ---------------------------------- |
| `onKeyDown` | срабатывает при нажатии клавиши    |
| `onKeyUp`   | срабатывает при отпускании клавиши |

- пример обработки клавиши `Escape`

```js
function KeyboardEventsDemo() {
  function handleKeyDown(event) {
    if (event.key === 'Escape') {
      console.log('пользователь нажал Escape');
    }
  }

  return <input onKeyDown={handleKeyDown} placeholder='нажми Escape' />;
}
```

- `event.key` содержит значение, описывающее нажатую клавишу, например `"Escape"`, `"Enter"` или `"a"`
- `event.code` описывает физическую клавишу с учётом её позиции на клавиатуре, например `"KeyA"`
- эти свойства не всегда взаимозаменяемы: `key` учитывает символ, который соответствует раскладке и модификаторам, а `code` ориентируется на физическое расположение клавиши
- `onKeyPress` встречается в старом коде, но этот обработчик устарел в браузерном API, поэтому в современном React-коде обычно используют `onKeyDown` и `onKeyUp`

### 3.3. события ввода и форм — Form Events

- эта группа особенно важна, потому что практически любое приложение работает с формами, поисковыми полями, фильтрами и другими элементами ввода

| обработчик  | назначение                                                                  |
| ----------- | --------------------------------------------------------------------------- |
| `onChange`  | сообщает об изменении значения элемента формы                               |
| `onInput`   | связан с вводом или изменением значения в текстовых элементах               |
| `onSubmit`  | срабатывает при отправке формы                                              |
| `onReset`   | срабатывает при сбросе формы                                                |
| `onFocus`   | срабатывает при получении элементом фокуса                                  |
| `onBlur`    | срабатывает при потере элементом фокуса                                     |
| `onInvalid` | срабатывает, когда элемент не проходит встроенную проверку валидности формы |

- особое внимание нужно уделить `onChange`, поскольку его поведение в React отличается от привычного поведения нативного `change` для текстовых полей

```js
function SearchInput() {
  function handleChange(event) {
    console.log(event.target.value);
  }

  return <input type='text' onChange={handleChange} />;
}
```

- при вводе символов в текстовое поле React вызывает `onChange` по мере изменения значения, поэтому этот обработчик удобно использовать для управления состоянием поля
- в нативном DOM событие `change` для текстового поля обычно срабатывает при фиксации изменения, например после потери фокуса, тогда как нативное событие `input` срабатывает по мере ввода
- React нормализует поведение `onChange`, чтобы разработчику было удобно реагировать на изменение значения в процессе ввода
- пример с отправкой формы

```js
function LoginForm() {
  function handleSubmit(event) {
    event.preventDefault();
    console.log('форма отправлена');
  }

  return (
    <form onSubmit={handleSubmit}>
      <input name='email' type='email' />
      <button type='submit'>войти</button>
    </form>
  );
}
```

- `event.preventDefault()` отменяет стандартное действие браузера, в данном случае стандартную отправку формы
- это не отменяет распространение события по дереву элементов — для этого существует отдельный метод `stopPropagation()`
- `onFocus` и `onBlur` полезны при валидации полей, отображении подсказок и управлении визуальным состоянием элемента

### 3.4. события указателя — Pointer Events

- события указателя (Pointer Events) объединяют взаимодействия с разными устройствами ввода, включая мышь, сенсорный экран и стилус

| обработчик             | назначение                           |
| ---------------------- | ------------------------------------ |
| `onPointerDown`        | указатель нажат                      |
| `onPointerUp`          | указатель отпущен                    |
| `onPointerMove`        | указатель перемещается               |
| `onPointerEnter`       | указатель вошёл в область элемента   |
| `onPointerLeave`       | указатель покинул область элемента   |
| `onPointerOver`        | указатель наведён на элемент         |
| `onPointerOut`         | указатель покинул элемент            |
| `onPointerCancel`      | взаимодействие с указателем отменено |
| `onGotPointerCapture`  | элемент получил захват указателя     |
| `onLostPointerCapture` | элемент потерял захват указателя     |

- преимущество этой группы в том, что не нужно отдельно реализовывать одинаковую логику для мыши, касаний и стилуса

```js
function PointerEventsDemo() {
  function handlePointerDown(event) {
    console.log(event.pointerType);
  }

  return <div onPointerDown={handlePointerDown}>нажми на эту область</div>;
}
```

- `event.pointerType` позволяет определить тип указателя, например `"mouse"`, `"touch"` или `"pen"`
- pointer-события особенно полезны при реализации рисования, перетаскивания, интерактивных редакторов и других интерфейсов, работающих с разными устройствами ввода

### 3.5. события касания — Touch Events

- эти события предназначены для отслеживания взаимодействий с сенсорным экраном

| обработчик      | назначение                                |
| --------------- | ----------------------------------------- |
| `onTouchStart`  | началось касание                          |
| `onTouchMove`   | палец перемещается по экрану              |
| `onTouchEnd`    | касание завершилось                       |
| `onTouchCancel` | браузер отменил взаимодействие с касанием |

- пример использования

```js
function TouchEventsDemo() {
  function handleTouchStart(event) {
    console.log(event.touches.length);
  }

  return <div onTouchStart={handleTouchStart}>коснись экрана здесь</div>;
}
```

- `event.touches` содержит список активных касаний, а `event.changedTouches` — список касаний, изменившихся в рамках конкретного события
- `event.targetTouches` содержит активные касания, начавшиеся на текущем целевом элементе
- для нового кода обычно стоит рассматривать Pointer Events как более универсальный вариант, однако Touch Events по-прежнему встречаются в существующих проектах и могут быть нужны для специфичных сценариев

### 3.6. события перетаскивания — Drag and Drop Events

- эти события позволяют реализовать перетаскивание элементов, например перемещение карточек между колонками канбан-доски или загрузку файла через специальную область

| обработчик    | назначение                                    |
| ------------- | --------------------------------------------- |
| `onDragStart` | началось перетаскивание                       |
| `onDrag`      | элемент перетаскивается                       |
| `onDragEnd`   | перетаскивание завершилось                    |
| `onDragEnter` | перетаскиваемый объект вошёл в область        |
| `onDragOver`  | перетаскиваемый объект находится над областью |
| `onDragLeave` | объект покинул область                        |
| `onDrop`      | объект сброшен в область                      |

- пример с разрешением сброса

```js
function DragDropDemo() {
  function handleDragOver(event) {
    event.preventDefault();
  }

  function handleDrop(event) {
    event.preventDefault();
    console.log('объект сброшен');
  }

  return (
    <div onDragOver={handleDragOver} onDrop={handleDrop}>
      перетащи сюда объект
    </div>
  );
}
```

- вызов `preventDefault()` в `onDragOver` обычно необходим, чтобы разрешить сброс перетаскиваемого объекта в эту область
- для полноценного HTML Drag and Drop нужно также учитывать `draggable`, объект `dataTransfer` и соответствующую логику начала перетаскивания

### 3.7. события прокрутки — Scroll Events

- `onScroll` позволяет реагировать на прокрутку содержимого элемента, например для отображения кнопки возврата наверх или отслеживания положения прокрутки

```js
function ScrollEventsDemo() {
  function handleScroll(event) {
    console.log(event.currentTarget.scrollTop);
  }

  return (
    <div onScroll={handleScroll} style={{ height: 150, overflowY: 'auto' }}>
      <div style={{ height: 600 }}>прокрути содержимое</div>
    </div>
  );
}
```

- `scrollTop` показывает, насколько содержимое прокручено по вертикали относительно верхнего края
- важно помнить, что `onScroll` в современном React не распространяется так же, как большинство обычных событий: обработчик следует размещать на том элементе, прокрутку которого нужно отслеживать

### 3.8. события буфера обмена — Clipboard Events

- эта группа нужна для обработки копирования, вырезания и вставки текста или других данных

| обработчик | назначение                    |
| ---------- | ----------------------------- |
| `onCopy`   | пользователь копирует данные  |
| `onCut`    | пользователь вырезает данные  |
| `onPaste`  | пользователь вставляет данные |

- пример обработки вставленного текста

```js
function ClipboardEventsDemo() {
  function handlePaste(event) {
    console.log(event.clipboardData.getData('text'));
  }

  return <input onPaste={handlePaste} />;
}
```

- объект `clipboardData` позволяет читать или изменять данные события в пределах доступных браузером возможностей и разрешений
- эти события могут пригодиться при форматировании вставляемого текста, обработке специальных полей и реализации редакторов

### 3.9. события загрузки и ошибок — Load and Error Events

- эта группа помогает отслеживать загрузку ресурсов и ошибки при их загрузке

| обработчик | назначение                            |
| ---------- | ------------------------------------- |
| `onLoad`   | ресурс успешно загрузился             |
| `onError`  | при загрузке ресурса произошла ошибка |

- например, если изображение недоступно, можно показать заглушку

```js
function ImageWithFallback() {
  function handleError(event) {
    event.currentTarget.src = '/fallback.png';
  }

  return <img src='/photo.png' onError={handleError} alt='фотография' />;
}
```

- в реальном приложении нужно дополнительно защититься от бесконечного цикла, если сама заглушка тоже не загрузится
- эти события особенно важны для изображений, медиа и других ресурсов, загружаемых браузером

### 3.10. события анимации и переходов

- эти события позволяют реагировать на этапы CSS-анимаций и переходов между стилями

| обработчик             | назначение                         |
| ---------------------- | ---------------------------------- |
| `onAnimationStart`     | анимация началась                  |
| `onAnimationIteration` | завершился очередной цикл анимации |
| `onAnimationEnd`       | анимация завершилась               |
| `onTransitionRun`      | переход был запущен                |
| `onTransitionStart`    | переход начал выполняться          |
| `onTransitionEnd`      | переход завершился                 |
| `onTransitionCancel`   | переход был отменён                |

- например, можно выполнить действие после завершения анимации появления элемента

```js
function AnimationEventsDemo() {
  function handleAnimationEnd() {
    console.log('анимация завершена');
  }

  return (
    <div className='animated-element' onAnimationEnd={handleAnimationEnd}>
      привет
    </div>
  );
}
```

- сами события не создают анимацию, а лишь сообщают о том, что происходит с анимацией или переходом, определёнными в CSS

### 3.11. события мультимедиа — Media Events

- эти события используются для управления аудио и видео, например при воспроизведении ролика или завершении его загрузки

| обработчик       | назначение                                                 |
| ---------------- | ---------------------------------------------------------- |
| `onPlay`         | воспроизведение началось или возобновилось                 |
| `onPause`        | воспроизведение приостановлено                             |
| `onEnded`        | воспроизведение завершилось                                |
| `onTimeUpdate`   | изменилось текущее время воспроизведения                   |
| `onVolumeChange` | изменился уровень громкости или состояние отключения звука |
| `onLoadedData`   | загружены данные для текущего кадра                        |
| `onCanPlay`      | браузер может начать воспроизведение                       |
| `onWaiting`      | воспроизведение приостановлено в ожидании данных           |

- такие обработчики полезны для создания собственных элементов управления плеером, отображения прогресса воспроизведения и индикации загрузки

## 4. важная особенность: React Events и нативные события браузера

- на собеседовании недостаточно просто перечислить типы событий — нужно понимать, что React предоставляет собственную систему обработки событий, согласованную с DOM, но не полностью идентичную ей
- в React обработчики обычно задаются через JSX-пропы с именами в `camelCase`, например `onClick` и `onKeyDown`, а в нативном JavaScript обработчик можно зарегистрировать через `addEventListener`

```js
function CompareEventHandlers() {
  function handleReactClick() {
    console.log('React handler');
  }

  return <button onClick={handleReactClick}>нажми меня</button>;
}
```

- нативный вариант выглядит так

```js
const nativeButton = document.querySelector('#native-button');

nativeButton.addEventListener('click', function handleNativeClick() {
  console.log('native handler');
});
```

- в первом случае React регистрирует обработчик через свою систему событий, а во втором браузер напрямую связывает функцию с конкретным DOM-элементом
- при работе с React обычно предпочтительнее JSX-обработчики, поскольку они естественно интегрируются с жизненным циклом компонентов и обновлением интерфейса

### 4.1. что такое SyntheticEvent

- `SyntheticEvent` — это объект события, который React предоставляет обработчику и который представляет собой кроссбраузерную обёртку над нативным событием
- он содержит привычные свойства и методы, такие как `type`, `target`, `currentTarget`, `preventDefault()` и `stopPropagation()`, а нативное событие доступно через `nativeEvent`

```js
function SyntheticEventDemo() {
  function handleClick(event) {
    console.log(event.type);
    console.log(event.nativeEvent);
  }

  return <button onClick={handleClick}>нажми</button>;
}
```

- не каждое событие React является просто прямой копией нативного события — React может нормализовать поведение и организовывать обработку через собственную систему
- в React 17 изменилась организация делегирования событий: большинство обработчиков, управляемых React, стали делегироваться на корневом DOM-элементе конкретного React-приложения, а не на `document`, как это обычно было в предыдущих версиях
- начиная с React 17 объект `SyntheticEvent` больше не переиспользуется через прежний механизм pooling, поэтому вручную вызывать `event.persist()` для сохранения события в асинхронном коде в современных версиях React не требуется

### 4.2. всплытие и перехват событий

- события в DOM могут распространяться по иерархии элементов, и React в большинстве случаев сохраняет привычную модель всплытия
- допустим, есть родительский и дочерний элементы

```js
function BubblingEventsDemo() {
  function handleParentClick() {
    console.log('родитель');
  }

  function handleChildClick() {
    console.log('потомок');
  }

  return (
    <div onClick={handleParentClick}>
      <button onClick={handleChildClick}>нажми</button>
    </div>
  );
}
```

- при нажатии кнопки сначала выполнится обработчик кнопки, затем обработчик родителя, потому что событие всплывает от дочернего элемента к родительскому
- если нужно остановить всплытие, можно вызвать `event.stopPropagation()`
- для некоторых обработчиков React поддерживает фазу перехвата (capture), которая обозначается суффиксом `Capture`, например `onClickCapture`
- перехват происходит раньше фазы всплытия, когда событие проходит от предков к целевому элементу

```js
function CaptureEventsDemo() {
  function handleParentCapture() {
    console.log('перехват родителя');
  }

  function handleChildClick() {
    console.log('клик по кнопке');
  }

  return (
    <div onClickCapture={handleParentCapture}>
      <button onClick={handleChildClick}>нажми</button>
    </div>
  );
}
```

- при клике сначала выполнится обработчик перехвата родителя, а затем обработчик кнопки
- понимание всплытия и перехвата необходимо для делегирования событий, вложенных компонентов, модальных окон и порталов

## 5. что важно знать на собеседовании

- типы событий — нужно понимать основные группы: мышь, клавиатура, формы, указатели, касания, перетаскивание, прокрутка, буфер обмена, загрузка ресурсов, анимации и медиа
- обработчики React — нужно уметь объяснить, что `onClick` и другие JSX-пропы принимают функции, которые вызываются при соответствующих событиях
- объект события — нужно знать назначение `target`, `currentTarget`, `type`, `preventDefault()` и `stopPropagation()`
- SyntheticEvent — нужно понимать, что это объект события React с нормализованным интерфейсом, а не просто другое название нативного события
- отличия React от DOM — нужно знать особенности `onChange`, делегирования событий и синтаксиса обработчиков
- всплытие и перехват — нужно уметь объяснить порядок вызова обработчиков и различие между `onClick` и `onClickCapture`
- современный подход — нужно знать, что Pointer Events подходят для разных устройств ввода, а `onKeyPress` считается устаревшим
- главное — не пытаться заучить абсолютно все обработчики наизусть, а понимать, к какой группе относится событие, когда оно возникает и как React позволяет на него реагировать
