# controlled / uncontrolled components в React

- эта тема про то, кто управляет значением элемента формы — React или сам DOM
- разберём всё с нуля: что значит управлять значением, чем отличаются подходы, когда какой выбирать, как писать код и какие нюансы важно знать на собеседовании

## 1. что такое controlled и uncontrolled components

- представь обычное поле ввода, в которое пользователь вводит своё имя

- есть два способа организовать работу с этим полем

### controlled component — контролируемый компонент

- React хранит текущее значение поля в `state` и передаёт его элементу через `value`
- пользователь вводит символ → обработчик обновляет `state` → React передаёт новое значение полю

### uncontrolled component — неконтролируемый компонент

- текущее значение хранится в самом DOM-элементе, а React не управляет им через `state`
- пользователь вводит символ → браузер обновляет поле самостоятельно → React может получить значение позже, например через `ref`

- важно понимать, что в обоих случаях React может отображать поле ввода и обрабатывать отправку формы, но отличается источник, который считается главным для текущего значения

## 2. controlled component — подробно

### как это работает

- начнём с простого функционального компонента

```js
import { useState } from 'react';

function ControlledNameInput() {
  const [nameValue, setNameValue] = useState('');

  function handleNameChange(event) {
    setNameValue(event.target.value);
  }

  return (
    <label>
      ваше имя:
      <input value={nameValue} onChange={handleNameChange} />
    </label>
  );
}
```

- здесь есть несколько важных частей, которые нужно понимать отдельно

- `useState('')` создаёт состояние со значением пустой строки, которая будет начальным значением поля

- `value={nameValue}` указывает React, какое значение должно отображаться в поле ввода

- `onChange={handleNameChange}` регистрирует обработчик изменения значения поля

- `event.target.value` — текущее значение элемента ввода после изменения, а не сам объект события

- `setNameValue(event.target.value)` обновляет состояние, после чего React повторно вызывает функцию компонента и применяет новое значение к полю

### что происходит при вводе символа

- допустим, пользователь вводит букву `А`

1. пользователь вводит «А» - браузер генерирует событие изменения

2. срабатывает onChange - обработчик читает event.target.value

3. обновляется state - setNameValue('А')

4. React повторно рендерит компонент - value получает актуальное значение из state

- именно поэтому поле называется контролируемым: React определяет его отображаемое значение через `state`

- есть важный нюанс: обновление состояния не означает, что браузер обязательно будет ждать завершения нового рендера, прежде чем показывать символ, — React организует обновление так, чтобы ввод работал естественно

### что будет, если убрать onChange

- рассмотрим такой код

```js
import { useState } from 'react';

function LockedNameInput() {
  const [nameValue, setNameValue] = useState('Анна');

  return <input value={nameValue} />;
}
```

- поле получит значение `Анна`, но пользователь не сможет нормально изменить его, потому что React продолжит передавать в `value` прежнее значение из состояния

- React также выдаст предупреждение о том, что поле с `value` должно иметь обработчик `onChange`, если оно не предназначено для редактирования

- если нужно именно запретить редактирование, следует явно указать `readOnly`, а если нужно разрешить редактирование — обновлять состояние в обработчике

## 3. что такое uncontrolled component

- теперь посмотрим на тот же сценарий, но без управления значением через `state`

```js
import { useRef } from 'react';

function UncontrolledNameInput() {
  const nameInputRef = useRef(null);

  function handleNameSubmit(event) {
    event.preventDefault();

    const currentName = nameInputRef.current.value;

    console.log(currentName);
  }

  return (
    <form onSubmit={handleNameSubmit}>
      <label>
        ваше имя:
        <input ref={nameInputRef} defaultValue='Анна' />
      </label>

      <button type='submit'>отправить</button>
    </form>
  );
}
```

- здесь мы используем `useRef`, чтобы получить доступ к DOM-элементу, и читаем его значение при отправке формы

- разберём ключевые части

- `useRef(null)` создаёт объект, свойство `current` которого изначально равно `null`

- `ref={nameInputRef}` связывает этот объект с DOM-элементом после его создания и монтирования

- `nameInputRef.current` позволяет обратиться к самому DOM-элементу `<input>`

- `nameInputRef.current.value` возвращает текущее значение, которое пользователь ввёл в поле

- `defaultValue="Анна"` задаёт начальное значение поля, но не заставляет React постоянно синхронизировать его с каким-либо состоянием

### почему здесь нужен defaultValue, а не value

- это одно из главных отличий, которое спрашивают на собеседованиях

- `value` задаёт текущее значение контролируемого поля, тогда как `defaultValue` задаёт начальное значение неконтролируемого поля

- после первоначальной установки `defaultValue` пользователь может менять текст самостоятельно, а React не должен восстанавливать значение из `defaultValue` при каждом рендере

- изменение `defaultValue` при последующих рендерах не следует рассматривать как способ обновления текущего значения уже работающего поля

- для чекбоксов действует аналогичное различие: `checked` управляет текущим состоянием галочки, а `defaultChecked` задаёт начальное состояние

## 4. как сравнивать эти подходы

### controlled

- источник текущего значения — `state`
- чтение значения — из состояния
- изменение значения — через обработчик и функцию обновления состояния
- удобно для валидации, масок, зависимых полей и динамического интерфейса

### uncontrolled

- источник текущего значения — DOM-элемент
- чтение значения — через `ref` или объект `FormData`
- изменение значения — преимущественно силами браузера
- удобно для простых форм, когда значение нужно получить при отправке

### плюсы и минусы controlled components

- плюсы

- React всегда располагает актуальным значением поля в состоянии
- можно сразу показывать ошибки валидации, счётчик символов и подсказки
- легко менять другие поля в зависимости от введённого значения
- можно программно очищать, форматировать или ограничивать ввод

- минусы

- требуется писать обработчики для изменяемых полей
- каждое обновление состояния может приводить к повторному рендеру компонента
- при большом количестве полей нужно продумать организацию состояния и производительность

- важный нюанс: сам по себе повторный рендер не означает проблему с производительностью — для обычных форм это нормальная и ожидаемая работа React

### плюсы и минусы uncontrolled components

- плюсы

- для простых полей требуется меньше кода
- можно не хранить каждое введённое значение в `state`
- удобно получать данные формы в момент отправки через `FormData`
- браузер самостоятельно управляет обычным вводом

- минусы

- React не располагает актуальным значением в `state`, если вы отдельно его туда не записываете
- сложнее строить интерфейс, который должен немедленно реагировать на каждое изменение поля
- для чтения конкретного поля через `ref` нужно управлять ссылкой и учитывать, существует ли DOM-элемент

- нюанс: uncontrolled не означает, что в компоненте вообще нельзя использовать `state` или что React никак не влияет на поле — речь именно об источнике управления его текущим значением

## 5. можно ли получить значение uncontrolled-полей без useRef

- да, и для обычных HTML-форм это очень полезный подход — использовать `FormData`

```js
function UncontrolledLoginForm() {
  function handleLoginSubmit(event) {
    event.preventDefault();

    const formData = new FormData(event.currentTarget);
    const loginValue = formData.get('login');
    const passwordValue = formData.get('password');

    console.log(loginValue, passwordValue);
  }

  return (
    <form onSubmit={handleLoginSubmit}>
      <input name='login' defaultValue='' placeholder='логин' />

      <input name='password' type='password' defaultValue='' placeholder='пароль' />

      <button type='submit'>войти</button>
    </form>
  );
}
```

- `event.currentTarget` здесь указывает на форму, на которой зарегистрирован обработчик

- `new FormData(event.currentTarget)` собирает данные успешных элементов этой формы

- `formData.get('login')` получает значение поля с атрибутом `name="login"`

- `name` здесь важен: без него поле обычно не попадёт в набор данных формы под ожидаемым именем

- такой способ особенно удобен, когда нужно собрать все значения только в момент отправки, а не реагировать на каждый введённый символ

- учти, что `FormData` может содержать значения разных типов, включая `File`, а не только строки

## 6. controlled и uncontrolled для разных элементов формы

- различия касаются не только обычного текстового `input`, но и чекбоксов, радиокнопок, списков выбора и текстовых областей

### checkbox — чекбокс

- у чекбокса контролируемое состояние задаётся через `checked`, а не через `value`

```js
import { useState } from 'react';

function ControlledAgreement() {
  const [isAgreed, setIsAgreed] = useState(false);

  return (
    <label>
      <input
        type='checkbox'
        checked={isAgreed}
        onChange={(event) => {
          setIsAgreed(event.target.checked);
        }}
      />
      я согласен с условиями
    </label>
  );
}
```

- `event.target.checked` возвращает булево значение `true` или `false`, которое показывает, установлена ли галочка

- для неконтролируемого чекбокса используется `defaultChecked`, а прочитать состояние можно через `ref.current.checked`

### select — список выбора

- контролируемый список получает текущее выбранное значение через `value`

```js
import { useState } from 'react';

function ControlledCitySelect() {
  const [selectedCity, setSelectedCity] = useState('moscow');

  return (
    <select
      value={selectedCity}
      onChange={(event) => {
        setSelectedCity(event.target.value);
      }}
    >
      <option value='moscow'>Москва</option>
      <option value='kazan'>Казань</option>
      <option value='perm'>Пермь</option>
    </select>
  );
}
```

- для неконтролируемого списка начальное выбранное значение задаётся через `defaultValue`

### textarea — многострочное поле

- в React контролируемый `textarea` использует `value` и `onChange`, так же как обычный текстовый `input`

```js
<textarea value={commentText} onChange={(event) => setCommentText(event.target.value)} />
```

- неконтролируемый `textarea` использует `defaultValue`, а не управление через состояние

- в React начальное значение `textarea` задают через `defaultValue` или начальное содержимое элемента, но не через HTML-атрибут `value`, как в обычной HTML-разметке

## 7. что важно знать про ref

- `ref` — это способ получить доступ к самому DOM-элементу, не используя состояние для управления его значением

- например, после нажатия кнопки можно прочитать значение поля, очистить его или установить на него фокус

```js
import { useRef } from 'react';

function UncontrolledSearch() {
  const searchInputRef = useRef(null);

  function handleSearch() {
    const searchValue = searchInputRef.current.value;

    console.log(searchValue);
    searchInputRef.current.focus();
  }

  return (
    <div>
      <input ref={searchInputRef} defaultValue='' placeholder='что найти?' />

      <button type='button' onClick={handleSearch}>
        найти
      </button>
    </div>
  );
}
```

- здесь `useRef` не управляет значением поля, а предоставляет доступ к DOM-элементу

- обрати внимание на отличие `ref` от `state`: изменение `ref.current` само по себе не вызывает повторный рендер компонента

- при этом изменение `input.value` через DOM может обновить само поле, но React не узнает об этом автоматически и не будет синхронизировать значение с состоянием

- поэтому `ref` подходит для императивных операций, например фокуса, а `state` — для данных, от которых зависит отображение интерфейса

## 8. типичные ошибки на собеседовании

### ошибка 1 — использовать value без onChange

- если поле должно редактироваться пользователем, но его `value` всегда берётся из неизменяемого состояния, React продолжит возвращать ему это значение

- решение — обновлять состояние в `onChange` или использовать `defaultValue`, если поле должно быть неконтролируемым

### ошибка 2 — переключать поле между controlled и uncontrolled

- поле должно оставаться контролируемым или неконтролируемым на протяжении своего жизненного цикла

- например, если сначала `value` равен `undefined`, а затем становится строкой, React может предупредить о переходе от uncontrolled к controlled

- для контролируемого текстового поля обычно безопаснее инициализировать состояние пустой строкой, а не `undefined`

```js
import { useState } from 'react';

function StableControlledInput() {
  const [emailValue, setEmailValue] = useState('');

  return <input value={emailValue} onChange={(event) => setEmailValue(event.target.value)} />;
}
```

### ошибка 3 — считать defaultValue способом обновления поля

- `defaultValue` задаёт начальное значение, но не предназначен для постоянной синхронизации поля с новыми данными из `props` или `state`

- если нужно, чтобы изменение внешнего значения немедленно меняло отображаемый текст, обычно используют controlled-подход

### ошибка 4 — считать ref полноценной заменой state

- если интерфейс должен показывать количество символов, отображать ошибку при каждом изменении или разблокировать кнопку в зависимости от введённого текста, одного `ref` недостаточно для автоматического обновления интерфейса

- значение через `ref` можно прочитать вручную, но React не отслеживает изменение `ref.current` как изменение состояния

## 9. можно ли комбинировать оба подхода

- да, в одном приложении можно использовать и controlled, и uncontrolled компоненты, выбирая подход для конкретной задачи

- например, поле поиска может быть контролируемым, потому что нужно фильтровать список по мере ввода, а поле загрузки файла может использоваться без управления через `state`, если файл нужен только при отправке формы

- существуют и гибридные решения, в которых часть данных хранится в состоянии, а часть читается из DOM в нужный момент

- главное — не пытаться одновременно использовать `value` и `defaultValue` как два независимых способа управления одним и тем же полем

## 10. как выбрать подход на практике

- используй controlled, когда интерфейс должен реагировать на изменение значения немедленно

- валидация при вводе
- динамический поиск и фильтрация
- зависимые поля формы
- форматирование номера телефона
- блокировка кнопки до заполнения обязательных полей

- используй uncontrolled, когда значение не требуется постоянно синхронизировать с React

- простая форма, данные которой нужны только при отправке
- получение значения через `FormData`
- доступ к полю через `ref`
- операции с DOM, например установка фокуса

- это не строгие правила, а рекомендации: оба подхода могут быть корректными, а выбор зависит от того, как данные используются в приложении

## 11. как ответить на собеседовании

- controlled components — это компоненты формы, текущим значением которых управляет React через `state` и пропсы `value` или `checked`, а обработчик `onChange` обновляет состояние
- uncontrolled components — это компоненты, текущим значением которых управляет сам DOM, а React при необходимости получает значение через `ref` или `FormData`; для задания начального значения используются `defaultValue` и `defaultChecked`
- controlled-подход удобен для динамической валидации и реактивного интерфейса, а uncontrolled-подход позволяет упростить формы, значения которых нужны преимущественно при отправке
