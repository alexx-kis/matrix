# bubbling events in React

- разберём тему с нуля до уровня собеседования: как всплывают события в React, как это связано с компонентами, чем React отличается от DOM и почему события продолжают всплывать через порталы

## 1. что такое bubbling

- Bubbling (всплытие) — это механизм распространения события от элемента, на котором оно произошло, вверх по иерархии DOM-элементов к его предкам
- представим, что внутри карточки товара находится кнопка покупки

```js
function ProductCard() {
  return (
    <div onClick={() => console.log('card')}>
      <button onClick={() => console.log('button')}>купить</button>
    </div>
  );
}
```

- если нажать на кнопку, в консоли появится

```
button
card
```

- почему так происходит: браузер сначала вызывает обработчик кнопки, а затем событие `click` всплывает к родительскому `div`, у которого тоже есть обработчик
- важно понимать, что событие не передаётся от дочернего компонента родительскому компоненту напрямую — оно распространяется по DOM, а React обрабатывает его в своей системе событий

## 2. как происходит всплытие по шагам

- допустим, DOM имеет следующую структуру

```js
<div id='parent'>
  <div id='child'>
    <button id='target'>нажми</button>
  </div>
</div>
```

- когда пользователь нажимает на `button`, происходит несколько этапов

1. возникает событие - пользователь нажимает на `button`, поэтому именно он становится целью события

2. событие всплывает - обработчик на `button` вызывается первым, затем событие доходит до `child`, после чего до `parent`

3. вызываются обработчики - если у каждого элемента есть обработчик `onClick`, все три обработчика могут выполниться по очереди

- это упрощённая модель фазы всплытия, в которой мы пока не рассматриваем фазу захвата и особенности React

## 3. почему это называется bubbling

- представь пузырёк воздуха под водой: он поднимается от нижней точки к поверхности
- событие движется похожим образом — от целевого элемента к его родителям
- при этом всплытие не означает, что React вызывает обработчики всех компонентов, которые визуально расположены выше
- значение имеет путь события по DOM, а не визуальное расположение элементов на экране

## 4. как bubbling работает в React

- в React мы обычно не добавляем обработчики напрямую через `addEventListener`, а передаём их через JSX

```js
function EventDemo() {
  function handleParentClick() {
    console.log('parent');
  }

  function handleChildClick() {
    console.log('child');
  }

  return (
    <div onClick={handleParentClick}>
      <button onClick={handleChildClick}>нажми</button>
    </div>
  );
}
```

- здесь `handleParentClick` и `handleChildClick` — обычные JavaScript-функции, а `onClick` — специальный JSX-проп, с помощью которого React регистрирует обработчик события
- когда пользователь нажимает на кнопку, React вызывает обработчик кнопки, а затем обработчик родительского `div`
- в результате вывод будет таким

```
child
parent
```

### важный нюанс: компонент React и DOM-элемент — не одно и то же

- рассмотрим два компонента

```js
function InnerButton() {
  return <button onClick={() => console.log('button')}>нажми</button>;
}

function OuterPanel() {
  return (
    <div onClick={() => console.log('panel')}>
      <InnerButton />
    </div>
  );
}
```

- `OuterPanel` и `InnerButton` — компоненты React, то есть функции, которые описывают интерфейс
- `div` и `button` — реальные DOM-элементы, которые создаются в браузере
- хотя `OuterPanel` использует `InnerButton`, обработчик `onClick` родительского `div` сработает не потому, что React специально передаёт событие от одного компонента к другому, а потому, что кнопка находится внутри этого `div` в DOM
- на собеседовании лучше формулировать так: React-события распространяются в соответствии с иерархией элементов React, соответствующей дереву DOM, за исключением случаев, когда между этими деревьями есть различия, например при использовании порталов

## 5. как остановить всплытие

- иногда нужно, чтобы обработчик дочернего элемента сработал, а обработчики его родителей — нет
- для этого у события есть метод `stopPropagation()`

```js
function StopPropagationDemo() {
  function handleContainerClick() {
    console.log('container');
  }

  function handleButtonClick(event) {
    event.stopPropagation();
    console.log('button');
  }

  return (
    <div onClick={handleContainerClick}>
      <button onClick={handleButtonClick}>нажми</button>
    </div>
  );
}
```

- при нажатии на кнопку в консоли будет только

```
button
```

- `event` здесь — объект события React, через который обработчику доступна информация о событии и методы управления его распространением
- `event.stopPropagation()` останавливает дальнейшее распространение события по пути к предкам, поэтому родительский обработчик `onClick` не вызывается в обычном сценарии всплытия
- важно: метод не отменяет само действие кнопки и не отменяет другие обработчики на том же элементе
- например, если кнопка отправляет форму, `stopPropagation()` сам по себе не запрещает отправку формы

### чем отличается `stopPropagation()` от `preventDefault()`

- `stopPropagation()` — прекращает дальнейшее распространение события по пути DOM/React
- `preventDefault()` — отменяет стандартное действие браузера, если оно отменяемое

```js
function LinkDemo() {
  function handleLinkClick(event) {
    event.preventDefault();
    console.log('ссылка не перешла на другую страницу');
  }

  return (
    <a href='https://example.com' onClick={handleLinkClick}>
      перейти
    </a>
  );
}
```

- здесь переход по ссылке отменяется, но событие при этом может продолжать всплывать к родительским элементам
- если вызвать оба метода, можно одновременно отменить стандартное действие и остановить всплытие

```js
function CombinedDemo() {
  function handleLinkClick(event) {
    event.preventDefault();
    event.stopPropagation();
  }

  return (
    <div onClick={() => console.log('parent')}>
      <a href='https://example.com' onClick={handleLinkClick}>
        ссылка
      </a>
    </div>
  );
}
```

- при клике переход не произойдёт и обработчик родителя не вызовется

## 6. как работает bubbling в фазе захвата

- до всплытия существует ещё одна фаза распространения события — capturing (захват)
- при захвате событие проходит путь от внешних предков к целевому элементу, а при всплытии — в обратном направлении
- в React для этого предусмотрены обработчики с суффиксом `Capture`

```js
function EventPhasesDemo() {
  return (
    <div onClickCapture={() => console.log('parent capture')} onClick={() => console.log('parent bubble')}>
      <button onClickCapture={() => console.log('button capture')} onClick={() => console.log('button bubble')}>
        нажми
      </button>
    </div>
  );
}
```

- при обычном клике вывод будет таким

```
parent capture
button capture
button bubble
parent bubble
```

- порядок объясняется фазами распространения: сначала захват идёт сверху вниз, затем событие достигает цели и начинает всплывать снизу вверх
- обработчик `onClickCapture` родителя полезен, например, для логирования пользовательских действий или контроля событий на уровне контейнера до того, как их обработает дочерний элемент
- нюанс: точный порядок для нескольких вложенных элементов определяется всей цепочкой предков и обработчиков, а `stopPropagation()` может прервать дальнейшее распространение

# 7. bubbling через React Portal

- это одна из наиболее важных частей темы для собеседования
- Portal позволяет отрисовать DOM-элемент в другом месте DOM-дерева, сохранив его принадлежность к исходному дереву React
- например, модальное окно может логически находиться внутри компонента приложения, но физически рендериться внутри `document.body` или специального DOM-контейнера для модальных окон
- для этого используется `createPortal` из `react-dom`

```js
import { createPortal } from 'react-dom';

function PortalDialog() {
  return createPortal(
    <button onClick={() => console.log('modal button')}>нажми в модальном окне</button>,
    document.body,
  );
}
```

- здесь React рендерит кнопку в `document.body`, а не внутрь DOM-узла, в котором находится компонент, вызвавший `createPortal`
- чтобы понять bubbling через портал, нужно различать два дерева

### дерево React

```
App
↓
Parent
↓
Portal → Button
```

- в дереве React кнопка портала остаётся потомком Parent

### дерево DOM

```
div#root
↓
Parent DOM
↓
здесь кнопки портала нет

body
↓
Portal Button
```

- в DOM кнопка находится внутри body и вне DOM-ветки Parent

- эти два дерева отличаются, и именно это объясняет поведение событий через порталы

### проверим на коде

```js
import { createPortal } from 'react-dom';

function PortalBubbleDemo() {
  function handleParentClick() {
    console.log('parent');
  }

  function handlePortalButtonClick() {
    console.log('portal button');
  }

  return (
    <div onClick={handleParentClick}>
      <p>обычный контент родителя</p>

      {createPortal(<button onClick={handlePortalButtonClick}>кнопка в портале</button>, document.body)}
    </div>
  );
}
```

- если нажать на кнопку в портале, в консоли появится

```
portal button
parent
```

- почему вызывается `handleParentClick`, если кнопка физически не является DOM-потомком родительского `div`
- потому что React распространяет синтетические события через дерево React, а не только через физическую иерархию DOM
- кнопка остаётся дочерним элементом родительского компонента в дереве React, поэтому событие может дойти до его обработчика
- это одно из принципиальных свойств порталов: они меняют физическое расположение DOM-элементов, но не разрывают их логическую связь в дереве React

### что произойдёт, если остановить всплытие в портале

```js
import { createPortal } from 'react-dom';

function PortalStopDemo() {
  function handleParentClick() {
    console.log('parent');
  }

  function handlePortalClick(event) {
    event.stopPropagation();
    console.log('portal button');
  }

  return (
    <div onClick={handleParentClick}>
      {createPortal(<button onClick={handlePortalClick}>кнопка в портале</button>, document.body)}
    </div>
  );
}
```

- при нажатии на кнопку в портале будет выведено только `portal button`, потому что `stopPropagation()` останавливает дальнейшее распространение React-события к родительскому обработчику
- здесь важно не делать вывод, что событие физически поднимается от кнопки к `div` через DOM — такого DOM-пути в этом примере нет
- также не стоит считать, что `stopPropagation()` универсально блокирует все нативные слушатели браузера: поведение зависит от того, где они зарегистрированы и на какой фазе работают

## 8. зачем вообще нужен bubbling через порталы

- типичный пример — модальное окно внутри приложения
- компонент приложения может обрабатывать клики на своём контейнере, а модальное окно при этом рендериться за пределами этого контейнера, чтобы не зависеть от его `overflow`, `z-index` или других CSS-ограничений
- несмотря на физическое расположение окна в другом месте DOM, обработчики родительских React-компонентов могут получать события от содержимого портала
- это полезно для логики приложения, но иногда становится источником ошибок
- например, родительский компонент может закрывать окно или переключать состояние при любом клике внутри своей React-ветки, в том числе при клике по элементам портала
- поэтому обработчик родителя не должен предполагать, что каждый полученный им клик произошёл внутри его DOM-области

## 9. частые ошибки на собеседовании

- ошибка 1: «событие всплывает по компонентам React»
  - точнее сказать, что браузерные события имеют путь распространения по DOM, а React обрабатывает синтетические события с учётом React-дерева, что особенно важно для порталов
- ошибка 2: «`stopPropagation()` отменяет действие элемента»
  - он останавливает распространение события, но не отменяет стандартное действие браузера — для этого предназначен `preventDefault()`
- ошибка 3: «Portal полностью отделяет элемент от родительского компонента»
  - портал меняет место, где React размещает DOM-узлы, но не разрывает родительские связи в React-дереве
- ошибка 4: «всплытие работает только при вложенных DOM-элементах»
  - для нативного DOM-события путь определяется DOM, однако обработчики React могут вызываться через логическую иерархию React и при использовании порталов
- ошибка 5: «все события всплывают»
  - не все нативные события всплывают, а поведение некоторых React-обработчиков отличается от поведения одноимённых нативных событий, поэтому нельзя автоматически переносить свойства одного события на другое

## 10. как ответить на собеседовании

- если спросят «что такое bubbling в React», можно ответить так

- bubbling — это распространение события от целевого элемента к его предкам, при котором обработчики родительских элементов могут сработать после обработчика дочернего элемента
- в React события обрабатываются через систему синтетических событий, и для обычных вложенных элементов порядок обработчиков соответствует распространению события по DOM
- чтобы остановить дальнейшее распространение, можно использовать `event.stopPropagation()`, а для отмены стандартного действия браузера — `event.preventDefault()`
- особенность порталов состоит в том, что они меняют физическое расположение DOM-элемента, но сохраняют его положение в React-дереве, поэтому событие из портала может всплыть к обработчикам React-родителей, которые не являются DOM-предками этого элемента

## 11. что нужно уметь объяснить своими словами

- обычное bubbling — почему при клике на кнопку срабатывает обработчик родительского `div`

- остановка всплытия — чем `stopPropagation()` отличается от `preventDefault()`

- capturing — почему `onClickCapture` родителя срабатывает раньше `onClick` кнопки

- bubbling через портал — почему обработчик React-родителя может сработать, хотя элемент портала физически находится в другой части DOM

- практическое применение — как избежать нежелательного вызова родительских обработчиков при кликах внутри модального окна
