# что такое `cloneElement`

- `React.cloneElement()` позволяет взять **уже существующий React element**, создать на его основе новый element и при этом изменить или добавить ему `props` и `children`

- то есть если `createElement()` создаёт новый React element с нуля, то `cloneElement()` берёт уже существующий и делает его изменённую копию

```js
const originalElement = React.createElement('button', { className: 'primary' }, 'Click');

const clonedElement = React.cloneElement(originalElement, { disabled: true });
```

- концептуально здесь происходит следующее

```
originalElement
      ↓
cloneElement()
      ↓
новый React element
      ↓
type остаётся "button"
className остаётся "primary"
disabled добавляется
children остаётся "Click"
```

## что именно копируется

- если сделать

```js
const baseElement = React.createElement('button', { className: 'primary', type: 'button' }, 'Click');

const modifiedElement = React.cloneElement(baseElement, { disabled: true });
```

- результат концептуально будет выглядеть примерно так

```js
{
  type: "button",
  props: {
    className: "primary",
    type: "button",
    disabled: true,
    children: "Click"
  }
}
```

- то есть существующие `props` сохраняются, а переданные в `cloneElement()` новые `props` добавляются или заменяют старые

## переопределение props

- если исходный element уже имеет какой-то prop, а мы передаём prop с таким же именем, новое значение заменяет старое

```js
const initialElement = React.createElement('button', { className: 'primary', disabled: false }, 'Click');

const updatedElement = React.cloneElement(initialElement, { className: 'secondary', disabled: true });
```

- здесь

```
className
primary → secondary

disabled
false → true
```

## что происходит с `children`

- `children` тоже можно заменить

```js
const sourceElement = React.createElement('button', null, 'Old text');

const replacementElement = React.cloneElement(sourceElement, null, 'New text');
```

- теперь у нового элемента будет `"New text"` вместо `"Old text"`

- это важный момент: если после второго аргумента передать новые аргументы `children`, старые `children` заменяются

## зачем вообще нужен `cloneElement`

- основная идея — **взять элемент, который уже был передан компоненту, и добавить или изменить его props, не создавая полностью новый element вручную**

- например, компонент может получить `children`

```jsx
function Wrapper({ children }) {
  // ...
}
```

- и захотеть добавить каждому дочернему элементу определённый prop

- тогда можно использовать `cloneElement`

```jsx
function Wrapper({ children }) {
  return React.cloneElement(children, {
    className: 'highlight',
  });
}
```

- если передать

```jsx
<Wrapper>
  <button>Click</button>
</Wrapper>
```

- `Wrapper` получит уже созданный React element, соответствующий `button`

- `cloneElement()` создаст на его основе новый element, добавив ему `className`

## `cloneElement` не клонирует DOM

- это очень важное отличие

- `React.cloneElement()` работает **с React element**, а не с настоящим DOM-узлом

```
React element
      ↓
cloneElement()
      ↓
новый React element
```

- здесь вообще не происходит операции вроде

```js
element.cloneNode();
```

- `cloneElement()` не обращается непосредственно к Browser DOM и не создаёт копию существующего DOM-элемента

## отличие от `createElement`

- `createElement()` говорит:

```
"создай мне React element с такими type, props и children"
```

- `cloneElement()` говорит:

```
"возьми этот существующий React element и создай его новую версию с изменёнными props/children"
```

- поэтому можно запомнить так

```
createElement
→ создать React element

cloneElement
→ создать новый React element на основе существующего
```

## что важно для собеседования

- `React.cloneElement()` **не изменяет исходный React element**
- он создаёт новый React element на его основе
- существующие `props` обычно сохраняются
- переданные новые `props` переопределяют одноимённые старые
- переданные `children` заменяют исходные `children`
- `cloneElement()` работает с **React elements**, а не с DOM-элементами
- типичный сценарий использования — когда компонент получает `children` или другой React element и хочет добавить ему дополнительные props
