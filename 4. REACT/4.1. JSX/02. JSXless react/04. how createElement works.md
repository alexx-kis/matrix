# как работает `createElement`

- `React.createElement()` — это функция React, которая **создаёт React element**, то есть JavaScript-объект, описывающий, что React должен отрисовать

- важно сразу разделить две вещи: `createElement()` **не создаёт DOM-элемент** и **не вставляет ничего в браузер**

```js
const element = React.createElement('h1', null, 'Hello');
```

- здесь React не создаёт настоящий

```html
<h1>Hello</h1>
```

- вместо этого он создаёт объект-описание примерно такого смысла

```js
{
  type: "h1",
  props: {
    children: "Hello"
  }
}
```

## какие аргументы принимает `createElement`

- в упрощённом виде сигнатура выглядит так

```js
React.createElement(type, props, ...children);
```

- `type` говорит **что нужно создать**

- `props` содержит свойства и атрибуты элемента

- `children` содержит его дочерние элементы или текст

## первый аргумент — `type`

- если мы передаём строку

```js
const titleElement = React.createElement('h1', null, 'Hello');
```

- `"h1"` означает обычный DOM-элемент `h1`

- если передаём компонент

```js
function Welcome() {
  return React.createElement('h1', null, 'Hello');
}

const welcomeElement = React.createElement(Welcome, null);
```

- `Welcome` уже означает **React-компонент**

- поэтому `type` может быть как строкой

```
"h1"
```

- так и ссылкой на компонент

```
Welcome
```

- это важное различие: строка означает встроенный элемент, а ссылка на функцию или класс — компонент

## второй аргумент — `props`

- например

```js
const buttonElement = React.createElement(
  'button',
  {
    className: 'primary',
    disabled: true,
  },
  'Click me',
);
```

- здесь React получает описание:

```
type → "button"

props → {
    className: "primary",
    disabled: true
  }

children → "Click me"
```

- `props` не становятся DOM-элементом сами по себе, они являются частью описания, которое React затем использует во время рендеринга

## третий и последующие аргументы — `children`

- например

```js
const containerElement = React.createElement('div', null, 'Hello', React.createElement('strong', null, 'world'));
```

- здесь у `div` два дочерних элемента

```
"Hello"
↓
React element <strong>
```

- поэтому `children` могут быть строками, числами, React elements и другими допустимыми React-значениями

## что возвращает `createElement`

- `createElement()` возвращает **React element**

- концептуально можно представить его примерно так

```js
{
  type: "button",
  props: {
    className: "primary",
    children: "Click me"
  }
}
```

- реальный объект React содержит дополнительные внутренние поля, поэтому это не точная структура объекта, а упрощённая модель для понимания

## где здесь JSX

- вот такой JSX

```jsx
const buttonElement = <button className='primary'>Click me</button>;
```

- старый JSX transform превращал его примерно в

```js
const buttonElement = React.createElement(
  'button',
  {
    className: 'primary',
  },
  'Click me',
);
```

- то есть `createElement()` — это фактически функция, которую старый JSX использовал для создания описания UI

## а где виртуальный DOM

- вот здесь особенно важно не сделать неправильный вывод

- **React element и Virtual DOM — не совсем одно и то же понятие**

- `createElement()` создаёт React element — объект, описывающий элемент UI

- из таких элементов React строит своё внутреннее представление дерева UI

- когда состояние меняется, React получает новое дерево элементов и сравнивает его с предыдущим представлением в процессе reconciliation

- затем React определяет, какие изменения нужно применить к настоящему Browser DOM

```
JSX
 ↓
React.createElement()
 ↓
React element
 ↓
дерево React elements
 ↓
reconciliation
 ↓
изменения Browser DOM
```

## самое важное для собеседования

- `React.createElement()` **не создаёт DOM-элемент**

- он принимает `type`, `props` и `children`

- на их основе создаёт **React element — объект-описание UI**

- JSX в старом React преобразовывался в вызовы `React.createElement()`

- React использует созданные элементы для построения и сравнения дерева UI, после чего применяет необходимые изменения к реальному DOM
