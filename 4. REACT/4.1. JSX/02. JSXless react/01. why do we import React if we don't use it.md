### почему мы импортировали `React`, если явно его не использовали

- это относится к React **до версии 17**, когда для JSX требовалось явно импортировать `React` в каждом файле, где использовался JSX

- на первый взгляд это действительно странно: мы пишем

```jsx
const element = <h1>Hello</h1>;
```

- но в исходном JavaScript никакого `<h1>` не существует, потому что JSX — это не JavaScript-синтаксис, который браузер понимает напрямую

- JSX сначала преобразуется специальным инструментом, например Babel, в обычный JavaScript

### что именно происходило

- в старых версиях React JSX обычно преобразовывался примерно так

```jsx
const element = <h1>Hello</h1>;
```

- превращалось в

```js
const element = React.createElement('h1', null, 'Hello');
```

- поэтому `React` фактически **использовался**, даже если мы не писали его имя непосредственно в исходном JSX

- когда мы писали

```jsx
import React from 'react';

const element = <h1>Hello</h1>;
```

- после преобразования получалось что-то концептуально похожее на

```js
const element = React.createElement('h1', null, 'Hello');
```

- следовательно, импорт был необходим, чтобы переменная `React` существовала в области видимости во время выполнения этого преобразованного кода

### почему без импорта возникала ошибка

- представим такой код

```jsx
const element = <h1>Hello</h1>;
```

- Babel преобразовывал его примерно в

```js
const element = React.createElement('h1', null, 'Hello');
```

- но `React` нигде не был объявлен

- поэтому JavaScript пытался найти переменную `React` и не находил её

```
ReferenceError: React is not defined
```

- то есть проблема была не в том, что **сам JSX использовал объект `React` напрямую**, а в том, что **результат компиляции JSX использовал `React.createElement`**

### причем здесь JSXless React

- JSXless React означает использование React **без JSX**, то есть мы сразу пишем JavaScript-вызовы

```js
const element = React.createElement('h1', null, 'Hello');
```

- здесь уже совершенно очевидно, зачем нужен импорт

```js
import React from 'react';

const element = React.createElement('h1', null, 'Hello');
```

- а JSX просто скрывал этот вызов от нас

```jsx
const element = <h1>Hello</h1>;
```

- поэтому старый React можно представить так

```
JSX
 ↓
Babel
 ↓
React.createElement(...)
 ↓
React element
```

### что изменилось начиная с React 17

- начиная с React 17 появился новый JSX transform

- теперь JSX больше не обязан преобразовываться непосредственно в `React.createElement`

- например

```jsx
const element = <h1>Hello</h1>;
```

- новый transform может преобразовать примерно в

```js
import { jsx } from 'react/jsx-runtime';

const element = jsx('h1', {
  children: 'Hello',
});
```

- поэтому `React` больше не требуется непосредственно в файле только ради JSX

- соответственно, начиная с React 17 такой код стал нормальным

```jsx
const element = <h1>Hello</h1>;
```

- без

```js
import React from 'react';
```

### что важно сказать на собеседовании

- **до React 17** JSX преобразовывался в вызовы `React.createElement`, поэтому файл с JSX должен был иметь `React` в области видимости, обычно через `import React from "react"`

- **с React 17** появился новый JSX transform, который использует функции из `react/jsx-runtime`, поэтому импорт `React` только ради JSX больше не нужен

- при этом `React` всё ещё нужно импортировать, если мы действительно используем что-то из него напрямую, например

```js
React.createElement(...)
```

или

```js
React.Component;
```

- то есть фраза **«раньше React нужно было импортировать для JSX»** технически означает: **старый JSX transform генерировал код, который обращался к `React.createElement`**
