## React Fragments

- `React.Fragment` нужен для того, чтобы **сгруппировать несколько элементов React без добавления дополнительного DOM-элемента**

- главная проблема появляется потому, что компонент должен возвращать **одно корневое значение**, а нам иногда логически нужно вернуть несколько соседних элементов

```jsx
function UserInfo() {
  return (
    <div>
      <h2>John</h2>
      <p>Frontend developer</p>
    </div>
  );
}
```

- здесь `div` используется только потому, что `h2` и `p` нужно объединить в один корневой элемент

- но этот `div` может быть совершенно не нужен в реальном DOM

- Fragment позволяет сделать то же самое без этого дополнительного `div`

```jsx
function UserInfo() {
  return (
    <React.Fragment>
      <h2>John</h2>
      <p>Frontend developer</p>
    </React.Fragment>
  );
}
```

- после рендера React создаст в DOM только `h2` и `p`

```html
<h2>John</h2>
<p>Frontend developer</p>
```

- самого `React.Fragment` в DOM **не существует**

### короткая форма

- Fragment обычно записывают с помощью пустых JSX-тегов

```jsx
function UserInfo() {
  return (
    <>
      <h2>John</h2>
      <p>Frontend developer</p>
    </>
  );
}
```

- это сокращённая запись

```jsx
<React.Fragment>
  <h2>John</h2>
  <p>Frontend developer</p>
</React.Fragment>
```

- то есть `<>...</>` — это не HTML-тег, а специальный JSX-синтаксис для Fragment

### зачем это вообще нужно

- основная цель — **не создавать лишнюю DOM-структуру только ради того, чтобы сгруппировать элементы**

- это особенно важно, когда дополнительный контейнер может повлиять на CSS, layout или семантику HTML

- например, если написать

```jsx
function Navigation() {
  return (
    <ul>
      <li>Home</li>
      <li>About</li>
      <li>Contacts</li>
    </ul>
  );
}
```

- здесь `ul` является настоящим смысловым контейнером, поэтому всё нормально

- но если компонент должен вернуть несколько `li` непосредственно родителю, добавлять ещё один элемент между ними уже неправильно

```jsx
function NavigationItems() {
  return (
    <>
      <li>Home</li>
      <li>About</li>
      <li>Contacts</li>
    </>
  );
}
```

- результатом будет

```html
<ul>
  <li>Home</li>
  <li>About</li>
  <li>Contacts</li>
</ul>
```

- а если вместо Fragment использовать `div`, получится некорректная структура

```html
<ul>
  <div>
    <li>Home</li>
    <li>About</li>
  </div>
</ul>
```

### что происходит внутри React

- Fragment — это специальный тип React-элемента, который позволяет React сохранить группу элементов как единое значение в React-дереве, но при reconciliation не создавать для этой группы отдельный DOM-узел

- условно можно представить React-дерево так

```text
Fragment
├── h2
└── p
```

- а DOM-дерево будет

```text
h2
p
```

- то есть **React-дерево и DOM-дерево не обязаны иметь одинаковую структуру**

- это важный момент для понимания React в целом

### Fragment и `key`

- у Fragment есть ещё одна важная особенность: полный `React.Fragment` может получать `key`

```jsx
const usersList = users.map((user) => (
  <React.Fragment key={user.id}>
    <dt>{user.name}</dt>
    <dd>{user.description}</dd>
  </React.Fragment>
));
```

- это особенно полезно, когда один элемент списка логически состоит из нескольких соседних DOM-элементов

- сокращённая форма `<>...</>` **не позволяет указать `key`**

```jsx
// так нельзя
<>...</>
```

- поэтому в таких случаях нужен именно

```jsx
<React.Fragment key={user.id}>...</React.Fragment>
```

### что важно сказать на собеседовании

- `React.Fragment` позволяет вернуть или сгруппировать несколько React-элементов без создания дополнительного DOM-элемента
- Fragment существует в **React-дереве**, но не создаёт соответствующий узел в DOM
- сокращённая форма Fragment — `<>...</>`
- если Fragment должен иметь `key`, необходимо использовать полную форму `<React.Fragment key="...">`
- главная причина использования Fragment — избежать ненужных wrapper-элементов и сохранить правильную DOM-структуру
- важный нюанс: Fragment не является способом «обойти» вообще все правила возвращаемого значения React, а является специальным способом представить несколько соседних элементов как одну группу для React
