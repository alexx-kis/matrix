### как это работает внутри

- здесь важно понять не столько внутренний исходный код React, сколько **архитектуру взаимодействия `React`, `ReactDOM`, React tree и Browser DOM**
- условно процесс можно представить так

```
JSX
 ↓
React elements
 ↓
React Fiber tree
 ↓
reconciliation
 ↓
commit
 ↓
ReactDOM
 ↓
Browser DOM
```

### 1. JSX превращается в React elements

- когда мы пишем

```js
function App() {
  return <h1>Hello</h1>;
}
```

- JSX сам по себе браузеру неизвестен
- сборщик преобразует его примерно в вызов `jsx`

```js
function App() {
  return jsx('h1', {
    children: 'Hello',
  });
}
```

- результатом является **React element**

- это обычный JavaScript-объект, который описывает, что мы хотим получить

- условно он содержит информацию вроде

```js
{
  type: 'h1',
  props: {
    children: 'Hello'
  }
}
```

- это ещё **не DOM-элемент**
- здесь React пока только получил описание будущего UI

### 2. React строит внутреннее дерево

- React использует это описание для построения внутреннего дерева, которое сегодня основано на архитектуре **Fiber**
- Fiber — это внутренняя структура React, представляющая узел дерева и дополнительную информацию, необходимую React для работы

```
Fiber tree

        App
         │
        h1
         │
      "Hello"
```

- важно не путать это дерево с Browser DOM
- Fiber tree существует внутри React и нужен ему для управления компонентами, состоянием, обновлениями и сравнением предыдущего и нового состояния UI

### 3. React выполняет reconciliation

- допустим, состояние компонента изменилось

```
старое состояние
      ↓
   React
      ↓
новое состояние
```

- React повторно получает описание UI
- теперь, например, вместо

```
<h1>Hello</h1>
```

получается

```
<h1>Hello, John</h1>
```

- React сравнивает новое дерево с предыдущим и определяет, **что действительно изменилось**

- этот процесс называется **reconciliation**

- React не обязан заново создавать весь DOM

- он пытается определить минимальный набор необходимых изменений

### 4. начинается commit phase

- после того как React определил необходимые изменения, начинается следующая важная стадия — **commit**
- здесь уже происходят реальные изменения внешнего мира

```
render phase
    ↓
что должно измениться?
    ↓
commit phase
    ↓
применить изменения
```

- для браузерного приложения эти изменения должен применить `ReactDOM`

### 5. ReactDOM работает с Browser DOM

- например, React определил, что текст внутри существующего `<h1>` нужно изменить

```
было:
<h1>Hello</h1>

стало:
<h1>Hello, John</h1>
```

- `ReactDOM` выполняет соответствующую DOM-операцию
- условно это можно представить как

```js
domNode.textContent = 'Hello, John';
```

- реальный внутренний код ReactDOM значительно сложнее, но принцип именно такой
- React определяет **что должно быть**, а DOM renderer знает **как применить это к конкретному типу среды**

### 6. где здесь `createRoot`

- когда мы пишем

```js
const root = createRoot(document.getElementById('root'));
```

- `createRoot` получает существующий DOM-контейнер

```html
<div id="root"></div>
```

- ReactDOM создаёт специальный объект `root`, который связывает React с этим DOM-контейнером
- после этого

```js
root.render(<App />);
```

- сообщает React: нужно начать управлять UI внутри этого root

- получается примерно такая связь

```
document.getElementById('root')
             │
             ↓
       ReactDOM root
             │
             ↓
       React/Fiber tree
```

### 7. почему React не меняет DOM напрямую

- потому что React должен оставаться максимально независимым от конкретной платформы
- React может работать с разными renderer'ами

```
                 React
                   │
                   ↓
             Fiber/Reconciler
                   │
        ┌──────────┼──────────┐
        ↓          ↓          ↓
    ReactDOM   React Native  ...
        ↓          ↓
   Browser DOM   Native UI
```

- для браузера renderer — `ReactDOM`
- для другой среды может существовать другой renderer
- общая React-логика при этом остаётся той же

### главное, что нужно запомнить

- `React element` — **описание того, каким должен быть UI**
- `Fiber tree` — **внутренняя структура React для управления этим UI**
- `reconciliation` — **определение того, что изменилось**
- `commit` — **применение необходимых изменений**
- `ReactDOM` — **renderer, который применяет эти изменения к Browser DOM**
- `Browser DOM` — **реальное DOM-дерево страницы**

```
JSX
 ↓
React element
 ↓
Fiber tree
 ↓
reconciliation
 ↓
commit
 ↓
ReactDOM
 ↓
Browser DOM
```

- именно поэтому разделение `React` и `ReactDOM` имеет смысл: **React занимается общей логикой UI, а ReactDOM отвечает за взаимодействие этой логики с браузерным DOM**
