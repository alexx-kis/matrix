# why was ReactDOM moved to a separate library

- исторически `React` и `ReactDOM` были тесно связаны, но со временем стало понятно, что у них **разные зоны ответственности**
- чтобы это понять, сначала разделим, что вообще делает `React`, а что делает `ReactDOM`

## роль React

- `React` отвечает за описание **UI как дерева компонентов**
- когда мы пишем

```js
function App() {
  return <h1>Hello</h1>;
}
```

- `React` занимается тем, чтобы на основе этого описания построить и поддерживать свою внутреннюю структуру элементов, то есть **React tree**
- при изменении состояния `React` определяет, каким должно стать новое представление UI, и вычисляет необходимые изменения
- сам по себе `React` при этом не обязан знать, **куда именно и каким способом физически выводить этот UI**

## роль ReactDOM

- `ReactDOM` связывает React с конкретной средой — **браузерным DOM**
- например, когда мы пишем

```js
import { createRoot } from 'react-dom/client';

const root = createRoot(document.getElementById('root'));

root.render(<App />);
```

- `React` предоставляет механизм создания и управления React-элементами
- `ReactDOM` предоставляет механизм, который позволяет этим React-элементам попасть в **Browser DOM**
- поэтому `ReactDOM` можно условно представить как адаптер между React и DOM браузера

```
React
  ↓
React tree
  ↓
ReactDOM
  ↓
Browser DOM
  ↓
браузер
```

## почему это разделили на библиотеки

- главная причина — **React не должен быть привязан только к браузерному DOM**

- если бы вся логика React находилась внутри одной библиотеки вместе с DOM-специфичным кодом, React было бы сложнее использовать в других средах

- например, существуют разные renderer'ы, которые позволяют использовать React-подход не только для обычного браузерного DOM

```
                 React
                   │
        ┌──────────┼──────────┐
        ↓          ↓          ↓
     ReactDOM    React Native  другие
        ↓
   Browser DOM
```

- здесь `React` содержит общую модель работы с компонентами, состоянием, reconciliation и React tree
- а конкретный renderer решает, **как представить результат работы React в конкретной среде**

## важный нюанс

- `React` действительно отвечает за очень большую часть работы: компоненты, элементы, состояние, reconciliation и определение того, каким должен быть UI

- `ReactDOM` отвечает именно за **DOM-специфичную часть** — работу с браузерным DOM и предоставление DOM renderer API

- это и есть основная идея разделения: **React отвечает за UI-модель, а renderer отвечает за её реализацию в конкретной среде**

## что важно сказать на собеседовании

- если спросят **«зачем ReactDOM вынесли в отдельную библиотеку?»**, хороший короткий ответ будет таким:

> - React отвечает за общую логику построения и обновления UI, а ReactDOM является renderer'ом для браузерного DOM, поэтому разделение позволяет не привязывать React к конкретной платформе и использовать его с другими renderer'ами
