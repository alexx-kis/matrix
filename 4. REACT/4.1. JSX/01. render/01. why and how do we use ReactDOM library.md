# зачем и как используется библиотека ReactDOM

- `ReactDOM` — это библиотека React, которая отвечает за **связь React с DOM браузера**
- сам React в основном занимается описанием того, **какой интерфейс мы хотим получить**, а `ReactDOM` отвечает за то, **как этот интерфейс появляется в настоящем DOM-документе страницы**

## зачем вообще нужен ReactDOM

- обычный JavaScript напрямую работает с DOM, например

```js
const titleElement = document.querySelector('#title');

titleElement.textContent = 'Hello';
```

- здесь мы сами находим DOM-элемент и изменяем его
- React работает иначе: мы описываем интерфейс декларативно через компоненты и JSX

```jsx
function App() {
  return <h1>Hello</h1>;
}
```

- здесь `<h1>Hello</h1>` ещё не является настоящим DOM-элементом браузера
- это описание того, **каким должен быть интерфейс**
- React создаёт на основе этого описания своё представление UI и определяет, какие изменения нужно внести в настоящий DOM
- именно `ReactDOM` предоставляет механизмы, позволяющие React работать с DOM браузера

## React и ReactDOM — не одно и то же

- это важное различие, которое часто спрашивают на собеседованиях

- `react` содержит основные механизмы React: компоненты, hooks, создание элементов и так далее

- `react-dom` содержит инструменты для отображения React-интерфейса именно в браузерном DOM

- условно можно представить это так

```
React
  ↓
описывает UI

ReactDOM
  ↓
связывает UI с браузерным DOM

Browser DOM
  ↓
показывает интерфейс пользователю
```

- поэтому React сам по себе не является исключительно браузерной библиотекой
- React можно использовать с разными способами отображения интерфейса, а `ReactDOM` — конкретная реализация для DOM

## что происходит при запуске React-приложения

- обычно HTML содержит контейнер, в который React должен поместить приложение

```html
<div id="root"></div>
```

- затем JavaScript получает этот элемент и создаёт React root

```jsx
import { createRoot } from 'react-dom/client';

const rootElement = document.querySelector('#root');

const root = createRoot(rootElement);
```

- `createRoot()` сообщает React, какой DOM-элемент является корневым контейнером приложения
- после этого через `render()` мы говорим, что именно нужно отображать

```jsx
root.render(<App />);
```

- в результате React начинает управлять содержимым `#root`

- получается следующая цепочка

```
index.html
    ↓
<div id="root"></div>
    ↓
document.querySelector()
    ↓
createRoot()
    ↓
root
    ↓
root.render(<App />)
    ↓
React-компоненты
    ↓
DOM
```

## почему используется `createRoot()`

- в современных версиях React для браузера используется API `createRoot()`

```jsx
import { createRoot } from 'react-dom/client';

const rootElement = document.querySelector('#root');
const applicationRoot = createRoot(rootElement);

applicationRoot.render(<App />);
```

- `createRoot()` создаёт **React root** — объект, через который React управляет конкретным DOM-контейнером

- затем вызов `render()` запускает отображение React-дерева внутри этого контейнера

- название `root` здесь не означает DOM-элемент

- это объект React, связанный с конкретным DOM-контейнером

## почему `render()` вызывается у root

- старый React API выглядел примерно так

```jsx
ReactDOM.render(<App />, rootElement);
```

- начиная с React 18 основной современный подход выглядит так

```jsx
const applicationRoot = createRoot(rootElement);

applicationRoot.render(<App />);
```

- то есть ответственность была перенесена с глобального `ReactDOM.render()` на созданный root

- на собеседовании важно понимать разницу

```
createRoot(domElement)
        ↓
создаёт React Root

root.render(reactElement)
        ↓
отображает React-дерево
```

## что именно делает render()

- `render()` получает React-элемент или React-дерево

```jsx
applicationRoot.render(<App />);
```

- `<App />` здесь является JSX

- JSX преобразуется JavaScript-инструментами в вызовы React API, концептуально соответствующие созданию React-элементов

- затем React строит внутреннее представление дерева компонентов и элементов

- React сравнивает новое состояние этого дерева с предыдущим

- после этого необходимые изменения применяются к реальному DOM

- например

```jsx
function App() {
  return (
    <main>
      <h1>Hello</h1>
      <p>Welcome</p>
    </main>
  );
}
```

- после рендеринга браузер в итоге получает примерно такой DOM

```html
<div id="root">
  <main>
    <h1>Hello</h1>
    <p>Welcome</p>
  </main>
</div>
```

- при этом React не обязан полностью пересоздавать весь DOM при каждом изменении
- он определяет, какие части интерфейса действительно изменились, и обновляет необходимые DOM-узлы

## что такое ReactDOM Client

- в современном React обычно импортируют API для браузерного рендера из `react-dom/client`

```jsx
import { createRoot } from 'react-dom/client';
```

- `react-dom/client` содержит современные клиентские API для работы React с браузерным DOM

- наиболее важный для обычного приложения API — `createRoot()`

- существует также `react-dom/server`

- он предназначен для серверного рендеринга React в HTML

- это уже отдельная тема, связанная с SSR

## что происходит при повторном render()

- `render()` можно вызвать снова

```jsx
applicationRoot.render(<App />);
```

- React не воспринимает каждый такой вызов как команду «удалить всё и создать заново»

- React сравнивает новое React-дерево с предыдущим и применяет необходимые изменения

- например, если компонент в результате состояния должен отображать

```jsx
<h1>Count: 1</h1>
```

- а после изменения состояния

```jsx
<h1>Count: 2</h1>
```

- React понимает, что структура практически та же самая, а изменился текст
- поэтому браузерный DOM обновляется соответствующим образом

## важный нюанс: ReactDOM не заменяет DOM API

- ReactDOM не является альтернативной реализацией браузерного DOM
- настоящий DOM всё равно существует и именно браузер его отображает
- ReactDOM является слоем, который позволяет React управлять этим DOM

```
React
  │
  │ описывает изменения
  ↓
ReactDOM
  │
  │ применяет изменения
  ↓
Browser DOM
  │
  ↓
рендеринг браузером
```

## минимальный пример современного React-приложения

```html
<div id="root"></div>
```

```jsx
import { createRoot } from 'react-dom/client';

function App() {
  return <h1>Hello React</h1>;
}

const rootElement = document.querySelector('#root');
const applicationRoot = createRoot(rootElement);

applicationRoot.render(<App />);
```

- здесь происходит четыре логических действия
- сначала определяется DOM-контейнер `#root`
- затем `createRoot()` создаёт React root для этого контейнера
- затем компонент `App` передаётся в `render()`
- React строит интерфейс и через `react-dom` отображает его внутри `#root`

## что важно знать для собеседования

- `React` и `ReactDOM` — разные пакеты с разными обязанностями
- `React` отвечает за создание компонентов и описание UI
- `ReactDOM` связывает React с браузерным DOM
- современное клиентское приложение использует `createRoot()` из `react-dom/client`
- `createRoot()` создаёт React root, связанный с конкретным DOM-контейнером
- `root.render(<App />)` запускает отображение React-дерева в этом контейнере
- повторный рендер не означает полное пересоздание DOM
- React сравнивает новое дерево с предыдущим и обновляет необходимые части реального DOM
- `ReactDOM` нужен именно потому, что React должен каким-то образом превратить декларативное описание интерфейса в изменения настоящего DOM

```
                         React-приложение
                                │
             ┌──────────────────┴──────────────────┐
             │                                     │
             ▼                                     ▼
           React                                ReactDOM
             │                                     │
             │                                     │
      ┌──────┴──────┐                    ┌─────────┴─────────┐
      │             │                    │                   │
   Components      JSX               createRoot()        render()
      │             │                    │                   │
      └──────┬──────┘                    │                   │
             │                           │                   │
             ▼                           ▼                   │
        React-дерево ─────────────────► React Root ◄────────┘
                                           │
                                           │
                                           ▼
                                    DOM-контейнер
                                    <div id="root">
                                           │
                                           ▼
                                     Browser DOM
                                           │
                                           ▼
                                         экран
```
