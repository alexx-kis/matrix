# HOC `connect` в Redux и React

- `connect` — это функция из библиотеки `react-redux`, которая связывает React-компонент с Redux Store и позволяет компоненту получать данные из глобального состояния и отправлять Actions без необходимости вручную реализовывать подписку на Store
- поскольку мы уже разобрали основные принципы Redux, теперь сосредоточимся на том, как `connect` интегрирует Redux в архитектуру React-приложения, почему он считается HOC и чем отличается от современных Redux Hooks

## 1. какую проблему решает `connect`

- вспомним архитектуру Redux: Store хранит состояние приложения, а React-компоненты должны получать необходимые данные и инициировать их изменение
- без `connect` пришлось бы самостоятельно организовывать подписку на Store, получать актуальное состояние и обеспечивать обновление компонента при изменениях
- `connect` делегирует эту работу библиотеке `react-redux` и позволяет компоненту взаимодействовать с Redux через обычные props
- например, компоненту корзины нужны количество товаров и возможность добавить товар

```
Redux Store
    ↓
connect(mapStateToProps, mapDispatchToProps)
    ↓
ConnectedCart (обёртка)
    ↓ props
Cart (обычный React-компонент)
```

- главное преимущество такой архитектуры — компонент `Cart` может сосредоточиться на отображении интерфейса, а получение данных из Redux и отправка Actions организуются отдельно

## 2. почему `connect` — это HOC

- HOC (Higher-Order Component) — это функция высшего порядка, которая принимает React-компонент и возвращает новый компонент, расширяющий его поведение
- в случае `connect` возвращаемый компонент связывается с Redux Store и передаёт исходному компоненту необходимые props

```js
const ConnectedCart = connect(mapStateToProps, mapDispatchToProps)(Cart);
```

- здесь `connect(mapStateToProps, mapDispatchToProps)` сначала возвращает функцию, которая принимает компонент, а затем эта функция оборачивает `Cart`
- в результате `ConnectedCart` — новый компонент, а `Cart` — исходный компонент, который получает данные и обработчики через props
- важно понимать, что `connect` не изменяет исходный компонент напрямую и не требует, чтобы сам компонент знал внутреннее устройство Redux

## 3. как работает `connect`: два основных аргумента

- обычно `connect` используют с двумя функциями: `mapStateToProps` и `mapDispatchToProps`

```js
connect(mapStateToProps, mapDispatchToProps)(Cart);
```

- обе функции необязательны, но решают разные задачи

### `mapStateToProps` — получение данных из Store

- `mapStateToProps` получает текущее состояние Redux и возвращает объект props, которые должны быть переданы компоненту

```js
const mapStateToProps = (state) => ({
  cartItems: state.cart.items,
  currentUser: state.user,
});
```

- если в Store есть состояние `cart` и `user`, компонент получит props `cartItems` и `currentUser`

```js
<Cart cartItems={state.cart.items} currentUser={state.user} />
```

- последний пример иллюстрирует результат, а не реальный JSX, который нужно писать вручную
- `mapStateToProps` вызывается при подключении компонента и при обновлениях Store, чтобы определить актуальные значения props
- React-Redux сравнивает результат с предыдущим результатом и обычно инициирует обновление подключённого компонента, если изменились соответствующие значения
- на практике важно выбирать только те части состояния, которые действительно нужны компоненту, вместо передачи всего Redux State

### `mapDispatchToProps` — отправка Actions

- `mapDispatchToProps` отвечает за то, как компонент будет инициировать изменения Redux-состояния
- существует два распространённых варианта: передать функцию `dispatch` в props либо передать объект Action Creators, который `connect` автоматически свяжет с `dispatch`

вариант 1 — функция

```js
const mapDispatchToProps = (dispatch) => ({
  addProduct: (product) => {
    dispatch({
      type: 'cart/productAdded',
      payload: product,
    });
  },
});
```

- в этом случае компонент получит prop `addProduct`, который отправляет Action в Store при вызове

```js
function ProductButton({ addProduct }) {
  return (
    <button
      onClick={() =>
        addProduct({
          id: 25,
          title: 'Monitor',
        })
      }
    >
      Add product
    </button>
  );
}
```

- компоненту не нужно знать, как именно устроен Action или где находится Store, поскольку эта логика скрыта за prop `addProduct`

вариант 2 — объект Action Creators

```js
const productActions = {
  addProduct: (product) => ({
    type: 'cart/productAdded',
    payload: product,
  }),
};

const ConnectedProductButton = connect(null, productActions)(ProductButton);
```

- когда вторым аргументом `connect` получает объект функций, React-Redux автоматически оборачивает эти функции в вызовы `dispatch`
- поэтому `addProduct(product)` внутри подключённого компонента уже отправляет сформированный Action в Store
- этот вариант часто удобнее, поскольку не требует вручную писать `dispatch` в каждом Action Creator
- если `mapDispatchToProps` не передан, `dispatch` по умолчанию доступен подключённому компоненту как prop

## 4. полный пример от Store до компонента

- объединим получение данных и отправку Actions в одном примере

```js
import { connect } from 'react-redux';

// исходный презентационный компонент
function InventoryPanel({ products, onProductSelect }) {
  return (
    <section>
      <h2>Products</h2>

      {products.map((product) => (
        <button key={product.id} onClick={() => onProductSelect(product.id)}>
          {product.title}
        </button>
      ))}
    </section>
  );
}

// чтение состояния Redux
const mapInventoryState = (state) => ({
  products: state.inventory.products,
});

// подготовка обработчиков, отправляющих Actions
const mapInventoryDispatch = (dispatch) => ({
  onProductSelect: (productId) => {
    dispatch({
      type: 'inventory/productSelected',
      payload: productId,
    });
  },
});

// создание подключённого компонента
export const ConnectedInventoryPanel = connect(mapInventoryState, mapInventoryDispatch)(InventoryPanel);
```

- предположим, что Store содержит `state.inventory.products`, а Reducer обрабатывает Action `inventory/productSelected`
- `InventoryPanel` получает массив `products` и функцию `onProductSelect` через props
- когда пользователь нажимает кнопку, компонент вызывает `onProductSelect(product.id)`, а связанная функция отправляет Action в Redux
- после обработки Action Store обновляется, а если изменились выбранные данные, `ConnectedInventoryPanel` получает актуальные props и React обновляет интерфейс при необходимости
- обрати внимание: для работы примера нужно, чтобы `ConnectedInventoryPanel` находился внутри `<Provider store={...}>`, а структура Store соответствовала путям, используемым в `mapInventoryState`

## 5. роль `connect` в архитектуре приложения

- главное архитектурное назначение `connect` — отделить представление интерфейса от механизма получения данных и управления состоянием
- такой подход особенно полезен в крупных приложениях, где хочется повторно использовать компоненты и не привязывать их напрямую к Redux

```
[Redux layer]
Store, Reducers, Actions
- хранение данных и правила изменения состояния

                ↑↓
  connect — адаптация данных к props

[React component]
Props, JSX, обработчики событий
- отображение интерфейса и реакция на действия пользователя
```

- в такой схеме компоненту не обязательно импортировать Store, знать структуру всего глобального состояния или самостоятельно вызывать `store.subscribe()`
- при этом `connect` не заменяет Reducers, Actions или Store, а обеспечивает адаптацию между Redux и компонентом
- ещё одно преимущество — возможность передавать компоненту данные и обработчики, не раскрывая детали реализации источника данных

### зачем разделять контейнерную и презентационную логику

- исторически компоненты, подключённые к данным и логике приложения, часто называли container components, а компоненты, отвечающие преимущественно за отображение, — presentational components
- `connect` хорошо поддерживает такой подход, хотя сам по себе не требует строгого разделения на два типа компонентов
- презентационный компонент можно использовать в разных местах, передавая ему разные props, а Redux-подключение вынести в отдельный компонент-обёртку
- это упрощает изолированное тестирование интерфейса, повторное использование компонентов и замену источника данных

## 6. что такое `ownProps`

- ещё одна важная особенность `connect` — возможность учитывать собственные props исходного компонента при выборе данных из Store
- если `mapStateToProps` объявлена с двумя параметрами, вторым параметром она получает props, переданные компоненту извне

```js
const mapProductDetailsState = (state, ownProps) => ({
  product: state.inventory.products.find((item) => item.id === ownProps.productId),
});

const ConnectedProductDetails = connect(mapProductDetailsState)(ProductDetails);
```

- здесь `ownProps.productId` — это prop, который приходит от родительского компонента, а не из Redux Store
- например, родитель может отрисовать `<ConnectedProductDetails productId={25} />`, и `mapProductDetailsState` выберет из Store товар с соответствующим идентификатором
- это позволяет создавать универсальные подключённые компоненты, которые используют Redux-состояние с учётом контекста конкретного экземпляра компонента
- аналогичным образом `mapDispatchToProps` в форме функции может получать `ownProps` вторым аргументом, если нужно учитывать props при создании обработчиков

## 7. как `connect` связан с `Provider` и подписками

- `connect` должен иметь доступ к Redux Store, а в стандартной архитектуре React-Redux этот доступ обеспечивает компонент `<Provider>`

```js
import { Provider } from 'react-redux';
import { appStore } from './appStore';

function ApplicationRoot() {
  return (
    <Provider store={appStore}>
      <ConnectedInventoryPanel />
    </Provider>
  );
}
```

- `Provider` передаёт Store через React Context, а `connect` использует этот контекст для взаимодействия с ним
- внутри подключённого компонента не нужно вручную вызывать `store.subscribe()` или самостоятельно управлять жизненным циклом подписки
- React-Redux управляет подписками, отслеживает изменения состояния и определяет, когда подключённому компоненту нужно передать обновлённые props
- при этом `connect` не создаёт отдельный Redux Store для каждого компонента — подключённые компоненты работают с переданным через `Provider` хранилищем

## 8. производительность и типичные ошибки

### передача всего состояния

- не стоит без необходимости возвращать всё состояние приложения из `mapStateToProps`

```js
// нежелательный подход
const mapAllState = (state) => ({
  entireState: state,
});
```

- такой подход связывает компонент со всем деревом состояния и может вызывать дополнительные обновления при изменениях, которые не относятся к его задаче
- предпочтительнее выбирать только необходимые данные

```js
const mapSelectedInventory = (state) => ({
  products: state.inventory.products,
});
```

### создание новых объектов и массивов

- если `mapStateToProps` каждый раз создаёт новый объект или массив, сравнение ссылок может показывать изменение даже тогда, когда исходные данные по существу не изменились

```js
const mapFilteredInventory = (state) => ({
  availableProducts: state.inventory.products.filter((product) => product.inStock),
});
```

- здесь `filter()` создаёт новый массив при каждом выполнении функции
- если вычисления сложные или компонент часто получает обновления Store, имеет смысл применять мемоизированные селекторы, например с помощью `createSelector` из Redux Toolkit
- при этом сам по себе новый объект, возвращаемый `mapStateToProps`, не означает, что компонент обязательно перерендерится: React-Redux сравнивает отдельные значения props по своим правилам

### путаница между `connect` и `dispatch`

- `connect` сам по себе не изменяет бизнес-логику Reducer и не определяет, как именно обновится состояние
- его задача — связать компонент с Store и предоставить ему нужные props
- `dispatch` отправляет Action, а Reducer определяет результат обработки Action

### забытый `Provider`

- если подключённый компонент не может получить Store через контекст React-Redux, приложение выдаст ошибку
- поэтому нужно убедиться, что компонент находится внутри соответствующего `Provider` и что используется правильный экземпляр Store

## 9. `connect` и React-Redux Hooks

- в современных React-приложениях часто используют `useSelector` и `useDispatch` вместо `connect`

```js
import { useSelector, useDispatch } from 'react-redux';

function InventoryPanelWithHooks() {
  const inventoryProducts = useSelector((state) => state.inventory.products);

  const inventoryDispatch = useDispatch();

  return (
    <section>
      {inventoryProducts.map((product) => (
        <button
          key={product.id}
          onClick={() =>
            inventoryDispatch({
              type: 'inventory/productSelected',
              payload: product.id,
            })
          }
        >
          {product.title}
        </button>
      ))}
    </section>
  );
}
```

- этот компонент самостоятельно обращается к Redux через Hooks, но при этом не нуждается в ручном управлении подписками
- сравним основные различия

`connect`

- использует HOC и передаёт данные и обработчики через props
- удобно отделяет компонент от Redux-зависимостей
- особенно распространён в существующих проектах с классическими connected-компонентами

`useSelector` и `useDispatch`

- позволяют функциональному компоненту напрямую получать данные и отправлять Actions
- обычно требуют меньше шаблонного кода
- естественно сочетаются с современным функциональным подходом React

- Hooks не делают `connect` устаревшим или неправильным: оба подхода поддерживаются React-Redux

- `connect` может оставаться удобным, если требуется изолировать компонент от Redux, сохранить существующую архитектуру или переиспользовать компонент с обычными props

- при использовании `useSelector` важно помнить, что результат селектора по умолчанию сравнивается по ссылке через строгое равенство `===`, тогда как `connect` по умолчанию сравнивает отдельные значения props из результата `mapStateToProps` поверхностно

## 10. как объяснить `connect` на собеседовании

- `connect` — это HOC из библиотеки React-Redux, который связывает React-компонент с Redux Store и возвращает новый компонент, передающий исходному компоненту необходимые props

- `mapStateToProps` определяет, какие данные из Redux State попадут в props компонента, а `mapDispatchToProps` определяет, какие функции для отправки Actions будут доступны компоненту

- `connect` использует Store, предоставленный через `Provider`, управляет подписками на изменения и позволяет компоненту получать актуальные данные без ручного взаимодействия с Redux Store

- архитектурно `connect` помогает отделить представление от управления состоянием, упрощает повторное использование компонентов и позволяет тестировать интерфейс независимо от Redux

- в современных проектах часто используют `useSelector` и `useDispatch`, но `connect` по-прежнему поддерживается и полезен для понимания существующих кодовых баз

- главное, что нужно запомнить: `connect` не является ни Store, ни Reducer, ни Action — это адаптер между Redux и React-компонентом, который преобразует данные Store и способы отправки Actions в обычные props
