# redux main principles

- начнём с фундаментальных принципов Redux, разберём, какую проблему он решает в React-приложении, как устроен его жизненный цикл, какие сущности участвуют в работе и как всё это связано между собой

## 1. что такое Redux и зачем он нужен

- Redux — это библиотека для управления состоянием приложения, которая предоставляет предсказуемый способ хранения состояния и его изменения через заранее определённые функции
- Redux не является частью React и может использоваться независимо от него, но исторически широко применяется вместе с React для управления общим состоянием приложения
- чтобы понять его назначение, сначала разберём проблему, которую он решает

### проблема общего состояния

- представим приложение интернет-магазина, в котором есть несколько компонентов

```
App
├── Header
│   └── CartCounter
├── ProductPage
│   └── AddToCartButton
└── CheckoutPage
    └── OrderSummary
```

- корзина используется в разных частях приложения: `CartCounter` отображает количество товаров, `ProductPage` позволяет добавлять товары, а `CheckoutPage` показывает итоговый заказ
- без централизованного управления состоянием можно поднять состояние корзины в общего родителя и передавать его через props, но по мере роста приложения появляются сложности
- компоненты, которым нужно взаимодействовать с корзиной, могут находиться далеко друг от друга в дереве, а промежуточным компонентам приходится передавать props, которые им самим не нужны
- этот подход называется prop drilling — последовательная передача данных через промежуточные компоненты
- другой вариант — хранить состояние в разных компонентах, но тогда придётся синхронизировать его, иначе разные части приложения могут показывать противоречивые данные
- Redux решает эту проблему, предоставляя общее хранилище состояния, доступное разным частям приложения

```
      Redux Store
      (состояние)
    /      |      \
   ↓       ↓       ↓
Header  Product  Checkout
```

- компоненты могут получать необходимые данные из общего хранилища и инициировать изменения состояния, не передавая данные друг другу напрямую

### когда Redux действительно нужен

- Redux особенно полезен, когда состояние используется большим количеством компонентов, обновляется из разных мест, имеет сложные переходы между состояниями или требует централизованной обработки изменений и побочных эффектов
- при этом Redux не обязателен для каждого React-приложения: локальное состояние интерфейса, например открытие dropdown или состояние конкретного input, часто удобнее оставить в `useState`
- Redux также не заменяет автоматически серверное состояние, кеширование запросов или состояние URL — для этих задач существуют специализированные подходы, в том числе Redux Toolkit Query и React Router

## 2. три главных принципа Redux

- классические три принципа Redux определяют, где находится состояние, как оно изменяется и каким образом изменения инициируются

1. единственный источник истины — single source of truth

- всё глобальное состояние приложения хранится в одном объекте Store
- это позволяет централизованно получать состояние и согласованно обновлять связанные данные

2. состояние доступно только для чтения — state is read-only

- нельзя изменять состояние напрямую из компонентов или произвольного кода
- для инициирования изменений отправляется Action через `dispatch`, после чего Reducer вычисляет новое состояние

3. изменения выполняются чистыми функциями — changes are made with pure functions

- Reducer получает предыдущее состояние и Action, а затем определяет новое состояние
- одинаковые входные данные должны приводить к одинаковому результату, а вычисление не должно зависеть от внешних побочных эффектов

### принцип 1. single source of truth

- Redux Store — это централизованное хранилище состояния Redux-приложения
- например, вместо независимого хранения количества товаров в нескольких компонентах можно хранить одну общую корзину

```js
const shopInitialState = {
  cart: {
    items: [
      { id: 1, title: 'Keyboard', quantity: 2 },
      { id: 2, title: 'Mouse', quantity: 1 },
    ],
  },
  user: {
    id: 42,
    name: 'Alex',
  },
};
```

- это условный пример объекта состояния, который может храниться в Redux Store
- `cart` содержит данные корзины, а `user` — данные пользователя
- любой компонент, подписанный на соответствующую часть состояния, может получить актуальные данные из Store
- важный нюанс: single source of truth не означает, что абсолютно всё состояние приложения должно находиться в Redux
- состояние фокуса input, временное состояние анимации или открытие локального меню вполне могут оставаться в React-компонентах
- принцип относится к тому состоянию, которое приложение решило централизованно хранить в Redux

### принцип 2. state is read-only

- состояние Redux нельзя произвольно изменять напрямую, поскольку тогда изменения происходили бы вне предусмотренного механизма и их было бы сложнее отслеживать
- вместо этого отправляется Action, описывающий произошедшее событие или желаемое изменение

```js
// так делать нельзя
shopStore.getState().cart.items.push({
  id: 3,
  title: 'Monitor',
  quantity: 1,
});

// так инициируют изменение
shopStore.dispatch({
  type: 'cart/itemAdded',
  payload: {
    id: 3,
    title: 'Monitor',
    quantity: 1,
  },
});
```

- в первом случае массив изменяется напрямую, минуя Redux-механизм обновления состояния
- во втором случае `dispatch` передаёт Action в Redux, после чего Reducer должен определить новое состояние
- в современном Redux состояние обычно доступно через `store.getState()`, а `store.dispatch()` используется для отправки Action
- технически обычный JavaScript-объект можно мутировать, если он не защищён от этого, поэтому read-only здесь прежде всего означает правило архитектуры Redux, а не автоматическую невозможность любого изменения объекта
- Redux Toolkit дополнительно помогает соблюдать это правило с помощью Immer, позволяя писать редактирование состояния в мутабельном стиле при фактическом создании иммутабельного результата

### принцип 3. pure reducers

- Reducer — это функция, которая получает предыдущее состояние и Action, а возвращает следующее состояние

```js
function cartReducer(state = { items: [] }, action) {
  switch (action.type) {
    case 'cart/itemAdded':
      return {
        ...state,
        items: [...state.items, action.payload],
      };

    default:
      return state;
  }
}
```

- при получении Action типа `cart/itemAdded` Reducer создаёт новый объект состояния и новый массив товаров, сохраняя остальные поля исходного состояния
- `...state` копирует поля предыдущего объекта, а `...state.items` переносит существующие элементы массива в новый массив
- исходное состояние при этом не изменяется
- ветка `default` возвращает исходное состояние, если Reducer не обрабатывает полученный Action
- здесь важно различать две вещи: Reducer не выполняет саму отправку Action и не должен самостоятельно менять Store — он лишь вычисляет результат
- Reducer также не должен выполнять HTTP-запросы, обращаться к DOM, запускать таймеры или генерировать случайные значения, от которых зависит результат
- такие операции относятся к побочным эффектам и выполняются в других частях архитектуры, например в middleware или асинхронных thunk-функциях

## 3. основные сущности Redux

- чтобы объяснить работу Redux на собеседовании, нужно уверенно различать Store, State, Action, Dispatch и Reducer

#### Store

- объект, который хранит текущее состояние Redux и предоставляет API для получения состояния, отправки Action и подписки на изменения
- основные методы: `getState()`, `dispatch()`, `subscribe()`

#### State

- текущее состояние приложения, хранящееся в Store
- обычно представляет собой дерево объектов и массивов с данными приложения

#### Action

- обычный JavaScript-объект, описывающий событие или намерение изменить состояние
- стандартный Action содержит обязательное поле `type` и может содержать `payload` с данными

#### Dispatch

- механизм отправки Action в Redux Store
- вызывается через `store.dispatch(action)` или через соответствующий метод, доступный компоненту React

#### Reducer

- функция, которая определяет, каким должно стать состояние после получения Action
- принимает `(state, action)` и возвращает новое состояние

### action: описание события

- Action сам по себе не изменяет состояние — он описывает, что произошло, или какое изменение требуется обработать

```js
const cartItemAddedAction = {
  type: 'cart/itemAdded',
  payload: {
    id: 10,
    title: 'Headphones',
    quantity: 1,
  },
};
```

- поле `type` определяет вид события, а `payload` содержит данные, необходимые для его обработки
- название `cart/itemAdded` — это строка, выбранная разработчиком, а не специальный синтаксис JavaScript или Redux
- часто Action создаётся через Action Creator — функцию, которая формирует объект Action

```js
function createCartItemAddedAction(item) {
  return {
    type: 'cart/itemAdded',
    payload: item,
  };
}
```

- это помогает стандартизировать структуру Action и уменьшить дублирование кода

### dispatch: отправка action

- когда пользователь нажимает кнопку добавления товара, компонент инициирует событие и отправляет Action в Store

```js
shopStore.dispatch(
  createCartItemAddedAction({
    id: 11,
    title: 'Webcam',
    quantity: 1,
  }),
);
```

- вызов `dispatch` передаёт Action Redux Store, который запускает предусмотренный механизм обработки Action
- в обычном синхронном Redux-потоке Reducer вызывается в ходе обработки `dispatch`, а после обновления состояния Store уведомляет подписчиков
- middleware может перехватывать Action до того, как он попадёт в Reducer, а асинхронные middleware могут организовать дополнительные операции

### reducer: вычисление нового состояния

- Reducer определяет результат обработки Action, но не решает самостоятельно, когда пользовательское событие должно произойти
- для наглядности объединим Reducer и Action в один пример

```js
function cartReducer(state = { items: [] }, action) {
  switch (action.type) {
    case 'cart/itemAdded':
      return {
        ...state,
        items: [...state.items, action.payload],
      };

    default:
      return state;
  }
}

const previousCartState = {
  items: [{ id: 1, title: 'Keyboard', quantity: 1 }],
};

const addedItemAction = {
  type: 'cart/itemAdded',
  payload: { id: 2, title: 'Mouse', quantity: 1 },
};

const nextCartState = cartReducer(previousCartState, addedItemAction);
```

- после выполнения `nextCartState` будет содержать оба товара, а `previousCartState` останется без изменений
- в этом примере Reducer вызван вручную, поэтому состояние Store не обновляется: для полноценного обновления Redux должен вызвать Reducer в процессе обработки Action через `dispatch`

## 4. как Redux работает изнутри

- теперь объединим сущности в единый жизненный цикл

```
    1. пользователь взаимодействует с UI
       например, нажимает Add to cart
                     ↓
       2. компонент отправляет Action
                 dispatch()
                     ↓
 3. Store передаёт Action по цепочке middleware
         если middleware подключены
                     ↓
    4. Reducer вычисляет новое состояние
   previous state + action → next state
                     ↓
   5. Store сохраняет новое состояние
текущее состояние заменяется результатом Reducer
                     ↓
    6. подписчики получают уведомление
  React-Redux проверяет подписанные компоненты
                     ↓
      7. React обновляет интерфейс
если выбранные компонентом данные изменились
```

- разберём ключевые моменты этой последовательности
- сначала инициируется Action — обычно обработчик события React вызывает `dispatch`, но Action также может отправляться из middleware, thunk-функции или другого кода приложения
- затем выполняется Reducer — Redux передаёт ему предыдущее состояние и Action, а Reducer возвращает результат без прямого изменения Store
- Store устанавливает новое состояние — он хранит результат вычисления Reducer, после чего уведомляет подписчиков
- React-Redux связывает Store с React — `useSelector` позволяет компоненту читать выбранную часть состояния и подписываться на её изменения
- React не обязан перерисовывать каждый компонент — React-Redux сравнивает предыдущее и новое выбранное значение, а затем инициирует обновление компонента, если это необходимо
- важный нюанс: изменение Redux Store и повторный рендер React-компонента — разные события; обновление Store само по себе не означает, что каждый компонент приложения должен перерендериться

## 5. минимальный пример Redux в React

- в современных проектах рекомендуется использовать Redux Toolkit, который предоставляет удобные инструменты для создания Store, Reducer и Action
- рассмотрим минимальный счётчик, чтобы увидеть принципы в практическом коде

### создание store

```js
import { configureStore, createSlice } from '@reduxjs/toolkit';

const counterSlice = createSlice({
  name: 'counter',
  initialState: {
    value: 0,
  },
  reducers: {
    increment(state) {
      state.value += 1;
    },
    decrement(state) {
      state.value -= 1;
    },
  },
});

export const { increment, decrement } = counterSlice.actions;

export const counterStore = configureStore({
  reducer: {
    counter: counterSlice.reducer,
  },
});
```

- `createSlice` принимает имя области состояния, начальное состояние и набор обработчиков Reducer
- Redux Toolkit автоматически создаёт Action Creators для описанных обработчиков
- например, вызов `increment()` создаёт Action с типом `counter/increment`
- выражение `state.value += 1` выглядит как мутация, но внутри `createSlice` используется Immer, который преобразует такие операции в безопасное иммутабельное обновление
- `configureStore` создаёт Store и настраивает стандартные middleware и полезные средства разработки

### подключение к React

```js
import { Provider, useDispatch, useSelector } from 'react-redux';
import { counterStore, increment, decrement } from './counterStore';

function CounterPanel() {
  const counterValue = useSelector((state) => state.counter.value);

  const counterDispatch = useDispatch();

  return (
    <div>
      <p>Counter: {counterValue}</p>

      <button onClick={() => counterDispatch(increment())}>Increment</button>

      <button onClick={() => counterDispatch(decrement())}>Decrement</button>
    </div>
  );
}

function App() {
  return (
    <Provider store={counterStore}>
      <CounterPanel />
    </Provider>
  );
}
```

- `Provider` предоставляет Store всему вложенному React-дереву через контекст React-Redux
- `useSelector` читает выбранное значение из Redux Store и подписывает компонент на изменения этого значения
- `useDispatch` возвращает функцию отправки Action
- при нажатии кнопки вызывается `increment()`, затем полученный Action передаётся в `dispatch`, Reducer вычисляет новое состояние, и компонент получает актуальное значение счётчика
- здесь хорошо видна связь Redux и React: Redux отвечает за состояние и правила его изменения, а React-Redux обеспечивает интеграцию этого состояния с компонентами React

## 6. что важно понимать глубже

### почему Redux называют предсказуемым

- предсказуемость достигается благодаря явному потоку изменений: можно увидеть, какой Action был отправлен, какое состояние существовало до него и какой результат вернул Reducer
- если Reducer является чистой функцией, то при одинаковом предыдущем состоянии и одинаковом Action результат будет одинаковым
- это облегчает отладку, тестирование и воспроизведение последовательности действий пользователя

### почему нельзя мутировать state

- Redux и React-Redux активно используют сравнение ссылок для определения изменений
- если изменить вложенный объект напрямую, сохранив прежние ссылки, подписчики и компоненты могут не обнаружить ожидаемое изменение
- иммутабельные обновления создают новые ссылки для изменённых объектов, сохраняя ссылки на неизменившиеся части состояния
- это не означает, что при каждом обновлении нужно глубоко копировать всё дерево состояния: обычно создаются новые объекты только на пути от корня до изменённого значения

### зачем нужен один store, если в приложении много reducer

- в Redux-приложении обычно один Store, но его состояние может состоять из множества логических областей

```
Redux Store
└── root state
    ├── user
    │   └── userReducer
    ├── cart
    │   └── cartReducer
    └── products
        └── productsReducer
```

- каждый отдельный Reducer отвечает за определённую часть состояния, а `combineReducers` или объект `reducer` в `configureStore` объединяет их в единый корневой Reducer
- это позволяет разделять ответственность по функциональным областям, не создавая отдельный Store для каждого компонента или каждой сущности

### Redux и React — разные уровни

- Redux можно использовать без React, например в Node.js или в другом JavaScript-приложении
- React можно использовать без Redux, управляя состоянием через `useState`, `useReducer`, Context API и другие механизмы
- `react-redux` — отдельная библиотека, которая связывает Redux Store с React-компонентами
- Redux Toolkit — рекомендуемый современный набор инструментов для Redux, уменьшающий количество шаблонного кода и помогающий следовать правильным практикам

## 7. как объяснить Redux на собеседовании

- Redux — это библиотека управления состоянием, которая позволяет централизованно хранить общее состояние приложения и предсказуемо изменять его
- его основные принципы — единый источник истины для глобального состояния, изменение состояния через отправку Action и вычисление нового состояния с помощью чистых Reducer-функций
- основные сущности — Store хранит состояние, State представляет текущее состояние, Action описывает событие, Dispatch отправляет Action, а Reducer определяет новое состояние
- основной поток работы — компонент инициирует Action, Action проходит через middleware, Reducer вычисляет новое состояние, Store сохраняет его и уведомляет подписчиков, после чего React-Redux при необходимости обновляет React-компоненты
- главное преимущество — изменения состояния становятся явными, структурированными и удобными для тестирования и отладки
- главное ограничение — Redux добавляет архитектурную сложность, поэтому для небольшого локального состояния он обычно избыточен
- на этом этапе важно уверенно понимать три принципа и весь жизненный цикл изменения состояния, поскольку следующие темы — Actions, Reducers, Middleware, Selectors и `connect` — подробно раскрывают отдельные части этого механизма
