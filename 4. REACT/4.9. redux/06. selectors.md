# selectors в Redux

- Selector — это функция, которая получает состояние Redux и возвращает необходимые данные или вычисляет на их основе производное значение
- селекторы помогают отделить логику чтения и преобразования состояния от React-компонентов, повторно использовать вычисления и контролировать лишние перерисовки
- разберём базовые селекторы, их применение в React, мемоизацию через `createSelector` и написание сложных селекторов в Redux Toolkit

## 1. зачем нужны селекторы

- представим, что в Redux Store хранятся товары интернет-магазина

```js
const initialProductsState = {
  products: [
    { id: 1, title: 'Keyboard', price: 100, inStock: true },
    { id: 2, title: 'Mouse', price: 50, inStock: false },
    { id: 3, title: 'Monitor', price: 300, inStock: true },
  ],
  discountPercent: 10,
};
```

- компоненту нужно показать только товары, которые есть в наличии
- самый простой вариант — написать фильтрацию непосредственно внутри компонента

```js
const availableProducts = useSelector((state) => state.products.products.filter((product) => product.inStock));
```

- такой код работает, но если аналогичная логика нужна в нескольких компонентах, фильтрация будет дублироваться
- кроме того, `filter()` при каждом выполнении создаёт новый массив, а `useSelector` по умолчанию сравнивает результат с предыдущим результатом с помощью `===`
- даже если исходные товары не изменились, новый массив имеет другую ссылку, поэтому компонент может перерендериться без необходимости
- селекторы позволяют вынести эту логику из компонента в отдельную функцию

```js
const selectAllProducts = (state) => state.products.products;

const selectAvailableProducts = (state) => selectAllProducts(state).filter((product) => product.inStock);
```

- теперь компонент может использовать именованный селектор, а логика выбора товаров определена в одном месте

```js
const availableProducts = useSelector(selectAvailableProducts);
```

- однако обычный селектор с `filter()` всё ещё создаёт новый массив при каждом вызове — для решения этой проблемы используют мемоизированные селекторы

## 2. что именно делает Selector

- селектор не изменяет состояние Redux и не отправляет Actions — он читает данные и возвращает результат
- у селекторов обычно выделяют две основные задачи

1. выбор данных

- получение конкретной части состояния

```js
const selectCartItems = (state) => state.cart.items;
```

2. вычисление производных данных

- получение значения на основе одной или нескольких частей состояния

```js
const selectCartTotal = (state) => state.cart.items.reduce((total, item) => total + item.price * item.quantity, 0);
```

- производные данные — это значения, которые можно вычислить из уже существующего состояния, например общая стоимость корзины, количество товаров в наличии, отфильтрованный список или число непрочитанных уведомлений
- если такое значение можно надёжно вычислить из исходных данных, обычно не нужно хранить его в Redux отдельно
- иначе возникает риск рассинхронизации: список товаров обновился, а сохранённое отдельно количество товаров осталось прежним

## 3. где селекторы располагаются в архитектуре Redux

- селекторы обычно располагаются рядом с соответствующим Redux-слайсом или в отдельном модуле, если используются несколькими частями приложения

```
Redux Store
    ↓
  State
    ↓
 Selectors
    │
    ├── selectCartItems
    ├── selectCartTotal
    └── selectAvailableProducts
             ↓
      React components
```

- Reducer отвечает за изменение состояния, а Selector — за чтение и преобразование состояния
- такое разделение позволяет компонентам не зависеть от подробной структуры Store и повторно использовать правила вычисления данных
- например, если структура корзины изменится с `state.cart.items` на `state.shoppingCart.items`, достаточно обновить базовый селектор, а компоненты, использующие его, могут остаться без изменений

## 4. использование селекторов в React

- для чтения Redux-состояния в функциональных компонентах обычно используют `useSelector` из `react-redux`

```js
import { useSelector } from 'react-redux';

const selectCartItemsForPanel = (state) => state.cart.items;

function CartPanel() {
  const cartItems = useSelector(selectCartItemsForPanel);

  return (
    <ul>
      {cartItems.map((item) => (
        <li key={item.id}>
          {item.title}: {item.quantity}
        </li>
      ))}
    </ul>
  );
}
```

- `useSelector` вызывает селектор с текущим состоянием Redux Store и подписывает компонент на изменения выбранного значения
- когда Store обновляется, селектор может быть вызван повторно, а React-Redux сравнивает новое выбранное значение с предыдущим
- по умолчанию используется строгое сравнение ссылок `===`, поэтому для объектов и массивов важно учитывать их ссылочную идентичность
- если выбранное значение не изменилось по ссылке, `useSelector` обычно не инициирует перерисовку именно из-за этого обновления Store, хотя компонент может перерендериться по другим причинам

## 5. мемоизация селекторов: `createSelector`

- мемоизация — это сохранение результата вычисления, чтобы при повторном вызове с теми же входными данными не выполнять вычисление заново
- для Redux-селекторов обычно используют `createSelector` из Redux Toolkit, который предоставляет возможности библиотеки Reselect
- рассмотрим проблему на примере фильтрации товаров

```js
const selectAvailableProductsBasic = (state) => state.products.products.filter((product) => product.inStock);
```

- при каждом вызове `selectAvailableProductsBasic` создаётся новый массив, даже если список товаров не изменился
- это может вызывать лишние вычисления и обновления компонентов, подписанных на результат селектора

### как работает `createSelector`

```js
import { createSelector } from '@reduxjs/toolkit';

const selectProducts = (state) => state.products.products;

const selectAvailableProductsMemoized = createSelector([selectProducts], (products) =>
  products.filter((product) => product.inStock),
);
```

- `createSelector` принимает массив входных селекторов и функцию преобразования их результатов
- сначала выполняются входные селекторы, затем их результаты сравниваются с результатами предыдущего вычисления
- если входные значения не изменились по ссылке, мемоизированный селектор возвращает сохранённый результат, не выполняя `filter()` повторно

```
state
  ↓
selectProducts
  ↓
ссылка на массив products
  ↓
сравнение с предыдущим результатом
  ├── ссылка не изменилась → вернуть кеш
  └── ссылка изменилась → выполнить filter()
```

- благодаря этому компонент может получать тот же объект массива по ссылке, пока входные данные остаются прежними
- важно: мемоизация не означает, что селектор вообще не вызывается при обновлении Store — он может вызываться, но дорогостоящее вычисление пропускается, если входные результаты не изменились

### когда мемоизация действительно полезна

- мемоизация особенно полезна для сложных вычислений, фильтрации больших массивов, сортировки, объединения данных из нескольких частей состояния и селекторов, возвращающих новые объекты или массивы
- для простого селектора вроде `state => state.user.name` мемоизация обычно не нужна, поскольку он лишь читает значение и не создаёт новый объект
- мемоизация также не гарантирует, что компонент никогда не перерендерится: компонент может обновиться из-за собственных props, локального состояния или родительского компонента

## 6. написание сложных селекторов

- сложный селектор обычно объединяет несколько частей состояния и вычисляет на их основе производные данные
- например, нужно получить товары, которые есть в наличии, стоят не дороже заданной цены и отсортированы по стоимости

```js
import { createSelector } from '@reduxjs/toolkit';

const selectInventoryProducts = (state) => state.inventory.products;

const selectMaximumPrice = (state) => state.inventory.filters.maximumPrice;

const selectOnlyAvailableProducts = createSelector(
  [selectInventoryProducts, selectMaximumPrice],
  (products, maximumPrice) =>
    products
      .filter((product) => product.inStock)
      .filter((product) => product.price <= maximumPrice)
      .sort((first, second) => first.price - second.price),
);
```

- здесь два входных селектора извлекают разные данные из Store, а функция преобразования получает уже извлечённые значения в виде аргументов
- затем вычисляется итоговый список: сначала исключаются отсутствующие товары, потом товары дороже установленного лимита, а оставшиеся сортируются по цене
- поскольку `filter()` возвращает новый массив, а `sort()` изменяет массив на месте, здесь сортируется именно новый массив, а не исходный массив из Redux State
- это важный нюанс: нельзя напрямую вызывать `state.inventory.products.sort(...)`, потому что такой вызов мутировал бы состояние

### цепочки селекторов

- сложные вычисления удобнее разделять на несколько небольших селекторов, каждый из которых отвечает за отдельную операцию

```js
const selectProductsForFiltering = (state) => state.inventory.products;

const selectInventoryMaximumPrice = (state) => state.inventory.filters.maximumPrice;

const selectAvailableInventory = createSelector([selectProductsForFiltering], (products) =>
  products.filter((product) => product.inStock),
);

const selectAffordableInventory = createSelector(
  [selectAvailableInventory, selectInventoryMaximumPrice],
  (products, maximumPrice) => products.filter((product) => product.price <= maximumPrice),
);

const selectAffordableInventoryCount = createSelector([selectAffordableInventory], (products) => products.length);
```

- здесь `selectAffordableInventoryCount` использует результат другого селектора, а не повторяет фильтрацию
- такая композиция делает логику более модульной и упрощает повторное использование вычислений
- если исходный массив товаров и лимит цены не изменились, мемоизированные селекторы могут использовать кешированные результаты на каждом этапе цепочки

## 7. селекторы с параметрами

- иногда компоненту нужно получить данные не обо всех товарах, а только об одном конкретном товаре по `id`
- для этого можно передавать дополнительные параметры через замыкание или использовать фабрику селекторов
- простой вариант — создать селектор, который возвращает функцию

```js
const selectProductById = (state, productId) => state.inventory.products.find((product) => product.id === productId);
```

- его можно использовать напрямую

```js
const selectedProduct = useSelector((state) => selectProductById(state, productId));
```

- этот вариант вполне подходит для простого поиска, но `find()` будет выполняться при каждом вызове селектора
- если поиск дорогой или результат создаётся как новый объект либо массив, можно использовать мемоизированный селектор с параметрами

```js
const selectProductsByCategory = createSelector(
  [(state) => state.inventory.products, (state, category) => category],
  (products, category) => products.filter((product) => product.category === category),
);
```

- такой селектор принимает состояние и категорию, после чего фильтрует товары по переданной категории

```js
const categoryProducts = useSelector((state) => selectProductsByCategory(state, selectedCategory));
```

- при использовании важно учитывать, что кеширование зависит от входных значений и настроек мемоизации
- в современных версиях Reselect стандартный `createSelector` использует мемоизатор, поддерживающий кеширование по комбинациям входных аргументов, но для специализированных сценариев можно настроить собственную стратегию мемоизации
- если один селектор используется множеством компонентов с разными параметрами, следует учитывать структуру кеша и частоту изменения аргументов, а не автоматически создавать отдельную фабрику для каждого случая

## 8. типичные ошибки при работе с селекторами

- возвращать новый объект или массив без необходимости — например, использовать `filter()` непосредственно внутри `useSelector`, когда мемоизация помогла бы сохранить ссылку на результат
- мутировать состояние внутри селектора — методы `sort()`, `push()` и другие операции, изменяющие исходные массивы или объекты, не должны применяться напрямую к данным Redux State
- мемоизировать каждый простой селектор — это добавляет сложность там, где вычисление и так дёшево и не создаёт новых ссылок
- дублировать производные данные в Redux State — если значение можно вычислить из уже имеющихся данных, часто лучше использовать селектор, чтобы избежать рассинхронизации
- неправильно определять входные селекторы — если селектор зависит от нескольких частей состояния, все существенные входы должны быть отражены в его зависимости, иначе результат может оказаться некорректным
- путать вызов селектора и подписку на Store — обычный селектор является функцией чтения данных, а подписку в React-компоненте организует `useSelector` или другой механизм React-Redux

## 9. как объяснить селекторы на собеседовании

- Selector — это функция, которая получает Redux State и возвращает выбранные данные или вычисляет производное значение
- селекторы отделяют логику чтения и преобразования состояния от React-компонентов, позволяют переиспользовать вычисления и уменьшают зависимость компонентов от структуры Store
- для простых селекторов достаточно обычных функций, а для дорогих вычислений и результатов в виде новых объектов или массивов используют мемоизацию через `createSelector` из Redux Toolkit
- сложные селекторы можно составлять из нескольких входных селекторов, объединяя разные части состояния и вычисляя производные данные
- при использовании `useSelector` важно учитывать сравнение ссылок: по умолчанию React-Redux использует строгое равенство `===` для сравнения выбранного значения
- главное, что нужно запомнить: Reducer отвечает за изменение состояния, а Selector — за получение и вычисление данных на основе состояния; мемоизация позволяет избежать повторных вычислений, когда входные данные не изменились
