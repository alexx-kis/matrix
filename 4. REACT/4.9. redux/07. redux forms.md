# redux-form в экосистеме React + Redux

- `redux-form` — это библиотека, которая управляет состоянием HTML-форм через Redux Store: значениями полей, их изменениями, ошибками валидации, состояниями отправки и другими аспектами работы формы
- тема немного отличается от предыдущих: Redux, Actions, Reducers, Middleware и Selectors — фундаментальные механизмы управления состоянием, а `redux-form` — конкретная библиотека, построенная поверх этих механизмов
- важный контекст для собеседования: `redux-form` — исторически популярная библиотека, но для новых React-проектов её обычно не выбирают, поскольку хранение каждого изменения поля формы в Redux может создавать лишние обновления и усложнять архитектуру
- при этом библиотеку полезно понимать, если предстоит работать с существующим проектом, где она уже используется

## 1. какую проблему решает redux-form

- представим форму регистрации с несколькими полями

```
RegistrationForm
├── email
├── password
├── confirmPassword
└── submit button
```

- без специализированной библиотеки разработчику нужно самостоятельно управлять значениями полей, ошибками валидации, touched-состоянием, статусом отправки и обработкой результата сервера
- например, при изменении поля `email` нужно сохранить новое значение, при потере фокуса — отметить поле как посещённое, при отправке — проверить форму, а при ошибке сервера — отобразить соответствующее сообщение
- React предоставляет для этого `useState` и `useReducer`, но при большом количестве полей управление всей логикой может стать громоздким
- `redux-form` предлагает готовую модель, в которой состояние формы хранится в Redux Store, а библиотека предоставляет API для связи полей, валидации и отправки формы

### что хранится в состоянии формы

- типичная форма может содержать несколько категорий данных

#### values - текущие значения полей, например `email: "user@example.com"`

#### errors - ошибки валидации, например `email: "Invalid email"`

#### touched - информация о том, какие поля пользователь уже посещал или с которыми взаимодействовал

#### состояние отправки - например, `submitting`, `submitSucceeded` и другие флаги, позволяющие управлять поведением интерфейса

- точная структура состояния зависит от версии библиотеки и конфигурации формы, но основная идея одна: `redux-form` централизованно управляет жизненным циклом формы

## 2. как redux-form работает вместе с Redux

- библиотека не заменяет Redux, а использует его механизмы: собственный Reducer, Actions и подключение компонентов к Store

```
Пользователь вводит значение
          ↓
      <Field />
          ↓
   redux-form API
          ↓
        Action
          ↓
      formReducer
          ↓
       Redux Store
          ↓
    обновление Field
```

- когда пользователь вводит текст в поле, библиотека отслеживает изменение и отправляет соответствующий Action
- `formReducer` обрабатывает Action и обновляет состояние конкретной формы в Redux Store
- подключённые компоненты получают обновлённые значения и состояния полей, после чего React обновляет интерфейс при необходимости
- например, состояние формы `login` может храниться по пути `state.form.login`, если Reducer библиотеки подключён под ключом `form`
- это означает, что значения формы становятся частью общего состояния Redux, а значит, доступны другим частям приложения через селекторы и Redux API

### подключение redux-form к Store

- прежде чем использовать библиотеку, нужно подключить её Reducer к Redux Store

```js
import { createStore, combineReducers } from 'redux';
import { reducer as formReducer } from 'redux-form';

const rootReducer = combineReducers({
  form: formReducer,
});

const legacyFormStore = createStore(rootReducer);
```

- здесь `formReducer` управляет состоянием всех форм, созданных через `redux-form`
- имя ключа `form` не является обязательным, но это общепринятое соглашение, на которое ориентируются многие примеры и интеграции
- если использовать другое имя, нужно учитывать это при чтении состояния и настройке связанных инструментов
- в современных проектах с Redux Toolkit можно подключать `formReducer` к `configureStore`, однако это не делает `redux-form` современным или предпочтительным выбором для новых форм

## 3. основной API redux-form

- в библиотеке есть несколько ключевых сущностей, каждая из которых отвечает за отдельную часть жизненного цикла формы

### `reduxForm()`

- HOC, который подключает React-компонент к управлению формой и предоставляет props для отправки, валидации и состояния формы

### `Field`

- компонент, связывающий конкретное поле ввода с состоянием формы и передающий ему значение, обработчики событий и состояние валидации

### `formReducer`

- Reducer библиотеки, который обрабатывает Actions и хранит состояние форм в Redux Store

### `handleSubmit`

- функция, предоставляемая `reduxForm`, которая организует обработку отправки формы и вызывает пользовательский submit-обработчик

### `formValueSelector()`

- функция для создания селектора, позволяющего получить значения отдельных полей формы из Redux Store

### `SubmissionError`

- специальный тип ошибки, позволяющий передать серверные ошибки отправки формы в механизм обработки ошибок `redux-form`

- также библиотека предоставляет API для валидации, сброса формы, изменения значений программно, обработки фокуса и других операций

## 4. `reduxForm()` — подключение формы

- `reduxForm()` — это HOC, то есть функция высшего порядка, которая принимает конфигурацию и возвращает функцию для подключения React-компонента

```js
import React from 'react';
import { reduxForm } from 'redux-form';

function LoginFormView({ handleSubmit, submitting }) {
  return (
    <form onSubmit={handleSubmit}>
      <button type='submit' disabled={submitting}>
        Sign in
      </button>
    </form>
  );
}

export default reduxForm({
  form: 'login',
})(LoginFormView);
```

- `form: 'login'` задаёт уникальное имя формы, по которому библиотека идентифицирует её состояние в Redux Store
- `handleSubmit` предоставляет механизм обработки отправки, а `submitting` показывает, выполняется ли submit-обработчик, возвращающий Promise
- в примере пока нет полей, поэтому это лишь минимальная демонстрация подключения формы
- в реальном приложении `reduxForm()` предоставляет и другие props, включая `pristine`, `dirty`, `valid`, `invalid`, `reset` и `initialize`, в зависимости от состояния и конфигурации формы
- в отличие от обычного React-компонента, подключённый компонент получает эти props от библиотеки, а не от родителя

## 5. `Field` — связь поля с состоянием формы

- `Field` — один из самых важных компонентов `redux-form`, поскольку он связывает конкретный input с Redux-состоянием формы
- каждому `Field` передаётся обязательное имя `name`, по которому библиотека сохраняет значение поля

```js
import React from 'react';
import { Field, reduxForm } from 'redux-form';

function renderTextInput({ input, meta, label }) {
  return (
    <div>
      <label>
        {label}
        <input {...input} />
      </label>

      {meta.touched && meta.error && <span>{meta.error}</span>}
    </div>
  );
}

function ProfileFormView({ handleSubmit }) {
  return (
    <form onSubmit={handleSubmit}>
      <Field name='email' component={renderTextInput} label='Email' />

      <Field name='displayName' component={renderTextInput} label='Display name' />

      <button type='submit'>Save</button>
    </form>
  );
}

export default reduxForm({
  form: 'profile',
})(ProfileFormView);
```

- `name="email"` означает, что значение этого поля будет связано с полем `email` в состоянии формы `profile`
- `component={renderTextInput}` задаёт компонент или функцию рендеринга, через которую `Field` отображает input
- `label` — пользовательский prop, который библиотека передаёт функции рендеринга вместе со служебными props
- `input` содержит props для взаимодействия с элементом ввода, включая `value`, `onChange`, `onBlur`, `onFocus` и `name`
- `meta` содержит метаданные поля, например `touched`, `error`, `warning`, `valid` и `dirty`
- благодаря этому не нужно самостоятельно подключать каждый input к Redux Store — библиотека обеспечивает связь и обновление состояния

### почему используется `{...input}`

- запись `<input {...input} />` передаёт input-элементу необходимые свойства и обработчики, которые `redux-form` подготовил для конкретного поля
- когда пользователь вводит текст, вызывается переданный `onChange`, и библиотека обновляет состояние поля
- когда поле теряет фокус, `onBlur` позволяет обновить связанные метаданные, например `touched`
- если не передать эти props элементу ввода, поле может отображаться, но перестать корректно синхронизироваться с состоянием формы

## 6. валидация формы

- `redux-form` поддерживает синхронную и асинхронную валидацию, а также обработку серверных ошибок после отправки формы
- самый распространённый вариант — передать функцию `validate` в конфигурацию `reduxForm()`

### синхронная валидация

```js
import { reduxForm, Field } from 'redux-form';

function validateProfileForm(values) {
  const errors = {};

  if (!values.email) {
    errors.email = 'Email is required';
  } else if (!/^[^s@]+@[^s@]+.[^s@]+$/.test(values.email)) {
    errors.email = 'Invalid email';
  }

  if (!values.password) {
    errors.password = 'Password is required';
  } else if (values.password.length < 8) {
    errors.password = 'Password must contain at least 8 characters';
  }

  return errors;
}
```

- функция получает объект `values` со значениями всех полей формы и возвращает объект ошибок
- ключи объекта ошибок должны соответствовать именам полей, объявленным через `Field`
- если ошибок нет, функция возвращает пустой объект

```js
const ValidatedProfileForm = reduxForm({
  form: 'validatedProfile',
  validate: validateProfileForm,
})(ProfileFormView);
```

- библиотека использует результат `validate` для определения ошибок и состояния валидности формы
- при этом саму функцию валидации можно тестировать независимо от React и Redux, поскольку она принимает обычный объект и возвращает другой объект

### как отображаются ошибки

- в предыдущем примере функция `renderTextInput` проверяет `meta.touched` и `meta.error`
- это позволяет не показывать ошибку сразу при первом рендере, а отобразить её после взаимодействия пользователя с полем
- `meta.error` содержит сообщение об ошибке, а `meta.touched` позволяет определить, взаимодействовал ли пользователь с полем в соответствии с логикой библиотеки
- ошибки формы и ошибки конкретного поля не всегда одно и то же: библиотека может хранить ошибки отдельных полей и общую ошибку формы отдельно

## 7. отправка формы: `handleSubmit`

- `handleSubmit` связывает событие отправки HTML-формы с пользовательским обработчиком и механизмом валидации `redux-form`

```js
function submitProfileForm(values) {
  return fetch('/api/profile', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify(values),
  }).then((response) => {
    if (!response.ok) {
      throw new Error('Failed to save profile');
    }

    return response.json();
  });
}
```

- функция принимает объект `values` со значениями полей формы и возвращает Promise, поскольку запрос выполняется асинхронно

```js
function ProfileFormView({ handleSubmit, submitting }) {
  return (
    <form onSubmit={handleSubmit(submitProfileForm)}>
      <Field name='email' component='input' type='email' />

      <button type='submit' disabled={submitting}>
        Save profile
      </button>
    </form>
  );
}
```

- при отправке формы `handleSubmit(submitProfileForm)` запускает предусмотренный библиотекой процесс отправки
- если синхронная валидация не пройдена, submit-обработчик не вызывается, а ошибки становятся доступны форме и полям
- если валидация пройдена, `redux-form` вызывает `submitProfileForm` с текущими значениями формы
- когда обработчик возвращает Promise, библиотека может управлять флагом `submitting` на время выполнения операции
- в случае ошибки отправки можно использовать `SubmissionError`, чтобы передать серверные ошибки в соответствующие поля формы

### обработка серверных ошибок

```js
import { SubmissionError } from 'redux-form';

function submitProfileWithServerValidation(values) {
  return fetch('/api/profile', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
    },
    body: JSON.stringify(values),
  }).then(async (response) => {
    const result = await response.json();

    if (!response.ok) {
      throw new SubmissionError({
        email: result.message || 'Unable to save email',
        _error: 'Profile submission failed',
      });
    }

    return result;
  });
}
```

- в этом примере `email` — ошибка конкретного поля, а `_error` — общая ошибка отправки формы
- сервер должен действительно возвращать подходящий ответ, а обработчик — корректно преобразовывать его в формат ошибок библиотеки
- `SubmissionError` помогает связать серверную валидацию с интерфейсом, но не заменяет проверку данных на сервере

## 8. другие важные API

- помимо `reduxForm`, `Field` и `handleSubmit`, библиотека предоставляет несколько инструментов для более сложных сценариев

### `formValueSelector(formName)`

- создаёт селектор для получения значений отдельных полей из Redux Store

```js
const selectLoginValues = formValueSelector('login');
```

- его можно использовать с `connect` для передачи выбранных значений через props

### `change(form, field, value)`

- Action Creator для программного изменения значения конкретного поля

```js
dispatch(change('login', 'email', 'user@example.com'));
```

### `reset(form)`

- Action Creator для сброса формы к начальному состоянию

```js
dispatch(reset('login'));
```

### `initialize(form, data)`

- Action Creator для инициализации формы значениями, например полученными с сервера

```js
dispatch(
  initialize('profile', {
    email: 'user@example.com',
  }),
);
```

### `FieldArray`

- компонент для управления динамическими списками полей, например несколькими адресами доставки или телефонными номерами

### `FormSection`

- позволяет логически группировать поля формы, в том числе организовывать вложенную структуру имён полей

- при использовании Action Creators вроде `change`, `reset` и `initialize` нужно учитывать, что это функции, создающие Actions, поэтому для отправки соответствующего действия обычно требуется `dispatch`
- некоторые операции также доступны через props, которые предоставляет `reduxForm()`, например `reset`, `initialize` и другие методы управления формой
- при выборе API нужно смотреть, где именно вызывается операция: через `dispatch` как Action Creator или через props подключённого компонента

### `formValueSelector` и `connect`

- если нужно получить значение поля вне самого `Field`, например показать превью выбранного режима формы, можно использовать `formValueSelector`

```js
import { connect } from 'react-redux';
import { formValueSelector } from 'redux-form';

const selectLoginEmail = formValueSelector('login');

function LoginStatus({ email }) {
  return <p>Current email: {email || 'Not entered'}</p>;
}

const ConnectedLoginStatus = connect((state) => ({
  email: selectLoginEmail(state, 'email'),
}))(LoginStatus);
```

- `formValueSelector('login')` создаёт селектор, который читает данные формы с именем `login`
- вызов `selectLoginEmail(state, 'email')` возвращает текущее значение поля `email`
- это пример интеграции `redux-form` с ранее изученным HOC `connect`

## 9. как redux-form управляет жизненным циклом формы

- полезно рассматривать форму как сущность, проходящую несколько этапов

```
инициализация
     ↓
изменение значений
     ↓
валидация
     ↓
отправка формы
     ↓
успех или ошибка
     ↓
сброс / дальнейшее редактирование
```

- при инициализации библиотека создаёт состояние формы и при необходимости заполняет поля начальными значениями
- при вводе данных `Field` передаёт изменения библиотеке, которая обновляет значения в Redux Store
- при валидации определяются ошибки полей и общее состояние валидности формы
- при отправке `handleSubmit` организует вызов обработчика после прохождения предусмотренной валидации
- после успешной отправки или ошибки библиотека обновляет соответствующие флаги, а интерфейс может отобразить результат
- если нужно редактировать уже существующий объект, например профиль пользователя, форму можно инициализировать данными, полученными от API
- важно учитывать опции вроде `enableReinitialize`, которая позволяет переинициализировать форму при изменении `initialValues`, и `keepDirtyOnReinitialize`, которая влияет на сохранение изменённых пользователем полей при повторной инициализации

## 10. недостатки redux-form и альтернативы

- несмотря на богатый API, хранение каждого изменения поля в Redux имеет определённую стоимость
- при вводе текста в обычный input может отправляться Action и обновляться Redux Store, что создаёт дополнительную работу для приложения
- если форма большая и содержит сложную логику, централизованное состояние может усложнить управление обновлениями, тестирование и разделение ответственности
- кроме того, библиотека добавляет зависимость формы от Redux, даже когда её значения нужны только внутри одного компонента
- по этой причине для новых приложений обычно рассматривают альтернативы

### React Hook Form

- популярная библиотека управления формами, ориентированная на работу с React Hooks и сокращение лишних обновлений при вводе

### Formik

- библиотека управления значениями, валидацией и отправкой форм через React-компоненты и Hooks

React без form-библиотеки

- для небольших форм часто достаточно `useState` или `useReducer` вместе с собственной валидацией

- если в проекте уже используется `redux-form`, важно знать его API и понимать существующую архитектуру, а не переписывать всё автоматически

- если проект создаётся с нуля, обычно разумнее хранить временное состояние формы локально, а в Redux передавать только данные, которые действительно должны быть доступны другим частям приложения

## 11. как объяснить redux-form на собеседовании

- `redux-form` — библиотека для управления формами в React, которая хранит значения полей и связанное состояние формы в Redux Store

- она предоставляет `formReducer` для обработки изменений состояния, `reduxForm()` для подключения формы, `Field` для связи отдельных полей с Store и `handleSubmit` для управления отправкой

- валидация реализуется через функции `validate`, а серверные ошибки можно передавать через `SubmissionError`

- для чтения значений вне полей используются селекторы вроде `formValueSelector`, а программное изменение и инициализация значений доступны через Actions и API подключённой формы

- основное преимущество — централизованное управление формой и готовая интеграция с Redux, а недостатки — дополнительная сложность и обновления Store при изменении полей

- главное, что нужно запомнить: `redux-form` связывает форму с Redux на протяжении всего её жизненного цикла, но для новых проектов это обычно не первый выбор — библиотеку прежде всего важно понимать для поддержки существующих приложений
