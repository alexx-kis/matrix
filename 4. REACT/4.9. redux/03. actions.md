# actions в Redux

- Action — одна из базовых сущностей Redux, которая описывает событие, произошедшее в приложении, или намерение изменить состояние
- чтобы уверенно работать с Actions и объяснять их на собеседовании, нужно понимать их структуру, назначение, жизненный цикл, связь с Reducers и Dispatch, а также разницу между Action и Action Creator

## 1. что такое Action и зачем он нужен

- вспомним основной принцип Redux: состояние нельзя произвольно изменять напрямую, вместо этого изменения проходят через контролируемый механизм
- Action выступает сообщением, которое описывает, что произошло, и передаёт необходимые данные для обработки этого события
- например, в приложении интернет-магазина могут возникать следующие события

```js
const productAddedAction = {
  type: 'cart/productAdded',
  payload: {
    id: 10,
    title: 'Keyboard',
    price: 120,
  },
};

const productRemovedAction = {
  type: 'cart/productRemoved',
  payload: {
    id: 10,
  },
};

const userLoggedOutAction = {
  type: 'auth/loggedOut',
};
```

- каждый объект описывает отдельное событие: добавление товара, удаление товара или выход пользователя из системы
- сами Actions не изменяют Redux State, не вызывают React-рендер и не выполняют бизнес-логику автоматически — они лишь передают информацию в Redux, где её могут обработать Reducers и middleware
- главная идея: Action описывает событие, а Reducer определяет, как это событие изменит состояние

## 2. структура Action

- стандартный Redux Action — это обычный JavaScript-объект с обязательным свойством `type`

```js
const orderSubmittedAction = {
  type: 'orders/orderSubmitted',
  payload: {
    orderId: 501,
    total: 250,
  },
  meta: {
    source: 'checkout',
  },
};
```

- разберём основные поля

### `type`

- `type` — обязательное строковое свойство, которое идентифицирует тип события
- Reducer использует его, чтобы определить, как обработать Action

```js
switch (action.type) {
  case 'orders/orderSubmitted':
    // обработка отправки заказа
    return state;

  case 'orders/orderCancelled':
    // обработка отмены заказа
    return state;

  default:
    return state;
}
```

- строки вроде `'orders/orderSubmitted'` — соглашение об именовании, а не специальный синтаксис Redux
- часто используют формат `domain/eventName`, например `cart/productAdded` или `auth/loggedOut`, чтобы было понятно, к какой области приложения относится событие
- `type` должен быть уникальным в пределах соответствующей архитектуры приложения, чтобы разные события случайно не обрабатывались как одно и то же

### `payload`

- `payload` — необязательное поле, которое обычно содержит данные, необходимые для обработки Action

```js
const quantityChangedAction = {
  type: 'cart/quantityChanged',
  payload: {
    productId: 10,
    quantity: 3,
  },
};
```

- Redux не требует, чтобы поле называлось именно `payload`, но такое соглашение широко используется, особенно в Redux Toolkit
- структура `payload` определяется приложением: это может быть идентификатор, строка, число, объект или массив
- полезно передавать только данные, необходимые для обработки события, и поддерживать понятный контракт между местом отправки Action и Reducer

### `meta` и `error`

- дополнительные поля `meta` и `error` не являются обязательными для обычного Redux Action, но встречаются в распространённых соглашениях, например в Flux Standard Action
- `meta` может содержать вспомогательную информацию: источник события, идентификатор запроса или другие метаданные
- `error` в соглашении Flux Standard Action используется для обозначения Action, представляющего ошибку
- обычный Redux не требует определённой структуры этих полей — их значение зависит от соглашений и инструментов, принятых в проекте

## 3. как Action проходит через Redux

- рассмотрим полный путь Action от пользовательского события до изменения интерфейса

```
     пользователь нажимает кнопку
  например, добавляет товар в корзину
                  ↓
    Action Creator создаёт Action
{ type: 'cart/productAdded', payload: ... }
                  ↓
      dispatch отправляет Action
       Store принимает сообщение
                  ↓
    middleware обрабатывают Action
        если они подключены
                  ↓
  Reducer вычисляет новое состояние
 на основе предыдущего State и Action
                  ↓
        Store сохраняет State
   React-Redux уведомляет подписчиков
```

- последовательность показывает, что Action — лишь одна часть механизма, а не самостоятельный инструмент изменения состояния
- важный нюанс: в обычном синхронном Redux Action проходит через middleware, если они настроены, затем Reducer вычисляет новое состояние, а Store уведомляет подписчиков
- middleware могут обрабатывать Action до передачи дальше, не передавать его дальше или выполнять дополнительные действия
- поэтому утверждение «каждый Action обязательно доходит до Reducer» неверно: это зависит от middleware и способа отправки

## 4. Action и Action Creator — в чём разница

- эти два понятия часто путают, хотя различие простое
- Action — объект, описывающий событие
- Action Creator — функция, которая создаёт такой объект

```js
const productAddedActionObject = {
  type: 'cart/productAdded',
  payload: {
    id: 10,
    title: 'Keyboard',
  },
};

function createProductAddedAction(product) {
  return {
    type: 'cart/productAdded',
    payload: product,
  };
}

const anotherProductAddedAction = createProductAddedAction({
  id: 11,
  title: 'Mouse',
});
```

- `createProductAddedAction` — Action Creator, а `anotherProductAddedAction` — созданный им Action
- Action Creator позволяет не дублировать структуру объектов и централизованно задавать тип события
- без Action Creators пришлось бы каждый раз вручную создавать объекты с одинаковым `type`, что повышает вероятность опечаток и несогласованности данных
- сам по себе Action Creator не обязан отправлять Action в Store: обычно он только возвращает объект, а отправка выполняется отдельно через `dispatch`

```js
const newProductAction = createProductAddedAction({
  id: 12,
  title: 'Webcam',
});

appStore.dispatch(newProductAction);
```

- здесь сначала создаётся Action, затем он отправляется в Store

## 5. зачем нужны Action Creators в Redux Toolkit

- в современном Redux обычно используют Redux Toolkit, где `createSlice` автоматически создаёт Action Creators на основе описанных Reducers

```js
import { createSlice } from '@reduxjs/toolkit';

const cartSlice = createSlice({
  name: 'cart',
  initialState: {
    items: [],
  },
  reducers: {
    productAdded(state, action) {
      state.items.push(action.payload);
    },

    productRemoved(state, action) {
      state.items = state.items.filter((item) => item.id !== action.payload);
    },
  },
});

export const { productAdded, productRemoved } = cartSlice.actions;
```

- в этом примере `productAdded` и `productRemoved` — автоматически созданные Action Creators
- вызов `productAdded({ id: 10, title: 'Keyboard' })` вернёт объект Action с типом `cart/productAdded` и переданными данными в `payload`

```js
const generatedCartAction = productAdded({
  id: 10,
  title: 'Keyboard',
});

// результат:
// {
//   type: 'cart/productAdded',
//   payload: { id: 10, title: 'Keyboard' }
// }
```

- затем этот Action можно отправить в Store

```js
appStore.dispatch(
  productAdded({
    id: 10,
    title: 'Keyboard',
  })
);
```

- запись `state.items.push(...)` выглядит как прямая мутация, но внутри `createSlice` Redux Toolkit использует Immer, который создаёт иммутабельное обновление состояния
- важно: объект Action остаётся обычным объектом JavaScript, даже если он создан Redux Toolkit

## 6. почему Actions должны быть сериализуемыми

- в Redux принято передавать в Actions обычные сериализуемые данные: строки, числа, boolean, массивы, простые объекты и `null`
- это помогает сохранять предсказуемость состояния, использовать Redux DevTools, записывать последовательность действий и воспроизводить её при отладке
- например, такой Action удобен для инструментов разработки

```js
const paymentSucceededAction = {
  type: 'payment/succeeded',
  payload: {
    transactionId: 'tx-501',
    amount: 250,
  },
};
```

- а передача функций, экземпляров классов, DOM-элементов, экземпляров `Promise` или `AbortController` в обычных Actions обычно не рекомендуется
- сериализуемость не является жёстким требованием JavaScript к любому объекту, но это важное соглашение Redux, которое поддерживается стандартными проверками Redux Toolkit
- существуют исключения: например, thunk middleware позволяет отправлять функции в `dispatch`, однако такая функция не является обычным Redux Action-объектом, который обрабатывает Reducer

## 7. обычные Actions и асинхронные операции

- стандартный Redux Reducer синхронно обрабатывает Action-объекты и возвращает новое состояние, но сама операция, инициирующая изменение, может быть асинхронной
- например, при загрузке товаров с сервера нужно учесть несколько событий: начало запроса, успешное получение данных и ошибку
- в современном Redux для этого часто используют `createAsyncThunk`

```js
import { createAsyncThunk, createSlice } from '@reduxjs/toolkit';

export const fetchInventory = createAsyncThunk('inventory/fetch', async () => {
  const response = await fetch('/api/products');

  if (!response.ok) {
    throw new Error('Failed to fetch products');
  }

  return response.json();
});

const inventorySlice = createSlice({
  name: 'inventory',
  initialState: {
    products: [],
    status: 'idle',
    error: null,
  },
  reducers: {},
  extraReducers: (builder) => {
    builder
      .addCase(fetchInventory.pending, (state) => {
        state.status = 'loading';
        state.error = null;
      })
      .addCase(fetchInventory.fulfilled, (state, action) => {
        state.status = 'succeeded';
        state.products = action.payload;
      })
      .addCase(fetchInventory.rejected, (state, action) => {
        state.status = 'failed';
        state.error = action.error.message;
      });
  },
});
```

- `createAsyncThunk` создаёт Action Creators для состояний `pending`, `fulfilled` и `rejected`, которые отражают жизненный цикл асинхронной операции
- сама функция `fetchInventory` возвращает thunk — функцию, которую обрабатывает соответствующее middleware, а не обычный Action-объект
- во время выполнения thunk отправляются обычные Actions, которые уже обрабатываются Reducers
- это важное различие: асинхронная операция не превращает Reducer в асинхронную функцию — Reducers по-прежнему синхронно вычисляют новое состояние на основе Action

## 8. типичные ошибки при работе с Actions

- изменение состояния внутри Action Creator — Action Creator должен создавать Action или, в специальных случаях, возвращать thunk, но не должен напрямую изменять Redux State
- выполнение HTTP-запроса внутри обычного Reducer — Reducer должен оставаться чистой функцией, а запрос организуется через middleware, thunk или другой механизм побочных эффектов
- передача слишком большого количества данных — payload должен содержать данные, необходимые для обработки события, а не произвольную копию всего состояния приложения
- путаница между вызовом Action Creator и отправкой Action — вызов `productAdded(item)` создаёт Action, но без `dispatch` этот Action не попадёт в Store
- непоследовательные типы событий — понятные имена вроде `cart/productAdded` лучше отражают событие и облегчают поиск в Redux DevTools

## 9. как объяснить Actions на собеседовании

- Action в Redux — это обычный JavaScript-объект с обязательным полем `type`, который описывает событие в приложении и может содержать данные в `payload`
- Action сам по себе не меняет состояние: он отправляется через `dispatch`, после чего проходит через middleware и обрабатывается Reducer, который вычисляет новое состояние
- Action Creator — функция, создающая Action; в Redux Toolkit такие функции обычно генерируются автоматически с помощью `createSlice`
- Actions помогают сделать изменения состояния явными, отслеживаемыми и удобными для тестирования, а сериализуемые Action-объекты позволяют использовать Redux DevTools и воспроизводить последовательности событий
- для асинхронных операций применяются middleware, например thunk, которые могут выполнять запросы и отправлять обычные Actions для состояний загрузки, успеха и ошибки
- главное, что нужно запомнить: Action описывает что произошло, Reducer определяет как изменится состояние, а `dispatch` отвечает за отправку Action в Redux
