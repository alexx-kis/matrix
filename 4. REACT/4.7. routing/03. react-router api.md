# React Router API: от базового уровня до глубокого понимания

- разберём API React Router так, чтобы ты мог не только использовать маршрутизацию в React-приложениях, но и объяснить на собеседовании, как она устроена, чем отличаются компоненты маршрутизации и как они взаимодействуют между собой
- важный нюанс: в React Router API существенно менялся между версиями, поэтому будем рассматривать два варианта — React Router v5, в котором используются `Switch`, `Redirect` и классический API из твоего списка, и React Router v6+, где появились `Routes`, `Navigate` и другие изменения

## 1. основы маршрутизации в React

### что такое routing и зачем он нужен

- маршрутизация — это механизм, который определяет, какой интерфейс нужно показать пользователю в зависимости от текущего URL
- например, у приложения могут быть следующие страницы:

```
/             → главная страница
/products     → список товаров
/products/42  → страница товара с id = 42
/profile      → профиль пользователя
/login        → страница авторизации
```

- в традиционном многостраничном приложении переход по ссылке обычно приводит к запросу нового HTML-документа с сервера
- в React SPA переход между страницами обычно происходит без полной перезагрузки документа: приложение определяет новый URL и отображает соответствующий компонент
- React Router связывает три основные вещи:
  - URL — адрес, соответствующий текущему состоянию навигации
  - route configuration — правила сопоставления URL с компонентами
  - React components — интерфейс, который необходимо отобразить для совпавшего маршрута

- Схематично это работает так:

```
URL: /products/42
        ↓
сопоставление с маршрутом
        ↓
<Route path="/products/:id">
        ↓
рендер компонента ProductPage
        ↓
отображение товара с id = 42
```

- React Router при этом не заменяет React и не является системой рендеринга компонентов — он определяет, какой интерфейс соответствует текущему маршруту, и предоставляет API для навигации

### как маршрутизация связана с браузером

- адресная строка браузера содержит URL, а его `pathname` — путь, например `/products/42`
- при изменении URL с помощью обычного перехода браузер может загрузить новый документ с сервера, но React Router может выполнять клиентскую навигацию, изменяя историю браузера без полной перезагрузки страницы
- для этого браузер предоставляет History API:

```js
window.history.pushState({}, '', '/products');
window.history.replaceState({}, '', '/profile');
```

- `pushState` добавляет новую запись в историю, а `replaceState` заменяет текущую запись
- сами методы `pushState` и `replaceState` не вызывают загрузку нового документа и не генерируют событие `popstate`
- React Router абстрагирует работу с этими механизмами и синхронизирует состояние маршрутизации с React-интерфейсом

## 2. `Route` — описание маршрута

- `Route` — компонент, который задаёт правило сопоставления URL с определённым интерфейсом
- в React Router v5 у маршрута обычно указывают `path` и `component`, `render` либо `children`

### простой пример

```js
import { BrowserRouter, Route } from 'react-router-dom';

function HomePage() {
  return <h1>Главная</h1>;
}

function ProductsPage() {
  return <h1>Товары</h1>;
}

function App() {
  return (
    <BrowserRouter>
      <Route exact path='/' component={HomePage} />
      <Route path='/products' component={ProductsPage} />
    </BrowserRouter>
  );
}
```

- когда URL равен `/`, будет отображаться `HomePage`, а когда путь соответствует `/products`, — `ProductsPage`
- обрати внимание: в v5 `Route` сам по себе не означает, что в каждый момент времени обязательно будет выбран только один маршрут
- если несколько маршрутов совпадают с текущим URL, они могут одновременно отрендерить свои компоненты
- именно поэтому в v5 часто использовался `Switch`, о котором поговорим дальше

### основные свойства `Route` в v5

- `path` — путь, с которым сопоставляется URL
- `exact` — требует полного совпадения пути, а не только совпадения его начала
- `component` — компонент, который React Router создаёт при совпадении маршрута
- `render` — функция, возвращающая React-элемент, когда маршрут совпал
- `children` — дочерний элемент или функция, поведение которой отличается от `component` и `render`

Рассмотрим различие между `component` и `render`:

```js
<Route
  path="/products"
  component={ProductsPage}
/>

<Route
  path="/products"
  render={(routeProps) => (
    <ProductsPage
      title="Каталог"
      {...routeProps}
    />
  )}
/>
```

- через `component` передаётся ссылка на компонент, который React Router создаёт при совпадении маршрута
- через `render` можно самостоятельно создать элемент и передать дополнительные props
- не следует передавать inline-функцию в `component`, если нужно избежать ненужного перемонтирования:

```js
<Route path='/products' component={() => <ProductsPage />} />
```

- такая функция воспринимается как тип компонента, отличный от `ProductsPage`, и при повторном рендеринге маршрута может приводить к размонтированию и повторному монтированию дочернего компонента
- если требуется передать дополнительные параметры, для v5 обычно лучше подходит `render`

### параметры маршрута

- динамические сегменты позволяют извлекать данные непосредственно из URL

```js
<Route path='/products/:productId' component={ProductPage} />
```

- при переходе на `/products/42` значение `productId` будет равно строке `"42"`
- в v5 параметр доступен через `match.params` в props маршрута или через хук `useParams`

```js
import { useParams } from 'react-router-dom';

function ProductPage() {
  const { productId } = useParams();

  return <h1>Товар: {productId}</h1>;
}
```

- это удобно, когда URL определяет идентификатор сущности, которую нужно загрузить с сервера
- важно помнить, что параметр маршрута изначально является строкой, поэтому при необходимости его нужно явно преобразовать и проверить

## 3. `Switch` — выбор одного маршрута

- `Switch` — компонент React Router v5, который перебирает дочерние маршруты и рендерит первый подходящий маршрут
- его основная задача — не допустить одновременного отображения нескольких маршрутов, когда URL подходит под несколько условий

### проблема без `Switch`

```js
<Route path="/products" component={ProductsPage} />
<Route path="/products/:productId" component={ProductPage} />
```

- допустим, текущий URL — `/products/42`
- в React Router v5 оба маршрута могут совпасть с этим URL, поскольку первый маршрут без `exact` допускает совпадение по началу пути
- в результате могут отрендериться и список товаров, и страница конкретного товара

### решение с `Switch`

```js
import { Switch, Route } from 'react-router-dom';

function AppRoutes() {
  return (
    <Switch>
      <Route exact path='/products' component={ProductsPage} />

      <Route path='/products/:productId' component={ProductPage} />
    </Switch>
  );
}
```

- `Switch` перебирает дочерние элементы сверху вниз и прекращает поиск после первого совпадения
- поэтому порядок маршрутов имеет значение: более специфичные маршруты обычно размещают перед более общими, если их шаблоны могут пересекаться
- `exact` и `Switch` решают разные задачи: `exact` ограничивает сопоставление конкретного маршрута, а `Switch` выбирает первый подходящий маршрут из набора

### маршрут 404

- в v5 можно использовать маршрут без `path` в конце `Switch`, чтобы он срабатывал, когда предыдущие маршруты не подошли

```js
<Switch>
  <Route exact path='/' component={HomePage} />
  <Route path='/products' component={ProductsPage} />
  <Route component={NotFoundPage} />
</Switch>
```

- маршрут без `path` здесь выступает как запасной вариант
- если поместить его в начало, он будет совпадать первым и остальные маршруты уже не получат возможности отобразиться

## 4. `Link` — навигация без полной перезагрузки страницы

- `Link` — компонент, предназначенный для переходов между маршрутами приложения
- визуально он обычно работает как HTML-ссылка `<a>`, но при обычном клиентском переходе React Router перехватывает действие, обновляет историю браузера и позволяет приложению отобразить новый интерфейс без загрузки нового документа

```js
import { Link } from 'react-router-dom';

function Navigation() {
  return (
    <nav>
      <Link to='/'>Главная</Link>
      <Link to='/products'>Товары</Link>
      <Link to='/profile'>Профиль</Link>
    </nav>
  );
}
```

- свойство `to` определяет целевой адрес, на который перейдёт пользователь
- в отличие от обычного `<a href="/products">`, `Link` предназначен для клиентской навигации внутри приложения, использующего React Router
- при этом `Link` остаётся настоящей ссылкой: браузер сохраняет стандартные возможности вроде открытия в новой вкладке через контекстное меню и использования клавиатуры

### `Link` и обычный `<a>`

```js
<a href="/products">Товары</a>

<Link to="/products">Товары</Link>
```

- обычный `<a>` инициирует навигацию браузера, которая при стандартном HTTP URL обычно приводит к запросу нового документа
- `Link` обычно выполняет навигацию на стороне клиента, если переход относится к управляемому приложением маршруту и не требует обычного поведения браузера
- обычный `<a>` подходит для внешних сайтов, скачивания файлов и случаев, когда нужна стандартная навигация браузера
- `Link` подходит для переходов между страницами внутри React-приложения

### относительные и динамические ссылки

- маршрут можно формировать из данных:

```js
function ProductLink({ productId }) {
  return <Link to={`/products/${productId}`}>Открыть товар</Link>;
}
```

- в данном случае путь формируется на основе идентификатора товара
- в более сложных сценариях, когда есть вложенные маршруты, важно учитывать базовый путь и правила относительной навигации конкретной версии React Router

### `Link` и `NavLink`

- `NavLink` используется, когда необходимо дополнительно определить, активна ли ссылка для текущего маршрута

```js
import { NavLink } from 'react-router-dom';

function MainNavigation() {
  return (
    <nav>
      <NavLink exact to='/' activeClassName='active'>
        Главная
      </NavLink>

      <NavLink to='/products' activeClassName='active'>
        Товары
      </NavLink>
    </nav>
  );
}
```

- в v5 для этого использовались `activeClassName` и `activeStyle`, а в v6 API изменился: например, `className` может получать функцию с состоянием `isActive`

## 5. `Redirect` — перенаправление на другой маршрут

- `Redirect` в React Router v5 используется для перехода с одного маршрута на другой без необходимости, чтобы пользователь нажимал ссылку
- например, он может применяться для перенаправления старого URL на новый или для перенаправления пользователя после проверки условия

```js
import { Switch, Route, Redirect } from 'react-router-dom';

function AppRoutes() {
  return (
    <Switch>
      <Route exact path='/'>
        <HomePage />
      </Route>

      <Route path='/old-products'>
        <Redirect to='/products' />
      </Route>

      <Route path='/products'>
        <ProductsPage />
      </Route>
    </Switch>
  );
}
```

- когда URL соответствует `/old-products`, приложение выполняет перенаправление на `/products`

### `Redirect` и `Link` — в чём разница

- `Link` инициирует навигацию в ответ на действие пользователя, обычно клик
- `Redirect` выполняет навигацию как часть логики маршрутизации, когда соответствующий элемент рендерится
- например, `Link` подходит для кнопки навигации в меню, а `Redirect` — для правила перенаправления со старого адреса

### `push` и `replace`

- по умолчанию `Redirect` в v5 заменяет текущую запись истории браузера, а не добавляет новую
- свойство `push` позволяет вместо замены добавить запись в историю

```js
<Redirect to='/login' />
```

- обычное перенаправление заменяет текущую запись истории

```js
<Redirect to='/login' push />
```

- с `push` переход добавляет новую запись, поэтому кнопка Back может вернуть пользователя на предыдущий адрес
- выбор зависит от сценария: при нормализации URL часто удобно использовать замену, а при некоторых пользовательских переходах может понадобиться сохранение истории

### защита маршрутов

- один из распространённых сценариев `Redirect` — проверка авторизации

```js
function PrivatePage({ isAuthenticated }) {
  return isAuthenticated ? <DashboardPage /> : <Redirect to='/login' />;
}
```

- идея заключается в том, что при отсутствии авторизации вместо защищённого интерфейса выполняется перенаправление на страницу входа
- однако это только управление интерфейсом на клиенте, а не полноценная защита данных: сервер всё равно обязан самостоятельно проверять права доступа к API и ресурсам
- в современных версиях React Router для аналогичных сценариев часто используют `Navigate` или перенаправления из `loader` и `action`

## 6. `BrowserRouter` — маршрутизация через History API

- `BrowserRouter` — компонент, который предоставляет приложению маршрутизацию на основе стандартной истории браузера
- он связывает текущий URL и историю навигации с React Router, чтобы приложение могло реагировать на переходы пользователя и программные изменения адреса

```js
import { BrowserRouter } from 'react-router-dom';

function Root() {
  return (
    <BrowserRouter>
      <App />
    </BrowserRouter>
  );
}
```

- обычно `BrowserRouter` размещают близко к корню приложения, чтобы все дочерние компоненты могли пользоваться маршрутизацией
- внутри него компоненты и хуки React Router получают доступ к контексту маршрутизатора

### как работает `BrowserRouter`

- допустим, пользователь находится на странице `/products`
- он нажимает на `Link`, ведущий на `/profile`
- React Router выполняет клиентскую навигацию и обновляет запись истории браузера
- состояние маршрутизации обновляется, после чего React отображает интерфейс, соответствующий `/profile`
- когда пользователь нажимает Back или Forward, браузер генерирует событие `popstate`, а маршрутизатор реагирует на изменение текущего адреса

```
Link / Navigate
      ↓
History API
      ↓
обновление состояния маршрутизации
      ↓
сопоставление URL с Route
      ↓
React обновляет интерфейс
```

- важно: браузерная история и состояние React Router связаны, но это не одно и то же — History API хранит записи навигации, а React Router использует состояние маршрутизатора, чтобы обновлять приложение

### почему сервер тоже должен поддерживать `BrowserRouter`

- при клиентском переходе на `/products` приложение может работать корректно, потому что HTML-документ уже загружен и маршрутизацию обрабатывает JavaScript
- но если пользователь напрямую откроет `https://example.com/products`, браузер сначала отправит серверу HTTP-запрос по пути `/products`
- если сервер не настроен на отдачу приложения для этого пути, он может вернуть `404`, даже если маршрут существует в React Router
- поэтому при использовании `BrowserRouter` сервер обычно настраивают так, чтобы неизвестные серверу пути приложения возвращали основной HTML-документ, после чего React Router обрабатывает URL на клиенте
- исключение составляют пути к реальным серверным ресурсам и API, которые должны обрабатываться соответствующими серверными правилами

## 7. `StaticRouter` — маршрутизация без браузерной истории

- `StaticRouter` предназначен прежде всего для серверного рендеринга (SSR), когда React-компоненты нужно отрендерить для определённого URL без использования браузерного History API
- в отличие от `BrowserRouter`, он не управляет историей браузера и не предполагает обычную интерактивную клиентскую навигацию
- в React Router v5 его можно использовать, например, так:

```js
import { StaticRouter } from 'react-router-dom';
import { renderToString } from 'react-dom/server';

function renderApplication(requestUrl) {
  return renderToString(
    <StaticRouter location={requestUrl}>
      <App />
    </StaticRouter>,
  );
}
```

- здесь `requestUrl` — путь, полученный сервером из HTTP-запроса, например `/products/42`
- `StaticRouter` предоставляет контекст маршрутизации, чтобы дочерние `Route` могли сопоставить этот путь и отобразить нужную страницу

### почему он называется `StaticRouter`

- при серверном рендеринге нет браузерной адресной строки, которую можно было бы изменять через History API, поэтому маршрутизатор работает с заданным адресом
- сервер получает запрос, рендерит соответствующее приложение и отправляет HTML клиенту
- после загрузки страницы клиентское приложение может пройти гидратацию и продолжить интерактивную работу с подходящим клиентским маршрутизатором

```
HTTP request: /products/42
           ↓
сервер получает URL
           ↓
StaticRouter(location)
           ↓
React рендерит ProductPage
           ↓
сервер отправляет HTML
           ↓
браузер получает страницу
           ↓
гидратация клиентского React-приложения
```

- `StaticRouter` сам по себе не выполняет HTTP-редиректы и не отправляет HTTP-ответы — серверное приложение должно обработать результат маршрутизации и сформировать соответствующий ответ
- в частности, сервер должен самостоятельно определить HTTP-статус, например `200`, `404` или `302`, если этого требует логика приложения

### что происходит с `Redirect` внутри `StaticRouter`

- в v5 `StaticRouter` предоставляет специальный контекст, через который `Redirect` может сообщить о необходимости перенаправления
- серверная инфраструктура должна прочитать результат и преобразовать его в HTTP-ответ с соответствующим статусом и заголовком `Location`
- это отличается от клиентского `BrowserRouter`, где перенаправление может выполняться через изменение клиентской истории

## 8. другие виды Router и их назначение

- помимо `BrowserRouter` и `StaticRouter`, React Router предоставляет и другие варианты маршрутизаторов, которые выбирают в зависимости от среды выполнения и способа хранения URL

### `BrowserRouter` - Обычные веб-приложения

- использует HTML5 History API и человекочитаемые пути, например `/products/42`

### `HashRouter` - Приложения с маршрутизацией в URL-фрагменте

- хранит маршрут после `#`, например `/#/products/42`, поэтому смена маршрута не требует серверной обработки нового пути

### `MemoryRouter` - Тестирование и среды без браузерной адресной строки

- хранит историю навигации в памяти приложения, не используя URL браузера

### `StaticRouter` - Серверный рендеринг в v5

- использует заданный URL и не управляет интерактивной браузерной историей

- выбор маршрутизатора влияет на то, где хранится состояние навигации и каким образом приложение реагирует на переходы
- при этом сами маршруты и отображаемые компоненты могут во многом оставаться одинаковыми

## 9. как компоненты взаимодействуют друг с другом

- теперь объединим API в одно приложение, чтобы увидеть, как `BrowserRouter`, `Switch`, `Route`, `Link` и `Redirect` работают вместе

```js
import { BrowserRouter, Switch, Route, Link, Redirect } from 'react-router-dom';

function HomePage() {
  return <h1>Главная</h1>;
}

function ProductsPage() {
  return <h1>Каталог товаров</h1>;
}

function ProductPage() {
  return <h1>Карточка товара</h1>;
}

function NotFoundPage() {
  return <h1>Страница не найдена</h1>;
}

function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to='/'>Главная</Link>
        <Link to='/products'>Товары</Link>
      </nav>

      <Switch>
        <Route exact path='/' component={HomePage} />

        <Route exact path='/products' component={ProductsPage} />

        <Route path='/products/:productId' component={ProductPage} />

        <Redirect exact from='/catalog' to='/products' />

        <Route component={NotFoundPage} />
      </Switch>
    </BrowserRouter>
  );
}
```

- здесь `BrowserRouter` предоставляет контекст маршрутизации, `Link` инициирует переходы, `Switch` выбирает первый совпавший маршрут, а `Route` отображает нужный компонент
- `Redirect` перенаправляет `/catalog` на `/products`, а последний `Route` отображает страницу 404, если ни одно предыдущее правило не подошло
- в этом примере есть важный нюанс: `Redirect` должен находиться в `Switch` в корректной позиции, а порядок правил определяет, какое совпадение будет обработано первым

## 10. различия React Router v5 и v6+

- на собеседовании недостаточно знать названия API: важно понимать, что часть привычных компонентов из v5 была заменена в v6

| React Router v5        | React Router v6+       |
| ---------------------- | ---------------------- |
| `Switch`               | `Routes`               |
| `Redirect`             | `Navigate`             |
| `component` / `render` | `element`              |
| `exact`                | обычно не требуется    |
| `activeClassName`      | `className` с функцией |
| `useHistory`           | `useNavigate`          |

- в v6 сопоставление маршрутов изменилось: `Routes` выбирает наиболее подходящий маршрут по алгоритму ранжирования, а не просто первый совпавший элемент, как `Switch` в v5
- это означает, что порядок объявления маршрутов обычно не определяет выбор между статическим и динамическим путями так, как это могло происходить с `Switch`

### пример API v6+

```js
import { BrowserRouter, Routes, Route, Link, Navigate } from 'react-router-dom';

function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to='/'>Главная</Link>
        <Link to='/products'>Товары</Link>
      </nav>

      <Routes>
        <Route path='/' element={<HomePage />} />

        <Route path='/products' element={<ProductsPage />} />

        <Route path='/products/:productId' element={<ProductPage />} />

        <Route path='/catalog' element={<Navigate to='/products' replace />} />

        <Route path='*' element={<NotFoundPage />} />
      </Routes>
    </BrowserRouter>
  );
}
```

- в v6 `element` принимает уже созданный React-элемент, а не ссылку на компонент, как `component` в v5
- `Navigate` заменяет `Redirect`, а `replace` указывает, что текущую запись истории нужно заменить
- путь `*` используется как маршрут по умолчанию, аналогичный последнему маршруту без `path` внутри `Switch` в v5
- в v6 обычное сопоставление учитывает вложенные маршруты, а `Routes` выбирает наиболее подходящую ветку маршрутизации
- современные версии также предлагают Data Router API, включая `createBrowserRouter`, `RouterProvider`, `loader`, `action` и другие возможности, которые расширяют маршрутизацию загрузкой данных и обработкой форм

## 11. типичные ошибки и нюансы для собеседования

- путать `Route` и `Switch` — `Route` описывает отдельное правило сопоставления, а `Switch` в v5 выбирает первый подходящий дочерний маршрут
- считать `exact` аналогом `Switch` — `exact` ограничивает совпадение одного маршрута, но не запрещает совпадать другим маршрутам
- использовать обычный `<a>` вместо `Link` для каждого внутреннего перехода — это может вызвать полную перезагрузку документа и потерю состояния клиентского приложения
- забывать серверную настройку для `BrowserRouter` — при прямом открытии вложенного URL сервер должен корректно отдавать приложение
- считать `Redirect` механизмом защиты API — перенаправление скрывает интерфейс, но не заменяет серверную авторизацию
- путать `StaticRouter` с `BrowserRouter` — первый предназначен для статической серверной маршрутизации в v5, второй использует браузерную историю
- переносить API v5 в v6 без изменений — `Switch`, `Redirect`, `component`, `render` и `exact` нельзя механически использовать в том же виде в v6

## 12. что важно уметь объяснить на собеседовании

- `Route` определяет соответствие между URL и компонентом
- `Switch` в v5 выбирает первый совпавший маршрут
- `Link` обеспечивает клиентскую навигацию без обычной полной перезагрузки документа
- `Redirect` в v5 перенаправляет пользователя на другой маршрут
- `BrowserRouter` работает с браузерной историей и History API
- `StaticRouter` в v5 используется для серверного рендеринга при заданном URL
- `HashRouter` хранит маршрут после символа `#`, а `MemoryRouter` — в памяти
- маршрутизатор предоставляет контекст, благодаря которому компоненты и хуки могут получать информацию о текущем маршруте
- сервер должен корректно обрабатывать прямые запросы к URL SPA
- API React Router v5 и v6+ отличается, поэтому при обсуждении конкретного проекта нужно учитывать версию библиотеки
- главная идея: React Router связывает URL, историю навигации и React-компоненты в единый механизм, а конкретные API определяют, как маршруты сопоставляются, как выполняются переходы и как маршрутизация адаптируется к браузеру или серверу
