# connected React Router

- `Connected React Router` — это интеграция React Router с Redux, которая позволяет синхронизировать состояние маршрутизации с глобальным состоянием приложения и управлять навигацией через Redux actions
- для подготовки к собеседованию важно разобраться, зачем такая интеграция нужна, как она работала в классических версиях библиотек, почему сегодня чаще используют обычный React Router вместе с Redux и как реализовать подобный механизм самостоятельно

## 1. базовые понятия

### что такое React Router

- React Router отвечает за сопоставление URL с React-компонентами и за навигацию между страницами без полной перезагрузки документа

```js
import { BrowserRouter, Routes, Route } from 'react-router-dom';

function App() {
  return (
    <BrowserRouter>
      <Routes>
        <Route path='/' element={<HomePage />} />
        <Route path='/profile' element={<ProfilePage />} />
      </Routes>
    </BrowserRouter>
  );
}
```

- когда пользователь открывает `/profile`, React Router сопоставляет URL с маршрутом и отображает `ProfilePage`

### что такое Redux

- Redux хранит состояние приложения в одном централизованном store, а изменения состояния выполняются через actions и reducers

```js
const initialState = {
  user: null,
  theme: 'dark',
};

function appReducer(state = initialState, action) {
  switch (action.type) {
    case 'SET_USER':
      return { ...state, user: action.payload };

    default:
      return state;
  }
}
```

- это позволяет разным частям приложения получать согласованное состояние без необходимости передавать его через множество уровней компонентов

### где возникает проблема интеграции

- у React Router есть собственное состояние маршрутизации: текущий URL, параметры маршрута, query-параметры и другая информация, необходимая для навигации
- у Redux есть отдельный store, в котором хранится состояние приложения
- если Redux используется для бизнес-логики, может возникнуть желание хранить в нём и состояние маршрутизации, чтобы реагировать на изменения URL через единый механизм управления состоянием

Упрощённая схема:

```
React Router
     |
     v
Current URL ---> React components

Redux Store
     |
     v
Application state
```

- без дополнительной интеграции эти механизмы работают совместно, но не представляют собой единую систему состояния

## 2. зачем нужен Connected React Router

- библиотека `connected-react-router` была создана для синхронизации состояния маршрутизации с Redux store

### Основные возможности:

- хранение location в Redux — текущее местоположение становится доступно через глобальный store
- навигация через actions — можно отправить Redux action для перехода на другой URL
- реакция middleware на навигацию — middleware может обрабатывать переходы, например выполнять дополнительные действия при изменении маршрута
- интеграция с Redux DevTools — изменения состояния маршрутизации можно наблюдать вместе с другими Redux actions
- согласованность с Redux-архитектурой — состояние маршрута можно использовать в селекторах и других частях приложения
- важно понимать, что это не обязательная часть React Router, а дополнительный способ интеграции с Redux

### когда это может быть полезно

- в приложениях, где архитектура построена вокруг Redux и Redux middleware
- когда переходы между страницами должны инициироваться из Redux-логики, например после выполнения определённого действия
- когда требуется централизованно отслеживать изменения маршрутов
- в legacy-проектах, где маршрутизация уже тесно связана с Redux
- для большинства современных React-приложений достаточно стандартного React Router, а Redux используется для бизнес-состояния отдельно

## 3. как работает connected-react-router

- исторически библиотека интегрировалась с React Router через объект `history`, который предоставляет интерфейс для управления историей браузера и получения текущего местоположения

Основной поток работы:

```
Пользователь нажимает Link
          ↓
React Router вызывает navigation
          ↓
Обновляется history
          ↓
connected-react-router синхронизирует location
          ↓
Redux Store получает новое состояние
          ↓
Подписанные компоненты обновляются
```

- обратный сценарий тоже возможен: Redux action инициирует навигацию, middleware вызывает метод `history`, а изменение маршрута синхронизируется с Redux
- здесь есть важный нюанс: Redux не заменяет браузерную историю — он хранит синхронизированное представление состояния маршрутизации, а переходы всё равно должны корректно взаимодействовать с `history`

## 4. базовое использование connected-react-router

- классический API `connected-react-router` относится к экосистеме React Router v4/v5 и Redux, поэтому этот пример не следует смешивать с API React Router v6/v7
- обычно настройка включала несколько частей: создание `history`, reducer маршрутизации, middleware, специальный компонент `ConnectedRouter` и action для навигации

### шаг 1. создаём history

```js
import { createBrowserHistory } from 'history';

export const appHistory = createBrowserHistory();
```

- объект `appHistory` предоставляет методы вроде `push`, `replace`, `goBack`, а также позволяет подписываться на изменения location

### шаг 2. подключаем reducer и middleware

```js
import { combineReducers, createStore, applyMiddleware } from 'redux';
import { routerMiddleware, connectRouter } from 'connected-react-router';
import { appHistory } from './history';

const rootReducer = combineReducers({
  router: connectRouter(appHistory),
  // другие reducers
});

const store = createStore(rootReducer, applyMiddleware(routerMiddleware(appHistory)));
```

- `connectRouter(appHistory)` создаёт reducer, который хранит состояние маршрутизации в Redux
- `routerMiddleware(appHistory)` обрабатывает специальные navigation actions и передаёт команды объекту `history`
- в полноценном приложении сюда также добавляют остальные reducers, middleware и, при необходимости, настройки Redux DevTools

### шаг 3. подключаем ConnectedRouter

```js
import { Provider } from 'react-redux';
import { ConnectedRouter } from 'connected-react-router';
import { appHistory } from './history';

function Root() {
  return (
    <Provider store={store}>
      <ConnectedRouter history={appHistory}>
        <App />
      </ConnectedRouter>
    </Provider>
  );
}
```

- `Provider` делает Redux store доступным компонентам
- `ConnectedRouter` связывает React Router с Redux и использует тот же объект `history`, что и reducer с middleware

### шаг 4. выполняем навигацию через Redux action

```js
import { push } from 'connected-react-router';

store.dispatch(push('/profile'));
```

- action `push('/profile')` обрабатывается middleware, который инициирует переход через `history`
- изменение location затем синхронизируется с Redux store
- это основной принцип интеграции: команда навигации отправляется через Redux, а фактический переход выполняется посредством history

## 5. как реализовать подобный механизм с нуля

- на собеседовании под реализацией с нуля обычно понимают не переписывание всего React Router, а демонстрацию механизма синхронизации между браузерной историей, Redux и React
- для этого нужно понимать три независимые части:
  - отслеживание изменений URL
  - сохранение текущего location в Redux
  - обработка команд навигации

### часть 1. reducer для маршрутизации

- начнём с простого состояния, которое хранит текущий pathname

```js
const initialRouterState = {
  location: {
    pathname: window.location.pathname,
  },
};

function routerReducer(state = initialRouterState, action) {
  switch (action.type) {
    case 'LOCATION_CHANGED':
      return {
        ...state,
        location: action.payload,
      };

    default:
      return state;
  }
}
```

- reducer не должен самостоятельно менять URL — его задача только вычислять новое состояние по action

### часть 2. action для обновления location

```js
function locationChanged(location) {
  return {
    type: 'LOCATION_CHANGED',
    payload: location,
  };
}
```

- этот action сообщает Redux, что текущее местоположение изменилось

### часть 3. синхронизация с браузерной историей

```js
function createRouterSync(store) {
  function syncLocation() {
    store.dispatch(
      locationChanged({
        pathname: window.location.pathname,
        search: window.location.search,
        hash: window.location.hash,
      }),
    );
  }

  window.addEventListener('popstate', syncLocation);

  syncLocation();

  return function cleanupRouterSync() {
    window.removeEventListener('popstate', syncLocation);
  };
}
```

- `popstate` возникает, когда пользователь перемещается по истории браузера, например нажимает Back или Forward
- обработчик считывает актуальный URL и отправляет его в Redux
- первоначальный вызов `syncLocation()` синхронизирует store при запуске приложения
- однако здесь есть ограничение: `popstate` не вызывается при обычном `history.pushState()` или `history.replaceState()`, поэтому одного этого обработчика недостаточно

### часть 4. собственная навигация

```js
function navigateTo(store, pathname) {
  window.history.pushState({}, '', pathname);

  store.dispatch(
    locationChanged({
      pathname: window.location.pathname,
      search: window.location.search,
      hash: window.location.hash,
    }),
  );
}
```

- `pushState()` меняет URL без перезагрузки документа
- браузер не отправляет `popstate` после `pushState()`, поэтому мы явно отправляем action в Redux
- так состояние store синхронизируется с новым URL
- для замены текущей записи вместо добавления новой можно использовать `replaceState()`

### что ещё потребуется для полноценной реализации

- поддержка `replace`, Back и Forward, query-параметров и hash
- корректная обработка подписок и очистка слушателей
- интеграция с React, чтобы компоненты обновлялись при изменении состояния
- сопоставление URL с маршрутами и параметрами
- обработка переходов из Redux middleware
- защита от рассинхронизации URL и store, в том числе при внешних изменениях location
- приведённый код показывает базовый механизм синхронизации, но не является полной заменой `connected-react-router` или React Router

## 6. почему сегодня обычно обходятся без connected-react-router

- библиотека была рассчитана на архитектуру React Router v4/v5 и исторические способы интеграции с Redux
- в современных версиях React Router есть собственные механизмы навигации и получения location, поэтому отдельная синхронизация маршрутизатора с Redux обычно не нужна
- например, если нужно перейти на другую страницу после успешного сохранения данных, можно использовать `useNavigate()` внутри React-компонента

```js
import { useNavigate } from 'react-router-dom';

function SaveButton() {
  const navigate = useNavigate();

  async function handleSave() {
    await saveData();
    navigate('/success');
  }

  return <button onClick={handleSave}>save</button>;
}
```

- если переход нужно инициировать из асинхронной Redux-логики, например thunk, архитектуру лучше спроектировать так, чтобы навигация оставалась отдельным эффектом, а бизнес-состояние хранилось в Redux
- например, компонент может наблюдать за результатом операции и выполнять переход после её успешного завершения

```js
import { useEffect } from 'react';
import { useNavigate } from 'react-router-dom';
import { useSelector } from 'react-redux';

function SavePage() {
  const navigate = useNavigate();
  const saveStatus = useSelector((state) => state.save.status);

  useEffect(() => {
    if (saveStatus === 'succeeded') {
      navigate('/success');
    }
  }, [saveStatus, navigate]);

  return <div>saving...</div>;
}
```

- такой подход сохраняет ответственность Redux за бизнес-состояние, а React Router — за маршрутизацию
- у него есть свои нюансы: нужно учитывать повторные эффекты, сброс статуса операции и возможность повторного перехода при изменениях состояния, поэтому в реальном приложении важно правильно организовать жизненный цикл операции

## 7. что важно сказать на собеседовании

- `connected-react-router` — это библиотека для синхронизации React Router с Redux store
- она позволяет хранить состояние маршрутизации в Redux, отслеживать изменения location и инициировать навигацию через Redux actions
- основными элементами классической интеграции были `connectRouter`, `routerMiddleware`, `ConnectedRouter` и общий объект `history`
- при реализации с нуля нужно синхронизировать браузерную историю с Redux, учитывать, что `pushState()` не вызывает `popstate`, и организовать обновление React-компонентов
- библиотека не заменяет React Router и не является обязательной частью Redux-архитектуры
- в современных приложениях чаще используют стандартный React Router отдельно от Redux, поскольку это уменьшает связанность и позволяет каждой библиотеке отвечать за свою область
