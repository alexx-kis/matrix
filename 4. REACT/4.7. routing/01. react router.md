# React Router: основы маршрутизации в React

- разберём три пункта из твоего плана: практическое использование React Router, понимание его внутреннего устройства и возможность написать собственную базовую реализацию

## 1. что такое маршрутизация и зачем она нужна

- React по умолчанию отвечает за построение пользовательского интерфейса, но сам по себе не определяет, какой компонент нужно показывать в зависимости от URL браузера
- например, у приложения могут быть следующие страницы

```
/                  → главная страница
/about             → страница о компании
/products          → список товаров
/products/42       → страница конкретного товара
```

- маршрутизация (routing) — это механизм, который сопоставляет текущий URL с определённой частью интерфейса приложения
- библиотека React Router предоставляет этот механизм для React-приложений

### как это работает концептуально

```
       [URL браузера]
       /products/42
            ↓
  [система маршрутизации]
сопоставление URL с маршрутом
            ↓
  [подходящий React-компонент]
       ProductPage
```

- ключевая идея: URL определяет, какой экран должен отображаться, а React Router связывает адрес браузера с соответствующим компонентом

## 2. как работать с React Router

- для современных React-приложений используется пакет `react-router` и соответствующий способ интеграции с браузером; во многих существующих проектах также встречается `react-router-dom`, особенно в приложениях, созданных на предыдущих версиях библиотеки
- ниже используем распространённый декларативный подход с `BrowserRouter`, `Routes` и `Route`

### установка

```bash
npm install react-router
```

- если проект использует версию React Router, в которой браузерные API импортируются из `react-router-dom`, импорты необходимо адаптировать под установленную версию

### объявление маршрутов

```js
import { BrowserRouter, Routes, Route, Link } from 'react-router';

function HomePage() {
  return <h1>Главная</h1>;
}

function AboutPage() {
  return <h1>О компании</h1>;
}

function ProductsPage() {
  return <h1>Список товаров</h1>;
}

function ProductPage() {
  return <h1>Карточка товара</h1>;
}

function NotFoundPage() {
  return <h1>Страница не найдена</h1>;
}

function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to='/'>Главная</Link>
        <Link to='/about'>О компании</Link>
        <Link to='/products'>Товары</Link>
        <Link to='/products/42'>Товар № 42</Link>
      </nav>

      <Routes>
        <Route path='/' element={<HomePage />} />
        <Route path='/about' element={<AboutPage />} />
        <Route path='/products' element={<ProductsPage />} />
        <Route path='/products/:productId' element={<ProductPage />} />
        <Route path='*' element={<NotFoundPage />} />
      </Routes>
    </BrowserRouter>
  );
}
```

- здесь используются основные элементы декларативной маршрутизации, которые важно понимать до изучения хуков и остальных API

#### `BrowserRouter`

- связывает React Router с историей браузера и предоставляет контекст маршрутизации компонентам внутри себя
- благодаря этому библиотека может отслеживать изменения адреса и обновлять интерфейс без полной перезагрузки страницы при обычной внутренней навигации

#### `Routes`

- выбирает наиболее подходящий маршрут из объявленных внутри него маршрутов
- это не просто последовательный вывод всех компонентов: при обычной маршрутизации выбираются подходящие ветви маршрутов

#### `Route`

- описывает связь между шаблоном URL и элементом интерфейса
- `path="/products"` соответствует адресу `/products`
- `path="/products/:productId"` содержит динамический сегмент, который позволяет сопоставлять адреса вроде `/products/42` и `/products/abc`
- `element={<ProductPage />}` задаёт React-элемент, который должен отображаться для подходящего маршрута

#### `Link`

- создаёт ссылку для навигации внутри приложения
- при обычном клике React Router перехватывает навигацию, изменяет URL через браузерную History API и обновляет соответствующую часть интерфейса без полной перезагрузки документа

#### `path="*"`

- используется как маршрут по умолчанию для адресов, которым не соответствует более конкретный маршрут
- часто применяется для страницы 404

### что происходит при переходе между страницами

- допустим, пользователь находится на `/about` и нажимает ссылку на `/products`

#### 1 пользователь нажимает `Link`

- ссылка ведёт на `/products`

#### 2 обновляется история браузера

- URL меняется через History API, обычно без полной перезагрузки документа

#### 3 React Router определяет подходящий маршрут

- сопоставляет новый URL с описаниями `Route`

#### 4 React обновляет интерфейс

- вместо страницы о компании отображается список товаров

- важно: речь идёт о стандартной клиентской навигации, когда переход обрабатывает React Router; обычная внешняя ссылка или перезагрузка страницы работают иначе

## 3. как React Router работает внутри

- для собеседования недостаточно сказать, что библиотека просто «переключает компоненты»: нужно понимать, как URL, история браузера и React связаны между собой

### 3.1. источник текущего маршрута — URL и история браузера

- в браузере есть объект `window.location`, из которого можно получить текущий путь, например `/products/42`
- объект `window.history` предоставляет History API, позволяющий изменять историю навигации и переходить между её записями

```js
// текущий адрес
console.log(window.location.pathname);

// добавить запись в историю без перезагрузки документа
window.history.pushState({}, '', '/products');

// заменить текущую запись
window.history.replaceState({}, '', '/about');
```

- `pushState` добавляет новую запись в историю, а `replaceState` заменяет текущую
- принципиальный нюанс: сами по себе эти методы не вызывают обычное событие `popstate` и не заставляют React перерисоваться
- поэтому роутеру необходимо самостоятельно отслеживать собственные переходы и синхронизировать React с изменившимся адресом
- при нажатии кнопок «назад» и «вперёд» браузер генерирует `popstate`, и маршрутизатор должен учитывать эти переходы тоже

### 3.2. сопоставление маршрута (route matching)

- после получения текущего URL библиотека сравнивает путь с объявленными шаблонами маршрутов

```
URL: /products/42

Шаблоны:
/
 /about
 /products
 /products/:productId
 *

Результат:
 /products/:productId
```

- динамический сегмент `:productId` позволяет одному маршруту обрабатывать множество адресов
- маршрут `/products/:productId` подходит как для `/products/42`, так и для `/products/100`
- параметры динамических сегментов извлекаются из URL и могут быть предоставлены компоненту маршрута через API библиотеки; сами эти API мы разберём позже
- сопоставление не сводится к простому сравнению строк: библиотека учитывает структуру пути, динамические сегменты, вложенность маршрутов и приоритет совпадений

### 3.3. связь с React

- React Router хранит и предоставляет состояние текущей навигации через свой механизм контекста и подписок
- когда маршрут изменяется, соответствующие потребители получают обновлённое состояние, React выполняет необходимый рендеринг, а интерфейс отражает новый URL
- это не означает, что всё приложение обязательно перемонтируется при каждом переходе: компоненты, которые сохраняются в общей части дерева маршрутов, могут оставаться смонтированными
- например, если у нескольких страниц общий `Header`, он может сохраняться при смене содержимого страницы — конкретное поведение зависит от структуры маршрутов и компонентов

### 3.4. почему нельзя просто менять URL вручную

- такой код меняет адрес в адресной строке, но сам по себе не синхронизирует его с React

```js
window.history.pushState({}, '', '/products');
```

- если изменить URL таким способом, не уведомив используемый механизм маршрутизации, приложение может продолжить отображать прежний экран
- в реальном приложении переходы следует выполнять средствами маршрутизатора, которые поддерживают его внутреннее состояние
- аналогичная проблема возникает при использовании обычного `<a href="/products">`: браузер, как правило, выполняет полноценную навигацию и загружает документ заново, если переход не перехвачен клиентским кодом
- это не всегда плохо: обычные ссылки необходимы для внешних адресов, а полная загрузка может быть уместна в зависимости от задачи

## 4. вложенные маршруты и общий интерфейс

- одна из важных возможностей React Router — описание иерархии маршрутов
- это позволяет отделить общий интерфейс раздела от содержимого конкретной страницы

```js
<BrowserRouter>
  <Routes>
    <Route path='/dashboard' element={<DashboardLayout />}>
      <Route path='profile' element={<ProfilePage />} />
      <Route path='settings' element={<SettingsPage />} />
    </Route>
  </Routes>
</BrowserRouter>
```

- здесь `/dashboard` — родительский маршрут, а `profile` и `settings` — дочерние
- итоговые пути дочерних маршрутов будут `/dashboard/profile` и `/dashboard/settings`
- чтобы дочерняя страница отображалась внутри родительского layout, родительский компонент должен предусматривать место для неё через `Outlet`

```js
import { Outlet } from 'react-router';

function DashboardLayout() {
  return (
    <div>
      <header>Панель управления</header>
      <aside>Навигация</aside>

      <main>
        <Outlet />
      </main>
    </div>
  );
}
```

- `Outlet` — это точка, в которой отображается соответствующий дочерний маршрут
- в результате при переходе между настройками и профилем общий layout сохраняется, а содержимое его основного блока меняется
- подробное изучение `Outlet` и других API оставим на дальнейшие темы, но сам принцип вложенности маршрутов нужно понимать уже сейчас

## 5. как написать собственную базовую реализацию

- на собеседовании могут попросить объяснить, как реализовать маршрутизацию без сторонней библиотеки
- полноценный аналог React Router написать сложно: необходимо учитывать вложенность, параметры, историю браузера, переходы назад и вперёд, обработку ошибок и множество пограничных случаев
- однако базовую реализацию можно сделать самостоятельно, чтобы понять фундаментальный механизм

### минимальный маршрутизатор на React

```js
import { useState, useEffect } from 'react';

const routeTable = {
  '/': () => <h1>Главная</h1>,
  '/about': () => <h1>О компании</h1>,
  '/products': () => <h1>Товары</h1>,
};

function MiniRouter() {
  const [currentPath, setCurrentPath] = useState(window.location.pathname);

  useEffect(() => {
    const handlePopState = () => {
      setCurrentPath(window.location.pathname);
    };

    window.addEventListener('popstate', handlePopState);

    return () => {
      window.removeEventListener('popstate', handlePopState);
    };
  }, []);

  function navigateTo(path) {
    window.history.pushState({}, '', path);
    setCurrentPath(path);
  }

  const matchedRoute = routeTable[currentPath];
  const PageComponent = matchedRoute ?? (() => <h1>404</h1>);

  return (
    <div>
      <nav>
        <button onClick={() => navigateTo('/')}>Главная</button>
        <button onClick={() => navigateTo('/about')}>О компании</button>
        <button onClick={() => navigateTo('/products')}>Товары</button>
      </nav>

      <PageComponent />
    </div>
  );
}
```

- это учебный пример, а не готовая замена React Router

### разбор ключевых частей

- `currentPath` хранит путь, соответствующий текущему экрану
- при первой загрузке начальное состояние берётся из `window.location.pathname`
- `handlePopState` синхронизирует состояние React при переходах назад и вперёд
- `navigateTo` добавляет запись в историю браузера и обновляет React-состояние
- `routeTable` хранит соответствия между конкретными путями и компонентами страниц
- если соответствия нет, отображается простая страница 404

### ограничения реализации

- здесь поддерживаются только точные совпадения путей, поэтому `/products/42` не сопоставится с `/products`
- не реализованы динамические параметры, вложенные маршруты, query-параметры, hash-навигация, редиректы и другие возможности
- нет обработки переходов, которые инициируются другими частями приложения через собственные вызовы History API
- для production-приложения пришлось бы также учитывать корректную работу ссылок, доступность, особенности SSR и конфигурацию сервера
- несмотря на ограничения, пример демонстрирует главное: базовый роутер связывает URL, состояние React и выбор отображаемого компонента

## 6. частые вопросы на собеседовании

чем маршрутизация отличается от рендеринга компонентов?

- React отвечает за отображение компонентов, а роутер определяет, какой компонент или ветвь дерева нужно отобразить для текущего маршрута

почему React Router позволяет переключать страницы без перезагрузки?

- потому что клиентская навигация использует History API для изменения URL и синхронизирует состояние маршрутизации с React, не выполняя полную загрузку документа

зачем нужен `BrowserRouter`?

- он связывает маршрутизацию с историей браузера и предоставляет необходимый контекст для компонентов маршрутов и навигации

как работает динамический маршрут?

- шаблон вроде `/products/:productId` сопоставляется с разными URL, а значение динамического сегмента извлекается из пути

почему недостаточно вызвать `history.pushState()`?

- этот метод меняет URL и запись истории, но не уведомляет React Router о переходе автоматически и сам по себе не вызывает перерисовку React

зачем нужны вложенные маршруты?

- они позволяют описывать общую структуру интерфейса, в которой layout родительского маршрута сохраняется, а дочернее содержимое изменяется

что произойдёт, если пользователь напрямую откроет `/products/42`?

- браузер сначала обращается к серверу за этим адресом, поэтому сервер должен быть настроен так, чтобы возвращать приложение для клиентских маршрутов; иначе можно получить серверный 404 ещё до запуска React
