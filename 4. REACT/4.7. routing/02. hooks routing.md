# React Router: hooks для маршрутизации

- в этом блоке разберём, какие хуки предоставляет React Router, для чего они нужны, как применять их на практике и как писать собственные хуки поверх API маршрутизации
- будем опираться на предыдущую тему: `BrowserRouter` связывает роутер с историей браузера, а `Route` определяет, какой компонент отображается для текущего URL
- теперь рассмотрим, как компонент может получать информацию о маршруте и управлять навигацией изнутри, не передавая все необходимые данные через props

## 1. зачем нужны routing hooks

- допустим, мы находимся на странице `/products/42` и хотим получить идентификатор товара, узнать текущий URL или программно перейти на другую страницу
- без хуков пришлось бы самостоятельно разбирать URL, следить за историей браузера и передавать данные между компонентами
- routing hooks предоставляют компонентам доступ к состоянию маршрутизации и операциям навигации

```
URL браузера
    ↓
React Router
    ↓
Routing hooks
    ↓
Компонент использует данные маршрута
или выполняет навигацию
```

- хуки нужно вызывать внутри функциональных компонентов React или внутри других хуков, а не в обычных функциях вне React
- также компонент должен находиться внутри подходящего контекста маршрутизатора, иначе большинство routing hooks не смогут получить необходимые данные

## 2. основные хуки React Router

- ниже перечислены наиболее важные хуки для декларативной маршрутизации; конкретный набор API и пути импорта зависят от версии React Router и используемого режима

### основные хуки и их назначение

- `useParams` — получает параметры динамических сегментов URL, например `productId` из `/products/42`
- `useNavigate` — выполняет программную навигацию, например после сохранения формы или нажатия кнопки
- `useLocation` — предоставляет информацию о текущем адресе: `pathname`, `search`, `hash`, `state` и другие поля
- `useSearchParams` — читает и изменяет query-параметры URL, например `?category=books&page=2`
- `useMatch` — проверяет, соответствует ли текущий URL заданному шаблону
- `useNavigationType` — определяет тип навигации: `POP`, `PUSH` или `REPLACE`
- `useHref` — вычисляет URL для указанного адреса с учётом правил маршрутизации
- `useResolvedPath` — разрешает относительный путь относительно текущего маршрута
- `useRoutes` — позволяет описывать маршруты объектами вместо JSX-разметки

- это основные хуки, с которыми полезно познакомиться на уровне назначения

## 3. `useParams` — получение параметров маршрута

- рассмотрим страницу товара с адресом `/products/42`, где `42` — идентификатор товара

```js
import { useParams } from 'react-router';

function ProductDetailsPage() {
  const { productId: currentProductId } = useParams();

  return <h1>Товар: {currentProductId}</h1>;
}
```

- маршрут для такого компонента объявляется следующим образом

```js
<Route path='/products/:productId' element={<ProductDetailsPage />} />
```

- когда URL равен `/products/42`, хук возвращает объект с параметром `productId`, значение которого будет строкой `"42"`

- важный нюанс: параметры URL имеют строковый тип, даже если выглядят как числа

```js
const rawProductId = '42';
const numericProductId = Number(rawProductId);
```

- если параметр нужен для числовых вычислений или идентификации сущности в API, нужно отдельно преобразовать его и проверить корректность значения
- также параметр может отсутствовать в зависимости от конфигурации маршрутов, поэтому нельзя бездумно считать, что он всегда существует
- типичный сценарий использования `useParams` — получение ID сущности, чтобы загрузить соответствующие данные, например товар, пользователя или заказ

## 4. `useNavigate` — программная навигация

- ссылки подходят для обычных переходов, но иногда перейти на другую страницу нужно в ответ на действие приложения
- например, после успешного сохранения формы можно открыть страницу созданного объекта

```js
import { useNavigate } from 'react-router';

function CreateProductPage() {
  const navigateAfterCreate = useNavigate();

  function handleProductCreated() {
    navigateAfterCreate('/products');
  }

  return <button onClick={handleProductCreated}>Сохранить товар</button>;
}
```

- `useNavigate` возвращает функцию, которая выполняет навигацию; её можно вызвать из обработчика события или эффекта

### основные варианты навигации

```js
navigateAfterCreate('/products');
```

- перейти на указанный адрес

```js
navigateAfterCreate('/login', { replace: true });
```

- заменить текущую запись в истории вместо добавления новой, например после редиректа

```js
navigateAfterCreate(-1);
```

- перейти на предыдущую запись истории браузера, если она существует

```js
navigateAfterCreate('/products', {
  state: { created: true },
});
```

- передать дополнительное состояние следующему маршруту, которое затем можно прочитать через `useLocation`

- не следует автоматически заменять обычные ссылки вызовами `navigate`: если пользователь должен перейти куда-то по ссылке, предпочтительнее использовать `Link`, а программную навигацию оставлять для сценариев, где она действительно необходима
- ещё один важный нюанс: `navigate(-1)` не гарантирует переход именно на нужную страницу, поскольку история может содержать внешний сайт или вообще не иметь предыдущей записи

## 5. `useLocation` — информация о текущем URL

- этот хук полезен, когда компоненту важно реагировать на изменение текущего адреса или читать состояние, переданное при навигации
- например, URL `https://example.com/products?category=books#results` содержит три значимые части

```
pathname: /products
search:   ?category=books
hash:     #results
```

```js
import { useLocation } from 'react-router';

function CurrentRouteInfo() {
  const currentLocation = useLocation();

  return (
    <section>
      <p>Путь: {currentLocation.pathname}</p>
      <p>Query: {currentLocation.search}</p>
      <p>Hash: {currentLocation.hash}</p>
    </section>
  );
}
```

- `pathname` — путь, по которому определяется маршрут
- `search` — строка query-параметров, включая начальный `?`
- `hash` — фрагмент URL, включая начальный `#`
- `state` — дополнительное состояние, переданное через `Link` или `navigate`
- `key` — идентификатор конкретной записи location, используемый библиотекой
- например, можно передать информацию о странице, с которой пользователь пришёл

```js
navigateAfterCreate('/products/42', {
  state: { fromCatalog: true },
});
```

- а на целевой странице прочитать её через `currentLocation.state`
- при этом `state` не является заменой постоянному хранилищу: он предназначен для вспомогательной информации о навигации и не должен быть единственным источником критически важных данных

## 6. `useSearchParams` — работа с query-параметрами

- query-параметры — это часть URL после символа `?`, которая часто используется для фильтров, сортировки, поиска и пагинации
- например, адрес `/products?category=books&page=2` содержит два параметра: `category` и `page`

```js
import { useSearchParams } from 'react-router';

function ProductFilters() {
  const [productSearchParams, setProductSearchParams] = useSearchParams();

  const selectedCategory = productSearchParams.get('category');
  const selectedPage = productSearchParams.get('page') ?? '1';

  function showBooks() {
    setProductSearchParams({
      category: 'books',
      page: '1',
    });
  }

  return (
    <section>
      <p>Категория: {selectedCategory ?? 'все'}</p>
      <p>Страница: {selectedPage}</p>

      <button onClick={showBooks}>Показать книги</button>
    </section>
  );
}
```

- `useSearchParams` возвращает пару значений: объект `URLSearchParams` и функцию его обновления

- чтение выполняется через методы вроде `.get()`, а изменение через `setSearchParams` инициирует навигацию к обновлённому URL

- это позволяет хранить состояние фильтров в URL, а не только в локальном состоянии компонента

- в результате пользователь может скопировать ссылку, обновить страницу или воспользоваться кнопкой «назад», сохраняя смысл текущего состояния фильтров

- важная тонкость: объект `URLSearchParams` изменяемый, поэтому не стоит мутировать его напрямую, рассчитывая, что React Router сам обнаружит изменение; изменения нужно применять через `setSearchParams`

## 7. `useMatch` — проверка совпадения с маршрутом

- иногда компоненту нужно знать, находится ли пользователь в определённом разделе, не обязательно используя отдельный `Route` для этого условия

```js
import { useMatch } from 'react-router';

function ProductNavigation() {
  const productRouteMatch = useMatch('/products/:productId');

  return <nav>{productRouteMatch ? 'Открыта карточка товара' : 'Открыт другой раздел'}</nav>;
}
```

- если текущий URL соответствует шаблону, `useMatch` возвращает объект совпадения, а если не соответствует — `null`
- хук полезен для условного поведения навигации и компонентов, которые должны понимать текущий раздел
- для стандартного выделения активной ссылки обычно лучше использовать `NavLink`, а не вручную реализовывать эту логику через `useMatch`

## 8. как выбрать подходящий хук

- полезно ориентироваться не на названия хуков, а на задачу, которую нужно решить:
  - нужно получить ID из `/users/15` - `useParams`
  - нужно перейти на другой экран после действия - `useNavigate`
  - нужно узнать текущий путь или прочитать `location.state` - `useLocation`
  - нужно хранить фильтры и страницу списка в URL - `useSearchParams`
  - нужно проверить соответствие текущего адреса шаблону - `useMatch`

## 9. собственные хуки для маршрутизации

- собственный routing hook — это обычный пользовательский React-хук, который объединяет существующие хуки React Router и добавляет удобную прикладную логику
- его смысл не в том, чтобы переписать библиотеку, а в том, чтобы скрыть повторяющиеся детали и предоставить компонентам понятный интерфейс

### пример 1. хук для страницы товара

- представим, что на странице товара часто нужно получать ID текущего товара и переходить к списку товаров
- без собственного хука разные компоненты могли бы повторять одни и те же вызовы `useParams` и `useNavigate`

```js
import { useParams, useNavigate } from 'react-router';

function useProductPageNavigation() {
  const { productId: routeProductId } = useParams();
  const navigateFromProduct = useNavigate();

  function openProductCatalog() {
    navigateFromProduct('/products');
  }

  function openAnotherProduct(nextProductId) {
    navigateFromProduct(`/products/${nextProductId}`);
  }

  return {
    productId: routeProductId,
    openProductCatalog,
    openAnotherProduct,
  };
}
```

- теперь компонент использует готовую абстракцию

```js
function ProductPageActions() {
  const { productId: displayedProductId, openProductCatalog, openAnotherProduct } = useProductPageNavigation();

  return (
    <section>
      <p>Текущий товар: {displayedProductId}</p>

      <button onClick={openProductCatalog}>Все товары</button>

      <button onClick={() => openAnotherProduct('100')}>Открыть товар 100</button>
    </section>
  );
}
```

- здесь `useProductPageNavigation` объединяет две низкоуровневые операции в интерфейс, понятный компоненту предметной области
- если правила переходов изменятся, их можно будет изменить в одном месте
- однако этот хук предполагает, что компонент находится в контексте маршрутизатора и используется там, где параметр `productId` имеет смысл
- также в реальном проекте динамический ID нужно валидировать, а URL с параметром следует формировать с учётом требований приложения

### пример 2. собственный хук для query-параметра

- допустим, несколько компонентов должны читать и изменять параметр `page` в URL
- вместо повторения парсинга и преобразования значения можно создать отдельный хук

```js
import { useSearchParams } from 'react-router';

function usePaginationQuery() {
  const [paginationParams, setPaginationParams] = useSearchParams();

  const parsedPage = Number(paginationParams.get('page') ?? '1');
  const currentPage = Number.isInteger(parsedPage) && parsedPage > 0 ? parsedPage : 1;

  function changePage(nextPage) {
    if (!Number.isInteger(nextPage) || nextPage < 1) {
      return;
    }

    setPaginationParams((previousParams) => {
      const updatedParams = new URLSearchParams(previousParams);
      updatedParams.set('page', String(nextPage));

      return updatedParams;
    });
  }

  return {
    currentPage,
    changePage,
  };
}
```

- использование в компоненте списка

```js
function ProductListPagination() {
  const { currentPage: visiblePage, changePage } = usePaginationQuery();

  return (
    <div>
      <p>Страница: {visiblePage}</p>

      <button disabled={visiblePage === 1} onClick={() => changePage(visiblePage - 1)}>
        Назад
      </button>

      <button onClick={() => changePage(visiblePage + 1)}>Вперёд</button>
    </div>
  );
}
```

- в отличие от предыдущего примера, здесь собственный хук не просто объединяет API, но и инкапсулирует правила валидации и преобразования данных
- создание нового `URLSearchParams` позволяет изменить параметр `page`, сохранив остальные параметры, например `category=books`
- этот подход удобен, когда query-параметры становятся частью бизнес-логики приложения
- важная деталь: если несколько параметров нужно изменять одновременно, лучше делать это в одном вызове `setSearchParams`, поскольку несколько отдельных вызовов за один цикл не работают как очередь обновлений React state

## 10. правила и типичные ошибки при написании routing hooks

### ошибка 1. вызов хука внутри условия

```js
function ProductPanel() {
  if (isProductVisible) {
    const { productId: conditionalProductId } = useParams();
  }

  return null;
}
```

- так делать нельзя: React Hooks должны вызываться на верхнем уровне функционального компонента или пользовательского хука, а не внутри условий, циклов и вложенных функций
- правильный вариант — вызвать `useParams` в начале компонента, а условие применить к полученному значению

### ошибка 2. использование роутингового хука вне маршрутизатора

```js
function ProductNavigationButton() {
  const navigateToCatalog = useNavigate();

  return <button onClick={() => navigateToCatalog('/products')}>Каталог</button>;
}
```

- сам компонент написан правильно, но если отрендерить его вне контекста React Router, вызов `useNavigate` приведёт к ошибке
- компонент должен находиться внутри соответствующего маршрутизатора, например `BrowserRouter`

### ошибка 3. создание собственного хука ради одной строки

- не всякий вызов `useNavigate` или `useParams` нужно оборачивать в собственный хук
- абстракция полезна, когда объединяет повторяющуюся логику, задаёт единые правила или предоставляет компонентам более понятный интерфейс
- если хук лишь переименовывает единственный вызов без дополнительной пользы, он может только усложнить код

### ошибка 4. выполнение навигации во время рендера

```js
function ProductRedirectPage() {
  const redirectToCatalog = useNavigate();

  redirectToCatalog('/products');

  return null;
}
```

- такой вызов выполняется непосредственно во время рендера, что может приводить к повторным обновлениям и некорректному поведению
- навигацию обычно выполняют в обработчике события или эффекте, а для декларативного редиректа React Router также предоставляет компонент `Navigate`
- для проверок доступа и перенаправлений в более сложных data-router-сценариях существуют другие механизмы, которые разберём отдельно
