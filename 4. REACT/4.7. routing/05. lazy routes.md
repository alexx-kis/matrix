# lazy routes в React

- `Lazy routes` — это подход, при котором код страниц приложения загружается не сразу при открытии сайта, а по мере необходимости, например когда пользователь впервые переходит на определённый маршрут
- эта тема напрямую связана с `lazy imports`, `React.lazy`, `Suspense` и разделением JavaScript-бандла на отдельные чанки

## 1. зачем нужны lazy routes

- представим приложение с несколькими страницами

```js
import HomePage from './pages/HomePage';
import ProfilePage from './pages/ProfilePage';
import SettingsPage from './pages/SettingsPage';
import AdminPage from './pages/AdminPage';
```

- при статических импортах модули этих страниц входят в граф зависимостей приложения и обычно попадают в первоначальный бандл или другие чанки, которые сборщик определит как необходимые для загрузки
- даже если пользователь открыл только главную страницу, код остальных страниц может быть загружен заранее, хотя пока не нужен
- `Lazy routes` позволяют отложить загрузку кода отдельных страниц до момента, когда пользователь перейдёт на соответствующий маршрут

## 2. как реализовать lazy routes

- в React для этого можно использовать `React.lazy` вместе с `Suspense`

```js
import { lazy, Suspense } from 'react';
import { BrowserRouter, Routes, Route } from 'react-router-dom';

const HomePage = lazy(() => import('./pages/HomePage'));
const ProfilePage = lazy(() => import('./pages/ProfilePage'));
const SettingsPage = lazy(() => import('./pages/SettingsPage'));

function LazyRoutesApp() {
  return (
    <BrowserRouter>
      <Suspense fallback={<div>Loading page...</div>}>
        <Routes>
          <Route path='/' element={<HomePage />} />
          <Route path='/profile' element={<ProfilePage />} />
          <Route path='/settings' element={<SettingsPage />} />
        </Routes>
      </Suspense>
    </BrowserRouter>
  );
}
```

- `lazy(() => import(...))` создаёт компонент, который загружает модуль при первом рендере этого lazy-компонента, а не при первоначальном выполнении статических импортов
- `import()` — динамический импорт, возвращающий `Promise` с модулем; сборщики вроде Vite и Webpack обычно используют его как точку разделения кода и создают отдельный чанк
- `Suspense` отображает `fallback`, пока React ожидает загрузку модуля, необходимого для рендера lazy-компонента
- `Routes` и `Route` определяют маршруты, а не механизм загрузки кода — за ленивую загрузку в этом примере отвечают `lazy` и `import()`
- каждый компонент страницы, импортируемый таким способом, должен иметь совместимый `default export`

```js
// pages/ProfilePage.jsx

export default function ProfilePage() {
  return <h1>Profile</h1>;
}
```

## 3. как это работает внутри

1. пользователь открывает /

- Загружается код, необходимый для начальной страницы

2. пользователь переходит на /profile

- React рендерит ProfilePage, если маршрут совпадает

3. запускается динамический импорт

- Браузер загружает чанк, если он ещё не загружен и не закеширован

4. React отображает страницу

- До завершения загрузки показывается fallback из Suspense

- важный нюанс: динамический импорт обычно не выполняется просто потому, что пользователь открыл сайт — он запускается при обращении к модулю, в данном случае при первом рендере соответствующего lazy-компонента
- после загрузки модуль, как правило, кешируется средствами загрузчика модулей и React, поэтому при повторном переходе дополнительная загрузка обычно не требуется

## 4. lazy routes в React Router

- в примере выше мы лениво загружали компоненты страниц, но React Router также предоставляет собственный механизм ленивой загрузки маршрутов
- в React Router 6.9+ и актуальных версиях React Router можно использовать свойство `lazy` у `Route` — оно позволяет отложенно загружать не только компонент, но и другие свойства маршрута, например `loader`, `action` и `ErrorBoundary`

```js
import { createBrowserRouter, RouterProvider } from 'react-router-dom';

const router = createBrowserRouter([
  {
    path: '/',
    Component: HomePage,
  },
  {
    path: '/profile',
    lazy: () => import('./routes/ProfileRoute'),
  },
]);

function LazyRouteApp() {
  return <RouterProvider router={router} />;
}
```

- файл `ProfileRoute.jsx` может экспортировать свойства маршрута

```js
export function Component() {
  return <h1>Profile</h1>;
}

export async function loader() {
  return { userId: 42 };
}
```

- в этом случае React Router загружает модуль маршрута и использует экспортированные свойства для настройки соответствующего маршрута
- при использовании `lazy` важно учитывать, что базовые свойства сопоставления маршрута, например `path`, `index` и `children`, должны быть известны заранее — их нельзя отложить таким способом, потому что роутеру нужно определить, какой маршрут подходит текущему URL
- это отличается от `React.lazy`: `React.lazy` загружает React-компонент, а `Route.lazy` загружает модуль с реализацией маршрута

## 5. что важно помнить на собеседовании

- цель — уменьшить первоначальный объём загружаемого JavaScript и ускорить загрузку приложения, особенно если оно содержит много страниц
- код-сплиттинг — сборщик разбивает код на несколько чанков, используя динамические импорты как точки разделения
- fallback — пользователь должен видеть понятное состояние загрузки, пока ленивый компонент недоступен
- обработка ошибок — если чанк не удалось загрузить, например из-за сетевой ошибки или устаревшего кеша после деплоя, нужен механизм обработки ошибки, обычно через Error Boundary или обработку ошибок маршрута
- не каждый маршрут обязательно нужно делать lazy — небольшие страницы, часто посещаемые компоненты или код, который всё равно загружается сразу, могут не дать заметного выигрыша
- предзагрузка — при необходимости можно заранее загружать вероятно нужные страницы, например при наведении на ссылку, чтобы уменьшить задержку при переходе
- lazy loading не означает, что страница никогда не попадёт в кеш или не загрузится заранее — это зависит от стратегии сборки, предзагрузки, браузерного кеша и поведения приложения

## краткий ответ для собеседования

- `Lazy routes` — это техника оптимизации React-приложений, при которой код страниц загружается по мере необходимости, а не целиком при первоначальной загрузке
- обычно это реализуется через `React.lazy`, динамический `import()` и `Suspense`, либо через `lazy` в React Router, если требуется лениво загружать весь модуль маршрута, включая `loader` и обработчики
- основная цель — уменьшить initial bundle и ускорить первоначальную загрузку приложения, сохранив возможность показывать состояние загрузки и обрабатывать ошибки при получении чанков
