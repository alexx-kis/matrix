# web workers terminating

- после создания Worker важно понимать, что его можно **остановить**, когда он больше не нужен
- для этого существует метод `terminate()`

## `terminate()`

- если у нас есть Worker

```js
const calculationWorker = new Worker('./worker.js');
```

- мы можем остановить его так

```js
calculationWorker.terminate();
```

- после вызова `terminate()` браузер прекращает выполнение этого Worker

```
Main Thread
     │
     │ terminate()
     ▼
Worker Thread
     │
     ✕
     └── выполнение прекращено
```

- это означает, что Worker больше не выполняет свой JavaScript-код и не обрабатывает новые задачи

## что именно делает `terminate()`

- `terminate()` — это **немедленное завершение Worker со стороны main thread**
- например, представим, что Worker выполняет бесконечный цикл

```js
while (true) {
  // тяжёлая работа
}
```

- если такой код выполняется в Worker, main thread при этом остаётся свободным
- но Worker сам никогда не закончит работу
- main thread может принудительно его остановить

```js
calculationWorker.terminate();
```

- после этого браузер прекращает Worker
- главное здесь слово — **принудительно**

## `terminate()` не ждёт завершения текущей работы

- это важный нюанс
- допустим, Worker сейчас выполняет какую-то тяжёлую операцию

```
Worker
│
├── выполняет задачу
│
│   ← main thread вызывает terminate()
│
└── выполнение прекращается
```

- `terminate()` не означает

> «закончи текущую задачу, а потом аккуратно завершись»

- это скорее

> «остановись сейчас»

- поэтому если Worker выполняет важную операцию, результат которой ещё нужен приложению, нельзя бездумно вызывать `terminate()`

## после `terminate()` Worker нельзя продолжить

- после

```js
calculationWorker.terminate();
```

- этот экземпляр Worker больше нельзя использовать для продолжения выполнения
- если Worker снова нужен, создаётся **новый экземпляр**

```js
const restartedWorker = new Worker('./worker.js');
```

- то есть это не временная пауза

```
terminate()
    ↓
Worker уничтожен
    ↓
нужно снова → new Worker(...)
```

## что возвращает `terminate()`

- метод `terminate()` возвращает `undefined`

```js
const terminationResult = calculationWorker.terminate();

console.log(terminationResult); // undefined
```

- поэтому использовать возвращаемое значение для проверки успешности завершения не нужно

## `terminate()` вызывается из main thread

- здесь есть важное различие между двумя способами завершения Worker
- **main thread** может завершить Worker через `worker.terminate()`

```js
calculationWorker.terminate();
```

- сам Worker может попросить браузер завершить себя через `self.close()`

```js
self.close();
```

- получается два направления

```
Main Thread
    │
    │ worker.terminate()
    ▼
 Worker
    │
    │ self.close()
    ▼
 Worker завершает себя
```

## `self.close()`

- `self` внутри Worker представляет глобальный объект Worker
- поэтому Worker может сделать

```js
self.close();
```

- после этого Worker завершает своё выполнение
- например

```js
self.onmessage = (event) => {
  const processedValue = event.data * 2;

  self.postMessage(processedValue);

  self.close();
};
```

- здесь Worker получает сообщение, выполняет работу, отправляет результат обратно и после этого закрывается

```
получил данные
     ↓
обработал
     ↓
отправил результат
     ↓
self.close()
     ↓
Worker завершён
```

## `terminate()` vs `self.close()`

- это один из главных моментов этой темы

|                | `worker.terminate()`      | `self.close()`     |
| -------------- | ------------------------- | ------------------ |
| кто вызывает   | main thread               | Worker             |
| кого завершает | Worker                    | самого себя        |
| характер       | принудительное завершение | завершение изнутри |
| вызов          | `worker.terminate()`      | `self.close()`     |

- можно запомнить очень просто

```
main thread → terminate()
worker      → self.close()
```

## а если Worker просто закончил свою работу?

- Worker не обязательно нужно вручную завершать сразу после каждой задачи
- например, Worker может обработать сообщение и продолжать существовать, ожидая следующего сообщения

```js
self.onmessage = (event) => {
  const resultValue = event.data * 2;

  self.postMessage(resultValue);
};
```

- после отправки результата Worker **не завершился**
- он продолжает существовать и может получить следующее сообщение

```
message 1
   ↓
обработка
   ↓
результат
   ↓
ждём

message 2
   ↓
обработка
   ↓
результат
   ↓
ждём
```

- это нормально, если Worker используется многократно

## когда Worker стоит завершать

- Worker имеет смысл завершить, когда он больше не нужен приложению
- например, пользователь закрыл страницу приложения, завершил определённый процесс или приложение больше не планирует отправлять этому Worker задачи
- особенно это актуально для Worker, который существует долгое время и больше не выполняет полезную работу
- идея похожа на управление ресурсами

```
создали ресурс
     ↓
использовали
     ↓
ресурс больше не нужен
     ↓
освободили ресурс
```

## важный нюанс про event handlers

- после `terminate()` обработчики событий Worker в main thread тоже уже не имеют смысла для этого экземпляра
- например

```js
const messageWorker = new Worker('./worker.js');

messageWorker.onmessage = (event) => {
  console.log(event.data);
};

messageWorker.terminate();
```

- после завершения Worker мы не можем ожидать, что он продолжит присылать сообщения
- если нам снова нужен Worker, создаём новый

## что происходит с задачами Worker

- при завершении Worker его дальнейшее выполнение прекращается
- поэтому если Worker должен был обработать несколько задач, но мы вызвали

```js
messageWorker.terminate();
```

- нельзя рассчитывать на то, что оставшиеся задачи будут автоматически выполнены
- это особенно важно, если Worker используется для обработки очереди данных

```
задача A → выполнена
задача B → выполняется
задача C → ожидает

           ↓
      terminate()

задача B → прекращена
задача C → не будет обработана этим Worker
```

## ещё один важный момент

- `terminate()` относится именно к **Web Worker**, а не к JavaScript-функции
- мы не можем написать

```js
terminate(certainFunction);
```

- Worker — это отдельный ресурс выполнения, у которого есть собственный жизненный цикл

```
new Worker()
      ↓
Worker создан
      ↓
Worker работает
      ↓
Worker получает сообщения
      ↓
Worker больше не нужен
      ↓
terminate()
```

## что нужно знать для собеседования

- `worker.terminate()` позволяет **main thread принудительно завершить Worker**
- `self.close()` позволяет **самому Worker завершить себя**
- `terminate()` не ждёт окончания текущей задачи
- после `terminate()` этот экземпляр Worker нельзя «запустить обратно»
- если Worker снова нужен, создаётся новый через `new Worker(...)`
- Worker, который просто закончил обработку одного сообщения, **не завершается автоматически**
- Worker может продолжать существовать и обрабатывать следующие сообщения
- поэтому жизненный цикл Worker выглядит примерно так

```
new Worker(...)
      ↓
  работа
      ↓
получение сообщений
      ↓
обработка
      ↓
Worker больше не нужен
      ↓
terminate()
```
