# error handling

- теперь разберём, что происходит, если внутри Worker возникает ошибка и как main thread может об этом узнать
- это особенно важно потому, что Worker выполняется отдельно от main thread, поэтому ошибка внутри Worker не является обычным исключением, которое можно поймать try...catch вокруг new Worker()
- простая ошибка внутри Worker
- допустим, создаём Worker

```js
const parserWorker = new Worker('./parser-worker.js');

parserWorker.onmessage = (event) => {
  console.log(event.data);
};
```

- а внутри parser-worker.js происходит ошибка

```js
throw new Error('Something went wrong');
```

- эта ошибка возникает в контексте Worker
- она не выбрасывается непосредственно в коде main thread

```
Main Thread                  Worker Thread

new Worker(...)
     │
     │                        throw new Error(...)
     │                              │
     │                              ▼
     │                           ошибка
     │                              │
     │ ◄──────────── error event ───┘
     │
  обработка ошибки
```

- для этого у Worker существует событие `error`

## `error` event

- в main thread можно установить обработчик

```js
const parserWorker = new Worker('./parser-worker.js');

parserWorker.onerror = (event) => {
  console.log('Worker error');
};
```

- либо использовать addEventListener

```js
const parserWorker = new Worker('./parser-worker.js');

parserWorker.addEventListener('error', (event) => {
  console.log('Worker error');
});
```

- когда внутри Worker возникает необработанная ошибка, main thread получает error event

## `ErrorEvent`

- объект события обычно является ErrorEvent
- у него есть несколько полезных свойств

```js
parserWorker.onerror = (event) => {
  console.log(event.message);
  console.log(event.filename);
  console.log(event.lineno);
  console.log(event.colno);
};
```

- message — сообщение об ошибке
- filename — файл, в котором произошла ошибка
- lineno — номер строки
- colno — номер столбца
- это позволяет получить информацию о том, где произошла ошибка внутри Worker

### пример

- пусть parser-worker.js содержит

```js
const brokenValue = undefined;

brokenValue.someMethod();
```

- main thread может получить информацию об ошибке

```js
const parserWorker = new Worker('./parser-worker.js');

parserWorker.onerror = (event) => {
  console.log(event.message);
  console.log(event.filename);
  console.log(event.lineno);
};
```

- здесь важно понимать направление передачи информации

```
Worker
  │
  │ возникла необработанная ошибка
  ▼
error event
  │
  ▼
Main Thread
  │
  ▼
parserWorker.onerror
```

## можно ли использовать try...catch

- да, но здесь есть очень важный нюанс
- try...catch работает в том JavaScript-контексте, где возникла ошибка
- например, внутри Worker можно сделать

```js
self.onmessage = (event) => {
  try {
    const parsedData = JSON.parse(event.data);

    self.postMessage(parsedData);
  } catch (error) {
    self.postMessage({
      type: 'error',
      message: error.message,
    });
  }
};
```

- здесь try...catch ловит ошибку непосредственно внутри Worker
- после этого Worker сам решает, что делать с ошибкой

```
Worker
 │
 ├── try
 │    │
 │    └── ошибка
 │
 └── catch
       │
       └── postMessage(...)
              │
              ▼
         Main Thread
```

## это отличается от onerror

- try...catch позволяет обработать ошибку внутри Worker
- onerror позволяет main thread узнать о необработанной ошибке Worker

### важный пример с try...catch

- вот это не поймает ошибку, которая возникнет позже внутри Worker

```js
try {
  const parserWorker = new Worker('./parser-worker.js');
} catch (error) {
  console.log(error);
}
```

### почему

- потому что new Worker() только инициирует создание Worker, а код parser-worker.js выполняется отдельно

```
try...catch в main thread
        │
        ▼
new Worker(...)
        │
        └── Worker запускается отдельно
                    │
                    ▼
             ошибка внутри Worker
```

- поэтому для ошибок, происходящих во время выполнения Worker, используются error events или try...catch непосредственно внутри Worker

## что происходит после необработанной ошибки

- это очень важный нюанс
- если ошибка внутри Worker не была обработана, Worker обычно становится недоступным для дальнейшего выполнения скрипта
- например

```js
console.log('before');

throw new Error('Fatal error');

console.log('after');
```

- before выполнится
- после throw возникнет ошибка
- after уже не выполнится
- main thread получит error event
- поэтому необработанная ошибка может фактически завершить выполнение Worker

```
Worker
 │
 ├── код до ошибки ✓
 │
 ├── throw Error
 │
 ├── error event ─────────► Main Thread
 │
 └── дальнейшее выполнение прекращается
```

## messageerror

- существует ещё одно событие, которое важно знать
- это messageerror
- оно связано не с ошибкой выполнения JavaScript-кода, а с ситуацией, когда сообщение не может быть корректно десериализовано или принято
- например, проблемы могут возникать при передаче данных, которые нельзя корректно обработать механизмом structured clone
- обработчик можно установить так

```js
const communicationWorker = new Worker('./communication-worker.js');

communicationWorker.onmessageerror = (event) => {
  console.log('Message could not be processed');
};
```

- для базового собеседования важно различать

```
error
  ↓
ошибка выполнения Worker

messageerror
  ↓
проблема с обработкой переданного сообщения
```

## ошибка и обычный postMessage

- ещё один важный момент связан с передачей данных
- postMessage() использует structured clone
- поэтому нельзя отправить некоторые значения
- например, функцию

```js
const communicationWorker = new Worker('./communication-worker.js');

communicationWorker.postMessage(() => {
  console.log('hello');
});
```

- функция не поддерживается structured clone, поэтому передача вызовет ошибку
- это хороший пример того, почему нужно понимать, что именно мы можем передавать между контекстами
- ошибка не становится обычным Error в main thread
- если Worker сделал

```js
throw new Error('Worker failed');
```

- нельзя рассчитывать, что main thread получит тот же самый объект Error, который можно будет обработать как локальное исключение
- main thread получает событие об ошибке

```js
parserWorker.onerror = (event) => {
  console.log(event.message);
};
```

- то есть модель здесь событийная

```
Worker
   │
   │ throw
   ▼
Browser
   │
   │ error event
   ▼
Main Thread
```

- можно передавать собственные ошибки через postMessage
- иногда нам вообще не нужно полагаться на error event
- Worker может самостоятельно сообщить main thread, что бизнес-операция завершилась ошибкой

```js
self.onmessage = (event) => {
  try {
    const parsedData = JSON.parse(event.data);

    self.postMessage({
      type: 'success',
      data: parsedData,
    });
  } catch (error) {
    self.postMessage({
      type: 'error',
      message: error.message,
    });
  }
};
```

- main thread тогда получает обычное message

```js
const parserWorker = new Worker('./parser-worker.js');

parserWorker.onmessage = (event) => {
  if (event.data.type === 'error') {
    console.log('Operation failed:', event.data.message);
    return;
  }

  console.log('Success:', event.data.data);
};
```

- здесь принципиальная разница

```
необработанная ошибка
        ↓
error event

обработанная ошибка,
которую Worker решил передать как данные
        ↓
message event
```

- это уже архитектурный вопрос приложения

## error vs message с ошибкой

```
| Ситуация                                       | Механизм                                 |
| ---------------------------------------------- | ---------------------------------------- |
| внутри Worker возникла необработанная ошибка   | `error`                                  |
| Worker сам поймал ошибку через `try...catch`   | ошибка больше не является необработанной |
| Worker хочет сообщить об ошибке приложения     | `postMessage()`                          |
| проблема с передачей/десериализацией сообщения | `messageerror`                           |
```

## что нужно запомнить для собеседования

- Worker выполняется в отдельном JavaScript-контексте, поэтому ошибки внутри него не являются обычными исключениями main thread
- main thread может слушать worker.onerror
- error event сообщает об необработанной ошибке внутри Worker
- у ErrorEvent есть полезные свойства вроде message, filename, lineno и colno
- try...catch можно использовать внутри самого Worker
- try...catch вокруг new Worker() не предназначен для ловли ошибок, возникающих позже при выполнении Worker-кода
- необработанная ошибка прекращает дальнейшее выполнение соответствующего Worker-скрипта
- Worker может самостоятельно поймать ошибку и отправить информацию о ней через postMessage()
- messageerror связан с проблемами обработки переданных сообщений, а не с обычной ошибкой выполнения JavaScript
