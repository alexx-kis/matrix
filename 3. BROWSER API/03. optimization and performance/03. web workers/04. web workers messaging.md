# web workers messaging

- теперь разберём, **как main thread и Worker вообще обмениваются данными**
- это центральная идея Web Workers, потому что Worker работает в отдельном JavaScript-контексте и не может просто взять и обратиться к переменной main thread

## зачем вообще нужны сообщения

- представим, что в `main.js` у нас есть данные

```js
const numbersData = [10, 20, 30, 40];
```

- Worker не может сделать так

```js
console.log(numbersData);
```

- у Worker нет доступа к лексическому окружению `main.js`
- поэтому нужен специальный механизм коммуникации

```
Main Thread                         Worker Thread

numbersData
     │
     │ message
     ├──────────────────────────────►
     │                               получает данные
     │                               обрабатывает
     │
     │ ◄──────────────────────────────
     │             message
     │
получает результат
```

- этот механизм называется **message passing**, то есть обмен сообщениями

# `postMessage()`

- для отправки сообщения используется метод `postMessage()`
- например, main thread создаёт Worker

```js
const calculationWorker = new Worker('./worker.js');
```

- затем отправляет ему данные

```js
calculationWorker.postMessage([10, 20, 30, 40]);
```

- здесь мы говорим Worker примерно следующее

> «вот тебе этот массив, обработай его»

- внутри Worker сообщение можно получить через `message` event

```js
self.onmessage = (event) => {
  console.log(event.data);
};
```

- `event.data` содержит данные, которые были переданы через `postMessage()`
- в нашем случае Worker получит

```js
[10, 20, 30, 40];
```

## полный минимальный пример

- `main.js`

```js
const calculationWorker = new Worker('./worker.js');

calculationWorker.postMessage(10);
```

- `worker.js`

```js
self.onmessage = (event) => {
  console.log(event.data);
};
```

- происходит следующее

```
main.js

new Worker(...)
      ↓
создан Worker
      ↓
postMessage(10)
      │
      │
      ▼
worker.js

self.onmessage
      ↓
event.data === 10
```

# как Worker отправляет сообщение обратно

- Worker тоже имеет `postMessage()`
- например

```js
self.onmessage = (event) => {
  const doubledValue = event.data * 2;

  self.postMessage(doubledValue);
};
```

- теперь main thread должен подписаться на `message`

```js
const calculationWorker = new Worker('./worker.js');

calculationWorker.onmessage = (event) => {
  console.log(event.data);
};

calculationWorker.postMessage(10);
```

- в результате main thread получит `20`

```
Main Thread                         Worker Thread

postMessage(10)
      │
      ├────────────────────────────►
      │                              event.data = 10
      │                                   │
      │                              10 * 2 = 20
      │                                   │
      │ ◄────────────────────────────postMessage(20)
      │
event.data = 20
```

- таким образом, `postMessage()` используется **в обе стороны**

```
Main Thread
     │
     │ worker.postMessage(...)
     ▼
 Worker
     │
     │ self.postMessage(...)
     ▼
Main Thread
```

# `message` и `onmessage`

- есть два основных способа установить обработчик сообщения

```js
calculationWorker.onmessage = (event) => {
  console.log(event.data);
};
```

- либо через `addEventListener`

```js
calculationWorker.addEventListener('message', (event) => {
  console.log(event.data);
});
```

- внутри Worker аналогично

```js
self.onmessage = (event) => {
  console.log(event.data);
};
```

- либо

```js
self.addEventListener('message', (event) => {
  console.log(event.data);
});
```

- принципиальной разницы для базового использования между этими вариантами нет

# что такое `event.data`

- `event` — это объект события `MessageEvent`
- Worker получает не просто переданное значение, а событие, внутри которого есть информация о сообщении
- главное свойство здесь — `data`

```js
self.onmessage = (event) => {
  console.log(event.data);
};
```

- если main thread сделал

```js
calculationWorker.postMessage({
  firstValue: 10,
  secondValue: 20,
});
```

- Worker получит соответствующий объект через

```js
event.data;
```

- то есть

```js
event.data.firstValue;
event.data.secondValue;
```

# можно передавать не только числа

- через `postMessage()` можно передавать множество структурированных данных
- например строки

```js
calculationWorker.postMessage('hello');
```

- массивы

```js
calculationWorker.postMessage([1, 2, 3]);
```

- объекты

```js
calculationWorker.postMessage({
  action: 'calculate',
  value: 100,
});
```

- `Map`, `Set`, `Date` и другие поддерживаемые структуры
- браузер использует механизм, называемый **structured clone algorithm**

# structured clone

- здесь находится важнейший нюанс
- данные при обычном `postMessage()` не становятся общей переменной между двумя потоками
- вместо этого браузер создаёт копию данных в другом контексте

```
Main Thread

originalObject
      │
      │ postMessage()
      ▼
structured clone
      │
      ▼
Worker

copiedObject
```

- поэтому Worker и main thread не получают одну и ту же обычную JavaScript-ссылку
- например

```js
const userData = {
  name: 'Alex',
};

calculationWorker.postMessage(userData);
```

- Worker получает структурированную копию этих данных
- изменение объекта внутри Worker не означает изменение исходного объекта в main thread

```
Main Thread                  Worker

userData                     copiedUserData
    │                              │
    │      postMessage()           │
    └─────────────────────────────►
                                   │
                              изменение
                                   │
                              не меняет
                              оригинал
```

- это очень важная причина, почему нельзя думать о Worker как о функции, которая работает непосредственно с переменными main thread

# а функции передавать можно?

- обычную JavaScript-функцию через structured clone передать нельзя

```js
calculationWorker.postMessage(() => {
  console.log('hello');
});
```

- такой код приведёт к ошибке клонирования, потому что функции не поддерживаются structured clone
- поэтому между main thread и Worker обычно передают **данные**, а не функции

# передача результата

- очень распространённый паттерн выглядит так

```js
const calculationWorker = new Worker('./worker.js');

calculationWorker.onmessage = (event) => {
  console.log('Result:', event.data);
};

calculationWorker.postMessage(50);
```

- `worker.js`

```js
self.onmessage = (event) => {
  const resultValue = event.data * 10;

  self.postMessage(resultValue);
};
```

- получается классическая схема

```
request
   ↓
main thread
   ↓
postMessage(data)
   ↓
Worker
   ↓
calculation
   ↓
postMessage(result)
   ↓
main thread
   ↓
result
```

# сообщения асинхронные

- `postMessage()` не означает «выполни Worker прямо сейчас и верни результат»
- он отправляет сообщение, после чего соответствующий обработчик будет вызван асинхронно
- например

```js
const calculationWorker = new Worker('./worker.js');

calculationWorker.onmessage = (event) => {
  console.log('Worker:', event.data);
};

console.log('A');

calculationWorker.postMessage(10);

console.log('B');
```

- main thread продолжает выполнение и не ждёт, пока Worker закончит работу
- поэтому сначала main thread продолжает свои задачи, а когда Worker отправит сообщение, будет выполнен обработчик `onmessage`

```
A
↓
postMessage(...)
↓
B
↓
Worker работает
↓
message event
↓
onmessage
```

- это одна из причин, почему Worker позволяет не блокировать интерфейс

# несколько сообщений

- Worker может получать сообщения многократно

```js
calculationWorker.postMessage(10);
calculationWorker.postMessage(20);
calculationWorker.postMessage(30);
```

- Worker может обработать их через один обработчик

```js
self.onmessage = (event) => {
  console.log(event.data);
};
```

- сообщения поступают в Worker в порядке отправки

```
10 → 20 → 30
│     │     │
▼     ▼     ▼
10    20    30
```

# важный нюанс: `postMessage()` не блокирует main thread

- например

```js
calculationWorker.postMessage(largeData);
console.log('Main thread continues');
```

- main thread не ждёт завершения Worker
- это принципиально отличается от обычного синхронного вызова функции

```js
const resultValue = calculateSomething();
```

- при обычном вызове функция выполняется непосредственно в текущем потоке
- при Worker мы отправляем сообщение другому контексту и продолжаем выполнение

# что нужно запомнить

- **`worker.postMessage(data)`** — main thread отправляет данные Worker
- **`self.postMessage(data)`** — Worker отправляет данные обратно
- **`onmessage`** — обработчик получения сообщения
- **`event.data`** — переданные данные
- коммуникация между main thread и Worker происходит через **message passing**
- Worker не получает доступ к переменным main thread напрямую
- обычные данные передаются через **structured clone**
- обычные функции через `postMessage()` передать нельзя
- `postMessage()` является асинхронным механизмом коммуникации
- один Worker может получать и отправлять множество сообщений
- концептуально весь механизм можно держать в голове так

```
              Main Thread
                  │
          worker.postMessage()
                  │
                  ▼
              Worker
                  │
          self.postMessage()
                  │
                  ▼
              Main Thread
```
