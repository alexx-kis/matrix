# web workers creating

- теперь разберём, **как именно создаётся Web Worker**, что происходит после `new Worker(...)` и как main thread начинает с ним взаимодействовать

## самый простой вариант

- Worker создаётся с помощью конструктора `Worker`

```js
const dataWorker = new Worker('worker.js');
```

- здесь происходит важная вещь: `new Worker(...)` создаёт новый объект `Worker` в main thread и одновременно просит браузер запустить указанный JavaScript-файл в отдельном worker thread
- `'worker.js'` — это путь к файлу, содержащему код Worker

```text
index.html
│
├── main.js
│
└── worker.js
```

- например, в `main.js` находится код основного приложения

```js
const dataWorker = new Worker('worker.js');

console.log('Main thread');
```

- а в `worker.js` находится код Worker

```js
console.log('Worker thread');
```

- после загрузки `main.js` браузер создаёт Worker

```text
main.js
   │
   │ new Worker('worker.js')
   ▼
Browser
   │
   ▼
worker.js
   │
   ▼
Worker thread
```

## что именно происходит при `new Worker()`

- рассмотрим эту строку подробнее

```js
const dataWorker = new Worker('worker.js');
```

- `Worker` — это встроенный браузерный конструктор
- `new` создаёт объект Worker
- `'worker.js'` указывает браузеру, какой JavaScript-файл нужно загрузить и выполнить внутри Worker
- после этого у main thread появляется объект `dataWorker`, через который можно управлять взаимодействием с Worker

```text
main.js
   │
   │ dataWorker
   ▼
Worker object
   │
   │ связь
   ▼
Worker thread
   │
   ▼
worker.js
```

- здесь особенно важно не перепутать **объект Worker** и **сам worker thread**
- `dataWorker` — это объект, доступный в main thread
- сам код `worker.js` выполняется в отдельном worker thread

## где должен находиться worker-файл

- путь передаётся относительно текущего документа или URL модуля, в зависимости от способа создания Worker
- например

```text
project/
│
├── index.html
│
├── main.js
│
└── workers/
    └── calculation.js
```

- тогда можно написать

```js
const calculationWorker = new Worker('./workers/calculation.js');
```

- браузер загрузит `calculation.js` и запустит его как Worker

## Worker начинает выполняться сразу

- после создания Worker его JavaScript-код начинает выполняться независимо от дальнейшего выполнения main thread
- например

```js
const processingWorker = new Worker('worker.js');

console.log('A');
```

- `worker.js`

```js
console.log('B');
```

- мы не должны воспринимать это как обычный последовательный вызов функции

```
main thread                 worker thread

new Worker(...)
      │
      ├──────────────────→ загрузка worker.js
      │                         │
console.log('A')               │
      │                         ▼
      │                   console.log('B')
      │
      ▼
продолжает работу
```

- поэтому порядок вывода `A` и `B` нельзя рассматривать как обычную синхронную последовательность
- Worker запускается независимо, и между созданием Worker и фактическим выполнением его кода есть асинхронность

## Worker не получает переменные из main thread

- это очень важный момент

```js
const userCount = 100;

const analyticsWorker = new Worker('worker.js');
```

- внутри `worker.js` переменной `userCount` автоматически нет

```js
console.log(userCount);
```

- это не сработает, потому что Worker имеет **своё глобальное окружение**
- Worker не является просто функцией, которую мы вызвали внутри текущего JavaScript-контекста
- это отдельный JavaScript-контекст

```text
Main Thread                  Worker Thread

userCount = 100              worker.js
someObject                   own variables
someFunction                 own global scope
DOM                          no normal DOM
```

## Worker создаётся не из функции

- нельзя сделать так

```js
const calculationWorker = new Worker(() => {
  // ...
});
```

- конструктор `Worker` ожидает URL скрипта, а не обычную JavaScript-функцию
- поэтому классический вариант выглядит так

```js
const calculationWorker = new Worker('./worker.js');
```

## создание Worker из Blob

- существует и другой способ, когда код Worker создаётся программно
- например

```js
const workerCode = `
    self.onmessage = event => {
        console.log(event.data);
    };
`;

const workerBlob = new Blob([workerCode], {
  type: 'text/javascript',
});

const workerUrl = URL.createObjectURL(workerBlob);
const blobWorker = new Worker(workerUrl);
```

- здесь мы не создаём отдельный физический файл `worker.js`
- вместо этого создаём `Blob` с JavaScript-кодом, превращаем его в URL и передаём этот URL в `Worker`
- для повседневного frontend-кода обычно гораздо понятнее и удобнее использовать отдельный файл Worker

## module workers

- Worker также можно создать как ES-модуль

```js
const moduleWorker = new Worker('./worker.js', {
  type: 'module',
});
```

- теперь `worker.js` работает как JavaScript-модуль
- это позволяет использовать внутри Worker стандартные `import` и `export`

```js
import { calculate } from './utils.js';

const result = calculate();
```

- без `type: 'module'` такой код не будет работать как обычный module worker

## важный нюанс: Worker не имеет DOM

- Worker получает собственный глобальный объект `self`
- поэтому внутри Worker можно написать

```js
console.log(self);
```

- в браузерном Worker `self` ссылается на глобальный объект самого Worker
- многие Web API доступны Worker, но DOM API страницы — нет
- например, такого объекта внутри обычного Worker нет

```js
document;
```

- поэтому Worker не предназначен для непосредственного изменения HTML

```text
Worker
   │
   ├── вычисления       ✓
   ├── fetch            ✓
   ├── timers           ✓
   ├── многие Web APIs  ✓
   │
   └── DOM              ✗
```

## важный нюанс: создание Worker может зависеть от origin

- Worker-скрипт загружается браузером как отдельный ресурс, поэтому применяются ограничения безопасности браузера
- в типичном приложении Worker-файл находится на том же origin, что и страница
- при разработке также стоит учитывать, что некоторые браузерные возможности могут вести себя иначе при открытии HTML напрямую через `file://`, поэтому Web Workers обычно проверяют через локальный HTTP-сервер

## что происходит концептуально

- весь процесс создания можно свести к четырём шагам

```
1. main thread выполняет

   new Worker('./worker.js')

             ↓

2. браузер создаёт Worker

             ↓

3. браузер загружает worker.js

             ↓

4. код worker.js начинает выполняться
   в отдельном worker thread
```

- после этого main thread и Worker существуют независимо

```
                 Browser
                    │
        ┌───────────┴───────────┐
        │                       │
   Main Thread             Worker Thread
        │                       │
     main.js                 worker.js
        │                       │
  Worker object                 │
        │                       │
        └──── messages ─────────┘
```

## что нужно знать для собеседования

- **Web Worker создаётся через** **`new Worker(url)`**
- URL указывает на JavaScript-файл, который будет выполняться в отдельном worker thread
- `new Worker()` возвращает объект `Worker`, находящийся в main thread
- код Worker имеет собственный JavaScript-контекст и не получает переменные из main thread автоматически
- обычный Worker не имеет доступа к DOM
- Worker можно создать как классический script worker или как module worker с `{ type: 'module' }`
- взаимодействие main thread с Worker осуществляется через сообщения, а не через прямой доступ к переменным
