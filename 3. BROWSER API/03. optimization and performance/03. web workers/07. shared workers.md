# shared workers

- SharedWorker — это специальный вид Web Worker, который позволяет нескольким независимым контекстам браузера использовать один и тот же Worker
- обычный Worker обычно создаётся конкретным контекстом и используется им

## обычный Worker

```
Tab A
 │
 └── Worker A
```

- SharedWorker позволяет построить другую архитектуру

```
SharedWorker

Tab A ─────┐
           │
Tab B ─────┼──► Shared Worker
           │
Tab C ─────┘
```

- например, несколько вкладок одного приложения могут подключиться к одному Shared Worker и обмениваться через него данными

## зачем нужен SharedWorker

- представим, что пользователь открыл одно приложение в трёх вкладках

```
Browser

Tab 1
Tab 2
Tab 3
```

- если каждая вкладка создаст обычный Worker

```
Tab 1 ──► Worker 1
Tab 2 ──► Worker 2
Tab 3 ──► Worker 3
```

- мы получим три отдельных Worker
- каждый из них будет иметь собственное состояние и выполнять свой JavaScript-код
- с SharedWorker можно организовать один общий Worker

```
Tab 1 ──┐
Tab 2 ──┼──► SharedWorker
Tab 3 ──┘
```

- это позволяет использовать один общий контекст для нескольких подключений

## главное отличие от обычного Worker

- обычный Worker:

```js
const dataWorker = new Worker('./worker.js');
```

- создаётся через Worker
- Shared Worker:

```js
const sharedDataWorker = new SharedWorker('./shared-worker.js');
```

- создаётся через SharedWorker
- уже по названию конструктора можно запомнить основную идею

```
Worker
→ отдельный Worker для конкретного контекста

SharedWorker
→ Worker, к которому могут подключаться несколько контекстов
```

## самое важное отличие — port

- вот здесь начинается главный нюанс SharedWorker
- с обычным Worker мы могли написать:

```js
const dataWorker = new Worker('./worker.js');

dataWorker.postMessage('hello');
```

- у SharedWorker взаимодействие происходит через MessagePort

```js
const sharedDataWorker = new SharedWorker('./shared-worker.js');

sharedDataWorker.port.postMessage('hello');
```

- port представляет собой канал связи между конкретным подключившимся контекстом и Shared Worker

```
Tab A
  │
  │ port A
  ▼
SharedWorker

Tab B
  │
  │ port B
  ▼
SharedWorker
```

- поэтому Shared Worker может одновременно иметь несколько подключений

```
             SharedWorker
              /    |    \
             /     |     \
          Port A Port B Port C
            │      │      │
          Tab A  Tab B  Tab C
```

## создание Shared Worker

- допустим, у нас есть

```
index.html
main.js
shared-worker.js
```

- в main.js создаём Shared Worker

```js
const sharedDataWorker = new SharedWorker('./shared-worker.js');
```

- после этого main thread получает объект SharedWorker
- но сообщения отправляются через его port

```js
sharedDataWorker.port.postMessage('hello');
```

- чтобы получать сообщения, можно подписаться на message

```js
sharedDataWorker.port.onmessage = (event) => {
  console.log(event.data);
};
```

## что происходит внутри Shared Worker

- здесь есть принципиальное отличие от обычного Worker
- обычный Worker может сразу использовать

```js
self.onmessage = (event) => {
  // ...
};
```

- Shared Worker получает событие connect

```js
self.onconnect = (event) => {
  const connectedPort = event.ports[0];

  connectedPort.onmessage = (messageEvent) => {
    console.log(messageEvent.data);
  };
};
```

### давай разберём это по шагам

`connect`

- когда новая вкладка или другой контекст подключается к Shared Worker, Worker получает connect event

```Tab A
  │
  │ new SharedWorker(...)
  ▼
SharedWorker
  │
  ▼
connect event
```

- через event.ports[0] мы получаем MessagePort, который соответствует этому конкретному подключению

```js
self.onconnect = (event) => {
  const connectedPort = event.ports[0];
};
```

- теперь через connectedPort можно общаться именно с подключившимся контекстом

```js
self.onconnect = (event) => {
  const connectedPort = event.ports[0];

  connectedPort.postMessage('Hello from Shared Worker');
};
```

- подключившаяся вкладка получит это сообщение через

```js
sharedDataWorker.port.onmessage = (event) => {
  console.log(event.data);
};
```

## полный минимальный пример

- main.js

```js
const sharedDataWorker = new SharedWorker('./shared-worker.js');

sharedDataWorker.port.onmessage = (event) => {
  console.log('Received:', event.data);
};

sharedDataWorker.port.start();

sharedDataWorker.port.postMessage('Hello');
```

- shared-worker.js

```js
self.onconnect = (event) => {
  const connectedPort = event.ports[0];

  connectedPort.onmessage = (messageEvent) => {
    console.log('Received from client:', messageEvent.data);

    connectedPort.postMessage('Hello from Shared Worker');
  };

  connectedPort.start();
};
```

- здесь можно увидеть полный путь сообщения

```
main.js
   │
   │ port.postMessage('Hello')
   ▼
MessagePort
   │
   ▼
SharedWorker
   │
   │ onmessage
   ▼
connectedPort.postMessage(...)
   │
   ▼
MessagePort
   │
   ▼
main.js
```

## почему появляется MessagePort

- Shared Worker должен понимать, кто именно отправил сообщение
- представим три вкладки

```
Tab A ── Port A ──┐
                  │
Tab B ── Port B ──┼──► SharedWorker
                  │
Tab C ── Port C ──┘
```

- если Worker получает сообщение от Tab B, ему нужно иметь возможность ответить именно Tab B
- для этого у каждого подключения есть собственный MessagePort

```
Port A → связь с Tab A
Port B → связь с Tab B
Port C → связь с Tab C
```

- SharedWorker может хранить общее состояние
- это одна из наиболее интересных возможностей
- поскольку несколько контекстов подключаются к одному Worker, Worker может хранить состояние, доступное через его собственную логику всем этим подключениям
- например

```js
let connectedClients = 0;

self.onconnect = (event) => {
  const connectedPort = event.ports[0];

  connectedClients += 1;

  connectedPort.postMessage({
    clients: connectedClients,
  });
};
```

- теперь разные вкладки подключаются к одному Shared Worker

```
Tab A
  │
  └── подключение → clients = 1

Tab B
  │
  └── подключение → clients = 2

Tab C
  │
  └── подключение → clients = 3
```

- connectedClients принадлежит Shared Worker, а не конкретной вкладке
- поэтому это действительно может использоваться как общее состояние между несколькими подключениями

## SharedWorker и обмен сообщениями между вкладками

- это один из классических вариантов использования

- допустим, есть две вкладки

```
Tab A                 Tab B
  │                     │
  │                     │
  └──────┐       ┌──────┘
         ▼       ▼
       SharedWorker
```

- Tab A может отправить сообщение Shared Worker

```
Tab A
  │
  │ "hello"
  ▼
SharedWorker
```

- Worker может затем отправить сообщение Tab B

```
SharedWorker
     │
     │ "message from Tab A"
     ▼
   Tab B
```

- таким образом Shared Worker может выступать посредником между несколькими вкладками

## SharedWorker ≠ просто общий объект

- важно не представить Shared Worker как обычный JavaScript-объект, доступный из нескольких вкладок
- такого прямого доступа нет
- вкладки не делают

```js
sharedWorker.someVariable;
```

- чтобы взаимодействовать с Worker, используются сообщения и MessagePort

```
Tab A
  │
  │ message
  ▼
SharedWorker
  │
  │ message
  ▼
Tab B
```

## когда SharedWorker особенно полезен

- концептуально он подходит для ситуаций, когда нескольким контекстам нужно пользоваться одним процессом фоновой логики
- например

```
несколько вкладок
       │
       ▼
единый Shared Worker
       │
       ├── общее состояние
       ├── общая логика
       ├── координация
       └── обмен сообщениями
```

- исторически одним из примеров применения была координация нескольких вкладок одного приложения
- однако перед использованием в реальном проекте всегда нужно учитывать поддержку браузерами и архитектурные требования приложения

## SharedWorker и обычный Worker

```
|                                | `Worker`                        | `SharedWorker`                                   |
| ------------------------------ | ------------------------------- | ------------------------------------------------ |
| создание                       | `new Worker()`                  | `new SharedWorker()`                             |
| количество подключений         | обычно один клиентский контекст | несколько контекстов                             |
| основной канал                 | Worker                          | `MessagePort`                                    |
| получение подключения          | нет                             | `connect`                                        |
| обработчик                     | `onmessage`                     | `onconnect` → `port.onmessage`                   |
| общий контекст между вкладками | нет                             | да                                               |
| отдельное состояние            | да                              | одно состояние Shared Worker для его подключений |
```

## важный нюанс про «несколько вкладок»

- Shared Worker не означает, что любые произвольные вкладки браузера автоматически могут подключиться к одному Worker
- доступ определяется правилами браузера, прежде всего origin и URL Worker
- если разные страницы относятся к разным origin, они не смогут просто так использовать один и тот же Shared Worker

```
https://example.com/page-a
        │
        ├── SharedWorker
        │
https://example.com/page-b
        │
        └── может подключиться

https://another-site.com/page
        │
        └── другой origin
```

## жизненный цикл Shared Worker

- ещё один важный момент — Shared Worker может существовать, пока у него есть активные подключения или другая причина для продолжения работы
- поэтому его жизненный цикл отличается от простого сценария «создал Worker → сделал одну задачу → завершил»

```
Tab A ──┐
Tab B ──┼──► SharedWorker
Tab C ──┘
```

- если Tab A закрывается, это не означает автоматически, что Shared Worker должен немедленно прекратить работу, потому что Tab B и Tab C всё ещё могут быть подключены

```
Tab A ──X
Tab B ──┐
Tab C ──┼──► SharedWorker
        │
        └── продолжает использоваться
```

- именно это и является одной из ключевых идей Shared Worker

## что нужно запомнить для собеседования

- SharedWorker позволяет нескольким контекстам подключаться к одному Worker
- создаётся через new SharedWorker(...)
- для общения используется MessagePort
- у клиента основной канал находится в sharedWorker.port
- внутри Shared Worker подключение обрабатывается через self.onconnect
- конкретный MessagePort получается через event.ports[0]
- каждый клиент имеет свой порт

```
Tab A ── Port A ──┐
Tab B ── Port B ──┼──► SharedWorker
Tab C ── Port C ──┘
```

- Shared Worker может хранить состояние, общее для его подключений
- через Shared Worker можно организовать коммуникацию и координацию между несколькими вкладками одного приложения
- для интервью особенно важно не перепутать две модели

```
Worker

Tab A ──► Worker A


SharedWorker

Tab A ──┐
Tab B ──┼──► SharedWorker
Tab C ──┘
```
