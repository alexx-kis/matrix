# что такое Web Workers и зачем они нужны

- Web Worker — это механизм браузера, который позволяет выполнять JavaScript-код в отдельном потоке, не блокируя основной поток, в котором работает интерфейс страницы
- чтобы понять, зачем это нужно, сначала разберёмся, как JavaScript обычно выполняется в браузере

## обычное выполнение JavaScript

- когда мы открываем страницу, у браузера есть главный поток (main thread), который занимается сразу несколькими важными задачами
- в частности, этот поток выполняет JavaScript, обрабатывает события пользователя, рассчитывает изменения DOM, выполняет layout и участвует в отрисовке страницы
- условно можно представить это так

```
Main Thread
│
├── JavaScript
├── обработка click/input
├── обработка DOM
├── layout
└── rendering
```

- поэтому если мы запустим в основном потоке очень тяжёлую синхронную операцию, этот поток будет занят её выполнением

```js
function calculateSomething() {
  let total = 0;

  for (let index = 0; index < 10000000000; index++) {
    total += index;
  }

  return total;
}

calculateSomething();
```

- пока выполняется этот цикл, основной поток занят JavaScript-кодом
- браузер в этот момент не может нормально заниматься остальными задачами основного потока
- например, пользователь может попытаться нажать кнопку, подвигать мышью или прокрутить страницу, но обработка интерфейса будет задерживаться
- в результате мы получаем зависание интерфейса (UI freezing)

## почему setTimeout здесь не спасает

- важно не путать многопоточность с асинхронностью
- например

```js
setTimeout(() => {
  calculateSomething();
}, 0);
```

- это не означает, что `calculateSomething()` будет выполняться параллельно
- `setTimeout` лишь говорит браузеру: поставь эту задачу на выполнение позже
- когда очередь дойдёт до этой задачи, функция всё равно будет выполняться в main thread

```Main Thread

JavaScript
   │
   ├── setTimeout(...)
   │
   ├── другие задачи
   │
   └── calculateSomething()
          │
          └── блокирует main thread
```

- поэтому setTimeout, setInterval, Promise и async/await сами по себе не создают новый поток для выполнения JavaScript

## что делает Web Worker

- Web Worker позволяет вынести тяжёлую работу из основного потока в отдельный worker thread

```
                Browser
                   │
        ┌──────────┴──────────┐
        │                     │
   Main Thread           Worker Thread
        │                     │
    UI / DOM              тяжёлые вычисления
    events                 обработка данных
    rendering              parsing
                           calculations
```

- теперь тяжёлая операция выполняется не в main thread
- основной поток может продолжать заниматься интерфейсом
- например

```js
const calculationWorker = new Worker('worker.js');
```

- после этого calculationWorker представляет собой объект, через который основной поток может взаимодействовать с worker
- сам код worker находится в другом JavaScript-контексте

## главный смысл Web Workers

- тяжёлую CPU-bound работу можно вынести из main thread, чтобы она не блокировала интерфейс

- типичные примеры задач, которые могут иметь смысл выполнять в Worker

```
большие вычисления
        ↓
обработка больших массивов данных
        ↓
сложный parsing
        ↓
обработка текста
        ↓
криптографические вычисления
        ↓
обработка изображений / аудио
        ↓
сложные алгоритмы
```

- например, если приложение получает огромный JSON и нужно выполнить над ним сложную обработку, такую работу можно потенциально перенести в Worker

## Worker ≠ второй main thread

- здесь есть важный нюанс для собеседования
- Worker действительно выполняет JavaScript в отдельном потоке, но он не получает прямой доступ ко всему, что доступно main thread
- например, обычный Web Worker не может напрямую работать с DOM

```js
document.querySelector('button');
```

- такой подход внутри обычного Worker невозможен, потому что document относится к DOM-контексту страницы, а Worker работает отдельно
- поэтому взаимодействие между main thread и Worker строится преимущественно через обмен сообщениями

```
Main Thread
     │
     │  message
     ▼
Worker
     │
     │  message
     ▼
Main Thread
```

- например, main thread может сказать Worker: «вот тебе данные, обработай их»
- Worker выполнит работу и отправит результат обратно

## почему это особенно важно для frontend

- браузер должен оставаться отзывчивым
- пользователь ожидает, что кнопки нажимаются, анимации работают, scrolling не дёргается и ввод текста происходит без задержек
- если мы выполняем тяжёлые вычисления в main thread, мы конкурируем с этими задачами за один поток
- Web Workers позволяют разделить ответственность

```
Main Thread
→ интерфейс
→ события
→ DOM
→ rendering

Worker
→ тяжёлые вычисления
→ обработка данных
→ CPU-intensive задачи
```

## но Worker не нужен для всего

- создавать Worker для любой функции было бы плохой идеей
- у взаимодействия между потоками есть собственные накладные расходы
- данные нужно передать Worker, Worker должен их обработать, а результат нужно вернуть обратно
- поэтому Worker особенно полезен, когда вычисление достаточно тяжёлое, чтобы стоимость этого взаимодействия была оправдана
- например, для обычного

```js
const resultValue = 2 + 2;
```

- Worker совершенно бессмысленен
- а для действительно тяжёлой обработки большого объёма данных он уже может дать заметный выигрыш в отзывчивости интерфейса

## что нужно запомнить для собеседования

- Web Worker — API браузера для выполнения JavaScript в отдельном потоке
- его основная задача — не допускать блокировки main thread тяжёлыми вычислениями
- Worker и main thread работают независимо
- Worker обычно не имеет доступа к DOM страницы
- взаимодействие между ними происходит через message passing
- setTimeout, Promise и async/await сами по себе не создают отдельный поток
- Worker прежде всего полезен для CPU-intensive задач, а не просто для любого асинхронного кода
