# compression — базовая концепция

- Compression — это процесс уменьшения количества данных, необходимых для хранения или передачи информации
- в контексте браузера нас прежде всего интересует сжатие файлов перед передачей по сети
- например, сервер может иметь JavaScript-файл размером 500 KB, а по сети отправить его в сжатом виде, занимающем условно 150 KB

## зачем вообще нужна compression

- представим, что браузеру нужно скачать JavaScript

```
server
   │
   │  500 KB
   ↓
browser
```

- чем больше данных нужно передать, тем больше времени и трафика требуется
- если сервер сможет представить те же данные в более компактном виде, браузер получит исходное содержимое после распаковки

```
server
   │
   │  150 KB compressed
   ↓
browser
   │
   │  decompress
   ↓
original JavaScript
```

- при этом по сети физически было передано меньше данных

## главная идея compression

- compression использует закономерности внутри данных и старается представить повторяющуюся информацию более компактно
- например, если в данных много одинаковых символов

```
AAAAAAAAAAAAAAAAAAAAAAAA
```

- нет необходимости буквально хранить или передавать каждый A отдельно
- можно использовать более компактное представление, условно

```
24 × A
```

- реальные алгоритмы работают гораздо сложнее, но принцип примерно такой — найти избыточность и убрать её из представления данных

## compression не изменяет содержимое

- это ключевой момент
- compression должна позволять восстановить исходные данные

```
original data
      ↓
 compression
      ↓
compressed data
      ↓
decompression
      ↓
original data
```

- поэтому compression обычно относится к lossless compression, то есть сжатию без потери информации
- например, если сервер сжимает JavaScript

```js
const userName = 'Alex';
console.log(userName);
```

- после распаковки браузер должен получить именно тот JavaScript, который был сжат

## compression и minification — разные процессы

- это одна из самых важных вещей в этой теме
- minification изменяет сам JavaScript, делая его короче

```js
function calculateTotal(productPrice, productQuantity) {
  return productPrice * productQuantity;
}
```

- после minification:

```js
function calculateTotal(e, t) {return e * t}
```

- это уже другой текст JavaScript, хотя его поведение осталось тем же
- compression не предназначена для изменения логики или исходного текста программы
- она создаёт компактное представление этих данных для хранения или передачи

```
source JavaScript
       ↓
   minification
       ↓
minified JavaScript
       ↓
   compression
       ↓
compressed bytes
       ↓
    network
       ↓
  decompression
       ↓
minified JavaScript
       ↓
    browser
```

### простой пример

- допустим, у нас есть production bundle

```
app.js
500 KB
```

- после minification он стал меньше

```
app.js
300 KB
```

- затем сервер применил compression

```
app.js
300 KB

  ↓ compression

compressed response
100 KB
```

- браузер получает 100 KB
- после распаковки получает обратно те же 300 KB minified JavaScript
- затем JavaScript выполняется

## почему compression особенно эффективна для текстовых файлов

- JavaScript, CSS, HTML, JSON и SVG являются текстовыми форматами
- в них много повторяющихся последовательностей
- например, одинаковые имена свойств, конструкции JavaScript, пробелы, символы и другие повторяющиеся данные
- алгоритм compression может хорошо использовать эту избыточность
- поэтому веб-серверы обычно сжимают такие ресурсы перед отправкой браузеру

## где происходит compression

- compression выполняется обычно на сервере или CDN
- браузер отправляет серверу запрос и сообщает, какие алгоритмы сжатия он умеет распаковывать
- например, браузер может сообщить серверу

```
Accept-Encoding: gzip, br
```

- это означает примерно

```
я умею работать с gzip и Brotli
```

- сервер выбирает подходящий алгоритм и отправляет ответ, например

```
Content-Encoding: br
```

- это означает: "содержимое ответа сжато алгоритмом Brotli"

## gzip и Brotli

- в веб-разработке тебе особенно важно знать два алгоритма

```
gzip
Brotli
```

- gzip — очень распространённый алгоритм сжатия, который давно используется в HTTP
- Brotli — более современный алгоритм, разработанный Google и хорошо подходящий для веб-контента
- оба позволяют передавать текстовые ресурсы в сжатом виде

## важный момент про размер

- нельзя сказать, что compression всегда уменьшает файл в какое-то фиксированное количество раз
- степень сжатия зависит от содержимого
- например

```
file A
1000 KB → 300 KB

file B
1000 KB → 800 KB
```

- если данные уже хорошо сжаты или содержат мало повторяющейся информации, дополнительное сжатие может дать небольшой эффект

## а изображения?

- здесь ситуация интереснее
- некоторые форматы изображений уже используют compression внутри самого формата
- например, JPEG и WebP уже используют собственные методы сжатия
- поэтому повторно применять gzip или Brotli к таким файлам обычно гораздо менее эффективно, чем к JavaScript, CSS или HTML

## зачем нам тогда minification + compression

- эти процессы хорошо дополняют друг друга

```
                  minification
                       ↓
developer code ──→ minified JS
                       ↓
                    Brotli
                       ↓
                network transfer
                       ↓
                    browser
                       ↓
                  decompression
                       ↓
                minified JS
```

- minification уменьшает сам JavaScript
- compression уменьшает количество байт, которое нужно передать по сети
- поэтому production-сайт обычно использует оба механизма

## что нужно запомнить для собеседования

- compression — уменьшение размера данных за счёт более компактного представления
- для веба compression особенно важна при передаче HTML, CSS, JavaScript и JSON
- compression обычно является lossless, поэтому после распаковки можно восстановить исходные данные
- gzip и Brotli — основные алгоритмы, которые нужно знать
- minification и compression — не одно и то же
- minification изменяет текст JavaScript, например удаляет пробелы и сокращает имена
- compression создаёт компактное представление уже готового файла для передачи
- обычно последовательность выглядит так: bundle → minification → compression → network → decompression → browser
