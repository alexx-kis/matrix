# Gzip vs Brotli compression

- Gzip и Brotli — это алгоритмы lossless compression, которые используются в HTTP для уменьшения размера передаваемых данных
- оба особенно полезны для текстовых ресурсов — JavaScript, CSS, HTML, JSON, SVG
- разница между ними в основном заключается в эффективности сжатия, скорости и поддержке

## gzip

- Gzip — очень старый и широко поддерживаемый алгоритм сжатия, который используется в интернете уже много лет
- технически gzip обычно использует алгоритм DEFLATE, который сочетает несколько методов сжатия
- для браузера процесс выглядит примерно так

```
    server
      │
      │ app.js = 300 KB
      ↓
    gzip
      │
      │ 90 KB
      ↓
    browser
      │
      ↓
decompression
      │
      ↓
app.js = 300 KB
```

- браузер сообщает серверу, что поддерживает gzip `Accept-Encoding: gzip`
- сервер отвечает `Content-Encoding: gzip`

## Brotli

- Brotli — более современный алгоритм compression, разработанный Google
- он специально хорошо подходит для веб-контента
- Brotli обычно способен получить меньший размер файла, чем gzip, особенно на текстовых ресурсах
- например, условно

```
original JavaScript
300 KB

gzip
100 KB

Brotli
85 KB
```

- это только иллюстрация, потому что реальное соотношение зависит от конкретного файла и настроек compression

## почему Brotli может сжимать лучше

- Brotli использует более современный алгоритм и имеет встроенный статический словарь
- этот словарь содержит часто встречающиеся последовательности, которые характерны для текстовых и веб-данных
- поэтому алгоритму проще находить повторяющиеся конструкции в HTML, CSS и JavaScript
- например, в JavaScript постоянно встречаются определённые последовательности символов и ключевые слова
- Brotli может эффективно использовать подобные закономерности

## сравнение размера

- условно представим production bundle

```
app.js
1000 KB
```

- после gzip `300 KB`

- после Brotli `250 KB`

- получается

```
1000 KB
   │
   ├── gzip   → 300 KB
   │
   └── Brotli → 250 KB
```

- это означает, что Brotli может уменьшить количество данных, передаваемых браузеру

## но размер — не единственный критерий

- compression требует CPU
- чем сильнее мы пытаемся сжать данные, тем больше вычислений может потребоваться
- поэтому у алгоритмов есть разные уровни compression

```
compression level
       ↓
больше compression
       ↓
меньше файл
       ↓
но больше CPU/time
```

- и наоборот

```
меньше compression
       ↓
больше файл
       ↓
но быстрее compression
```

- поэтому нельзя просто сказать «всегда использовать максимально сильное сжатие»

## Brotli имеет уровни compression

- Brotli поддерживает уровни от 0 до 11
- низкие уровни быстрее
- высокие уровни обычно дают меньший файл, но требуют больше вычислений
- для static compression это особенно удобно
- можно потратить больше CPU во время build

```
build
 ↓
Brotli level 11
 ↓
app.js.br
 ↓
deploy
```

- после этого пользователи получают уже готовый результат
- серверу не приходится каждый раз выполнять тяжёлое сжатие

## gzip тоже имеет уровни

- gzip обычно использует уровни от 0 до 9
- принцип такой же

```
низкий уровень
    ↓
быстрее compression
    ↓
больше файл

высокий уровень
    ↓
медленнее compression
    ↓
меньше файл
```

## поддержка браузерами

- для современного frontend Brotli давно имеет широкую поддержку
- поэтому сегодня обычно можно рассматривать Brotli как предпочтительный вариант для современных браузеров
- при этом gzip всё ещё очень важен как fallback

```
browser
   │
   ├── supports Brotli → app.js.br
   │
   └── supports gzip   → app.js.gz
```

- поэтому сервер или CDN может иметь оба варианта

```
dist/
├── app.js
├── app.js.br
└── app.js.gz
```

## как браузер сообщает, что он поддерживает

- браузер отправляет HTTP-заголовок `Accept-Encoding: br, gzip`
- здесь br означает Brotli
- gzip означает gzip
- сервер выбирает подходящий алгоритм и сообщает браузеру, каким алгоритмом был сжат ответ `Content-Encoding: br`
- браузер видит br и автоматически распаковывает содержимое перед использованием

## важный момент: Brotli не заменяет minification

- это принципиально разные этапы

```
source code
     ↓
tree shaking
     ↓
minification
     ↓
  app.js
     ↓
  Brotli
     ↓
 app.js.br
     ↓
  network
```

- например, minification превращает

```js
function calculateTotal(productPrice, productQuantity) {
  return productPrice * productQuantity;
}
```

- в более компактный JavaScript `function calculateTotal(e,t){return e*t}`
- а Brotli уже берёт этот готовый текстовый файл и создаёт его сжатое представление для передачи

## static Brotli

- для frontend production очень часто удобно заранее создать Brotli-файлы

```
app.js
   ↓
Brotli
   ↓
app.js.br
```

- сервер или CDN затем просто отдаёт app.js.br
- это особенно хорошо подходит для файлов с content hash

```
app.a8f31c.js
app.a8f31c.js.br
```

- пока hash не изменился, содержимое файла не меняется
- значит, заранее созданная сжатая версия тоже остаётся актуальной

## dynamic Brotli

- Brotli можно использовать и динамически

```
request
   ↓
server
   ↓
Brotli compression
   ↓
response
```

- это удобно для динамического контента
- но сервер должен тратить CPU на compression при обработке запросов
- поэтому для больших неизменяемых frontend-файлов часто выгоднее precompression, а для динамического контента может использоваться dynamic compression

## gzip vs Brotli

```
|                      | gzip                 | Brotli                               |
| -------------------- | -------------------- | ------------------------------------ |
| возраст              | старый               | более современный                    |
| compression          | хорошая              | обычно лучше для web-текста          |
| размер результата    | обычно больше        | обычно меньше                        |
| скорость compression | обычно очень хорошая | зависит от уровня                    |
| уровни               | `0–9`                | `0–11`                               |
| современный frontend | используется         | часто предпочтительный вариант       |
| fallback             | —                    | gzip часто используется как fallback |
```

## что происходит в реальном production

- условно production pipeline может выглядеть так

```
source
  ↓
bundling
  ↓
tree shaking
  ↓
minification
  ↓
app.js
  ↓
 ┌──────────────┐
 ↓              ↓
gzip           Brotli
 ↓              ↓
app.js.gz      app.js.br
 └──────┬───────┘
        ↓
      server/CDN
        ↓
      browser
```

- браузер сообщает поддерживаемые алгоритмы через Accept-Encoding
- сервер или CDN выбирает подходящую версию
- браузер распаковывает ответ автоматически

## что важно не перепутать

- gzip и Brotli не являются форматами JavaScript
- они не изменяют JavaScript-логику
- они являются алгоритмами сжатия передаваемых данных
- minification уменьшает сам код
- Brotli/gzip уменьшают размер его представления при передаче

## что нужно запомнить для собеседования

- gzip и Brotli — алгоритмы lossless compression
- оба используются для уменьшения размера HTTP-ответов
- Brotli обычно обеспечивает лучшее сжатие веб-текста, чем gzip
- gzip остаётся очень распространённым и полезным fallback
- браузер сообщает поддерживаемые алгоритмы через Accept-Encoding
- сервер сообщает использованный алгоритм через Content-Encoding
- br означает Brotli
- Brotli имеет уровни compression 0–11, gzip — 0–9
- высокий уровень compression обычно означает меньший файл, но больше затрат CPU и времени
- для статических frontend-файлов Brotli можно выполнить заранее во время build/deploy
- minification и Brotli решают разные задачи: minification уменьшает код, Brotli уменьшает объём данных для передачи
