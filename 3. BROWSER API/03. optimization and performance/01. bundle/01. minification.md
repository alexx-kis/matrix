# minification

- Minification — это процесс уменьшения размера JavaScript-файла за счёт удаления всего, что не влияет на его выполнение
- главная цель minification — уменьшить количество байт, которые браузеру приходится скачать, чтобы приложение загрузилось быстрее

## что именно удаляется

- в исходном коде программисту нужны пробелы, переносы строк, отступы и комментарии, чтобы код было удобно читать
- JavaScript-движку эти элементы в большинстве случаев не нужны

### например, исходный код может выглядеть так
```js
function calculateTotal(price, quantity) {
    // calculate final price
    const total = price * quantity;


    return total;
}
```
- после minification он может превратиться примерно в такой код
```js
function calculateTotal(e,t){return e*t}
```

- здесь были удалены комментарий, пробелы и переносы строк
- кроме этого, minifier переименовал локальные переменные price и quantity в короткие e и t

## зачем переименовывать переменные

- это позволяет дополнительно уменьшить размер файла
- например, имя calculateSomethingVeryImportant занимает гораздо больше символов, чем a
```js
function calculateSomethingVeryImportant(firstValue, secondValue) {
    const result = firstValue + secondValue;
    return result;
}
```

- после минификации это может стать
```js
function calculateSomethingVeryImportant(a,b){return a+b}
```
- но minifier обычно может сократить и имя самой функции, если он уверен, что это безопасно
- например, внутренние переменные и функции, которые не используются за пределами определённой области видимости, можно агрессивно переименовывать

## важно: minification не меняет смысл программы

- главная идея заключается в том, что после минификации программа должна вести себя так же, как до неё
```js
const firstNumber = 10;
const secondNumber = 20;

console.log(firstNumber + secondNumber);
```

- может превратиться в
```js
const o=10,c=20;console.log(o+c);
```

- результат останется 30
- изменилось представление кода, а не его логика

## minification и compression — это не одно и то же

- здесь есть важный нюанс, который часто спрашивают на собеседованиях
- minification изменяет сам текст JavaScript, делая его короче
- compression сжимает уже получившийся файл специальным алгоритмом передачи данных
- например, типичный production-процесс может выглядеть так
```
исходный JS
    ↓
bundle
    ↓
minification
    ↓
bundle.js
    ↓
gzip / Brotli
    ↓
передача браузеру
```

- то есть сначала мы можем получить один большой bundle, затем уменьшить его с помощью minification, а затем сервер дополнительно сожмёт его с помощью Brotli или gzip
## зачем это особенно важно для bundle

- bundle может содержать десятки или сотни тысяч строк JavaScript
- если оставить весь код в удобном для человека формате, размер файла будет значительно больше
- после minification браузеру приходится скачивать меньше данных
- например, условно
```
development:
500 KB

после minification:
300 KB

после Brotli:
90 KB
```

- конкретные цифры зависят от содержимого файла, поэтому это только иллюстрация принципа

## что делает minifier

- современный minifier обычно выполняет не просто удаление пробелов
- он анализирует JavaScript и может выполнять различные code transformations
- например, сокращать имена локальных переменных
```js
function calculatePrice(productPrice, productQuantity) {
    const totalPrice = productPrice * productQuantity;
    return totalPrice;
}
function calculatePrice(e,t){return e*t}
```

- удалять комментарии
```js
// calculate price
const totalPrice = productPrice * productQuantity;
const totalPrice=productPrice*productQuantity;
```

- удалять необязательные пробелы и переносы строк
```js
const result = firstValue + secondValue;
const result=firstValue+secondValue;
```

- а также выполнять более сложные оптимизации, если конкретный minifier это поддерживает

## minification ≠ uglification

- иногда можно встретить термин uglify
- исторически существовал популярный инструмент UglifyJS, название которого как раз отражало идею превращения - кода в «некрасивый» для человека вид
- сегодня обычно говорят minification, а инструменты вроде Terser выполняют гораздо больше, чем простое удаление пробелов

## почему minified-код неудобен человеку

- после минификации код специально становится плохо читаемым
```js
function calculateTotal(e,t){return e*t}
```

- поэтому production-файл обычно не предназначен для ручного редактирования
- разработчик работает с исходными файлами
```
src/
    cart.js
    products.js
    checkout.js
```
- а сборщик создаёт production bundle
```
dist/
    app.min.js
```

- именно поэтому в реальном проекте обычно существуют два представления одного приложения — читаемый исходный код для разработчика и оптимизированный код для браузера

## важный нюанс с const, let и переменными

- minifier не может просто бездумно переименовать любую переменную
- он должен сохранить семантику программы
```js
const userName = "Alex";

function showUser() {
    const userName = "Kate";
    console.log(userName);
}

showUser();
console.log(userName);
```

- здесь два разных `userName`
- они находятся в разных лексических окружениях
- безопасный minifier может переименовать их независимо, потому что изменение имени внутри одной области видимости не должно изменить поведение программы

## а что с именами, которые видны снаружи

- здесь становится сложнее
- если имя используется как часть внешнего API, его нельзя просто переименовать без последствий
```js
window.calculatePrice = function () {
    // ...
};
```

- внешний код может обращаться именно к
```js
window.calculatePrice();
```

- если minifier превратит calculatePrice в другое имя, внешний код перестанет его находить
- поэтому minification должен учитывать границы между внутренним кодом программы и тем, что доступно извне

## что нужно запомнить для собеседования

- minification — уменьшение размера исходного кода без изменения его поведения
- удаляются комментарии, лишние пробелы и переносы строк
- могут сокращаться имена локальных переменных и выполняться дополнительные безопасные оптимизации
- цель — уменьшить размер JavaScript bundle и ускорить его передачу браузеру
- minification происходит на этапе сборки, а не в браузере
- minification и compression — разные вещи
- minified-код обычно плохо читается человеком, поэтому разработчик продолжает работать с исходным кодом
- после minification часто применяется gzip или Brotli, что дополнительно уменьшает объём передаваемых данных
