# critical css

- Critical CSS — это CSS, который необходим для отображения первой видимой части страницы, то есть того, что пользователь видит сразу после открытия страницы
- идея очень простая: браузеру не обязательно ждать загрузки всего CSS, чтобы показать пользователю первый экран

## в чём проблема

- представим страницу, на которой огромный CSS-файл

```
styles.css
    ↓
500 KB
    ↓
загрузка
    ↓
CSS parsing
    ↓
только после этого браузер может нормально отрисовать страницу
```

- при этом пользователю в первую очередь нужны, например, только стили для:
  - header
  - navigation
  - hero section
  - main heading
  - button

- стили для нижней части страницы ему прямо сейчас не нужны, потому что он её ещё не видит
- Critical CSS позволяет дать браузеру эти необходимые стили как можно раньше

## что такое critical

- critical здесь означает не «важный вообще», а необходимый для первоначального отображения
- например, пользователь сразу видит:

```
┌──────────────────────────┐
│        HEADER            │
├──────────────────────────┤
│                          │
│      Welcome!            │
│                          │
│      [ Get started ]     │
│                          │
└──────────────────────────┘
```

- CSS для этих элементов относится к critical CSS
- а стили для:
  - footer
  - comments
  - нижних секций

- не являются critical для первого отображения

## как это работает

- один из вариантов — поместить critical CSS прямо в `<head>`

```html
<head>
  <style>
    header {
      height: 60px;
    }

    .hero {
      display: flex;
      align-items: center;
    }

    .button {
      padding: 12px 20px;
    }
  </style>

  <link rel="stylesheet" href="styles.css" />
</head>
```

- браузер получает эти небольшие стили непосредственно вместе с HTML
- поэтому ему не обязательно ждать отдельной загрузки большого styles.css, чтобы начать отображать первый экран

```
HTML
 ↓
critical CSS
 ↓
быстрая initial render
 ↓
остальной CSS
 ↓
полная стилизация страницы
```

## почему это ускоряет загрузку

- CSS по умолчанию является render-blocking resource
- это означает, что браузеру обычно необходимо получить и обработать CSS, прежде чем он сможет корректно отрисовать страницу
- поэтому большой CSS может задерживать first render
- Critical CSS уменьшает объём CSS, необходимого для первого отображения

```
без Critical CSS

HTML
 ↓
большой styles.css
 ↓
download
 ↓
parse
 ↓
render
```

```
с Critical CSS

HTML
 ↓
critical CSS
 ↓
render first screen
 ↓
остальной CSS
```

- но зачем тогда вообще нужен остальной CSS
- потому что Critical CSS покрывает только первоначально видимую область
- после этого браузеру всё равно нужны остальные стили

```
Critical CSS
     ↓
first viewport

Full CSS
     ↓
вся остальная страница
```

- поэтому Critical CSS не заменяет основной CSS

## важный нюанс — inline CSS

- если Critical CSS помещается непосредственно в HTML через `<style>`, это называется inlining Critical CSS

```html
<style>
  /* critical styles */
</style>
```

- преимущество в том, что браузеру не нужен отдельный HTTP-запрос за этими стилями
- недостаток в том, что HTML становится больше
- поэтому Critical CSS стараются делать маленьким

## что происходит на практике

- обычно специальный инструмент анализирует страницу и определяет, какие CSS-правила нужны для первого viewport

```
full CSS
   ↓
analysis
   ↓
critical CSS
   +
remaining CSS
```

- затем critical часть может быть встроена в HTML, а оставшийся CSS загружается отдельно

## Critical CSS и responsive design

- здесь есть ещё один важный нюанс
- что является Critical CSS, зависит от размера viewport
- например, на desktop пользователь сразу видит
  - header
  - hero
  - sidebar

- а на mobile:
  - header
  - hero
  - mobile menu

- поэтому Critical CSS может отличаться для разных устройств и разрешений

## Critical CSS и JavaScript

- Critical CSS относится именно к стилям, необходимым для первого отображения
- он не означает, что JavaScript становится critical или что JavaScript вообще не нужен
- это отдельная оптимизация rendering/loading pipeline

## как это связано с предыдущими темами

- у нас уже были:
  - minification
  - compression
  - caching
  - async / defer
  - Critical CSS
- это разные оптимизации

- minification → уменьшаем содержимое CSS/JS

- compression → уменьшаем данные при передаче

- caching → не скачиваем ресурс повторно

- async / defer → оптимизируем загрузку и выполнение JS

- Critical CSS → быстрее показываем первый экран

## что нужно знать на собеседовании

- Critical CSS — минимальный набор CSS, необходимый для первоначального отображения видимой части страницы
- его цель — ускорить initial render и уменьшить задержку первого отображения
- CSS обычно является render-blocking resource
- Critical CSS часто помещают inline в `<head>`
- остальной CSS загружается отдельно
- Critical CSS не заменяет весь CSS
- состав Critical CSS зависит от того, что пользователь видит в первом viewport
- главная идея: сначала дать браузеру стили, необходимые для первого экрана, а остальной CSS обработать позже
