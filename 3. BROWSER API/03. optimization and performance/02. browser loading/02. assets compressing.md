# assets compressing

- **asset compression** — это уменьшение размера файлов, которые браузер должен скачать для работы сайта
- под `assets` обычно понимаются статические ресурсы приложения: JavaScript, CSS, изображения, шрифты, видео и другие файлы

```
 исходный файл
      ↓
  compression
      ↓
файл меньшего размера
      ↓
   download
      ↓
    browser
```

- например, если `app.js` весит `1 MB`, после сжатия HTTP-сервер может передать его браузеру в гораздо меньшем размере

## зачем это нужно

- чем меньше данных нужно передать по сети, тем быстрее ресурс обычно загружается
- это особенно важно для мобильных устройств и медленных соединений
- уменьшается также количество передаваемых данных и нагрузка на сервер и сеть
- при этом важно понимать, что **compression не обязательно изменяет сам исходный asset**
- сервер может хранить обычный `app.js`, а перед отправкой сжимать его для передачи

## compression и minification — не одно и то же

- это очень важное различие для собеседования
- **minification** изменяет содержимое файла, удаляя всё ненужное для выполнения программы

```js
function calculateTotal(price, tax) {
  return price + price * tax;
}
```

- после minification это может превратиться примерно в

```
function calculateTotal(a,b){return a+a*b}
```

- **compression** уменьшает количество байтов в передаваемом файле с помощью алгоритма сжатия

```text
JavaScript
   ↓
minification
   ↓
меньше текста
   ↓
compression
   ↓
ещё меньше передаваемых байтов
```

- поэтому на практике эти оптимизации часто используются вместе

## compression бывает разным для разных assets

- для текстовых ресурсов вроде `JS`, `CSS`, `HTML`, `JSON` обычно хорошо подходят алгоритмы **Gzip** и **Brotli**
- для изображений используются специализированные форматы и алгоритмы

```text
JS / CSS / HTML / JSON
        ↓
   Brotli / Gzip

images
        ↓
JPEG / WebP / AVIF

fonts
        ↓
WOFF2
```

- нельзя просто взять любой файл и ожидать одинакового выигрыша от compression
- например, JPEG уже содержит собственное сжатие, поэтому дополнительный Gzip часто практически ничего не даст

## что происходит при загрузке сайта

- допустим, браузеру нужен `app.js`

- браузер отправляет HTTP-запрос
- сервер видит, что клиент поддерживает Brotli, и может отправить сжатую версию

```
Accept-Encoding: br, gzip
```

- сервер может ответить

```
Content-Encoding: br
```

- это означает, что содержимое HTTP-ответа сжато алгоритмом Brotli
- браузер получает сжатые данные и автоматически распаковывает их перед использованием

```
app.js
   ↓
server compression
   ↓
compressed data
   ↓
network
   ↓
browser
   ↓
decompression
   ↓
JavaScript
```

## compression vs file size

- здесь есть важный нюанс
- когда в DevTools ты видишь размер ресурса, можно увидеть разные значения, например размер **transferred** и размер **resource**
- условно:

```
Resource size:    1 MB
Transferred:      300 KB
```

- это может означать, что исходное содержимое ресурса занимает `1 MB`, но по сети реально было передано около `300 KB` благодаря compression
- поэтому нельзя автоматически считать, что asset на сервере стал физически весить `300 KB`

## compression vs caching

- эти механизмы решают разные проблемы
- **compression** уменьшает количество данных, которые нужно передать
- **caching** позволяет вообще не передавать ресурс повторно

```
первое посещение:
server → compressed asset → browser cache

повторное посещение:
browser cache → browser
```

- поэтому они отлично работают вместе

## что нужно запомнить

- **assets compression** — уменьшение количества байтов, передаваемых по сети
- для `HTML`, `CSS`, `JS`, `JSON` обычно используются Brotli или Gzip
- для изображений применяются специализированные форматы вроде WebP и AVIF
- compression не то же самое, что minification
- minification уменьшает содержимое исходного текста
- compression уменьшает размер данных при передаче
- caching вообще позволяет избежать повторной передачи ресурса
- типичная production-цепочка выглядит примерно так

```
source code
    ↓
bundling
    ↓
minification
    ↓
hashed assets
    ↓
HTTP compression
    ↓
browser cache
```

- для собеседования особенно важно не смешивать **minification**, **compression** и **caching**, потому что это три разных механизма оптимизации загрузки
