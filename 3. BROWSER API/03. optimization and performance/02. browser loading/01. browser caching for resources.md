# browser caching for resources

- browser caching — это механизм, при котором браузер сохраняет уже загруженные ресурсы сайта локально, чтобы при следующих обращениях не скачивать их заново
- к таким ресурсам относятся HTML, CSS, JavaScript-файлы, изображения, шрифты, видео и другие файлы
- главная цель — ускорить загрузку сайта и уменьшить количество сетевых запросов

## как это работает

- допустим, браузер впервые открывает https://example.com
- сервер отправляет HTML, а HTML говорит браузеру загрузить, например, style.css и app.js
- браузер скачивает эти файлы и может сохранить их в HTTP cache
- при следующем открытии сайта браузер смотрит на cache и проверяет, можно ли использовать сохранённые файлы

- первое посещение:

```
Browser
   ↓ request
Server
   ↓ response: app.js
Browser
   ↓
HTTP Cache
```

- при повторном посещении браузер может сделать так

```
Browser
   ↓
HTTP Cache
   ↓
app.js уже есть
```

- то есть запрос к серверу для получения самого файла может вообще не понадобиться

## но браузер не может просто вечно использовать старый файл

- представь, что пользователь однажды скачал app.js
- через неделю разработчик изменил код и загрузил новый app.js на сервер
- если браузер всегда использовал бы свою старую копию, пользователь продолжал бы получать старый JavaScript
- поэтому сервер сообщает браузеру сколько времени ресурс можно считать актуальным и как проверить, не изменился ли он
- для этого используются HTTP-заголовки кэширования

## Cache-Control

- один из главных заголовков — Cache-Control

```
Cache-Control: max-age=3600
```

- max-age=3600 означает, что браузер может считать ресурс свежим в течение 3600 секунд, то есть одного часа
- например, браузер получил app.js в 12:00
- до 13:00 он может использовать сохранённую копию без повторной загрузки файла

## что происходит после истечения max-age

- после истечения срока браузер не обязательно сразу скачивает весь файл заново
- он может спросить сервер, изменился ли ресурс
- для этого используются условные запросы и заголовки вроде ETag и Last-Modified

```
If-None-Match: "abc123"
```

- сервер сравнивает этот идентификатор со своей текущей версией ресурса
- если файл не изменился, сервер может ответить

```
304 Not Modified
```

- это означает примерно «у тебя уже есть актуальная версия, используй её»
- в таком случае браузеру не приходится заново передавать содержимое всего файла

## `ETag`

- ETag — это идентификатор конкретной версии ресурса

```
ETag: "abc123"
```

- браузер сохраняет этот идентификатор вместе с ресурсом
- когда ресурс становится stale, браузер может отправить его серверу обратно в условии

```
If-None-Match: "abc123"
```

- если версия всё ещё та же, сервер отвечает 304
- если файл изменился, сервер отправляет новую версию

## `Last-Modified`

- другой вариант — сервер сообщает, когда ресурс последний раз изменялся

```
Last-Modified: Wed, 26 Aug 2026 10:00:00 GMT
```

- браузер впоследствии может отправить

```
If-Modified-Since: Wed, 26 Aug 2026 10:00:00 GMT
```

- сервер опять же может ответить 304 Not Modified, если файл не изменился

## самое важное различие

- есть два принципиально разных сценария

```
resource fresh
↓
используем cache
↓
сервер вообще не нужен
```

- либо

```
resource stale
↓
спрашиваем сервер
↓
304 Not Modified
↓
используем cache
```

- либо

```
resource stale
↓
спрашиваем сервер
↓
resource изменился
↓
получаем новый файл
```

## почему это особенно важно для frontend

- представь, что твой production bundle весит 500 KB
- без эффективного caching пользователь может скачивать эти 500 KB при каждом посещении
- с caching браузер скачивает их один раз, а последующие посещения используют локальную копию
- поэтому caching напрямую влияет на loading performance

## важный нюанс с JavaScript и CSS

- возникает проблема, когда файл называется всегда одинаково `app.js`
- ты изменил код, но браузер может продолжать использовать старую закэшированную версию
- поэтому современные сборщики используют content hashing `app.a83f21.js`
- после изменения содержимого hash меняется

```
app.a83f21.js
        ↓
app.f91c72.js
```

- для браузера это уже другой URL, поэтому он скачает новый файл
- старый файл при этом можно очень долго хранить в cache

```
Cache-Control: max-age=31536000, immutable
```

- именно поэтому связка cache + hashed filenames является очень распространённым подходом в production frontend

## что нужно запомнить для собеседования

- browser cache — локальное хранилище HTTP-ресурсов, позволяющее не скачивать их повторно
- Cache-Control определяет правила кэширования
- max-age определяет, сколько секунд ресурс считается свежим
- ETag позволяет проверить, изменилась ли версия ресурса
- Last-Modified позволяет проверять ресурс по времени изменения
- 304 Not Modified означает, что сохранённая версия всё ещё актуальна
- fresh resource → браузер может использовать cache без запроса к серверу
- stale resource → браузер может проверить ресурс у сервера
- content hashing (app.a83f21.js) позволяет безопасно кэшировать статические frontend-ресурсы на длительный срок
