# async и defer scripts

- async и defer — это атрибуты `<script>`, которые определяют, как браузер загружает и выполняет внешний JavaScript-файл относительно парсинга HTML
- чтобы понять разницу, сначала нужно понять обычный `<script>`

## обычный `<script>`

- представим HTML

```html
<script src="app.js"></script>

<h1>Hello</h1>
```

- браузер читает HTML сверху вниз

```
HTML parsing
     ↓
<script>
     ↓
остановка parsing
     ↓
загрузка app.js
     ↓
выполнение app.js
     ↓
продолжение parsing
     ↓
<h1>
```

- то есть обычный script блокирует парсинг HTML
- браузер встречает `<script>`, останавливает построение DOM, загружает JavaScript и выполняет его, и только после этого продолжает читать HTML

## defer

- теперь добавим defer

```html
<script defer src="app.js"></script>

<h1>Hello</h1>
```

- здесь поведение меняется

```
HTML parsing ────────────────────────┐
                                     │
                 download app.js     │
                     ↓               │
                     └───────────────┤
                                     ↓
                               HTML parsed
                                     ↓
                               execute app.js
```

- главное отличие — загрузка JavaScript происходит параллельно с parsing HTML
- браузер не останавливает parsing только потому, что встретил defer
- но выполнение скрипта происходит после того, как HTML полностью распарсен

## важное свойство defer

- несколько defer-скриптов сохраняют порядок выполнения

```html
<script defer src="first.js"></script>
<script defer src="second.js"></script>
```

- браузер может загружать их параллельно

```
download first.js  ──────────┐
download second.js ───────┐  │
                           ↓  ↓
                    HTML parsing done
                           ↓
                       first.js
                           ↓
                      second.js
```

- поэтому second.js не выполнится раньше first.js, даже если скачался раньше
- это важно, когда один скрипт зависит от другого

## async

- теперь посмотрим на async

```html
<script async src="analytics.js"></script>

<h1>Hello</h1>
```

- async тоже позволяет загружать JavaScript параллельно с parsing HTML

```
HTML parsing ───────────────────────────
              │
download ─────┘
              ↓
         execute script
              ↓
         HTML parsing
```

- но есть принципиальная разница с defer
- как только async-скрипт загрузился, браузер сразу его выполняет
- при этом parsing HTML может быть прерван

## главное различие async и defer

```
                  async               defer

download       parallel               parallel

HTML parsing   может прерваться       продолжается

execution      сразу после загрузки   после полного parsing HTML

order          НЕ гарантирован        гарантирован
```

- можно представить это так

```
async:

HTML parsing ────────────┬──────────────
                         ↓
                    script loaded
                         ↓
                    EXECUTION
                         ↓
HTML parsing ────────────┴──────────────
```

```
defer:

HTML parsing ───────────────────────────┐
                                        ↓
                                   parsing done
                                        ↓
                                   EXECUTION
```

## почему async не гарантирует порядок

- допустим

```html
<script async src="one.js"></script>
<script async src="two.js"></script>
```

- one.js может быть большим, а two.js маленьким

```
one.js   ────────────────→ loaded

two.js   ─────→ loaded
              ↓
          execute two.js
              ↓
          execute one.js
```

- поэтому two.js может выполниться раньше one.js
- если скрипты зависят друг от друга, async может привести к ошибке

## когда использовать async

- async хорошо подходит для независимых скриптов
- например, аналитика, рекламные скрипты или другие скрипты, которым неважно, когда именно выполнятся другие JavaScript-файлы

```html
<script async src="analytics.js"></script>
```

- идея здесь такая: «загрузи этот скрипт как можно быстрее и выполни, когда он будет готов»

## когда использовать defer

- defer обычно подходит для JavaScript приложения, которое работает с DOM

```html
<script defer src="app.js"></script>
```

- браузер сначала спокойно распарсит HTML
- после этого выполнит app.js
- поэтому к моменту выполнения defer-скрипта DOM уже построен

## ещё один важный нюанс

- defer и async имеют смысл прежде всего для внешних скриптов с src

```html
<script defer src="app.js"></script>
```

- для обычного inline-скрипта

```html
<script>
  console.log('hello');
</script>
```

- эти атрибуты не дают такого же поведения загрузки, потому что здесь вообще нечего загружать по сети

## а что если написать async defer вместе

```
<script async defer src="app.js"></script>
```

- для современных браузеров приоритет имеет async
- то есть такой скрипт будет вести себя как async
- исторически комбинация использовалась для совместимости со старыми браузерами

## а где ставить `<script>` — в `<head>` или в конце `<body>`

- раньше часто использовали такой подход

```html
<body>
  ...
  <script src="app.js"></script>
</body>
```

- скрипт ставили в конец body, чтобы браузер сначала успел построить HTML
- с defer можно спокойно разместить внешний скрипт в <head>

```html
<head>
  <script defer src="app.js"></script>
</head>
```

- при этом HTML продолжает парситься, пока JavaScript загружается

## что происходит с DOM

- это особенно важно понимать для frontend-собеседования
- обычный script может выполнить JavaScript до того, как нижняя часть HTML была превращена в DOM
- defer выполняется после завершения parsing HTML
- поэтому

```html
<script defer src="app.js"></script>

<div id="app"></div>
```

- к моменту выполнения `app.js` элемент `#app` уже будет создан в DOM

## короткая модель для запоминания

- обычный script — «остановись, скачай, выполни, продолжай»
- async — «скачивай параллельно и выполни сразу, как только скачал»
- defer — «скачивай параллельно, но выполни после parsing HTML»

```
обычный:

parse → STOP → download → execute → parse


async:

parse →──────────────→
         download
             ↓
           STOP
             ↓
          execute


defer:

parse →────────────────────→ done
         download             ↓
                          execute
```

- для собеседования главное запомнить четыре вещи: оба позволяют скачивать внешний скрипт параллельно с parsing HTML, async выполняется сразу после загрузки, defer выполняется после parsing HTML, порядок async не гарантирован, а порядок defer сохраняется
