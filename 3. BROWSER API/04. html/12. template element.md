# `<template>` element

- `<template>` предназначен для хранения **HTML-шаблона, который не отображается и не участвует в DOM страницы до момента его использования**
- это позволяет заранее описать структуру элемента, а затем создавать её копии через JavaScript

## базовый пример

```html
<template id="user-card-template">
  <article class="user-card">
    <h2 class="user-name"></h2>
    <p class="user-email"></p>
  </article>
</template>
```

- содержимое `<template>` не появляется на странице

- чтобы использовать шаблон, обычно получают его `content`

```js
const userTemplate = document.querySelector('#user-card-template');
const userFragment = userTemplate.content.cloneNode(true);

document.body.append(userFragment);
```

- `template.content` содержит содержимое шаблона в виде `DocumentFragment`
- `cloneNode(true)` создаёт копию всей структуры
- только после добавления этой копии в документ элементы становятся частью отображаемого DOM

---

## зачем нужен `<template>`

- основной сценарий — когда одна и та же HTML-структура должна создаваться много раз с разными данными

```html
<template id="product-template">
  <article class="product-card">
    <h2 class="product-title"></h2>
    <p class="product-price"></p>
  </article>
</template>

<section id="products"></section>
```

- JavaScript может использовать один шаблон для создания множества карточек

```js
const productTemplate = document.querySelector('#product-template');
const productsContainer = document.querySelector('#products');

const productFragment = productTemplate.content.cloneNode(true);

productFragment.querySelector('.product-title').textContent = 'Laptop';
productFragment.querySelector('.product-price').textContent = '$1200';

productsContainer.append(productFragment);
```

- шаблон остаётся неизменным, а каждая созданная копия может содержать свои данные

---

## почему не просто скрытый `<div>`

- можно было бы написать

```html
<div hidden>
  <article class="card">
    <h2 class="title"></h2>
  </article>
</div>
```

- но это обычный DOM-элемент

- он уже является частью DOM-документа и имеет обычную семантику элемента

- `<template>` специально предназначен для **неактивной HTML-структуры**

- его содержимое не отображается, не запускает scripts и не загружает обычные ресурсы так, как если бы они находились в активном DOM

---

## `DocumentFragment`

- `template.content` возвращает `DocumentFragment`

```js
const cardTemplate = document.querySelector('#product-template');
const cardFragment = cardTemplate.content.cloneNode(true);
```

- `DocumentFragment` — временный контейнер для DOM-узлов

- он удобен тем, что можно собрать целую структуру в памяти, а затем добавить её в документ одной операцией

- после

```js
productsContainer.append(cardFragment);
```

- содержимое fragment перемещается в `productsContainer`
- сам `DocumentFragment` не становится отдельным элементом DOM

---

## важный нюанс с клонированием

- `template.content` нельзя просто один раз добавить и ожидать, что тот же шаблон можно будет многократно использовать как готовую DOM-структуру

- обычно делают

```js
const firstCard = productTemplate.content.cloneNode(true);
const secondCard = productTemplate.content.cloneNode(true);
```

- `true` означает глубокое клонирование, то есть вместе со всеми дочерними элементами

---

## `<template>` и Web Components

- `<template>` особенно важен при создании Web Components
- шаблон часто используется для определения внутренней HTML-структуры компонента

```html
<template id="alert-template">
  <div class="alert">
    <span class="alert-message"></span>
  </div>
</template>
```

- затем этот шаблон может клонироваться внутри custom element и добавляться в Shadow DOM

- поэтому на собеседовании полезно понимать связь

```
<template>
      ↓
HTML-структура
      ↓
cloneNode()
      ↓
DocumentFragment
      ↓
DOM / Shadow DOM
```

---

## главное отличие от обычного HTML

- содержимое `<template>` существует в `template.content`, а не как обычные дочерние элементы самого `<template>` в активном DOM
- браузер не отображает этот контент автоматически
- JavaScript сам решает, когда и сколько раз использовать шаблон
- один `<template>` можно использовать для создания множества одинаковых структур

## что важно сказать на собеседовании

- `<template>` хранит HTML, который не отображается сразу
- его содержимое доступно через `.content`
- `.content` является `DocumentFragment`
- для создания экземпляра обычно используется `cloneNode(true)`
- шаблон удобен для повторяющихся DOM-структур
- `<template>` часто используется вместе с Web Components и Shadow DOM
- главное преимущество — браузер хранит структуру как неактивный шаблон, пока JavaScript явно не вставит её в документ
