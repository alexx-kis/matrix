# html symbols usage

- в HTML есть символы, которые нельзя просто написать в исходном коде как обычный текст, потому что браузер может интерпретировать их как часть HTML-разметки
- для таких символов используются **HTML entities**, или HTML-сущности
- HTML-сущность — это специальная запись символа, которую браузер при отображении преобразует обратно в нужный символ

## зачем нужны HTML entities

- представим, что мы хотим показать пользователю текст

```html
<p>I use <p> elements</p>
```

- здесь возникает проблема, потому что браузер воспринимает `<p>` как настоящий HTML-тег, а не как текст
- если наша задача — показать именно символы `<` и `>`, их нужно записать через HTML entities

```html
<p>I use &lt;p&gt; elements</p>
```

- браузер покажет

```text
I use <p> elements
```

- то есть исходный HTML и отображаемый текст могут отличаться

```text
HTML source       →      browser output

&lt;              →      <
&gt;              →      >
```

---

## основные способы записи

- существует два основных вида HTML entities

```html
&name;
```

- и

```html
&#number;
```

- также существует hexadecimal-вариант

```html
&#xhex;
```

- например, символ `<` можно записать несколькими способами

```html
&lt; &#60; &#x3C;
```

- все три варианта отображаются как

```text
<
```

---

## именованные entities

- самый читаемый вариант — использовать имя сущности

```html
&lt; &gt; &amp; &quot; &apos; &nbsp;
```

- здесь после `&` находится имя, а `;` обозначает конец entity

- например

```html
<p>5 &lt; 10</p>
```

- браузер покажет

```text
5 < 10
```

- аналогично

```html
<p>10 &gt; 5</p>
```

- результат

```text
10 > 5
```

---

## `&lt;` и `&gt;`

- `&lt;` означает **less-than sign**, то есть `<`

```html
<p>5 &lt; 10</p>
```

- `&gt;` означает **greater-than sign**, то есть `>`

```html
<p>10 &gt; 5</p>
```

- особенно часто они нужны, когда мы хотим показать HTML-код пользователю

```html
<pre>
  &lt;button&gt;Click me&lt;/button&gt;
</pre>
```

- браузер отобразит

```text
<button>Click me</button>
```

- при этом браузер не создаст настоящий `<button>`, потому что `<button>` находится внутри текстового содержимого в виде entities

---

## `&amp;`

- `&amp;` представляет символ `&`

```html
<p>Tom &amp; Jerry</p>
```

- браузер покажет

```text
Tom & Jerry
```

- это особенно важно, потому что `&` используется как начало HTML entity

```html
&lt; &amp; &quot;
```

- поэтому если нам действительно нужен обычный символ `&`, в некоторых контекстах его необходимо записывать как `&amp;`

---

## `&quot;`

- `&quot;` представляет двойные кавычки `"`

```html
<p>He said &quot;Hello&quot;</p>
```

- браузер покажет

```text
He said "Hello"
```

- особенно полезно понимать это в контексте HTML-атрибутов

```html
<div title='He said "Hello"'></div>
```

- здесь entity позволяет безопасно представить кавычку внутри значения атрибута

---

## `&apos;`

- `&apos;` представляет одинарную кавычку `'`

```html
<p>It&apos;s a test</p>
```

- браузер покажет

```text
It's a test
```

- однако в обычном HTML-тексте одинарную кавычку обычно можно написать непосредственно

```html
<p>It's a test</p>
```

- поэтому `&apos;` нужен далеко не всегда

---

## `&nbsp;`

- `&nbsp;` означает **non-breaking space**
- это пробел, который браузер не должен использовать как место для переноса строки

```html
Hello&nbsp;world
```

- визуально это выглядит примерно как

```text
Hello world
```

- но между словами находится специальный неразрывный пробел
- например, это может быть полезно для конструкций вроде

```html
10&nbsp;kg
```

- тогда `10` и `kg` не будут разделены переносом строки

- при этом `&nbsp;` **не следует использовать для обычного управления отступами**

- если нужно добавить расстояние между элементами, для этого обычно используется CSS

---

## числовые entities

- вместо имени можно использовать числовой код символа

```html
&#60;
```

- это `<`

```html
&#62;
```

- это `>`

```html
&#38;
```

- это `&`

- существует и hexadecimal-форма

```html
&#x3C;
```

- это также `<`

- разница только в системе счисления

```text
&#60;   → decimal
&#x3C;  → hexadecimal
```

---

## entities для Unicode-символов

- HTML entities можно использовать не только для специальных HTML-символов, но и для большого количества Unicode-символов

- например, символ ©

```html
<p>&copy; 2026</p>
```

- результат

```text
© 2026
```

- символ €

```html
<p>&euro;100</p>
```

- результат

```text
€100
```

- символ ™

```html
<p>Brand&trade;</p>
```

- результат

```text
Brand™
```

- при этом благодаря UTF-8 многие Unicode-символы можно просто писать непосредственно в HTML

```html
<p>© 2026</p>
<p>€100</p>
<p>Привет</p>
<p>😊</p>
```

- поэтому entities нужны не для того, чтобы заменить вообще все специальные символы

---

## entity и обычный Unicode-символ

- важно различать две вещи

```html
<p>© 2026</p>
```

- и

```html
<p>&copy; 2026</p>
```

- визуально браузер обычно покажет одинаковый результат

```text
© 2026
```

- первый вариант содержит непосредственно Unicode-символ
- второй вариант содержит HTML entity, которую браузер декодирует в этот символ

---

## почему `&` особенно важен

- `&` используется как начало именованной или числовой entity

```html
&amp; &lt; &#60;
```

- поэтому если в тексте встречается последовательность, похожая на entity, браузер может попытаться её интерпретировать

- при работе с пользовательским текстом это особенно важно учитывать при HTML escaping

- например, строка

```text
Tom & Jerry
```

- при генерации HTML обычно должна быть корректно экранирована

```html
Tom &amp; Jerry
```

- иначе `&` может быть воспринят как начало entity, если за ним следует подходящая последовательность

---

## HTML escaping

- преобразование специальных символов в безопасные HTML-представления часто называют **HTML escaping**
- например

```text
<
>
&
"
'
```

- могут быть представлены как

```text
&lt;
&gt;
&amp;
&quot;
&apos;
```

- это особенно важно, когда данные пользователя вставляются в HTML

- HTML escaping помогает браузеру воспринимать пользовательский ввод как текст, а не как HTML-разметку

- например, если пользователь ввёл

```html
<script>
  alert('Hello');
</script>
```

- при корректном отображении как текста браузер не должен создать настоящий `<script>`, а должен показать введённую строку пользователю

- именно поэтому тема entities связана не только с отображением символов, но и с безопасностью веб-приложений

---

## важный нюанс с `<` и `>`

- символ `<` особенно важен, потому что он используется для начала HTML-тега

```html
<h1></h1>
```

- если нам нужно показать `<` как текст, безопаснее использовать

```html
&lt;
```

- символ `>` обычно менее проблемный в обычном текстовом содержимом, но для единообразного отображения HTML-кода часто используют и `&gt;`

```html
&lt;div&gt;Hello&lt;/div&gt;
```

- результат

```text
<div>Hello</div>
```

---

## что важно знать для собеседования

- **HTML entity** — специальная запись символа, которую браузер преобразует в соответствующий символ
- entity обычно начинается с `&` и заканчивается `;`
- наиболее важные сущности

```text
&lt;    <
&gt;    >
&amp;   &
&quot;  "
&apos;  '
&nbsp;  неразрывный пробел
```

- entity можно записывать именем или числовым кодом

```html
&lt; &#60; &#x3C;
```

- `<` особенно важно экранировать, когда он должен отображаться как обычный текст
- `&` также требует внимания, потому что используется для начала entity
- `&nbsp;` создаёт неразрывный пробел, но не должен использоваться вместо CSS для построения layout
- HTML entities особенно часто встречаются при отображении HTML-кода и при HTML escaping пользовательских данных
- UTF-8 позволяет непосредственно использовать огромное количество Unicode-символов, поэтому entity не является обязательной для каждого специального символа
