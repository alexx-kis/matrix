# `<iframe>` element

- `<iframe>` позволяет встроить **другой HTML-документ внутрь текущей страницы**
- чаще всего его используют для карт, видео, внешних виджетов, документов и других независимых страниц

## базовый пример

```html
<iframe src="https://example.com" width="800" height="600" title="Example website"></iframe>
```

- `src` определяет документ, который должен быть загружен
- `width` и `height` задают размеры iframe
- `title` важен для accessibility, чтобы screen reader мог объяснить назначение встроенного содержимого

---

## iframe как отдельный документ

- содержимое `<iframe>` не становится обычными дочерними HTML-элементами родительской страницы
- внутри iframe существует собственный `document` и собственный `window`

```text
родительская страница
│
├── document
│
└── iframe
     │
     ├── window
     └── document
```

- поэтому CSS родительской страницы не применяется напрямую к содержимому iframe
- JavaScript родительской страницы также не может свободно обращаться к его содержимому

---

## same-origin policy

- доступ JavaScript между родительской страницей и iframe зависит от **origin**

- если iframe загружен с того же origin, доступ к его документу возможен

```js
const embeddedFrame = document.querySelector('#content-frame');

const embeddedDocument = embeddedFrame.contentDocument;
```

- если iframe находится на другом origin, браузер ограничивает такой доступ из-за Same-Origin Policy

```text
https://app.example.com
        ↓
iframe
        ↓
https://other.example.com
```

- JavaScript родительской страницы не может просто прочитать DOM другого origin

---

## `sandbox`

- `sandbox` позволяет ограничить возможности содержимого iframe

```html
<iframe src="https://example.com" sandbox title="Restricted content"></iframe>
```

- пустой `sandbox` применяет максимально строгий набор ограничений
- отдельные возможности можно разрешать явно

```html
<iframe src="https://example.com" sandbox="allow-scripts" title="Embedded application"></iframe>
```

- можно разрешать разные возможности, например `allow-scripts`, `allow-forms`, `allow-popups`
- чем меньше разрешений, тем меньше потенциальная поверхность атаки

---

## `allow`

- `allow` используется для управления определёнными browser features, доступными iframe

```html
<iframe src="https://example.com" allow="fullscreen" title="Video player"></iframe>
```

- это особенно часто встречается у встроенных видео и других сторонних приложений

---

## `allowfullscreen`

- позволяет iframe использовать fullscreen API

```html
<iframe src="https://example.com/video" allowfullscreen title="Video player"></iframe>
```

- в современном коде также можно встретить соответствующую настройку через `allow`

---

## `loading="lazy"`

- iframe можно загружать лениво

```html
<iframe src="https://example.com/widget" loading="lazy" title="External widget"></iframe>
```

- это позволяет не загружать iframe сразу, если он находится далеко за пределами viewport

- особенно полезно, если iframe содержит тяжёлый сторонний контент

---

## безопасность

- iframe особенно важен с точки зрения безопасности, потому что он позволяет загружать сторонний код
- для недоверенного содержимого стоит рассматривать `sandbox`

```html
<iframe src="https://external.example" sandbox title="External content"></iframe>
```

- нельзя считать iframe автоматически безопасным только потому, что он изолирован от DOM родительской страницы
- встроенный ресурс всё равно может выполнять свой JavaScript и взаимодействовать с доступными ему browser APIs

---

## `postMessage`

- если родительская страница и iframe находятся на разных origin, для контролируемого обмена сообщениями используется `window.postMessage`

- родитель может отправить сообщение iframe

```js
const messageFrame = document.querySelector('#message-frame');

messageFrame.contentWindow.postMessage({ type: 'theme-change', value: 'dark' }, 'https://widget.example.com');
```

- iframe может принять сообщение

```js
window.addEventListener('message', (messageEvent) => {
  if (messageEvent.origin !== 'https://app.example.com') {
    return;
  }

  console.log(messageEvent.data);
});
```

- проверка `origin` важна, потому что нельзя бездумно доверять любому полученному сообщению

---

## `iframe` и SEO

- содержимое iframe не следует рассматривать как обычное содержимое основной страницы

- поэтому основной текст и важная информация страницы не должны прятаться исключительно внутри iframe

- iframe больше подходит для независимого внешнего контента, чем для основной структуры страницы

---

## `iframe` vs `<object>` / `<embed>`

- сегодня `<iframe>` является наиболее распространённым способом встроить другой HTML-документ
- `<object>` и `<embed>` существуют для встраивания других типов ресурсов, но для обычных внешних веб-страниц обычно используется именно `<iframe>`

---

## что важно для собеседования

- `<iframe>` встраивает другой HTML-документ в текущую страницу
- iframe имеет собственные `window` и `document`
- доступ между iframe и родительской страницей ограничивается Same-Origin Policy
- для общения между разными origin используется `postMessage`
- `sandbox` ограничивает возможности iframe
- `allow` управляет доступом к определённым browser features
- `loading="lazy"` позволяет отложить загрузку iframe
- `title` важен для accessibility
- iframe особенно часто используется для видео, карт, внешних виджетов и независимых приложений
