# html links. link target

- ссылка в HTML создаётся с помощью элемента `<a>`, который называется **anchor element**
- основное назначение ссылки — позволить пользователю перейти к другому ресурсу, странице, месту внутри текущей страницы или выполнить другое действие, связанное с навигацией

## базовая ссылка

- минимальная ссылка выглядит так

```html
<a href="https://example.com">Visit example.com</a>
```

- `<a>` — сам элемент ссылки

- `href` — адрес ресурса, на который ведёт ссылка

- текст между `<a>` и `</a>` — содержимое, которое пользователь видит и нажимает

- если `href` отсутствует, `<a>` сам по себе не становится обычной навигационной ссылкой

```html
<a>Not a link</a>
```

- поэтому для нормальной навигационной ссылки обычно нужен `href`

---

# атрибут `href`

- `href` означает **hypertext reference**
- он указывает, куда должна вести ссылка

```html
<a href="https://example.com">Example</a>
```

- значение `href` может быть абсолютным URL

```html
<a href="https://developer.mozilla.org/">MDN</a>
```

- или относительным URL

```html
<a href="/about">About</a>
```

- относительный путь интерпретируется относительно текущего документа или текущего URL

---

# абсолютные и относительные ссылки

## абсолютный URL

- абсолютная ссылка содержит полный адрес ресурса

```html
<a href="https://example.com/about">About</a>
```

- здесь явно указаны протокол, домен и путь

```text
https://example.com/about
```

## относительный URL

- относительная ссылка описывает путь относительно текущего расположения

```html
<a href="/about">About</a>
```

- например, если сайт находится на

```text
https://example.com
```

- ссылка `/about` ведёт на

```text
https://example.com/about
```

- можно использовать и относительный путь вроде

```html
<a href="./about.html">About</a>
```

- здесь `./` означает текущую директорию

- `../` позволяет подняться на уровень выше

```html
<a href="../index.html">Home</a>
```

---

# ссылка на другую страницу

- типичный пример многостраничного сайта

```html
<nav>
  <a href="/index.html">Home</a>
  <a href="/about.html">About</a>
  <a href="/contacts.html">Contacts</a>
</nav>
```

- при нажатии браузер загружает соответствующий ресурс

- для навигации по сайту предпочтительнее использовать настоящие `<a>` с `href`, а не имитировать ссылки через `<div>` или `<button>`

---

# ссылка на определённое место страницы

- HTML позволяет перейти не только на другую страницу, но и к конкретному элементу текущей или другой страницы

- для этого используются **fragment identifiers**

- сначала элементу задаётся `id`

```html
<h2 id="contacts">Contacts</h2>
```

- затем создаётся ссылка на этот `id`

```html
<a href="#contacts">Go to contacts</a>
```

- `#contacts` означает fragment `contacts`

- при нажатии браузер прокрутит страницу к элементу

```text
href="#contacts"
      │
      └── id элемента
```

- аналогично можно перейти к элементу на другой странице

```html
<a href="/about.html#team">Our team</a>
```

- браузер сначала перейдёт на `/about.html`, а затем найдёт элемент

```html
<section id="team">...</section>
```

---

# ссылка на email

- для открытия почтового клиента используется схема `mailto:`

```html
<a href="mailto:hello@example.com">Send email</a>
```

- при нажатии браузер передаст управление приложению, зарегистрированному для обработки email-ссылок

- можно указать тему письма

```html
<a href="mailto:hello@example.com?subject=Hello"> Send email </a>
```

---

# ссылка на телефон

- для телефонного номера используется схема `tel:`

```html
<a href="tel:+381111234567">Call us</a>
```

- особенно полезно на мобильных устройствах

- браузер или операционная система может предложить выполнить звонок

---

# ссылка на скачивание

- у `<a>` есть атрибут `download`, который сообщает браузеру, что ресурс предполагается скачать

```html
<a href="/files/report.pdf" download>Download report</a>
```

- можно указать предполагаемое имя файла

```html
<a href="/files/report.pdf" download="annual-report.pdf"> Download report </a>
```

- поведение `download` зависит от браузера, типа ресурса и политики сервера
- для ресурсов другого origin есть дополнительные ограничения, поэтому нельзя рассчитывать, что браузер всегда скачает любой внешний URL только из-за `download`

---

# `target`

- атрибут `target` определяет, **где открыть ресурс, на который указывает ссылка**

```html
<a href="https://example.com" target="_blank"> Open example.com </a>
```

- наиболее часто на собеседованиях спрашивают про `_blank`

## `_self`

```html
<a href="https://example.com" target="_self"> Open </a>
```

- открывает ресурс в текущем browsing context
- это фактически обычное поведение ссылки по умолчанию

```html
<a href="https://example.com"> Open </a>
```

- и

```html
<a href="https://example.com" target="_self"> Open </a>
```

- в обычной ситуации приводят к одному результату

---

## `_blank`

```html
<a href="https://example.com" target="_blank"> Open </a>
```

- открывает ресурс в новом browsing context

- обычно браузер отображает его в новой вкладке, хотя конкретное поведение определяется браузером

- важный нюанс — при использовании `_blank` часто добавляют

```html
<a href="https://example.com" target="_blank" rel="noopener"> Open </a>
```

- `noopener` не позволяет открытой странице использовать `window.opener` для доступа к исходному окну

- это защищает от определённого класса проблем, связанных с открытием внешних страниц

- в современных браузерах при `target="_blank"` поведение с `noopener` во многих случаях уже применяется по умолчанию, но явное указание `rel="noopener"` всё ещё является понятным и распространённым способом явно выразить намерение

---

## `_parent`

```html
<a href="/page.html" target="_parent"> Open </a>
```

- открывает ресурс в родительском browsing context

- особенно имеет значение при работе с `<iframe>`

- если документ не находится внутри вложенного browsing context, `_parent` обычно ведёт себя практически так же, как `_self`

---

## `_top`

```html
<a href="/page.html" target="_top"> Open </a>
```

- открывает ресурс в самом верхнем browsing context

- это особенно важно для документов, находящихся внутри `<iframe>`

- условно

```text
top-level page
│
└── iframe
    │
    └── current document
```

- `_top` позволяет навигации выйти из iframe и заменить верхнюю страницу

---

# собственное имя target

- `target` может содержать не только специальные значения вроде `_blank`, но и имя browsing context

```html
<a href="/about.html" target="content"> About </a>
```

- если существует browsing context с именем `content`, навигация произойдёт именно там
- это может использоваться, например, вместе с iframe

```html
<iframe name="content"></iframe>

<a href="/about.html" target="content"> About </a>
```

- в этом случае страница `/about.html` будет загружена внутрь iframe с именем `content`

- это важный момент: `target` работает не только с вкладками, но и с browsing contexts

---

# `_unfencedTop`

- существует также специальное значение `_unfencedTop`, связанное с fenced frames
- для обычной разработки это редко требуется
- для базового понимания HTML достаточно хорошо знать `_self`, `_blank`, `_parent` и `_top`

---

# `target` и `<base>`

- существует ещё один связанный механизм — `<base>`
- `<base>` позволяет задать базовый URL и target для относительных ссылок документа

```html
<head>
  <base href="https://example.com/" />
</head>
```

- после этого относительные ссылки будут разрешаться относительно указанного базового URL

```html
<a href="about">About</a>
```

- может разрешаться как

```text
https://example.com/about
```

- у `<base>` также может быть `target`

```html
<base target="_blank" />
```

- тогда ссылки без собственного `target` будут использовать это значение

- это уже более редкий случай, но его полезно знать как нюанс

# ссылка и кнопка — не одно и то же

- это один из важных вопросов на frontend-собеседованиях

- `<a>` используется для **навигации**

```html
<a href="/profile">Profile</a>
```

- `<button>` используется для **действия**

```html
<button type="button">Open menu</button>
```

- если нажатие должно привести пользователя на другую страницу или ресурс, обычно нужен `<a>`

- если нажатие должно выполнить действие внутри интерфейса, обычно нужен `<button>`

- не стоит делать так

```html
<div onclick="goToProfile()">Profile</div>
```

- такой элемент не получает автоматически всю семантику и клавиатурное поведение настоящей ссылки

---

# `href="#"`

- часто можно встретить

```html
<a href="#">Click me</a>
```

- `#` означает пустой fragment identifier

- такая ссылка может привести к перемещению к началу текущего документа

- часто этот приём использовали как заглушку для JavaScript

- например, старый подход

```html
<a href="#" onclick="openMenu()">Open menu</a>
```

- семантически это плохой вариант, если действие не является навигацией
- для действия интерфейса здесь лучше использовать `<button>`

```html
<button type="button">Open menu</button>
```

---

# ссылки и доступность

- текст ссылки должен объяснять, куда она ведёт

- хорошо

```html
<a href="/documentation">Read the documentation</a>
```

- хуже

```html
<a href="/documentation">Click here</a>
```

- `Click here` не сообщает пользователю смысл ссылки, особенно если screen reader позволяет просматривать список ссылок отдельно от окружающего текста

- поэтому текст ссылки должен быть информативным сам по себе

# `rel`

- атрибут `rel` описывает отношения между текущим документом и ресурсом, на который ведёт ссылка

- например

```html
<a href="https://example.com" target="_blank" rel="noopener noreferrer"> External website </a>
```

- `noopener` связан с безопасностью при открытии нового browsing context

- `noreferrer` дополнительно запрещает передачу `Referer` в соответствующих навигационных сценариях и также подразумевает `noopener`

- другие значения `rel` используются для других отношений, например

```html
<a href="/author" rel="author">Author</a>
```

- или

```html
<a href="https://example.com" rel="nofollow"> External link </a>
```

- `nofollow` является сигналом для поисковых систем и не означает запрет перехода для браузера

# краткая схема

```text
<a>
│
├── href
│   └── куда перейти
│
├── target
│   └── где открыть
│
├── rel
│   └── отношение / дополнительные указания
│
└── текст
    └── что видит и активирует пользователь
```

- например

```html
<a href="https://example.com" target="_blank" rel="noopener noreferrer"> Visit example.com </a>
```

- здесь `href` определяет адрес
- `target="_blank"` просит открыть ресурс в новом browsing context
- `rel="noopener noreferrer"` задаёт дополнительные отношения и ограничения безопасности
- `Visit example.com` является доступным пользователю названием ссылки

# что важно знать для собеседования

- `<a>` используется прежде всего для навигации
- `href` определяет ресурс, к которому ведёт ссылка
- `target` определяет browsing context, в котором выполняется навигация
- `_self` — текущий browsing context
- `_blank` — новый browsing context, обычно новая вкладка
- `_parent` — родительский browsing context
- `_top` — самый верхний browsing context
- `target` может содержать собственное имя browsing context
- `href="#some-id"` позволяет перейти к элементу с соответствующим `id`
- `mailto:` используется для email-ссылок
- `tel:` используется для телефонных ссылок
- `download` может использоваться для предложения скачать ресурс
- `<a>` и `<button>` имеют разную семантику: ссылка навигирует, кнопка выполняет действие
- `target="_blank"` часто используют вместе с `rel="noopener"`
- текст ссылки должен быть понятным сам по себе, а не просто `Click here`
