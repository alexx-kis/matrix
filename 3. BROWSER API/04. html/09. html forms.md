# HTML forms

- форма в HTML предназначена для сбора данных от пользователя и их отправки или последующей обработки JavaScript
- основной контейнер — `<form>`

```html
<form action="/login" method="post">...</form>
```

- `action` определяет URL, куда отправляются данные
- `method` определяет HTTP-метод отправки

## `GET` и `POST`

- `GET` обычно используется для получения данных или выполнения поиска

```html
<form action="/search" method="get">
  <input name="query" />
  <button type="submit">Search</button>
</form>
```

- после отправки параметры попадут в URL примерно так

```
/search?query=javascript
```

- `POST` используется для передачи данных в теле HTTP-запроса

```html
<form action="/account" method="post">
  <input name="username" />
  <input name="password" type="password" />

  <button type="submit">Sign in</button>
</form>
```

- чувствительные данные вроде пароля не следует передавать через `GET`, потому что параметры GET находятся в URL

---

## `input`

- `<input>` — основной элемент для ввода данных

```html
<input type="text" name="username" />
```

- `type` определяет вид поля

- `name` определяет имя параметра, под которым значение попадёт в отправляемые данные

- например

```html
<input type="email" name="email" />
<input type="password" name="password" />
<input type="number" name="age" />
<input type="date" name="birthday" />
```

- наиболее часто используемые типы — `text`, `email`, `password`, `number`, `date`, `checkbox`, `radio`, `file`, `submit`

---

## `name`

- `name` особенно важен при отправке формы

```html
<input type="text" name="username" value="alex" />
```

- при отправке браузер сформирует параметр примерно такого вида

```
username=alex
```

- поле без `name` обычно не участвует в стандартной отправке формы

---

## `label`

- `<label>` связывает текстовое описание с конкретным контролом

```html
<label for="user-email">Email</label> <input id="user-email" type="email" name="email" />
```

- `for` должен совпадать с `id` элемента

- можно связывать `label` и вложением

```html
<label>
  Email
  <input type="email" name="contact-email" />
</label>
```

- `label` важен для accessibility и позволяет пользователю нажать на текст, чтобы активировать соответствующее поле

---

## основные атрибуты `input`

- `required` делает поле обязательным

```html
<input type="email" name="contact" required />
```

- `placeholder` показывает подсказку внутри пустого поля

```html
<input type="text" name="nickname" placeholder="Enter nickname" />
```

- `value` задаёт начальное значение

```html
<input type="text" name="city" value="Belgrade" />
```

- `disabled` полностью отключает контрол

```html
<input type="text" name="account-id" value="42" disabled />
```

- disabled-поле не отправляется при стандартной отправке формы

- `readonly` запрещает изменение, но значение может отправляться

```html
<input type="text" name="profile-name" value="Alex" readonly />
```

- `required`, `disabled`, `readonly` — разные вещи и на собеседовании их часто сравнивают

---

## `textarea`

- `<textarea>` используется для многострочного текста

```html
<label for="user-message">Message</label>

<textarea id="user-message" name="message" rows="5" cols="40"></textarea>
```

- в отличие от `<input>` начальное значение `<textarea>` задаётся между тегами

```html
<textarea name="description">Initial text</textarea>
```

---

## `select`

- `<select>` создаёт выпадающий список

```html
<label for="country-select">Country</label>

<select id="country-select" name="country">
  <option value="rs">Serbia</option>
  <option value="de">Germany</option>
  <option value="fr">France</option>
</select>
```

- отправляться будет значение `value`, а не обязательно отображаемый текст

- можно задать выбранный вариант

```html
<option value="rs" selected>Serbia</option>
```

---

## `checkbox`

- checkbox позволяет выбрать независимое значение

```html
<label>
  <input type="checkbox" name="subscribe" />
  Subscribe to newsletter
</label>
```

- checkbox отправляется как параметр только если он отмечен

- `checked` задаёт начальное состояние

```html
<input type="checkbox" name="terms" checked />
```

---

## `radio`

- radio используется для выбора **одного варианта из группы**

```html
<label>
  <input type="radio" name="plan" value="basic" />
  Basic
</label>

<label>
  <input type="radio" name="plan" value="pro" />
  Pro
</label>
```

- одинаковый `name` объединяет radio-кнопки в одну группу
- одновременно выбрать несколько вариантов с одинаковым `name` нельзя

---

## `button`

- кнопка внутри формы может иметь разные типы

```html
<button type="submit">Submit</button>
<button type="reset">Reset</button>
<button type="button">Open dialog</button>
```

- `submit` отправляет форму

- `reset` возвращает элементы к исходным значениям

- `button` ничего автоматически не делает и обычно используется вместе с JavaScript

- важный нюанс — если у `<button>` внутри `<form>` не указать `type`, по умолчанию его поведение — `submit`

---

## валидация

- HTML предоставляет встроенную client-side validation без JavaScript

```html
<input type="email" name="email" required />
```

- браузер проверит обязательность поля и корректность email перед отправкой

- можно задавать ограничения

```html
<input type="text" name="username" required minlength="3" maxlength="20" />
```

- для чисел

```html
<input type="number" name="quantity" min="1" max="100" />
```

- для произвольного формата используется `pattern`

```html
<input type="text" name="postal-code" pattern="[0-9]{5}" />
```

- HTML-валидация удобна, но сервер всё равно обязан самостоятельно проверять полученные данные

---

## `autocomplete`

- `autocomplete` подсказывает браузеру, какие данные ожидаются

```html
<input type="email" name="email" autocomplete="email" />
```

- это помогает браузеру правильно подставлять сохранённые данные

- часто используются значения `name`, `email`, `username`, `current-password`, `new-password`, `street-address`

---

## `fieldset` и `legend`

- `<fieldset>` группирует связанные элементы формы

```html
<fieldset>
  <legend>Delivery address</legend>

  <label>
    City
    <input type="text" name="delivery-city" />
  </label>

  <label>
    Street
    <input type="text" name="delivery-street" />
  </label>
</fieldset>
```

- `<legend>` задаёт название группы
- это особенно полезно для accessibility и сложных форм

---

## отправка формы через JavaScript

- стандартное поведение формы можно перехватить через событие `submit`

```html
<form id="feedback-form">
  <input type="text" name="message" required />
  <button type="submit">Send</button>
</form>
```

```js
const feedbackForm = document.querySelector('#feedback-form');

feedbackForm.addEventListener('submit', (submitEvent) => {
  submitEvent.preventDefault();

  const submittedData = new FormData(feedbackForm);

  console.log(submittedData.get('message'));
});
```

- `preventDefault()` отменяет стандартную отправку браузером
- `FormData` позволяет получить значения формы в удобном виде
- это типичный подход для SPA, где данные отправляются через `fetch`

---

## `enctype`

- `enctype` определяет формат данных при отправке формы

- обычный вариант

```html
<form method="post" enctype="application/x-www-form-urlencoded"></form>
```

- для загрузки файлов используется

```html
<form method="post" enctype="multipart/form-data"></form>
```

- при наличии `<input type="file">` обычно нужен именно `multipart/form-data`

```html
<input type="file" name="avatar" />
```

---

## что важно запомнить

- `<form>` — контейнер формы
- `action` — куда отправлять данные
- `method` — каким HTTP-методом отправлять
- `name` — имя параметра при отправке
- `label` — доступное название поля
- `input` — однострочный ввод разных типов
- `textarea` — многострочный текст
- `select` + `option` — выбор из списка
- `checkbox` — независимый выбор
- `radio` с одинаковым `name` — выбор одного варианта
- `button type="submit"` — отправка формы
- `required`, `minlength`, `maxlength`, `min`, `max`, `pattern` — встроенная валидация
- `FormData` — удобное получение данных формы в JavaScript
- `multipart/form-data` — типичный `enctype` для отправки файлов
- client-side validation улучшает UX, но **не заменяет серверную валидацию**
