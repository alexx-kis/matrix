# storage events

- Storage Event - это специальное DOM-событие, которое браузер генерирует, когда содержимое localStorage или sessionStorage изменяется
- главное назначение - сообщить другой вкладке/окну, что storage изменился

## зачем нужен storage event

- пусть есть две открытые вкладки одного сайта

```
┌───────────────┐      ┌───────────────┐
│    Tab 1      │      │    Tab 2      │
│               │      │               │
│ localStorage  │      │ localStorage  │
└───────────────┘      └───────────────┘
```

- в первой вкладке:

```js
localStorage.setItem('theme', 'dark');
```

- во второй вкладке браузер может сообщить, что в localStorage произошло изменение
- именно для этого существует storage event

## как подписаться на событие

- можно повесить обработчик на window

```js
window.addEventListener('storage', (event) => {
  console.log('storage changed');
});
```

- событие слушается на `window`, а не на `localStorage`

## что находится в event

- у storageEvent есть несколько важных свойств

```js
window.addEventListener('storage', (event) => {
  console.log(event.key);
  console.log(event.oldValue);
  console.log(event.newValue);
});
```

```
| Свойство      | Что содержит                           |
| ------------- | -------------------------------------- |
| `key`         | изменённый ключ                        |
| `oldValue`    | старое значение                        |
| `newValue`    | новое значение                         |
| `storageArea` | какой Storage изменился                |
| `url`         | URL документа, где произошло изменение |
```

## пример

- допустим, в первой вкладке выполняется:

```js
localStorage.setItem('theme', 'dark');
```

- во второй вкладке сработает:

```js
window.addEventListener('storage', (event) => {
  console.log(event.key);
  console.log(event.oldValue);
  console.log(event.newValue);
});
```

- можно получить:

```
theme
null
dark
```

- `oldValue === null`, потому что ключа `theme` до этого не существовало

## изменение существующего значения

- было:

```
theme -> light
```

- вкладка #1:

```js
localStorage.setItem('theme', 'dark');
```

- вкладка #2 получит:

```js
key       → "theme"
oldValue  → "light"
newValue  → "dark"
```

- то есть можно понять не только, что изменилось, но и как именно оно изменилось

## удаление значения

- если выполнить:

```js
localStorage.removeItem('theme');
```

- событие тоже произойдет:

```
key       → "theme"
oldValue  → "dark"
newValue  → null
```

- `newValue === null` означает, что значение было удалено

## очистка

- если выполнить:

```js
localStorage.clear();
```

- то key будет null, потому что удаляются сразу все ключи, а не какой-то конкретный
- при этом:

```
oldValue → null
newValue → null
key      → null
```

## важно: событие не срабатывает в той же вкладке

- если написать:

```js
window.addEventListener('storage', (event) => {
  console.log('changed');
});

localStorage.setItem('theme', 'dark');
```

- в той же вкладке обработчик не сработает

- это сделано специально
- если нужно отреагировать на собственное изменение Storage в той же вкладке, нужно вызвать соответствующую логику самостоятельно

## это особенно полезно для синхронизации вкладок

- например, пользователь авторизован в двух вкладках
- пользователь нажал logout в первой вкладке, приложение удаляет данные, вторая вкладка получает storage event
- таким образом вкладки могут синхронизировать состояние

## пример: переключение тем

- если пользователь поменял тему в одной вкладке, вторая вкладка получает событие, и интерфейс второй вкладки можно автоматически обновить

## sessionStorage

- storage event существует и для sessionStorage, но
- так как sessionStorage привязан к конкретной вкладке, он не используется для обычной синхронизации между независимыми вкладками, как localStorage

## storageArea

- можно проверить, какой Storage изменился

```js
window.addEventListener('storage', (event) => {
  if (event.storageArea === localStorage) {
    console.log('localStorage changed');
  }
});
```

- аналогично можно проверить sessionStorage

## url

- `event.url` содержит URL страницы, в контексте которой произошло изменение
- например `https://example.com/profile`

- это может быть полезно, если нужно знать, откуда произошло изменение
