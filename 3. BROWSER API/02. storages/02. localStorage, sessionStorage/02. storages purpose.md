# storages purpose

- без хранилищ браузер забывал бы практически все после обновления страницы
- например, пользователь включил темную тему, выбрал другой язык, свернул боковое меню, заполнил половину формы
- затем обновил страницу

- без хранения данных все пришлось бы делать заново
- именно для решения этой проблемы появились браузерные хранилища

## главная задача storage

- сохранить данные на стороне клиента (в браузере), чтобы их можно было использовать позже без обращения к серверу

## какие задачи они решают

1. сохранение пользовательских настроек, например:

- тема сайта
- язык интерфейса
- размер шрифта
- вид карточек товаров
- положение сайдбара

2. сохранение состояния интерфейса

- иногда нужно помнить не настройки пользователя, а текущее состояние страницы, например:
  - пользователь открыл аккордеон
  - развернул меню
  - отсортировал таблицу
  - включил фильтр
- после обновления страницы можно восстановить это состояние

3. временное хранение данных

- некоторые данные нужны только до закрытия вкладки, например:
  - текущий шаг регистрации
  - черновик формы
  - временные фильтры
  - результаты поиска
- здесь удобно использовать sessionStorage

4. уменьшение количества запросов к серверу

- представим страницу профиля
- после входа пользователь получил:

```json
{
  "name": "Alex",
  "language": "en",
  "theme": "dark"
}
```

- если каждый раз при открытии страницы заново запрашивать эти настройки у сервера, получится лишняя нагрузка
- можно сохранить их локально
- тогда при следующем открытии страницы интерфейс сразу знает:
  - язык
  - тему
  - расположение элементов
- это делает приложение более отзывчивым

⚠️ важно: речь идет о некритичных данных. источником истины для важных данных обычно остается сервер

5. работа без постоянного подключения к интернету

- некоторые приложения могут продолжать работать даже при отсутствии сети
- например: заметки, список задач, форма обратной связи
- пользователь может продолжить работу, а когда интернет появится - данные отправятся на сервер
- конечно, для сложных offline-приложений чаще используют `IndexedDB`, но сама идея хранения данных на клиенте остается той же

## почему нельзя просто хранить все в переменных?

- потому что после обновления страницы скрипт загрузится заново -> все переменные создадутся заново
- storage существует независимо от выполнения JS кода
- он хранит данные между загрузками страницы

## почему нельзя хранить все на сервере?

- можно, но это не всегда удобно, потому что требует сетевых запросов

## данные, которые подходят для хранения в storage

- настройки интерфейса
- язык
- тема
- положение элементов
- история поиска
- недавно просмотренные товары
- черновики
- фильтры
- предпочтения пользователя

## данные, которые не стоит хранить в storage

- пароли
- секретные ключи
- данные банковских карт
- чувствительную персональную информацию
- долгоживущие токены доступа (если есть возможность использовать `HttpOnly` cookies)

- потому что любой JS, выполняющийся на странице (в том числе внедренный злоумышленником при XSS-атаке), может получить доступ к содержимому `localStorage` и `sessionStorage`
