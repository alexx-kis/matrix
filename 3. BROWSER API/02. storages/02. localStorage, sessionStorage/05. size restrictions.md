# size restrictions

- у localStorage и sessionStorage есть ограничение на объем данных, которые сайт может хранить в браузере
- это важно понимать, потому что Storage - не полноценная база данных

## 1. сколько можно хранить?

- нет единого стандарта, который гарантировал бы конкретный размер для всех браузеров
- на практике обычно ориентируются примерно на около 5-10 MB на origin
- но конкретный лимит зависит от:
  - браузера
  - платформы
  - режима браузера
  - типа хранилища
  - доступного дискового пространства

## 2. что значит "на origin"?

- лимит относится к конкретному origin `https://example.com`
- другой origin `https://another-site.com` имеет свое отдельное хранилище и свой лимит

## 3. ограничение относится к данным, а не к количеству ключей

- можно иметь:

```js
localStorage.setItem('theme', 'dark');
localStorage.setItem('language', 'en');
localStorage.setItem('fontSize', '18');
```

- но можно иметь и:

```
key1 → очень большая строка
key2 → очень большая строка
key3 → очень большая строка
...
```

- пока общий объем не достигнет ограничения
- то есть ограничиваются прежде всего объем хранимых данных, а не количество записей

## 4. что произойдет при превышении лимита?

- если попытаться записать больше разрешенного объема, браузер не сможет выполнить запись
- обычно `setItem()` выбрасывает исключение:

```js
localStorage.setItem('hugeData', veryLargeString);
```

- результатом может быть `QuotaExceededError`

- поэтому в реальном приложении потенциально большие записи иногда стоит выполнять с обработкой ошибок

```js
try {
  localStorage.setItem('settings', settingsData);
} catch (error) {
  console.error('Storage quota exceeded');
}
```

## 5. почему нельзя использовать localStorage как базу данных?

- у него:
  - небольшой лимит
  - синхронный API
  - строковый формат данных
  - нет нормальной системы запросов
  - нет индексов
  - нет транзакционной модели, как у полноценной БД

- для больших объемов данных существует, например, IndexedDB
- она предназначена именно для серьезного клиентского хранения

## 6. Storage и большие JSON

- особенно легко столкнуться с ограничением, если мы сериализуем большой объект

```js
const hugeData = JSON.stringify(largeObject);

localStorage.setItem('data', hugeData);
```

- сам `largeObject` может быть очень большим
- после `JSON.stringify()` мы получаем одну большую строку и пытаемся целиком положить ее в Storage
- если объем превышает quota - получим ошибку

## 7. как узнать, сколько места осталось?

- у хранилищ нет стандартного метода, чтобы это узнать
- можно приблизительно контролировать размер собственных данных, но точный доступный остаток зависит от браузера и его политики quota
- для более общего Storage API существует `navigator.storage.estimate()`, например:

```js
const storageInfo = await navigator.storage.estimate();

console.log(storageInfo.usage);
console.log(storageInfo.quota);
```

- здесь:
  - `usage` - сколько storage сейчас используется
  - `quota` - приблизительная доступная quota

- но это относится к общему storage-контексту браузера, а не является точным счетчиком свободного места именно в localStorage
