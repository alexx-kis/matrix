# version control в indexedDB

- version control в IndexedDB — это механизм управления версией структуры базы данных
- он нужен потому, что приложение со временем меняется, а вместе с ним может меняться и структура локальной базы
- например, сначала приложению достаточно хранилища users, а в новой версии понадобилось ещё `products`

## зачем нужна версия

- представим, что первая версия приложения создала такую базу

```
myApp
└── users
```

- браузер сохранил эту базу на компьютере пользователя
- через некоторое время мы выпустили новую версию приложения и теперь хотим получить

```
myApp
├── users
└── products
```

- просто вызвать `createObjectStore('products')` при каждом запуске приложения нельзя, потому что products уже может существовать или база может находиться в другой версии
- поэтому IndexedDB использует номер версии

```js
const databaseRequest = indexedDB.open('myApp', 2);
```

- число 2 означает, что приложение хочет работать со второй версией структуры базы

## как работает изменение версии

- допустим, сейчас у пользователя база версии 1

```
browser
  ↓
myApp
version: 1
  ↓
users
```

- приложение вызывает

```js
const databaseRequest = indexedDB.open('myApp', 2);
```

- браузер видит, что запрошена версия 2, а текущая версия базы — 1
- поэтому сначала вызывается `onupgradeneeded`

```js
databaseRequest.onupgradeneeded = (event) => {
  const database = event.target.result;

  database.createObjectStore('products', {
    keyPath: 'id',
  });
};
```

- после успешного изменения структуры вызывается onsuccess

```js
databaseRequest.onsuccess = (event) => {
  const database = event.target.result;

  console.log(database.version);
};
```

- в результате получаем

```
version 1
   ↓
open(..., 2)
   ↓
onupgradeneeded
   ↓
изменение структуры
   ↓
version 2
   ↓
onsuccess
```

### версия относится именно к структуре базы

- это очень важный момент
- version не означает версию данных внутри базы
- например, если пользователь добавил ещё одного пользователя

```
users
├── Alex
├── John
└── Anna
```

- версия базы от этого не изменяется
- версия нужна именно тогда, когда мы меняем структуру IndexedDB

```
добавили запись       → версия не меняется
изменили запись       → версия не меняется
удалили запись        → версия не меняется

добавили object store → нужна новая версия
удалили object store  → нужна новая версия
добавили index        → нужна новая версия
изменили структуру    → нужна новая версия
```

### `onupgradeneeded` — место для миграций

- на практике `onupgradeneeded` можно воспринимать как место, где приложение мигрирует старую структуру базы в новую например, была версия 1

```
version 1
└── users
```

- появилась версия 2

```
version 2
├── users
└── products
```

- код может выглядеть так

```js
const databaseRequest = indexedDB.open('myApp', 2);

databaseRequest.onupgradeneeded = (event) => {
  const database = event.target.result;

  if (event.oldVersion < 1) {
    database.createObjectStore('users', {
      keyPath: 'id',
    });
  }

  if (event.oldVersion < 2) {
    database.createObjectStore('products', {
      keyPath: 'id',
    });
  }
};
```

- здесь `event.oldVersion` показывает, с какой версии пользователь пришёл
- например, если у него была версия 1, то условие event.oldVersion < 2 позволит создать products

## почему нельзя просто пересоздать базу

- потому что в базе уже могут находиться пользовательские данные

```
version 1

users
├── Alex
├── John
└── Anna
```

- если удалить базу и создать новую, эти данные исчезнут
- миграция позволяет изменить структуру существующей базы, сохранив данные

```
старые данные
     ↓
migration
     ↓
новая структура
     ↓
старые данные остаются
```

## что произойдёт, если указать старую версию

- допустим, база уже находится на версии 2

```js
const databaseRequest = indexedDB.open('myApp', 1);
```

- понизить версию таким способом нельзя
- браузер выдаст ошибку VersionError
- версия базы может двигаться только вперёд

```
1 → 2 → 3 → 4
```

- но не

```
3 → 2
```

## важный практический момент

- номер версии нужно увеличивать только при изменении структуры базы
- например, мы добавили products → 2
- затем добавили индекс email → 3
- затем добавили ещё один object store → 4

```
version 1
  ↓
users

version 2
  ↓
users
products

version 3
  ↓
users + email index
products

version 4
  ↓
users
products
orders
```

- каждый переход должен корректно преобразовывать предыдущую структуру в новую

## что важно для собеседования

- indexedDB.open(name, version) открывает базу с указанной версией
- если базы ещё нет, создаётся новая база и вызывается onupgradeneeded
- если запрошенная версия больше текущей, вызывается onupgradeneeded
- onupgradeneeded используется для изменения структуры и миграций
- onsuccess вызывается после успешного открытия базы
- версия относится к структуре базы, а не к отдельным данным
- уменьшить версию базы нельзя
- изменение object store или index требует повышения версии
- обычные add, put или delete не требуют изменения версии
