# cursors

- Cursor в IndexedDB — это механизм, который позволяет последовательно проходить по записям object store или index
- если `get()` нужен, когда мы хотим получить конкретную запись, то cursor нужен, когда нам нужно пройти по нескольким записям

## зачем нужен cursor

- допустим, в users лежат:

```
id   name
1    Alex
2    John
3    Anna
4    Mike
```

- если нам нужен пользователь с id = 3, достаточно:

```js
const userRequest = userStore.get(3);
```

- но если мы хотим обработать всех пользователей по очереди, можно использовать cursor

```
1 → 2 → 3 → 4
```

- cursor в этом смысле можно представить как указатель, который перемещается от одной записи к следующей

## как создать cursor

- для этого используется `openCursor()`

```js
const cursorRequest = userStore.openCursor();
```

- как и другие операции `IndexedDB`, `openCursor()` возвращает `IDBRequest`

- поэтому результат получаем асинхронно

```js
cursorRequest.onsuccess = (event) => {
  const cursor = event.target.result;

  if (cursor) {
    console.log(cursor.value);
  }
};
```

- `cursor.value` — текущая запись

- например, первый вызов даст:

```
{ id: 1, name: 'Alex' }
```

- но здесь есть очень важный момент
- cursor сам по себе не перейдёт к следующей записи
- для этого нужно вызвать:

```js
cursor.continue();
```

### полный пример

```js
const cursorTransaction = database.transaction('users', 'readonly');

const cursorStore = cursorTransaction.objectStore('users');

const cursorRequest = cursorStore.openCursor();

cursorRequest.onsuccess = (event) => {
  const cursor = event.target.result;

  if (cursor) {
    console.log(cursor.value);

    cursor.continue();
  }
};
```

- теперь происходит следующее:

```
openCursor()
    ↓
record #1
    ↓
continue()
    ↓
record #2
    ↓
continue()
    ↓
record #3
    ↓
continue()
    ↓
record #4
    ↓
continue()
    ↓
null
```

- когда записей больше нет, event.target.result становится null

```js
if (cursor) {
  // запись существует
} else {
  // записи закончились
}
```

## что находится внутри cursor

- cursor предоставляет несколько важных свойств:
  - cursor.key — ключ текущей позиции cursor
  - cursor.value — значение текущей записи
  - cursor.primaryKey особенно важен при работе с индексами

- например:

```js
const cursorKey = cursor.key;
const cursorValue = cursor.value;
```

- для нашего пользователя это может быть:

```
cursor.key
↓
42
```

```
cursor.value
↓
{
  id: 42,
  name: "Alex"
}
```

## направление движения

- по умолчанию cursor движется вперёд

```
1 → 2 → 3 → 4
```

- но можно указать направление

```js
const reverseRequest = userStore.openCursor(null, 'prev');
```

- теперь движение будет:

```
4 → 3 → 2 → 1
```

- основные направления:
  - next — вперёд
  - prev — назад
  - nextunique и prevunique используются с индексами, когда нужно пропускать повторяющиеся значения ключей

## cursor и index

- cursor можно открывать не только непосредственно у objectStore, но и у index

```
objectStore
    ↓
index
    ↓
cursor
```

- например, у нас есть пользователи:

```
id   name
1    Alex
2    John
3    Alex
4    Anna
```

- мы можем иметь индекс name и открыть cursor по этому индексу
- тогда cursor будет проходить записи в порядке ключей этого индекса

## cursor vs getAll

- здесь возникает закономерный вопрос
- если нам нужны все записи, зачем использовать cursor, если существует getAll()?
- действительно, если нам просто нужен массив всех записей:

```js
const allUsersRequest = userStore.getAll();
```

- это проще
- cursor нужен, когда нам нужен контроль над процессом перебора
- например, мы можем:

```
прочитать запись
      ↓
что-то с ней сделать
      ↓
перейти дальше
      ↓
прочитать следующую
```

- cursor также позволяет не обязательно обрабатывать все записи
- мы можем остановить перебор в нужный момент

- например:

```js
const limitedRequest = userStore.openCursor();

limitedRequest.onsuccess = (event) => {
  const cursor = event.target.result;

  if (!cursor) {
    return;
  }

  console.log(cursor.value);

  if (cursor.key < 3) {
    cursor.continue();
  }
};
```

- здесь мы не обязаны проходить всю базу

## cursor как итератор

- полезно провести аналогию с обычным JavaScript

```
массив
  ↓
iterator
  ↓
next()
в IndexedDB похожая идея:
object store
  ↓
cursor
  ↓
continue()
```

- только cursor работает непосредственно с данными IndexedDB и учитывает её механизм асинхронных запросов

- что важно для собеседования

- Cursor позволяет последовательно обходить записи
- создаётся через openCursor()
- текущая запись находится в cursor.value
- ключ текущей записи — cursor.key
- переход к следующей записи выполняется через cursor.continue()
- когда записи закончились, event.target.result становится null
- можно двигаться вперёд или назад
- cursor можно использовать как с object store, так и с index
- если нужно просто получить все записи, часто проще использовать getAll()
- cursor нужен, когда нужен контролируемый последовательный обход записей

- главная схема:

```
openCursor()
     ↓
  cursor
     ↓
cursor.value
     ↓
continue()
     ↓
  cursor
     ↓
cursor.value
     ↓
continue()
     ↓
   null
```

- главное отличие от get() можно сформулировать совсем коротко: get() отвечает на вопрос «дай мне эту запись», а cursor — «проведи меня по этим записям одну за другой»
