# DB setup

- DB setup — это создание и открытие базы данных IndexedDB, с которой наше приложение будет работать

- в отличие от localStorage, где можно сразу написать localStorage.setItem(...), IndexedDB сначала нужно инициализировать

## 1 сначала открываем базу

- для этого используется глобальный объект `indexedDB`

```js
const databaseRequest = indexedDB.open('myApp', 1);
```

- `'myApp'` — название нашей базы данных
- `1` — версия базы данных
- `indexedDB.open()` не возвращает саму базу, он возвращает специальный объект `IDBOpenDBRequest` поэтому дальше мы работаем с событиями этого запроса

```js
databaseRequest.onsuccess = (event) => {
  const database = event.target.result;

  console.log(database);
};
```

- если база успешно открылась, в `event.target.result` находится объект `IDBDatabase`
- именно этот объект представляет открытую базу данных и через него мы дальше будем работать с `IndexedDB`

## 2 но есть важный момент с созданием структуры

- база данных сама по себе ещё не содержит таблиц
- в `IndexedDB` аналогом таблицы является object **store**
- например, мы хотим хранить пользователей

```
myApp
  ↓
users
  ↓
{ id: 1, name: "Alex" }
{ id: 2, name: "John" }
```

- `myApp` — database
- `users` — object store
- объекты внутри users — записи

## 3 где создаётся object store

- для этого используется событие onupgradeneeded

```js
const databaseRequest = indexedDB.open('myApp', 1);

databaseRequest.onupgradeneeded = (event) => {
  const database = event.target.result;

  database.createObjectStore('users', {
    keyPath: 'id',
  });
};
```

- `onupgradeneeded` вызывается, когда `IndexedDB` создаёт новую базу или мы открываем её с более новой версией здесь мы создаём структуру базы данных
- `keyPath: 'id'` означает, что свойство id объекта будет использоваться как его ключ
- поэтому такая запись:

```js
{
  id: 42,
  name: 'Alex'
}
```

- будет иметь ключ 42

## 4 полный минимальный setup

```js
const databaseRequest = indexedDB.open('myApp', 1);

databaseRequest.onupgradeneeded = (event) => {
  const database = event.target.result;

  database.createObjectStore('users', {
    keyPath: 'id',
  });
};

databaseRequest.onsuccess = (event) => {
  const database = event.target.result;

  console.log('database opened', database);
};

databaseRequest.onerror = () => {
  console.log('database error');
};
```

- здесь происходит примерно следующее:

```
indexedDB.open('myApp', 1)
          ↓
    нужно открыть DB
          ↓
┌───────────────────────┐
│ база существует?      │
└───────────┬───────────┘
            │
      нет → onupgradeneeded
            ↓
      создаём users
            ↓
         onsuccess
            ↓
      база готова
```

# 5 зачем нужна версия 1

- версия нужна потому, что структура IndexedDB может изменяться со временем
- например, сегодня у нас:

```
version 1
  users
```

- потом мы захотели добавить:

```
version 2
  users
  products
```

- тогда открываем базу с версией 2

```js
const databaseRequest = indexedDB.open('myApp', 2);
```

- браузер увидит, что текущая версия 1, а мы запросили 2, и вызовет `onupgradeneeded`
- внутри него можно изменить структуру базы

```js
databaseRequest.onupgradeneeded = (event) => {
  const database = event.target.result;

  database.createObjectStore('users', {
    keyPath: 'id',
  });

  database.createObjectStore('products', {
    keyPath: 'id',
  });
};
```

- поэтому `onupgradeneeded` — это фактически место для миграции структуры `IndexedDB`

### главное, что нужно запомнить

- indexedDB.open() — открыть или создать базу
- name — имя базы
- version — версия структуры базы
- onupgradeneeded — создать или изменить структуру базы
- createObjectStore() — создать хранилище записей, аналог таблицы
- onsuccess — база успешно открыта
- onerror — произошла ошибка
- и здесь пока не нужно пытаться запомнить весь API IndexedDB
