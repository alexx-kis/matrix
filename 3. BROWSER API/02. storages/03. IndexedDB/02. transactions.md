# transactions

- `transaction` в IndexedDB — это операция или группа операций с базой данных, которая выполняется как единое целое
- главная задача transaction — обеспечить, чтобы работа с данными была безопасной и предсказуемой

## Зачем вообще нужны transactions

- представь, что у нас есть users и мы хотим изменить пользователя

```
users
  ↓
id: 1
name: Alex
age: 30
```

- мы можем захотеть выполнить несколько операций:
  1. получить пользователя
  2. изменить name
  3. сохранить пользователя

- IndexedDB не позволяет просто сказать `database.users.update(...)`
- сначала мы должны создать transaction, которая разрешает нам работать с конкретным `object store`

```
database
   ↓
transaction
   ↓
object store
   ↓
record
```

## Создание transaction

- допустим, у нас уже есть открытая база в переменной `database`

```js
const userTransaction = database.transaction('users', 'readwrite');
```

- первый аргумент — с каким `object store` работаем
- второй аргумент — режим доступа

#### основные режимы:

- readonly
- readwrite

### readonly

- readonly разрешает читать данные, но не изменять их

```js
const readTransaction = database.transaction('users', 'readonly');
```

- это режим по умолчанию

### readwrite

- `readwrite` разрешает и читать, и изменять данные

```js
const writeTransaction = database.transaction('users', 'readwrite');
```

- если мы хотим добавить, изменить или удалить запись, нужен readwrite

## Получение object store

- после создания transaction мы получаем нужное хранилище

```js
const store = writeTransaction.objectStore('users');
```

- теперь store позволяет выполнять операции над записями

```
database
   ↓
transaction
   ↓
objectStore('users')
   ↓
add / get / put / delete
```

### Например, добавляем пользователя

```js
const saveTransaction = database.transaction('users', 'readwrite');

const userStore = saveTransaction.objectStore('users');

userStore.add({
  id: 1,
  name: 'Alex',
});
```

- здесь происходит не так: `database → сразу записать`
- а так:

```
database
   ↓
создали transaction
   ↓
получили users
   ↓
выполнили add()
   ↓
transaction завершилась
```

## Почему это называется transaction

- представь банковский перевод

```
счёт A: -100 €
счёт B: +100 €
```

- нельзя допустить ситуацию, когда деньги списались с A, но не попали на B
- обе операции должны рассматриваться как единое целое
- если одна часть операции не удалась, transaction может быть отменена
- в этом и заключается идея atomicity — операции внутри transaction выполняются как единое целое

### В IndexedDB transaction может содержать несколько операций

- например:

```js
const transferTransaction = database.transaction(['users', 'orders'], 'readwrite');

const usersStore = transferTransaction.objectStore('users');
const ordersStore = transferTransaction.objectStore('orders');
```

- одна transaction может работать сразу с несколькими object store, если они указаны при её создании

## Важный нюанс

- transaction в IndexedDB не нужно воспринимать как что-то, что мы вручную открываем и потом обязательно закрываем
- мы создаём transaction, выполняем операции, и браузер сам завершает её
- если всё прошло успешно:

```
transaction
     ↓
   commit
     ↓
изменения сохранены
```

- если произошла ошибка:

```
transaction
     ↓
  abort
     ↓
изменения отменены
```

## Главное для собеседования

- transaction — это механизм безопасного выполнения операций с IndexedDB
- readonly используется для чтения
- readwrite используется для изменения данных
- через transaction мы получаем objectStore
- операции add(), get(), put(), delete() выполняются через objectStore
- transaction может содержать несколько операций
- успешная transaction фиксирует изменения, а отменённая не сохраняет изменения
- цепочка, которую сейчас важно держать в голове:

```
IndexedDB
   ↓
Database
   ↓
Transaction
   ↓
Object Store
   ↓
Record
```
