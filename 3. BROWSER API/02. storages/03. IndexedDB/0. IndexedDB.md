# что такое IndexedDB

- IndexedDB — это встроенная в браузер база данных, которая позволяет веб-приложению хранить большие объёмы структурированных данных прямо на устройстве пользователя

- то есть:

```
JavaScript
   ↓
IndexedDB
   ↓
данные сохраняются на компьютере/телефоне
```

- например, сайт может сохранить:
  - пользователя
  - товары
  - настройки
  - историю действий
  - кэшированные данные
  - большие JSON-объекты
  - файлы / Blob

- и потом получить их даже после перезагрузки страницы

## зачем она нужна, если уже есть localStorage?

### localStorage

```js
localStorage.setItem(
  'user',
  JSON.stringify({
    name: 'Alex',
    age: 30,
  }),
);
```

- подходит для относительно простых данных: `ключ → строка`

- например:

```
theme → "dark"
token → "abc123"
language → "ru"
```

- но localStorage имеет серьёзные ограничения

### IndexedDB

- IndexedDB уже больше похожа на настоящую базу данных:

```
Database
 ├── users
 ├── products
 ├── orders
 └── settings
```

- в ней можно хранить не только строки, а структурированные JavaScript-значения

- например:

```js
{
  id: 42,
  name: 'Alex',
  skills: ['JavaScript', 'React', 'TypeScript'],
  settings: {
    theme: 'dark',
    language: 'ru'
  }
}
```

- причём не нужно превращать объект в JSON-строку, как в localStorage

## почему она называется IndexedDB?

- название можно примерно разобрать так:

**Indexed** → данные можно организовывать с помощью индексов

**DB** → Database, база данных

- то есть это действительно база данных внутри браузера, а не просто механизм хранения нескольких строк

- например, у нас есть:

```
users


id | name  | age
---|-------|----
1  | Alex  | 30
2  | John  | 25
3  | Anna  | 31
```

- мы можем искать пользователя по id, а при правильной настройке — эффективно искать и по другим полям через индексы

## где физически находятся данные?

- когда ты пишешь:

```js
localStorage.setItem(...)
```

- или работаешь с IndexedDB, данные не отправляются автоматически на сервер

- они сохраняются локально в браузере на устройстве пользователя

- условно:

```
                    Интернет
                       │
                       │
        ┌──────────────┴──────────────┐
        │                             │
      SERVER                       БРАУЗЕР
                                        │
                              ┌─────────┴─────────┐
                              │                   │
                         localStorage        IndexedDB
```

- поэтому IndexedDB часто используется для приложений, которым нужно работать с данными даже при плохом или отсутствующем интернете

### пример из реального приложения

- представь приложение для заметок

- Пользователь создал 10 000 заметок

- Можно было бы каждый раз отправлять их на сервер:

```
создал заметку
     ↓
POST /notes
     ↓
SERVER
```

- но приложение может дополнительно хранить локальную копию:

```
SERVER
  ↕
IndexedDB
  ↓
React UI
```

- если интернет пропал:

```
пользователь
     ↓
создаёт заметку
     ↓
IndexedDB
     ↓
заметка сохранена локально
```

- интернет появился:

```
IndexedDB
     ↓
синхронизация
     ↓
SERVER
```

- это один из важных сценариев использования IndexedDB

## а почему не хранить всё в localStorage?

- потому что IndexedDB рассчитана именно на более серьёзное локальное хранилище

- очень грубо:

```
|                          | localStorage      | IndexedDB                  |
| ------------------------ | ----------------- | -------------------------- |
| Тип                      | key-value storage | база данных                |
| Данные                   | строки            | структурированные значения |
| Объёмы                   | небольшие         | значительно больше         |
| Индексы                  | ❌                | ✅                         |
| Запросы                  | очень примитивные | гораздо мощнее             |
| Асинхронность            | синхронная        | асинхронная                |
| Сложные данные           | неудобно          | подходит                   |
| Большие локальные данные | ❌                | ✅                         |
```

- особенно важно запомнить:

- `localStorage` — простой механизм хранения небольших значений

- `IndexedDB` — полноценное локальное хранилище структурированных данных в браузере

### и ещё один важный нюанс

- IndexedDB — это не серверная база данных.

- Например:
  - PostgreSQL
  - MySQL
  - MongoDB

- обычно находятся на сервере.

- а:
  - IndexedDB
  - localStorage
  - sessionStorage
  - cookies

- относятся к браузерному/клиентскому хранению

- то есть IndexedDB находится на стороне client
