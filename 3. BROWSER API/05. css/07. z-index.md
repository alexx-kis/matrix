# z-index

- `z-index` определяет порядок наложения элементов по оси **Z**, то есть какой элемент визуально находится выше, если элементы пересекаются

```css
.first {
  position: absolute;
  z-index: 1;
}

.second {
  position: absolute;
  z-index: 2;
}
```

- если элементы пересекаются, `.second` обычно будет отображаться поверх `.first`

```

      ┌───────────────┐
      │    second     │  z-index: 2
      │               │
   ┌──┼───────────────┤
   │  │               │
   │  └───────────────┘
   │ first
   └───────────────────┘
   z-index: 1
```

## ось Z

- обычно мы думаем о CSS layout в двух измерениях — `X` и `Y`

```
        Y
        ↑
        │
        │
        └────────→ X
```

- `Z` отвечает за глубину

```
        пользователь
             ↓
        ┌────────┐
        │ z: 3   │
        └────────┘
        ┌────────┐
        │ z: 2   │
        └────────┘
        ┌────────┐
        │ z: 1   │
        └────────┘
```

- чем выше stacking order, тем ближе элемент визуально к пользователю

## значение `z-index`

- `z-index` может принимать целые числа

```css
.modal {
  z-index: 100;
}

.header {
  z-index: 10;
}
```

- `z-index: 100` не означает, что элемент автоматически будет поверх **всего документа**

- это очень важный нюанс

- `z-index` сравнивается внутри определённого **stacking context**

## stacking context

- **stacking context** — это независимая область, внутри которой браузер определяет порядок наложения элементов

- можно представить stacking context как отдельный "слой"

```
page
│
├── stacking context A
│   ├── element z-index: 1
│   └── element z-index: 999
│
└── stacking context B
    ├── element z-index: 1
    └── element z-index: 999
```

- `z-index: 999` внутри одного stacking context не обязательно окажется выше элемента из другого stacking context с `z-index: 1`

## классический пример с родителями

```html
<div class="first-layer">
  <div class="element-a"></div>
</div>

<div class="second-layer">
  <div class="element-b"></div>
</div>
```

```css
.first-layer {
  position: relative;
  z-index: 1;
}

.element-a {
  position: relative;
  z-index: 9999;
}

.second-layer {
  position: relative;
  z-index: 2;
}

.element-b {
  position: relative;
  z-index: 1;
}
```

- может показаться, что `.element-a` должен быть выше `.element-b`, потому что `9999 > 1`

- но это не так

- `.element-a` находится внутри stacking context `.first-layer` с уровнем `1`

- `.element-b` находится внутри stacking context `.second-layer` с уровнем `2`

- поэтому весь stacking context `.second-layer` находится выше `.first-layer`

```
second-layer: 2
└── element-b: 1

first-layer: 1
└── element-a: 9999
```

- внутренний `9999` не может "вырваться" за пределы родительского stacking context

## когда работает `z-index`

- исторически часто говорили, что `z-index` работает только у positioned elements

- это хорошее упрощение для старого CSS, но сегодня оно **неполное**

- `z-index` работает, например, у flex items и grid items даже без явного `position`

```css
.container {
  display: flex;
}

.item {
  z-index: 2;
}
```

- поэтому правильнее говорить, что поведение `z-index` зависит от типа элемента и stacking context, а не просто от наличия `position`

## `position` и `z-index`

- для обычного positioned элемента можно использовать

```css
.element {
  position: relative;
  z-index: 10;
}
```

- `position: relative` здесь не обязательно означает, что элемент нужно визуально переместить

- часто его используют только для участия в позиционировании и управления stacking order

## отрицательный `z-index`

- `z-index` может быть отрицательным

```css
.background {
  position: absolute;
  z-index: -1;
}
```

- элемент будет находиться ниже элементов с более высоким stacking level

- но отрицательный `z-index` может вести себя неожиданно из-за stacking contexts и фона родителя, поэтому использовать его нужно осознанно

## `z-index: 0`

- `z-index: 0` не означает "элемент находится над всем"

- он просто задаёт определённый stacking level внутри соответствующего контекста

- поэтому числа `0`, `1`, `100` и `9999` нельзя рассматривать как глобальные уровни всей страницы

## почему `z-index: 9999` иногда не работает

- это один из самых частых вопросов на собеседовании

- например, есть modal

```css
.modal {
  position: fixed;
  z-index: 9999;
}
```

- но он всё равно оказывается под каким-то другим элементом

- проблема может быть не в недостаточно большом числе, а в том, что `.modal` находится внутри stacking context, который сам находится ниже другого stacking context

- поэтому увеличение `z-index` с `9999` до `999999` не обязательно решит проблему

## что создаёт stacking context

- stacking context может создаваться разными CSS-свойствами

- среди наиболее важных случаев

```css
position: relative;
z-index: 1;
```

- также stacking context может возникать у positioned элементов с `z-index`, отличным от `auto`

- `position: fixed` и `position: sticky` имеют особенности создания stacking context

- `opacity` меньше `1`

```css
.element {
  opacity: 0.9;
}
```

- `transform`, отличный от `none`

```css
.element {
  transform: translateX(0);
}
```

- `filter`, `isolation: isolate`, определённые значения `mix-blend-mode`, `contain` и другие свойства также могут создавать stacking context

- поэтому изменение seemingly unrelated CSS-свойства иногда неожиданно меняет поведение `z-index`

## `z-index: auto`

- `auto` означает, что элемент не получает явно заданный stacking level через `z-index`

```css
.element {
  z-index: auto;
}
```

- это не то же самое, что `z-index: 0`

- `auto` позволяет элементу участвовать в естественном порядке наложения своего stacking context, тогда как `0` задаёт конкретный уровень

## порядок при одинаковом `z-index`

- если элементы находятся в одном stacking context и имеют одинаковый stacking level, важную роль играет порядок в документе

```html id="m3k7vz"
<div class="first"></div>
<div class="second"></div>
```

- при прочих равных условиях более поздний элемент может оказаться выше более раннего

```
first
second ← выше
```

## практический пример: modal

- часто задают условную систему уровней

```css
.header {
  z-index: 10;
}

.dropdown {
  z-index: 20;
}

.modal {
  z-index: 100;
}

.tooltip {
  z-index: 200;
}
```

- смысл такой системы не в магических больших числах, а в том, чтобы заранее определить уровни интерфейса

- гораздо лучше иметь понятную систему слоёв, чем использовать `999`, `9999`, `99999` без причины

## главное для собеседования

- `z-index` управляет порядком наложения элементов по оси Z
- большее значение обычно означает более высокий stacking level **в пределах соответствующего stacking context**
- `z-index` не является глобальным числом для всей страницы
- главный термин для понимания `z-index` — **stacking context**
- дочерний элемент не может своим `z-index` выйти за пределы stacking context родителя
- stacking context может создаваться не только через `position` и `z-index`, но и через свойства вроде `opacity`, `transform`, `filter`, `isolation` и другие
- `z-index: 9999` не гарантирует, что элемент будет поверх всего
- если `z-index` "не работает", первым делом нужно проверить stacking contexts и положение элемента относительно других stacking contexts
