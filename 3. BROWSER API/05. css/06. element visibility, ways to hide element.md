# element visibility

- в CSS существует несколько способов скрыть элемент, но они **неэквивалентны** — элемент может исчезнуть визуально, перестать занимать место, перестать реагировать на события мыши или даже стать недоступным для accessibility API

## `display: none`

```css
.hidden {
  display: none;
}
```

- элемент полностью исключается из layout

```
до:

┌───────┐ ┌───────┐ ┌───────┐
│   A   │ │   B   │ │   C   │
└───────┘ └───────┘ └───────┘

display: none у B:

┌───────┐ ┌───────┐
│   A   │ │   C   │
└───────┘ └───────┘
```

- соседние элементы занимают освободившееся место

- элемент также недоступен для обычного взаимодействия с пользователем

- это хороший вариант, когда элемент действительно не должен существовать в текущем layout

## `visibility: hidden`

```css
.hidden {
  visibility: hidden;
}
```

- элемент становится невидимым, но **продолжает занимать своё место в layout**

```
до:

┌───────┐ ┌───────┐ ┌───────┐
│   A   │ │   B   │ │   C   │
└───────┘ └───────┘ └───────┘

visibility: hidden у B:

┌───────┐ ┌───────┐ ┌───────┐
│   A   │ │       │ │   C   │
└───────┘ └───────┘ └───────┘
```

- место под `B` остаётся зарезервированным

- элемент обычно не является целью обычных pointer events

- основное отличие от `display: none` — layout сохраняется

## `opacity: 0`

```css
.hidden {
  opacity: 0;
}
```

- элемент становится полностью прозрачным, но **остаётся в layout**

- в отличие от `visibility: hidden`, прозрачный элемент по умолчанию всё ещё может участвовать во взаимодействии

```css
.button {
  opacity: 0;
}
```

- кнопка визуально исчезнет, но пользователь всё ещё может потенциально кликнуть по её области

- поэтому `opacity: 0` нельзя автоматически считать полноценным способом "отключить" элемент

- часто вместе с ним используют

```css
.hidden {
  opacity: 0;
  pointer-events: none;
}
```

- тогда элемент не будет получать pointer events

## сравнение

| способ                                | виден | занимает место | участвует в layout | pointer events |
| ------------------------------------- | ----- | -------------- | ------------------ | -------------- |
| `display: none`                       |   нет |            нет |                нет |            нет |
| `visibility: hidden`                  |   нет |             да |                 да |            нет |
| `opacity: 0`                          |   нет |             да |                 да |             да |
| `opacity: 0` + `pointer-events: none` |   нет |             да |                 да |            нет |

## `position` и скрытие

- иногда элемент убирают за пределы видимой области

```css
.element {
  position: absolute;
  left: -9999px;
}
```

- элемент остаётся частью layout в другом смысле, но визуально оказывается далеко за пределами viewport

- такой подход исторически использовался для визуально скрытого текста, например для screen reader

- однако для этой задачи сейчас обычно используют специальный visually-hidden паттерн

## visually hidden

- иногда элемент должен быть невидимым для обычного пользователя, но при этом оставаться доступным для screen reader

- тогда `display: none` использовать нельзя, потому что элемент становится недоступен и для accessibility API

- типичный паттерн выглядит примерно так

```css
.visually-hidden {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip: rect(0 0 0 0);
  white-space: nowrap;
  border: 0;
}
```

- такой элемент визуально не виден, но его содержимое может оставаться доступным assistive technologies

- это принципиально отличается от `display: none`

## `visibility: collapse`

- значение `collapse` существует прежде всего для таблиц

```css
tr {
  visibility: collapse;
}
```

- поведение зависит от типа элемента, поэтому использовать `collapse` как универсальную замену `hidden` не следует

## `content-visibility`

- `content-visibility` — более современный механизм, связанный не столько с "невидимостью", сколько с оптимизацией rendering

```css
.section {
  content-visibility: auto;
}
```

- браузер может пропускать часть работы по рендерингу содержимого, которое в данный момент находится вне viewport

- это **не обычный способ скрытия элемента**, поэтому не стоит смешивать `content-visibility` с `display: none` или `visibility: hidden`

## важный нюанс: скрытие ≠ удаление из DOM

- все перечисленные CSS-способы только меняют визуальное представление или участие элемента в layout

- сам HTML-элемент продолжает существовать в DOM

```js
document.querySelector('.hidden');
```

- JavaScript всё ещё может найти элемент, изменить его стили или содержимое

- если элемент действительно нужно удалить из DOM, это уже задача JavaScript, а не CSS

## как выбрать способ

- если элемент **вообще не должен занимать место** — `display: none`
- если нужно **сохранить место**, но сделать элемент невидимым — `visibility: hidden`
- если нужна **прозрачность**, например для анимации — `opacity: 0`
- если элемент должен быть невидимым, но доступным для screen reader — visually-hidden pattern
- если нужно временно скрыть часть страницы ради производительности — можно рассматривать `content-visibility`, но это уже другая задача

## частый вопрос на собеседовании

- **чем отличаются `display: none`, `visibility: hidden` и `opacity: 0`**
- `display: none` — элемент исключён из layout и не отображается
- `visibility: hidden` — элемент не отображается, но его место в layout сохраняется
- `opacity: 0` — элемент полностью прозрачный, но остаётся в layout и по умолчанию может продолжать получать pointer events
- это различие особенно важно при создании dropdown, modal, tooltip и CSS-анимаций, потому что выбор способа скрытия влияет не только на внешний вид, но и на layout, взаимодействие и accessibility
