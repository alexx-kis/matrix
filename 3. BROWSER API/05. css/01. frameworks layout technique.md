# frameworks layout technique

- в CSS под **frameworks layout technique** обычно понимают вёрстку с использованием готового CSS-фреймворка, который предоставляет заранее реализованные правила для построения layout, сеток, отступов, адаптивности и типовых компонентов

- наиболее известные примеры — Bootstrap, Foundation, Tailwind CSS и Bulma

## зачем нужны CSS-фреймворки

- основная идея фреймворка — не писать каждый раз базовую инфраструктуру layout самостоятельно

- например, без фреймворка разработчик может сам создать систему колонок на `flex` или `grid`, написать media queries, классы для отступов и правила для разных размеров экрана

- фреймворк предоставляет большую часть этой инфраструктуры уже готовой

- условно вместо собственного CSS

```css
.layout {
  display: flex;
  gap: 24px;
}

.sidebar {
  width: 25%;
}

.content {
  width: 75%;
}

@media (max-width: 768px) {
  .layout {
    flex-direction: column;
  }

  .sidebar,
  .content {
    width: 100%;
  }
}
```

- можно использовать готовые классы фреймворка

```html
<div class="container">
  <div class="row">
    <aside class="col-md-3"></aside>
    <main class="col-md-9"></main>
  </div>
</div>
```

- конкретные названия классов зависят от фреймворка, но принцип один — HTML описывает структуру, а готовые CSS-классы задают layout

## grid system

- одна из главных особенностей классических CSS-фреймворков — **grid system**, то есть заранее определённая система колонок

- например, Bootstrap использует сетку из 12 колонок

- если нужно разделить контейнер на две равные части, условно можно получить

```
|------ 6 ------|------ 6 ------|
```

- если нужно расположить sidebar и основной контент

```
|--- 3 ---|--------- 9 ---------|
```

- это позволяет описывать ширину элементов относительно сетки, а не вручную вычислять проценты

- например

```html
<div class="row">
  <aside class="col-3">Sidebar</aside>
  <main class="col-9">Content</main>
</div>
```

- здесь `col-3` означает примерно четверть доступной ширины, а `col-9` — оставшиеся три четверти

## responsive grid

- современная grid-система обычно сразу учитывает разные размеры viewport

- например, один и тот же элемент может занимать

```html
<div class="col-12 col-md-6 col-lg-4">Card</div>
```

- условно это означает

```
маленький экран  → 12 колонок → вся ширина
средний экран    → 6 колонок  → половина ширины
большой экран    → 4 колонки  → треть ширины
```

- таким образом responsive layout можно описывать непосредственно через классы

## container и row

- в классических framework grid-системах часто встречается структура

```html
<div class="container">
  <div class="row">
    <div class="column"></div>
    <div class="column"></div>
  </div>
</div>
```

- `container` обычно отвечает за максимальную ширину контента и горизонтальное центрирование

- `row` представляет строку сетки

- колонки располагаются внутри `row`

- это не специальное поведение HTML, а договорённость конкретного CSS-фреймворка

## utility classes

- современные фреймворки часто предоставляют не только сетку, но и **utility classes**

- utility class — маленький класс, который выполняет одну конкретную задачу

```html
<div class="d-flex gap-3 p-4">Content</div>
```

- условно здесь один класс включает `display: flex`, другой задаёт `gap`, третий — `padding`

- в результате часть CSS можно писать непосредственно через классы HTML

- это особенно характерно для Tailwind CSS, где классы являются очень мелкими строительными блоками

```html
<div class="flex items-center gap-4 p-6">Content</div>
```

- такой подход отличается от классического Bootstrap-подхода, где чаще используются более семантически или компонентно ориентированные классы

## framework layout vs собственный CSS

- важно понимать, что CSS-фреймворк **не является отдельной технологией layout**

- внутри framework всё равно используются обычные CSS-механизмы — чаще всего `flexbox`, `grid`, `position`, media queries и CSS custom properties

- поэтому framework не заменяет знание CSS

- наоборот, чтобы нормально работать с framework, нужно понимать CSS-механизм, который находится под его абстракцией

- например, если framework предоставляет класс для горизонтального расположения элементов, внутри может находиться примерно

```css
.some-class {
  display: flex;
}
```

- если разработчик не понимает `flexbox`, ему будет сложно разобраться, почему элементы ведут себя определённым образом

## преимущества

- высокая скорость разработки

- готовая responsive grid system

- большое количество utility-классов

- готовые базовые стили и компоненты

- единый подход к layout внутри проекта

- меньше необходимости писать однотипный CSS вручную

- часто есть готовые breakpoint'ы для разных размеров viewport

## недостатки

- увеличивается зависимость от конкретного framework

- HTML может становиться перегруженным большим количеством классов

- может быть сложнее полностью контролировать внешний вид

- готовая grid system не всегда идеально соответствует требованиям конкретного проекта

- использование большого framework ради нескольких utility-классов может быть избыточным

- при неправильном использовании разработчик может фактически перестать понимать, какой CSS стоит за используемыми классами

## что важно сказать на собеседовании

- **CSS framework layout technique** — это использование готовой системы CSS-классов для построения layout вместо самостоятельной реализации всей базовой инфраструктуры

- обычно framework предоставляет grid system, responsive breakpoints, контейнеры, колонки, spacing utilities и другие инструменты

- при этом сам layout внутри framework обычно построен на стандартных CSS-механизмах, прежде всего `flexbox` и `grid`

- поэтому framework следует воспринимать как **готовую абстракцию над CSS**, а не как замену самому CSS
