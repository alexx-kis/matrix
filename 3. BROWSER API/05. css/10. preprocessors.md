# preprocessors

- **CSS-препроцессор** — это инструмент, который позволяет писать CSS с дополнительными возможностями, которых нет в обычном CSS или которые исторически появились в CSS позже
- исходный код препроцессора браузер напрямую не понимает
- сначала специальный инструмент преобразует его в обычный CSS, который уже загружается браузером

```
SCSS / LESS
    ↓
preprocessor
    ↓
обычный CSS
    ↓
браузер
```

- наиболее известные CSS-препроцессоры — **Sass** и **Less**
- Sass сегодня значительно распространённее Less

## зачем вообще нужны препроцессоры

- обычный CSS долгое время был довольно ограниченным языком для организации больших stylesheet-файлов
- например, в старом CSS нельзя было нормально объявить переменную и использовать её во многих местах

```css
.header {
  background: #2563eb;
}

.button {
  background: #2563eb;
}

.link {
  color: #2563eb;
}
```

- если основной цвет изменится, его пришлось бы менять в нескольких местах
- препроцессор позволяет вынести такое значение в переменную

```scss
$brand-color: #2563eb;

.header {
  background: $brand-color;
}

.button {
  background: $brand-color;
}

.link {
  color: $brand-color;
}
```

- после компиляции браузер получит обычный CSS

```css
.header {
  background: #2563eb;
}

.button {
  background: #2563eb;
}

.link {
  color: #2563eb;
}
```

- это ключевая идея препроцессора: **разработчик пишет расширенный синтаксис, а браузер получает обычный CSS**

## Sass

- **Sass** — CSS-препроцессор, который существует в двух основных синтаксических вариантах: `.sass` и `.scss`
- `.scss` использует синтаксис, очень похожий на обычный CSS

```scss
$accent-color: #7c3aed;

.notice {
  color: $accent-color;
  padding: 16px;
}
```

- `.sass` использует indentation-based синтаксис и не использует `{}` и `;`

```sass
$accent-color: #7c3aed

.notice
  color: $accent-color
  padding: 16px
```

- в современных проектах чаще встречается именно **SCSS**, потому что его проще воспринимать как расширение обычного CSS

## переменные

- Sass позволяет создавать переменные через `$`

```scss
$main-color: #2563eb;
$spacing-unit: 8px;
$radius-size: 12px;

.profile-card {
  color: $main-color;
  padding: $spacing-unit;
  border-radius: $radius-size;
}
```

- это позволяет централизованно хранить повторяющиеся значения
- важно понимать, что это **переменная препроцессора**, а не CSS custom property

```scss
$theme-color: #2563eb;
```

- значение `$theme-color` подставляется во время компиляции

- CSS custom property существует уже в браузере:

```css
:root {
  --theme-color: #2563eb;
}
```

```css
.profile-card {
  color: var(--theme-color);
}
```

- это важное различие для собеседования

## nesting

- Sass позволяет вкладывать селекторы друг в друга

```scss
.navigation-panel {
  background: white;

  .navigation-link {
    color: #333;

    &:hover {
      color: #2563eb;
    }
  }
}
```

- после компиляции получится примерно такой CSS:

```css
.navigation-panel {
  background: white;
}

.navigation-panel .navigation-link {
  color: #333;
}

.navigation-panel .navigation-link:hover {
  color: #2563eb;
}
```

- `&` обозначает текущий родительский селектор

```scss
.action-button {
  &:hover {
    opacity: 0.8;
  }

  &.is-active {
    background: #2563eb;
  }
}
```

- это превращается в:

```css
.action-button:hover {
  opacity: 0.8;
}

.action-button.is-active {
  background: #2563eb;
}
```

- nesting удобен, но чрезмерная вложенность создаёт длинные селекторы и увеличивает specificity
- поэтому современные проекты обычно стараются не делать глубокую вложенность

## mixins

- **mixin** — переиспользуемый кусок стилей, который можно подключать в разных местах

```scss
@mixin center-content {
  display: flex;
  justify-content: center;
  align-items: center;
}

.dialog-content {
  @include center-content;
}

.loader-area {
  @include center-content;
}
```

- после компиляции стили будут продублированы в соответствующих местах
- mixin может принимать параметры

```scss
@mixin rounded-box($radius) {
  border-radius: $radius;
}

.small-panel {
  @include rounded-box(6px);
}

.large-panel {
  @include rounded-box(20px);
}
```

- mixin особенно полезен, когда нужно переиспользовать набор связанных CSS-свойств с разными параметрами

## functions

- Sass позволяет создавать собственные функции, которые возвращают значение

```scss
@function spacing($level) {
  @return $level * 8px;
}

.content-area {
  padding: spacing(3);
}
```

- после компиляции:

```css
.content-area {
  padding: 24px;
}
```

- это позволяет создавать собственные системы расчётов и design tokens

## математические операции

- препроцессор может выполнять вычисления

```scss
$base-size: 8px;

.panel-area {
  padding: $base-size * 3;
  margin-bottom: $base-size * 2;
}
```

- результат:

```css
.panel-area {
  padding: 24px;
  margin-bottom: 16px;
}
```

- сегодня для части подобных задач уже хватает возможностей самого CSS, например `calc()`, поэтому это преимущество препроцессора стало менее значимым

## partials и modules

- большие CSS-проекты можно разделять на несколько файлов
- например:

```
styles/
├── _variables.scss
├── _mixins.scss
├── _buttons.scss
├── _forms.scss
└── main.scss
```

- затем части можно подключать в основной файл
- современный Sass предпочитает систему `@use` и `@forward`

```scss
@use 'variables';
@use 'buttons';
@use 'forms';
```

- это помогает разделять код по ответственности и не превращать один файл в огромную простыню

## наследование

- Sass поддерживает `@extend`, который позволяет одному селектору наследовать набор правил другого

```scss
.message-base {
  padding: 12px;
  border-radius: 8px;
}

.success-message {
  @extend .message-base;
  color: green;
}

.error-message {
  @extend .message-base;
  color: red;
}
```

- Sass объединит селекторы там, где это возможно
- однако `@extend` может неожиданно влиять на итоговую структуру селекторов, поэтому многие команды предпочитают mixins для более предсказуемого переиспользования

## Less

- **Less** — другой CSS-препроцессор с похожей концепцией
- он тоже поддерживает переменные, nesting, mixins, функции и математические операции

```less
@brand-color: #2563eb;
@space-unit: 8px;

.panel-area {
  color: @brand-color;
  padding: @space-unit * 2;
}
```

- после компиляции:

```css
.panel-area {
  color: #2563eb;
  padding: 16px;
}
```

- главное синтаксическое отличие от Sass — обозначение переменных

```scss
$color: blue;
```

```less
@color: blue;
```

## Sass vs Less

| Возможность          | Sass / SCSS        | Less                             |
| -------------------- | ------------------ | -------------------------------- |
| Переменные           | `$name`            | `@name`                          |
| Nesting              | да                 | да                               |
| Mixins               | да                 | да                               |
| Functions            | да                 | да                               |
| Математика           | да                 | да                               |
| Modules              | `@use`, `@forward` | другая система                   |
| `@extend`            | да                 | поддержка отличается по механике |
| Популярность сегодня | выше               | ниже                             |
| Синтаксис            | SCSS близок к CSS  | близок к CSS                     |

- концептуально они решают одну и ту же задачу
- на собеседовании обычно важнее понимать **зачем нужен препроцессор и какие проблемы он решает**, чем помнить все различия синтаксиса

## преимущества препроцессоров

- **переиспользование** — mixins, functions и другие механизмы позволяют не дублировать код
- **организация** — большой stylesheet можно разделить на логические модули
- **переменные** — удобно централизованно хранить значения
- **nesting** — позволяет группировать связанные селекторы
- **вычисления** — можно выполнять расчёты во время компиляции
- **абстракции** — можно создавать собственные инструменты поверх CSS
- **совместимость со старыми проектами** — большое количество существующих проектов до сих пор используют Sass или Less

## недостатки

- появляется дополнительный этап сборки
- разработчику приходится понимать ещё один синтаксис
- debugging может быть сложнее, если неправильно настроены source maps
- некоторые возможности, ради которых раньше использовали Sass или Less, теперь существуют непосредственно в CSS
- чрезмерное использование nesting, `@extend` и абстракций может сделать CSS сложнее, а не проще

## препроцессоры и современный CSS

- это особенно важный момент для современного собеседования
- Sass появился в эпоху, когда CSS действительно не хватало многих возможностей
- сейчас CSS получил native variables, nesting, `calc()`, `min()`, `max()`, `clamp()`, Grid, более мощные функции и другие возможности
- поэтому нельзя говорить, что **«Sass нужен, потому что в CSS нет переменных»**
- CSS-переменные уже существуют
- нельзя также говорить, что **«nesting есть только в Sass»**
- современный CSS поддерживает native nesting

```css
.card-wrapper {
  color: black;

  & .card-title {
    font-weight: 700;
  }
}
```

- поэтому сегодня Sass — это скорее дополнительный слой абстракций и инструментов разработки, а не необходимость для любого проекта

## что выбрать сегодня

- если проект уже использует Sass, обычно нет смысла просто переписывать всё на чистый CSS
- если проект новый, стоит сначала посмотреть, достаточно ли возможностей современного CSS
- если команде нужны Sass modules, mixins, сложные compile-time функции или уже существует большая Sass-кодовая база, Sass по-прежнему может быть оправдан

## что сказать на собеседовании

- **CSS-препроцессор — это инструмент, который расширяет возможности CSS и затем компилирует исходный код в обычный CSS**
- **Sass и Less решают похожие задачи: переменные, nesting, mixins, функции, вычисления и организацию больших stylesheet-проектов**
- **Sass сейчас распространён сильнее Less, а SCSS является его синтаксисом, максимально близким к обычному CSS**
- **главные преимущества — переиспользование кода, организация больших стилей и дополнительные абстракции**
- **при этом современный CSS уже реализует многие возможности, которые раньше были главной причиной использовать препроцессоры, поэтому необходимость Sass нужно оценивать с учётом конкретного проекта**
