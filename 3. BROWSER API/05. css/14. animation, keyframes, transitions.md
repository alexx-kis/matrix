# animation, keyframes и transitions

- в CSS есть два основных механизма для создания движения — **transitions** и **animations**
- `transition` предназначен в первую очередь для плавного перехода свойства из одного состояния в другое
- `animation` позволяет описать полноценную последовательность состояний с помощью `@keyframes`

```
transition

state A ───────────────→ state B


animation

state A → state B → state C → state D
```

# transitions

- `transition` говорит браузеру: **если значение CSS-свойства изменится, не меняй его мгновенно, а плавно переходи от старого значения к новому**

```css
.action-link {
  color: black;
  transition: color 200ms;
}

.action-link:hover {
  color: blue;
}
```

- без `transition` цвет изменится практически сразу
- с `transition` браузер создаст промежуточные значения между `black` и `blue`

```
без transition:

black ───────────────→ blue
       мгновенно


с transition:

black → dark gray → gray → blue
          плавный переход
```

## transition не запускает движение сам

- важный момент — `transition` не является самостоятельной анимацией
- ему нужно **изменение состояния**, которое вызовет переход

```css
.control-button {
  transform: scale(1);
  transition: transform 180ms;
}

.control-button:hover {
  transform: scale(1.05);
}
```

- когда `:hover` появляется, значение `transform` меняется с `scale(1)` на `scale(1.05)`

- `transition` делает этот переход плавным

- когда `:hover` исчезает, происходит обратный переход

```
normal
  ↓
hover
  ↓
плавное увеличение

hover
  ↓
normal
  ↓
плавное уменьшение
```

# свойства transition

- у `transition` есть несколько основных параметров

```css
.control-button {
  transition:
    transform 200ms ease,
    opacity 150ms linear;
}
```

- основные компоненты — `transition-property`, `transition-duration`, `transition-timing-function` и `transition-delay`

## transition-property

- определяет, какие свойства должны анимироваться

```css
.control-button {
  transition-property: transform;
}
```

- можно указать несколько:

```css
.control-button {
  transition-property: transform, opacity;
}
```

- `all` означает переход для всех подходящих изменяющихся свойств, но использовать `all` без необходимости обычно не рекомендуется

## transition-duration

- определяет продолжительность перехода

```css
.control-button {
  transition-duration: 200ms;
}
```

- можно использовать секунды:

```css
.control-button {
  transition-duration: 0.2s;
}
```

- `200ms` и `0.2s` эквивалентны

## transition-timing-function

- определяет **скорость изменения во времени**

```css
.control-button {
  transition-timing-function: ease;
}
```

- наиболее известные значения:

```
linear
ease
ease-in
ease-out
ease-in-out
```

- `linear` — скорость постоянная

- `ease-in` — медленнее в начале

- `ease-out` — медленнее в конце

- `ease-in-out` — медленнее в начале и конце

- также можно использовать `cubic-bezier()`

```css
.control-button {
  transition-timing-function: cubic-bezier(0.2, 0.8, 0.2, 1);
}
```

- это позволяет точно управлять кривой скорости

## transition-delay

- определяет задержку перед началом перехода

```css
.control-button {
  transition-delay: 100ms;
}
```

- например, `duration: 200ms` и `delay: 100ms` означают, что сначала браузер ждёт `100ms`, а затем выполняет переход в течение `200ms`

# shorthand transition

- чаще всего используют сокращённую запись

```css
.control-button {
  transition: transform 200ms ease 100ms;
}
```

- порядок соответствует:

```
property duration timing-function delay
```

- можно указать несколько переходов через запятую

```css
.control-button {
  transition:
    transform 200ms ease,
    opacity 150ms linear;
}
```

# какие свойства хорошо анимировать

- наиболее предпочтительны для производительности `transform` и `opacity`

```css
.panel-item {
  transition:
    transform 200ms ease,
    opacity 200ms ease;
}
```

- например:

```css
.panel-item:hover {
  transform: translateY(-4px);
  opacity: 0.9;
}
```

- браузеру обычно проще оптимизировать такие изменения, чем постоянное изменение геометрии layout

- свойства вроде `width`, `height`, `top`, `left`, `margin` могут приводить к перерасчёту layout и потенциально быть дороже

- это не означает, что их **нельзя** анимировать

- просто для производительности часто стоит сначала рассмотреть `transform`

# animations

- `animation` отличается от `transition` тем, что не требует изменения состояния вроде `:hover`
- animation использует **keyframes**, в которых описывается последовательность состояний

```css
@keyframes slide-in {
  from {
    transform: translateX(-20px);
    opacity: 0;
  }

  to {
    transform: translateX(0);
    opacity: 1;
  }
}
```

- затем animation назначается элементу:

```css
.notification-panel {
  animation: slide-in 300ms ease-out;
}
```

- браузер выполнит последовательность:

```
translateX(-20px), opacity 0
             ↓
        промежуточные
             ↓
translateX(0), opacity 1
```

# keyframes

- `@keyframes` определяет **ключевые состояния анимации**
- между этими состояниями браузер сам вычисляет промежуточные значения

```css
@keyframes loading-pulse {
  0% {
    opacity: 0.4;
  }

  50% {
    opacity: 1;
  }

  100% {
    opacity: 0.4;
  }
}
```

- здесь есть три ключевых состояния

```
0%       50%       100%
 │         │          │
 ↓         ↓          ↓
0.4       1.0        0.4
```

- браузер интерполирует значения между ними

## from и to

- если есть только начало и конец, можно использовать `from` и `to`

```css
@keyframes fade-show {
  from {
    opacity: 0;
  }

  to {
    opacity: 1;
  }
}
```

- это эквивалентно:

```css
@keyframes fade-show {
  0% {
    opacity: 0;
  }

  100% {
    opacity: 1;
  }
}
```

## несколько keyframes

- можно создать любое количество промежуточных состояний

```css
@keyframes attention-shake {
  0% {
    transform: translateX(0);
  }

  25% {
    transform: translateX(-5px);
  }

  50% {
    transform: translateX(5px);
  }

  75% {
    transform: translateX(-3px);
  }

  100% {
    transform: translateX(0);
  }
}
```

- это позволяет создавать сложные последовательности движений

# animation properties

- как и у `transition`, у animation есть несколько отдельных свойств

```css
.notification-panel {
  animation-name: slide-in;
  animation-duration: 400ms;
  animation-timing-function: ease-out;
  animation-delay: 100ms;
  animation-iteration-count: 2;
  animation-direction: normal;
  animation-fill-mode: both;
  animation-play-state: running;
}
```

## animation-name

- указывает имя `@keyframes`

```css
.notification-panel {
  animation-name: slide-in;
}
```

## animation-duration

- определяет продолжительность одного цикла

```css
.notification-panel {
  animation-duration: 500ms;
}
```

## animation-iteration-count

- определяет количество повторений

```css
.notification-panel {
  animation-iteration-count: 3;
}
```

- можно использовать `infinite`

```css
.notification-panel {
  animation-iteration-count: infinite;
}
```

- тогда animation будет повторяться бесконечно

## animation-direction

- определяет направление выполнения

```css
.loader-icon {
  animation-direction: alternate;
}
```

- основные варианты:

```
normal
reverse
alternate
alternate-reverse
```

- `normal` — каждый цикл идёт от начала к концу
- `reverse` — от конца к началу
- `alternate` — направления чередуются
- `alternate-reverse` — начинает в обратном направлении и затем чередуется

## animation-timing-function

- определяет скорость изменения значений

```css
.loader-icon {
  animation-timing-function: linear;
}
```

- для бесконечного вращения `linear` часто используется, чтобы скорость не менялась

## animation-delay

- определяет задержку перед стартом

```css
.notification-panel {
  animation-delay: 300ms;
}
```

# animation-fill-mode

- `animation-fill-mode` определяет, какие стили animation применяются **до начала и после окончания**

- основные значения:

```
none
forwards
backwards
both
```

### `forwards`

- после завершения animation элемент сохраняет состояние последнего keyframe

```css
.notification-panel {
  animation: slide-in 300ms forwards;
}
```

- без `forwards` после завершения animation обычные CSS-стили снова становятся актуальными

### `backwards`

- во время `animation-delay` применяются стили первого keyframe

### `both`

- сочетает поведение `forwards` и `backwards`

# animation-play-state

- позволяет поставить animation на паузу или продолжить её

```css
.loader-icon {
  animation-play-state: paused;
}
```

- значения:

```
running
paused
```

- это можно использовать, например, чтобы при наведении приостанавливать декоративную animation

# shorthand animation

- все основные параметры можно объединить

```css
.notification-panel {
  animation: slide-in 400ms ease-out 100ms 1 normal both;
}
```

- условно:

```
name
duration
timing-function
delay
iteration-count
direction
fill-mode
```

- при чтении сложного shorthand иногда удобнее использовать отдельные свойства, особенно если animation много

# transition vs animation

- это принципиальное различие, которое часто спрашивают

| Transition                                                         | Animation                                  |
| ------------------------------------------------------------------ | ------------------------------------------ |
| обычно переход между двумя состояниями                             | последовательность нескольких состояний    |
| обычно нужен trigger изменения состояния                           | может запускаться самостоятельно           |
| использует `transition`                                            | использует `@keyframes` + `animation`      |
| нет встроенных циклов                                              | можно повторять `infinite`                 |
| удобно для hover/focus                                             | удобно для сложных движений                |
| автоматически работает и в обратную сторону при возврате состояния | направление и повторение задаются отдельно |

- классический пример transition:

```css
.action-link {
  transform: scale(1);
  transition: transform 200ms;
}

.action-link:hover {
  transform: scale(1.05);
}
```

- классический пример animation:

```css
@keyframes rotate-loader {
  to {
    transform: rotate(360deg);
  }
}

.loader-icon {
  animation: rotate-loader 1s linear infinite;
}
```

- transition здесь отвечает на вопрос **«как плавно перейти из одного состояния в другое»**
- animation отвечает на вопрос **«как выполнить последовательность состояний во времени»**

# animation и JavaScript

- CSS animation и transition часто можно запускать и изменять через JavaScript
- например, JavaScript может добавить класс:

```js id="m9c4vw"
panelElement.classList.add('is-visible');
```

```css
.panel-element {
  opacity: 0;
  transform: translateY(10px);
  transition:
    opacity 200ms ease,
    transform 200ms ease;
}

.panel-element.is-visible {
  opacity: 1;
  transform: translateY(0);
}
```

- JavaScript здесь отвечает за **изменение состояния**

- CSS отвечает за **визуальный переход**

- это часто предпочтительнее, чем вручную изменять CSS-свойства через JavaScript на каждом кадре

# accessibility и `prefers-reduced-motion`

- некоторые пользователи испытывают дискомфорт от большого количества движения
- операционная система может сообщить браузеру, что пользователь предпочитает уменьшенное количество анимаций

```css
@media (prefers-reduced-motion: reduce) {
  .animated-element {
    animation: none;
    transition: none;
  }
}
```

- это особенно важно для полноэкранных, постоянно движущихся и декоративных animation
- при этом не всегда нужно полностью отключать всё движение
- иногда достаточно значительно уменьшить его продолжительность или заменить сложное движение простым изменением opacity

# производительность

- для анимаций чаще всего стоит отдавать предпочтение:

```css
animated {
  transform: translateX(20px);
  opacity: 0.5;
}
```

- а не постоянно изменять свойства, которые влияют на layout

```
transform / opacity
        ↓
обычно проще оптимизировать

width / height / top / left / margin
        ↓
могут вызывать дополнительные layout calculations
```

- `will-change` иногда используется для подсказки браузеру:

```css
.moving-element {
  will-change: transform;
}
```

- но `will-change` не следует добавлять ко всем элементам заранее
- чрезмерное использование может увеличить потребление ресурсов

# важный нюанс с `display: none`

- `transition` не позволяет плавно анимировать переход между `display: none` и `display: block`

- `display` не является обычным интерполируемым свойством для такого сценария

- вместо этого часто используют комбинацию:

```css
.dialog-panel {
  opacity: 0;
  visibility: hidden;
  transition:
    opacity 200ms ease,
    visibility 200ms;
}

.dialog-panel.is-open {
  opacity: 1;
  visibility: visible;
}
```

- здесь визуальное состояние меняется плавно, а `visibility` позволяет дополнительно контролировать доступность элемента для взаимодействия

# что важно запомнить

- `transition` — плавный переход **между состояниями**
- `animation` — самостоятельная последовательность состояний, описанная через `@keyframes`
- `@keyframes` содержит ключевые точки animation
- браузер вычисляет промежуточные значения между keyframes
- `animation-iteration-count: infinite` создаёт бесконечный цикл
- `animation-fill-mode` определяет, какие стили сохраняются до или после animation
- для производительности обычно предпочтительнее анимировать `transform` и `opacity`
- для accessibility нужно учитывать `prefers-reduced-motion`

# что сказать на собеседовании

- **CSS transition предназначен для плавного перехода свойства между двумя состояниями, например при `:hover`**
- **CSS animation использует `@keyframes`, где задаются ключевые состояния, и позволяет создавать более сложные последовательности, циклы и управлять направлением выполнения**
- **transition обычно требует изменения состояния, тогда как animation может запускаться самостоятельно**
- **для производительности предпочтительно анимировать `transform` и `opacity`, а для пользователей с повышенной чувствительностью к движению стоит учитывать `prefers-reduced-motion`**
