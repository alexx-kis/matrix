# responsive design — setup

- в предыдущей теме мы разобрали **что такое responsive design**, а здесь разберём именно **как его технически настроить в проекте**
- задача setup — сделать так, чтобы браузер правильно определял viewport, CSS мог реагировать на его размер, а layout корректно перестраивался

## базовая настройка viewport

- первым делом в HTML обычно добавляют `viewport` meta tag

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
```

- `width=device-width` говорит браузеру использовать ширину устройства как ширину CSS viewport

- `initial-scale=1.0` задаёт начальный масштаб страницы

- без этого responsive layout на мобильных устройствах может работать не так, как ожидается

## базовая структура responsive CSS

- дальше нужно строить layout так, чтобы он не зависел от одной фиксированной ширины

```css
.page-wrapper {
  width: 100%;
  max-width: 1200px;
  margin-inline: auto;
  padding-inline: 16px;
}
```

- `width: 100%` позволяет контейнеру занимать доступную ширину
- `max-width` ограничивает его максимальный размер на больших экранах
- `margin-inline: auto` центрирует контейнер
- `padding-inline` оставляет пространство между контентом и краями экрана

```
desktop

┌─────────────────────────────────────────────────────────┐
│                                                         │
│      ┌───────────────────────────────────────────┐      │
│      │               content                     │      │
│      └───────────────────────────────────────────┘      │
│                                                         │
└─────────────────────────────────────────────────────────┘


mobile

┌───────────────────────┐
│ ┌───────────────────┐ │
│ │      content      │ │
│ └───────────────────┘ │
└───────────────────────┘
```

## breakpoints через media queries

- основной механизм адаптации layout — `@media`

```css
.feature-layout {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 24px;
}

@media (max-width: 900px) {
  .feature-layout {
    grid-template-columns: repeat(2, 1fr);
  }
}

@media (max-width: 600px) {
  .feature-layout {
    grid-template-columns: 1fr;
  }
}
```

- здесь используется desktop-first подход
- сначала описан layout для большого экрана
- затем через `max-width` он постепенно упрощается

## mobile-first setup

- другой вариант — начать с мобильной версии

```css
.feature-layout {
  display: grid;
  grid-template-columns: 1fr;
  gap: 16px;
}

@media (min-width: 601px) {
  .feature-layout {
    grid-template-columns: repeat(2, 1fr);
    gap: 20px;
  }
}

@media (min-width: 901px) {
  .feature-layout {
    grid-template-columns: repeat(3, 1fr);
    gap: 24px;
  }
}
```

- здесь базовые стили работают для маленьких экранов

- затем для более широких экранов добавляются возможности

- такой подход называется **mobile-first**

## почему часто используют mobile-first

- маленький экран имеет меньше доступного пространства
- поэтому сначала приходится определить действительно необходимое содержимое
- затем на больших экранах можно постепенно добавлять дополнительные элементы и пространство

```
mobile
  ↓
минимальный layout
  ↓
tablet
  ↓
расширенный layout
  ↓
desktop
  ↓
полный layout
```

- это также хорошо сочетается с progressive enhancement

## breakpoint не обязан соответствовать устройству

- распространённая ошибка — создавать breakpoints специально под конкретные устройства

```
❌ iPhone
❌ iPad
❌ Samsung
❌ MacBook
```

- правильнее смотреть на сам layout

- breakpoint нужен там, где текущая структура перестаёт быть удобной

- например, если три карточки перестают нормально помещаться при `840px`, можно сделать breakpoint около этого значения

```css
@media (max-width: 840px) {
  .feature-layout {
    grid-template-columns: 1fr;
  }
}
```

- поэтому breakpoint называют **content-based**, если он определяется содержимым, а не конкретным устройством

## относительные единицы

- responsive layout не должен состоять только из `px`
- для адаптивности часто используются `%`, `vw`, `vh`, `rem`, `em`, а также функции CSS

```css
.content-column {
  width: 80%;
}

.page-heading {
  font-size: clamp(2rem, 5vw, 4rem);
}
```

- `%` обычно рассчитывается относительно определённого размера родительского элемента
- `vw` зависит от ширины viewport
- `vh` зависит от высоты viewport
- `rem` зависит от размера шрифта root element
- `clamp()` позволяет задать минимальное, предпочтительное и максимальное значение

## min-width и max-width

- `min-width` и `max-width` позволяют ограничить область, в которой элемент может изменяться

```css
.article-column {
  width: 100%;
  max-width: 720px;
}
```

- это позволяет элементу быть fluid на маленьком экране, но не становиться чрезмерно широким на большом

- можно использовать и минимальную ширину

```css
.data-panel {
  min-width: 280px;
}
```

- но с `min-width` нужно быть осторожным на маленьких экранах, потому что слишком большое минимальное значение может вызвать горизонтальный overflow

## responsive images

- изображения тоже должны адаптироваться к ширине контейнера

```css
.content-image {
  display: block;
  max-width: 100%;
  height: auto;
}
```

- `max-width: 100%` не позволяет изображению стать шире родителя
- `height: auto` сохраняет исходное соотношение сторон

## responsive typography

- текст тоже должен адаптироваться

```css
.page-heading {
  font-size: clamp(2rem, 6vw, 4.5rem);
}
```

- `clamp(min, preferred, max)` работает так:

```
минимум ← предпочтительное значение → максимум
```

- например, если viewport увеличивается, размер шрифта может плавно увеличиваться, но не выйти за установленные границы

## responsive spacing

- адаптировать можно не только ширину и шрифт, но и spacing

```css
.content-section {
  padding-block: clamp(32px, 6vw, 96px);
}
```

- на маленьком экране отступ будет меньше
- на большом — больше
- при этом не обязательно создавать отдельный breakpoint

## overflow

- responsive layout должен контролировать ситуацию, когда содержимое становится шире контейнера

```css
.page-wrapper {
  max-width: 100%;
  overflow-x: hidden;
}
```

- однако использовать `overflow-x: hidden` как универсальное средство исправления responsive-проблемы не стоит

- если появляется горизонтальный scroll, сначала нужно найти элемент, который создаёт переполнение

- типичные причины:

```
слишком большая фиксированная width
        ↓
min-width слишком большой
        ↓
длинный текст без переноса
        ↓
изображение шире контейнера
        ↓
элемент с transform / position выходит за пределы
```

## responsive navigation

- при адаптации часто меняется не только размер, но и сама структура интерфейса

```css
.site-menu {
  display: flex;
}

@media (max-width: 700px) {
  .site-menu {
    display: none;
  }
}
```

- например, desktop navigation может быть заменена мобильной кнопкой меню
- при этом нужно учитывать accessibility и не делать важный интерфейс доступным только через CSS-визуализацию

## responsive Grid без большого количества breakpoints

- современные CSS-возможности позволяют сделать адаптивную сетку иногда вообще без media queries

```css
.product-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(240px, 1fr));
  gap: 20px;
}
```

- `minmax(240px, 1fr)` говорит, что колонка не должна становиться уже `240px`, но при наличии свободного места может занимать дополнительное пространство

- `auto-fit` позволяет браузеру автоматически определить количество подходящих колонок

- например:

```
широкий экран

┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐
│      │ │      │ │      │ │      │
└──────┘ └──────┘ └──────┘ └──────┘


узкий экран

┌──────┐ ┌──────┐
│      │ │      │
└──────┘ └──────┘


ещё уже

┌──────┐
│      │
└──────┘
```

- это один из хороших примеров того, что responsive design не обязательно означает большое количество `@media`

## `auto-fit` и `auto-fill`

- `auto-fit` старается растянуть существующие колонки, заполняя доступное пространство
- `auto-fill` сохраняет потенциальные tracks, даже если для некоторых из них пока нет элементов
- в большинстве типичных responsive-card layouts чаще используют `auto-fit`

## container queries

- ещё один современный подход — **container queries**
- обычный media query реагирует на размер viewport
- container query позволяет компоненту реагировать на размер собственного контейнера

```css
.card-list {
  container-type: inline-size;
}

@container (min-width: 600px) {
  .profile-card {
    display: grid;
    grid-template-columns: 160px 1fr;
  }
}
```

- это особенно полезно для переиспользуемых компонентов
- компоненту не обязательно знать, насколько широк весь экран
- ему важно только, сколько места выделил его конкретный контейнер

```
viewport
┌─────────────────────────────────────────┐
│                                         │
│   container A       container B         │
│   ┌──────────┐      ┌──────────────┐    │
│   │ component│      │   component  │    │
│   └──────────┘      └──────────────┘    │
│                                         │
└─────────────────────────────────────────┘

container query
      ↓
реагирует на размер component container
```

- это важное отличие от классических media queries

## responsive setup в итоге

```
HTML
 │
 ├── viewport meta
 │
 ↓
CSS
 │
 ├── fluid widths
 ├── max/min constraints
 ├── Flexbox / Grid
 ├── responsive images
 ├── responsive typography
 ├── media queries
 └── container queries
 │
 ↓
адаптация под доступное пространство
```

## что важно помнить

- responsive design не означает «написать несколько media queries»
- основа — это гибкий layout, который способен использовать доступное пространство
- media queries нужны, когда layout должен **переключиться** между разными вариантами
- `clamp()`, Grid, Flexbox и другие современные возможности позволяют сделать много адаптации без breakpoint
- breakpoint лучше выбирать по содержимому, а не по названиям устройств
- mobile-first означает, что базовые стили рассчитаны на маленький экран, а более широкие варианты добавляются через `min-width`
- viewport meta tag необходим для корректной работы responsive layout на мобильных устройствах
- container queries позволяют адаптировать компоненты к размеру контейнера, а не всего viewport

## что сказать на собеседовании

- **для настройки responsive design сначала задают корректный viewport через meta tag, затем строят fluid layout с помощью Flexbox, Grid, относительных единиц и ограничений `min/max`**
- **для изменения layout в зависимости от ширины используются media queries, причём breakpoints лучше выбирать по моменту, когда контент перестаёт нормально помещаться**
- **часто применяется mobile-first подход, где базовые стили рассчитаны на маленький экран, а для больших экранов добавляются правила через `min-width`**
- **современный responsive CSS также позволяет использовать `clamp()`, `auto-fit`/`minmax()` в Grid и container queries, поэтому далеко не всегда требуется большое количество breakpoints**
