# selectors and their weight

- **CSS-селектор** — это часть CSS-правила, которая определяет, к каким HTML-элементам применяются стили

```css
button {
  color: red;
}
```

- здесь `button` — селектор, а `color: red` — объявление стиля

## основные виды селекторов

### universal selector

- универсальный селектор `*` выбирает все элементы

```css
* {
  box-sizing: border-box;
}
```

- его часто используют для базового сброса или настройки поведения всех элементов

### type selector

- выбирает элементы по имени HTML-тега

```css
p {
  color: gray;
}

button {
  cursor: pointer;
}
```

- такой селектор имеет относительно низкую специфичность

### class selector

- выбирает элементы по значению атрибута `class`

```css
.card {
  padding: 20px;
}
```

- один элемент может иметь несколько классов

```html
<div class="card featured"></div>
```

- поэтому class selector очень часто используется для стилизации

### id selector

- выбирает элемент по значению `id`

```css
#header {
  height: 80px;
}
```

- `id` должен идентифицировать конкретный элемент на странице, поэтому использовать `id` для обычной стилизации обычно не рекомендуется

### attribute selector

- выбирает элементы по наличию или значению HTML-атрибута

```css
input[type='email'] {
  border-color: blue;
}
```

- можно проверять и само наличие атрибута

```css
[disabled] {
  opacity: 0.5;
}
```

- существуют и другие варианты сравнения значений

```css
[class^='icon-'] {
  /* class начинается с "icon-" */
}

[class$='-active'] {
  /* class заканчивается на "-active" */
}

[class*='card'] {
  /* class содержит "card" */
}
```

## combinators

- combinator определяет отношение между элементами

### descendant

```css
.card p {
  color: gray;
}
```

- выбирает `p`, находящиеся внутри `.card` на любом уровне вложенности

```html
<div class="card">
  <section>
    <p>Text</p>
  </section>
</div>
```

- `p` подходит, потому что он является потомком `.card`

### child

```css
.card > p {
  color: gray;
}
```

- `>` означает **непосредственного ребёнка**

```html
<div class="card">
  <p>Text</p>
</div>
```

- здесь `p` подходит

```html
<div class="card">
  <section>
    <p>Text</p>
  </section>
</div>
```

- здесь `p` уже не подходит, потому что непосредственный ребёнок `.card` — это `section`

### adjacent sibling

```css
h2 + p {
  margin-top: 0;
}
```

- `+` выбирает элемент, который непосредственно следует за указанным элементом на том же уровне

```html
<h2>Title</h2>
<p>Text</p>
```

- здесь `p` подходит

### general sibling

```css
h2 ~ p {
  color: gray;
}
```

- `~` выбирает последующих соседей, которые находятся на том же уровне

```html
<h2>Title</h2>
<div>Something</div>
<p>Text</p>
<p>Another text</p>
```

- оба `p` подходят

## pseudo-classes

- **псевдокласс** описывает состояние элемента или определённое условие

```css
button:hover {
  background: black;
}

input:focus {
  outline: 2px solid blue;
}
```

- `:hover` означает состояние наведения

- `:focus` означает состояние фокуса

- другие распространённые псевдоклассы

```css
:first-child
:last-child
:nth-child()
:not()
:checked
:disabled
:required
```

- например

```css
li:nth-child(2) {
  color: red;
}
```

- выберет второй `li` среди соответствующих соседей

## pseudo-elements

- **псевдоэлемент** позволяет стилизовать определённую виртуальную часть элемента

```css
.card::before {
  content: '';
  display: block;
}
```

- распространённые псевдоэлементы

```css
::before
::after
::first-letter
::first-line
::selection
```

- `::before` и `::after` особенно часто используются для декоративных элементов

## selector list

- несколько селекторов можно объединить через запятую

```css
h1,
h2,
h3 {
  font-weight: 600;
}
```

- правило будет применено ко всем трём типам элементов

## specificity — вес селектора

- когда несколько CSS-правил подходят одному элементу и задают одно и то же свойство, браузеру нужно определить, какое правило победит

- для этого используется **specificity**, которую часто называют весом или специфичностью селектора

- чем выше specificity, тем выше приоритет конкретного правила

- основная иерархия выглядит так

```
inline styles
    ↓
ID
    ↓
class / attribute / pseudo-class
    ↓
element / pseudo-element
```

- это не означает, что браузер просто сравнивает количество символов или количество селекторов

- specificity фактически можно представить как несколько независимых категорий

```
(A, B, C, D)
```

- `A` — inline styles

- `B` — количество `id`

- `C` — количество class, attribute и pseudo-class

- `D` — количество element и pseudo-element

## пример расчёта

```css
#menu .item {
  color: red;
}
```

- здесь один `id` и один `class`

```
(0, 1, 1, 0)
```

- другой селектор

```css
.menu .item.active {
  color: blue;
}
```

- здесь три class

```
(0, 0, 3, 0)
```

- первый селектор победит, потому что `ID` имеет отдельную более высокую категорию

## важный нюанс с "количеством"

- нельзя просто сказать, что `10` классов всегда сильнее одного `id`

- например

```css
#menu {
  color: red;
}

.a.b.c.d.e.f.g.h.i.j {
  color: blue;
}
```

- `#menu` всё равно имеет более высокую specificity

- сравнение идёт слева направо по категориям

```
(0,1,0,0)
(0,0,10,0)
 ↑
сначала сравнивается эта категория
```

- как только найдена отличающаяся более приоритетная категория, остальные уже не имеют значения

## пример с элементами

```css
p {
  color: red;
}
```

```
(0,0,0,1)
```

```css
.article p {
  color: blue;
}
```

```
(0,0,1,1)
```

- `.article p` победит, потому что у него есть один class

```css
#content .article p {
  color: green;
}
```

```
(0,1,1,1)
```

- это правило имеет ещё более высокую specificity из-за `id`

## `!important`

- `!important` меняет обычный порядок приоритетов

```css
p {
  color: red !important;
}
```

- такое правило может победить обычное правило с большей specificity

- например

```css
#content p {
  color: blue;
}

p {
  color: red !important;
}
```

- `red` победит из-за `!important`

- при этом `!important` не следует использовать как обычный способ повышения specificity

- большое количество `!important` обычно приводит к тому, что CSS становится трудно переопределять и поддерживать

## source order

- specificity — не единственный фактор

- если два правила имеют одинаковую specificity, победит правило, которое находится **позже** в CSS

```css
.button {
  color: red;
}

.button {
  color: blue;
}
```

- результатом будет `blue`

- здесь specificity одинаковая, поэтому срабатывает порядок следования

## specificity у `:where()` и `:is()`

- это особенно полезный нюанс для собеседования

- `:where()` всегда имеет **нулевую specificity**

```css
:where(.card) p {
  color: red;
}
```

- несмотря на наличие `.card`, specificity этого селектора определяется только `p`

```
(0,0,0,1)
```

- `:is()` ведёт себя иначе — его specificity определяется наиболее специфичным аргументом

```css
:is(#main, .card) p {
  color: red;
}
```

- здесь внутри `:is()` есть `#main`, поэтому specificity учитывает `id`

## главное для собеседования

- селекторы определяют, какие элементы будут стилизоваться

- основные селекторы — `*`, element, class, `id`, attribute, combinators, pseudo-classes и pseudo-elements

- **specificity** определяет приоритет CSS-правила при конфликте

- порядок specificity можно запомнить как `inline → id → class/attribute/pseudo-class → element/pseudo-element`

- если specificity одинаковая, побеждает правило, расположенное позже

- `!important` имеет отдельный высокий приоритет и должен использоваться крайне осторожно

- хорошая практика — держать specificity как можно более низкой и предсказуемой, предпочитая классы вместо сложных цепочек `id` и вложенных селекторов
