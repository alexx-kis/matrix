# responsive design

- **Responsive design** — это подход к созданию интерфейса, при котором страница автоматически адаптируется под разные размеры экрана и разные условия использования
- главная идея — один и тот же сайт должен нормально работать на широком мониторе, ноутбуке, планшете и смартфоне без создания отдельной версии сайта для каждого устройства

## зачем нужен responsive design

- раньше сайты часто проектировали преимущественно под конкретную ширину экрана, например `1024px`

- на маленьком экране такой сайт приходилось масштабировать, горизонтально прокручивать или делать отдельную мобильную версию

- сегодня размеры экранов слишком разнообразны, поэтому правильнее сделать интерфейс адаптивным

- важно понимать, что responsive design — это не просто «уменьшить всё на телефоне»

- элементы могут менять размеры, расположение, количество колонок, отступы и даже способ взаимодействия

например, на desktop:

```
┌─────────────────────────────────────────────┐
│                    header                   │
├───────────────┬─────────────────────────────┤
│   sidebar     │          content            │
│               │                             │
│               │                             │
└───────────────┴─────────────────────────────┘
```

- а на мобильном устройстве тот же интерфейс может превратиться в:

```
┌─────────────────────┐
│       header        │
├─────────────────────┤
│       content       │
│                     │
│                     │
├─────────────────────┤
│       sidebar       │
└─────────────────────┘
```

## основные идеи responsive design

### fluid layout

- **fluid layout** — интерфейс использует относительные размеры и способен плавно изменяться вместе с шириной viewport
- вместо того чтобы задавать всему фиксированную ширину `1200px`, можно использовать проценты, `max-width`, `min()`, `max()`, `clamp()` и другие инструменты CSS

например:

```css
.page-shell {
  width: 90%;
  max-width: 1200px;
  margin-inline: auto;
}
```

- при широком экране элемент может перестать увеличиваться после `1200px`
- при уменьшении экрана он начинает занимать доступную ширину

### flexible elements

- элементы интерфейса тоже должны уметь изменять размер
- например, изображение не должно вылезать за пределы родителя

```css
.preview-image {
  max-width: 100%;
  height: auto;
}
```

- здесь `max-width: 100%` означает, что изображение не должно быть шире своего контейнера

### breakpoints

- **breakpoint** — это условная граница ширины viewport, после которой интерфейс переключается на другой вариант расположения
- чаще всего breakpoints реализуются через `@media`

```css
.feature-grid {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
}

@media (max-width: 900px) {
  .feature-grid {
    grid-template-columns: repeat(2, 1fr);
  }
}

@media (max-width: 600px) {
  .feature-grid {
    grid-template-columns: 1fr;
  }
}
```

- здесь на широком экране будет три колонки

- до `900px` останется две

- до `600px` останется одна

- конкретные значения `600px`, `900px` и другие не являются универсальным стандартом

- breakpoint должен определяться содержимым интерфейса, а не конкретной моделью телефона

## mobile-first

- **mobile-first** — подход, при котором сначала создают интерфейс для маленького экрана, а затем добавляют улучшения для более широких экранов

```css
.mobile-nav {
  display: block;
}

@media (min-width: 768px) {
  .mobile-nav {
    display: flex;
  }
}
```

- базовые стили здесь предназначены для маленького экрана

- затем через `min-width` добавляется desktop-вариант

- противоположный подход называется **desktop-first**

- там сначала пишут desktop-стили, а затем через `max-width` адаптируют их для меньших экранов

```css
.dashboard-area {
  display: grid;
  grid-template-columns: 280px 1fr;
}

@media (max-width: 767px) {
  .dashboard-area {
    grid-template-columns: 1fr;
  }
}
```

- mobile-first обычно удобнее для адаптивной разработки, потому что сначала приходится определить самое важное содержимое и минимально необходимый интерфейс
- при этом сам по себе mobile-first не является обязательным правилом

## viewport

- responsive design зависит не только от физического размера устройства, но прежде всего от размера **viewport**

- viewport — это область браузера, в которой отображается веб-страница

- для мобильных устройств важно правильно указать viewport через `<meta>`

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
```

- `width=device-width` говорит браузеру использовать ширину устройства как ширину CSS viewport

- `initial-scale=1.0` задаёт начальный масштаб страницы

- без этого мобильный браузер исторически мог использовать виртуальный viewport шириной около desktop-размера и затем масштабировать страницу, из-за чего media queries работали не так, как ожидалось

## responsive typography

- адаптироваться должны не только блоки, но и текст

- слишком большой desktop-заголовок может занимать несколько строк на мобильном экране

- для плавного изменения размера часто используется `clamp()`

```css
.hero-heading {
  font-size: clamp(2rem, 5vw, 4rem);
}
```

- `2rem` — минимальный размер

- `5vw` — предпочтительный размер, зависящий от ширины viewport

- `4rem` — максимальный размер

- поэтому размер шрифта изменяется плавно, а не только скачком в момент срабатывания media query

## responsive images

- изображения должны учитывать доступное пространство
- базовый вариант:

```css
.gallery-photo {
  width: 100%;
  height: auto;
}
```

- для более сложных случаев можно использовать `<picture>` и `srcset`, чтобы браузер выбирал подходящий ресурс

```html
<img
  src="photo-small.jpg"
  srcset="photo-small.jpg 480w, photo-medium.jpg 800w, photo-large.jpg 1200w"
  sizes="(max-width: 600px) 100vw, 50vw"
  alt="Описание изображения"
/>
```

- это уже не только визуальная адаптация, но и оптимизация загрузки
- мобильному устройству нет смысла всегда скачивать огромную desktop-картинку

## responsive navigation

- навигация часто меняется сильнее остальных элементов
- например, desktop может показывать все пункты:

```
Home   Products   Pricing   About   Contact
```

- а мобильный вариант может использовать кнопку открытия меню:

```
☰
```

- это хороший пример того, что responsive design может менять не только размеры, но и структуру взаимодействия

## что responsive design не означает

- responsive design не означает, что все элементы должны постоянно уменьшаться пропорционально экрану
- иногда элемент должен перестроиться
- иногда элемент должен исчезнуть
- иногда элементы должны поменяться местами
- иногда несколько колонок должны стать одной
- иногда desktop-навигация должна превратиться в mobile menu
- поэтому правильнее воспринимать responsive design как **адаптацию layout и поведения интерфейса**, а не как простое масштабирование

## responsive design и adaptive design

- эти термины часто используют как синонимы, но концептуально между ними можно провести различие
- **responsive design** обычно подразумевает плавное изменение интерфейса в зависимости от доступного пространства
- **adaptive design** чаще подразумевает несколько заранее подготовленных вариантов интерфейса для определённых диапазонов размеров

например:

```
responsive:

1200px ──────────────── 900px ──────────────── 600px
       плавное изменение размеров и layout


adaptive:

desktop layout ──┐
                 ├── tablet layout
                 │
                 └── mobile layout
```

- на практике современные проекты часто используют комбинацию обоих подходов

## важный принцип для собеседования

- не стоит думать о responsive design как о наборе «магических размеров для iPhone, iPad и desktop»
- правильнее начинать с контента и спрашивать: **при какой ширине текущий layout перестаёт быть удобным**
- именно в этот момент и появляется необходимость breakpoint
- например, если карточки нормально помещаются в три колонки до `960px`, но после этого текст становится слишком узким, breakpoint логично поставить примерно там, а не потому что существует устройство с шириной ровно `960px`

## что обычно используется для responsive design

- основными инструментами являются `@media`, Flexbox, CSS Grid, относительные единицы измерения, `min-width`, `max-width`, `min()`, `max()`, `clamp()`, responsive images и правильный viewport
- JavaScript для обычной responsive-вёрстки обычно не нужен
- CSS сам умеет реагировать на размеры viewport и менять layout

## что сказать на собеседовании

- **responsive design — это подход к разработке интерфейса, при котором layout и размеры элементов адаптируются под доступное пространство и разные устройства**
- **основные инструменты — media queries, Flexbox, Grid, относительные единицы, ограничения через min/max и responsive images**
- **breakpoints лучше выбирать исходя из того, когда текущий layout перестаёт работать, а не под конкретные модели устройств**
- **часто используется mobile-first подход, когда базовые стили рассчитаны на маленький экран, а для больших экранов добавляются улучшения через `min-width`**
